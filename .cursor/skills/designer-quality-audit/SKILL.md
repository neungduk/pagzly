# 디자이너 수준 감사

## 판단 기준

- 결과를 경쟁 상위 페이지 옆에 놓았을 때 뒤처져 보이지 않는가.
- 규칙을 지켰다는 것만으로는 완료가 아니다.

## 절차

1. 6카테고리 견본 풀 페이지를 390·750 폭으로 캡처한다.
   - 지연 로딩 사진은 천천히 스크롤하고, 모든 `img`에 `decode()`를 기다린 뒤 찍는다. 빈 사진 칸이 캡처 문제인지 먼저 가린다.
2. `review/285cha-bench`, `review/competitor-screens`의 상위 페이지를 같은 폭으로 나란히 놓고 비교한다.
3. 아래 체크리스트로 약한 곳을 찾는다.
4. 영향도 × 수정 난이도 표를 만들고, 영향도가 큰 것부터 고친다.
5. 수정 전후 캡처를 `review/` 아래에 남긴다(섹션 단위 나란히 이미지).

## 체크리스트

- [ ] 섹션 간 여백 리듬이 일정한가. 이유 없는 큰 빈칸이나 답답한 구간이 없는가
- [ ] 타이포 위계(제목·부제·본문·캡션)가 한눈에 읽히는가
- [ ] 이미지 비율과 크롭이 자연스러운가. 제품이 잘리거나 작게 떠 있지 않은가
- [ ] 줄바꿈이 어색하거나 한 글자만 남는 곳이 없는가
- [ ] 색이 3색 토큰(accent / baseNeutral / deepAccent) 안에서 정돈되어 있는가
- [ ] 인포그래픽의 수치·라벨이 입력 정보에 근거하는가
- [ ] 의미 없는 배지, 장식, 중복 문장이 없는가

## 표 형식

| # | 발견 | 영향 | 난이도 | 처리 |
|---|---|---|---|---|
| 1 | (무엇이 어디서 어떻게 약한지) | 높음/중간/낮음 | 높음/중간/낮음 | 수정 / 다음 후보 |

## 주의

- 경쟁사 이름은 `review/` 안에서만 쓴다. Pagzly 출력·UI·코드에는 쓰지 않는다.
- 렌더링을 고치면 live-export-parity 스킬 절차를 함께 따른다.
