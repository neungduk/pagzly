## 2. 그림자 가시성 진단

`npx tsx scripts/258cha-shadow-visibility-diagnose.ts` → `review/258cha-shadow-diagnosis/`

- `pasteCutoutOnScene()`의 단계(회전·리사이즈 → 페더 → WB → 선명도 → 그레인 → 주변색 틴트 → 실루엣 그림자 multiply → 붙이기)를 같은 lib 함수로 재조립해 **그림자 합성 유무만 다른 두 장**을 만듦.
- 재조립 정확도: with-shadow 결과가 실제 `pasteCutoutOnScene()` 출력과 **14/14 케이스 바이트 동일**.
- 측정 영역: 그림자 알파 ≥ 3/255 이고 컷아웃이 덮지 않는 픽셀.
- 컷아웃·placement는 257차와 같음(실사진 4장은 `xPct 36 / yPct 50`). 그림자 입력은 `DEFAULT_SHADOW`(intensity 0.18 → opacity 0.26).
- ΔL* = CIE L* 차이. 대략 1 ≈ 겨우 구분 가능, 2 이상 ≈ 확실히 보임.

### 2-2. 해석

- **가설 맞음.** 지각 변화(ΔL*)는 씬 밝기에 거의 비례해 줄어들고, 밝기 16 이하에서는 **눈에 보이는 픽셀이 0%**. 257 씬에서도 상품을 검정 배경 쪽에 놓으면 그림자는 0%, 손바닥(밝기 53) 위에 놓은 지금 배치에선 39%가 겨우 보이는 수준.
- 원인은 "곱셈 비율이 작아서"가 아님: % 변화는 어두운 곳에서도 5~16%로 밝은 곳(4~5%)과 같거나 큼. **어두운 픽셀은 어둡게 만들 여지 자체가 없음.** 예: 밝기 6.3의 L*는 약 1.7 → 그림자를 **완전한 검정·불투명**으로 칠해도 최대 ΔL* 1.7.
- 그림자 자체도 약함: 영역 평균 그림자 알파 0.043~0.05 (opacity 상한 0.26을 σ 6~28 블러로 넓게 펴서). 중간 밝기(128)에서도 최대 ΔL* 5.9.

### 2-3. 옵션 검토 (코드화 안 함)

**(a) 어두운 씬에서만 opacity를 올리거나 darken/overlay 섞기**
- darken: 결과 = min(씬, 그림자색). 그림자색이 씬보다 어두워야만 효과가 있고, 효과 상한은 multiply와 같이 "씬 → 0"까지. 여지가 없는 건 똑같음.
- overlay: 씬이 어두운(< 128) 쪽에서는 결과 = 2 × 씬 × 그림자색 / 255 → multiply와 같은 곱셈 계열이라 여지 문제 동일.
- opacity 상향: 밝기 20~60 구간(257 씬의 손바닥·천 같은 곳)에서는 실제로 효과 있음 — 예: 회색 32에서 알파를 2배로 올리면 ΔL* 약 2 수준 기대(선형 근사). 밝기 < 16 구간은 어떤 blend mode로도 1.7 이하.
- → **부분 효과만.** 거의 검정인 배경에서는 수학적으로 불가능.

**(b) 접촉부 미세 하이라이트(밝은 림)** — 가능성만 기록
- 어두운 배경에는 **밝게 만들 여지**가 큼(밝기 6.3 → 20만 올려도 ΔL* ≈ 4.5 — 같은 곳에 완전한 검정 그림자를 칠할 때의 최대치 1.7의 약 2.6배). 그림자와 반대 방향의 신호라 이 구간에서 산술적으로 훨씬 잘 보임.
- 실제 저조도 사진에서 물체 경계가 보이는 건 주로 반사광/림 라이트 때문이라 방향상 자연스러울 수 있음. 단 광원이 없는 곳에 림을 넣으면 오히려 "오려 붙인 티"가 날 위험 — 씬의 하이라이트 방향 추정과 같이 설계해야 함. 새 기능이라 이번엔 기록만.

### 2-4. 새 발견 — 실루엣 그림자가 사각형으로 잘림 (수정 안 함)

`*-diff-x8.png`(그림자 유무 차이 × 8)을 보면 그림자 영역 가장자리가 **직선 사각형**으로 끊김. 257 씬(`257-scene-A-placement_palm_case-diff-x8.png`)과 밝은 씬(`real_L_214_02-pexels-6801218-diff-x8.png`) 모두 동일.

원인 (`lib/photo-composite.ts` `buildSilhouetteShadowBuffer`, 734~785행):
- 실루엣을 컷아웃과 **같은 크기(w×h) 캔버스**에 그린 뒤 `blur(σ)` — 여백 없이 블러하므로 번짐이 캔버스 경계에서 잘림.
- σ = 6~28px(짧은 변 × 0.055)라 번짐이 자연스럽게 사라지려면 3σ ≈ 18~84px 여백이 필요한데,
- 두 경로 모두 컷아웃을 `trimCutoutToOpaqueBounds(buffer)`(기본 여백 6px)로 잘라서 넘김 — 라이프스타일 `lib/lifestyle-product-composite.ts:738`, 히어로 `lib/photo-enhance.ts:1713`.
- → 프로덕션에서도 히어로·라이프스타일 둘 다 그림자 가장자리가 bbox(+오프셋) 모양으로 잘리고 있을 가능성이 높음. 밝은 배경일수록 잘 보임.

제안(다음 라운드, 유료 API 불필요): 블러 전에 실루엣 캔버스를 사방 `ceil(3σ)`만큼 투명 확장(`extend`)하고 합성 좌표를 같은 만큼 빼기. 순수 sharp 연산이라 이 진단 스크립트로 전/후 diff 바로 확인 가능. 브리프가 이번 라운드 그림자 수정을 금지해서 손대지 않음.
