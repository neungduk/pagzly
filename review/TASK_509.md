# 509차 — OCR 마무리 보강(시간 제한·회원 화면 통일·한도 안내)

> 순서: 508차 완료 후(완료·검토됨). 이번은 **작은 보강**이다. 새 기능 추가 금지.

## 0. 절대 규칙
1. 실제 OCR·네트워크 호출, 키·`.env*` 열람/생성/커밋 금지. 테스트는 fixture·가짜 fetch만. main push 금지, 코드 삭제 금지, 새 의존성 금지.
2. 판정 규칙·`review/data/*` 수정 금지. 금지어 검사 통과. `node_modules/next/dist/docs/`에서 route `maxDuration` 설명을 먼저 읽는다.
3. 마무리 전: `npx tsc --noEmit`, `npm run build`, `npm run regression:label-check`. 커밋 최대 4개. 보고서 `review/509cha-report.md`(맨 위 "확인하지 못한 항목"). **보고서의 커밋 해시는 push 후 `git log --oneline`으로 확인한 실제 값만 적는다**(508 보고서의 해시가 실제 로그와 달랐다).

## 1. 이미 한 것(건드리지 말 것)
`label_ocr_usage` 테이블과 `label_ocr_consume` 함수는 **내가 Supabase에 적용했고** 동작을 확인했다. 그 과정에서 `anon`·`authenticated`가 함수를 실행할 수 있는 것을 발견해 **권한을 회수**했다(서버 `service_role`만 실행). 마이그레이션 파일은 이미 같은 내용으로 고쳐 두었다. 이 파일은 수정하지 않는다.

## 2. 작업
### 2-1. 공급자 호출에 시간 제한
- `ocr/clova.ts`, `ocr/google-vision.ts`의 `fetch`마다 `AbortController`로 **호출당 8초** 제한. 시간 초과는 일반 오류 문구로 처리(`OCR_TIMEOUT` 코드, 키·응답 원문 노출 금지).
- 현재 route의 `maxDuration = 10`: 문서를 읽고 **Hobby에서 허용되는 값 범위**를 보고서에 적는다. 허용 범위가 더 크면 값을 올리고, 아니면 한 요청당 조각 수를 **CLOVA 6개 / Google 8개 이하**로 줄여 클라이언트가 더 잘게 나눠 보내게 한다(동시 4개 기준으로 10초 안에 끝나는지 계산식을 보고서에 적는다).
- 시간 초과가 난 조각은 **이미 consume한 수를 되돌리지 않는다**(보수적, 기존 정책 유지)고 코드 주석에 쓴다.

### 2-2. 회원 `/label-check/new`의 OCR 확인 화면을 게스트와 동일하게
- 508 보고서에 "회원 화면은 게스트와 동일 수준으로 복제하지 않음"이라 적혀 있다. **게스트용 OCR 확인 컴포넌트(읽은 글자 편집, 보정 표시, 외부 전송 안내, 신뢰도 낮음 경고)를 공용 컴포넌트로 빼서 두 화면이 같이 쓰게** 한다. 회원은 점검 후 기존대로 저장(`unreadable`은 저장 안 함, 기존 규칙 유지).
- 320px·390px에서 가로 스크롤이 없어야 한다(정적 검사 또는 CSS 규칙 점검으로 확인).

### 2-3. 한도 도달 시 화면 문구
- `OCR_LIMIT`(월 한도/일일 한도)일 때 고객 문구를 구분: 월 한도 → "이번 달 사진 읽기 한도에 도달했어요. 문구 붙여넣기로 점검해 주세요.", 일일 한도 → "오늘 사진 읽기 횟수를 모두 사용했어요. 내일 다시 시도하거나 문구 붙여넣기로 점검해 주세요."
- 둘 다 **붙여넣기 입력칸으로 이동하는 버튼**을 함께 보여준다. 점수 칸·"발견된 항목이 없어요"는 표시 금지(508 규칙 유지).

### 2-4. 테스트
- `label-check-509-ocr-hardening.ts`: (1) 공급자 fetch가 8초 넘게 멈추는 가짜 → `OCR_TIMEOUT`, 응답에 키·원문 없음 (2) 조각 상한 분할 계산(CLOVA 6/Google 8) (3) 한도 문구 두 종류 (4) 공용 확인 컴포넌트가 게스트·회원 양쪽에서 쓰이는지 정적 검사. 기존 19개 묶음 + 새 묶음 통과, `label-check-suites.ts` 등록.

## 3. 하지 말 것
실제 호출·키 열람, 마이그레이션 수정(이미 적용됨), 판정 규칙 변경, 상세페이지·결제 화면 변경.
