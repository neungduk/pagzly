## 1. 기획 담당이 474차를 직접 렌더해서 본 판정
좋아진 점: 제목 서체가 아키타입마다 확실히 다르다(굵은 디스플레이, 명조, 손글씨 느낌). 사진 처리(원형 마스크, 기울인 프레임, 겹침 콜라주, 풀블리드)가 보이고, 첫 화면~중간까지 8종이 서로 다른 페이지로 읽힌다. 가로 넘침 0.

남은 문제(캡처에서 직접 확인):
1. **페이지 아랫부분이 8종 모두 똑같다.** 원피스 기준 "목둘레 마감" 설명, "핏·소재·마감" 3칸 카드(드롭숏더/중간/화이트), "봄여름 단독, 겨울 이너" 이미지+글, 가격 막대 같은 일반 섹션은 아키타입과 상관없이 거의 동일한 흰 카드·분홍 면 모양이다. 위쪽은 디자인했는데 아래는 기본 부품이다. 스크롤의 절반 이상이 여기다.
2. **상품 색이 페이지 전체를 한 색조로 덮는다.** 원피스는 4종이 모두 분홍 일색이다. 디자이너는 주조색 + 보조색 + 어두운 글자색 + 포인트색(보색 계열)의 4역할을 나눠 쓴다. 지금은 한 색의 농담만 쓴다.
3. 어두운 아키타입(impact/pop)의 중간~아래 구간이 위쪽 장면에 비해 평평하다(같은 초록 배경 박스가 반복).
4. softlife ↔ luxe, catalog ↔ techsheet는 474차 보고서도 인정한 대로 여전히 비슷하다.
5. 카드 밀도(C3)가 "부분 달성"이다.

## 2. 이번 라운드 항목
### A. 일반 섹션 V5 패밀리 (최우선)
- 일반 섹션 종류(상품 정보형 feature, 3칸 비교/옵션 카드, 이미지+글, 가격/구매 막대, 접점/공지 문구 등 코퍼스에 나오는 전부)를 `scripts`로 전수 나열해 `review/475-notes.md`에 표로 정리하고, 종류마다 아키타입 8종별 **서로 다른 DOM/레이아웃 변형**을 만든다. 변형 방식 예: 3칸 카드 → 가로 스크롤 스냅 / 번호 있는 세로 목록 / 큰 숫자 아래 칸 / 타임라인 / 표(구분선만) / 겹친 카드 스택.
- 하드 규칙: 가격·필수 고지·구매 카드·접점 문구·수치 게이트·비교 정책 불변, 데이터(카피) 불변, 편집 모드 불변. 안전하지 않은 섹션은 기존 렌더 유지하고 이유를 notes에 기록.
- 지표: 일반 섹션 종류별로 8종 쌍마다 시각 시그니처(레이아웃 방식, 카드 유무, 정렬, 강조 방식)가 3개 이상 달라야 한다(자동 시험).

### B. 색 역할 체계
- `lib/color-roles-v5.ts`: 상품 팔레트에서 주조색(surface) / 보조색(surface-alt) / 잉크(글자) / 포인트(accent, 주조색의 보색 또는 분할 보색) 4역할을 만들고, 아키타입마다 **면 비율**을 다르게 쓴다(예: luxe=잉크 70%+포인트 극소, pop=포인트 30%, editorial=종이색+잉크+포인트 선).
- 규칙: 한 페이지에서 서로 다른 hue 계열 ≥2(주조+포인트), 포인트색 면적 5~15%, 글자 대비 4.5:1 이상, 같은 상품의 8종이 hue가 모두 같지 않게(분홍 일색 금지: 주조 hue는 상품에서, 포인트/배경 hue는 아키타입에서 이동).
- 가짜 사진/SVG에서도 확인되도록 색은 CSS 토큰으로만.

### C. 어두운 아키타입 중간·아래 구간
- impact/pop/narrative의 어두운 면에 질감(노이즈/그리드/사선), 큰 숫자·거대 제목 장면 재배치, 어두운 면 안에서 밝은 반전 카드 1개씩으로 평평함 해소.

### D. 비슷한 쌍 분화
- softlife ↔ luxe: luxe는 여백·세리프·가는 선·좌우 비대칭, softlife는 둥근 면·파스텔 겹침·큰 아이콘으로 어휘를 분리(본문 시그니처 6칸 중 5칸 이상 다르게).
- catalog ↔ techsheet: catalog=이미지 중심 카드 격자, techsheet=표·모노 숫자·구분선 중심으로 구조 분리.
