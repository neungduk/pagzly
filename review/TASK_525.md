# TASK 525 — 토스 앱 시작 화면을 PC 버전(pagzly.com)과 같은 결로: 위쪽 설명 + 설정 화면 안으로 + 전반 다듬기

## 왜 하는가
- 현재 토스 시작 화면은 "큰 제목 → 업로드 카드 → 예시 행 → 점검 설정 행"만 있다. 처음 들어온 사람은 **이 서비스가 무엇을 점검하는지, 무엇을 받는지, 파일이 어떻게 다뤄지는지** 알 수 없다.
- PC 버전은 이를 이미 갖췄다. 참고 파일:
  - `/label-check` 화면: `app/label-check/page.tsx`(제목, 업로드 카드 + 오른쪽 "점검 설정" 카드: 판매 국가, 해당하는 제품 칩)
  - 홈(랜딩): `components/label-check/ui-511/LabelCheckLanding.tsx` → `LandingStage519`, `LandingBelt515`, `lc514-stats`(규칙 수·입력 방식·보관 0), `FixShowcase519`, `Finale519`, `LabelFooter511`
- PC의 점검 설정은 **화면에 바로 보이는데**, 토스는 맨 아래 "점검 설정" 행을 눌러야 열리는 시트에 숨어 있다. PC 흐름과 같아지도록 한다.
- 사용자 요청 원문: "PC버전이랑 UI 비슷하게 가져가자. 위에 설명도 있고 해야 하니까 전반적인 수정이 필요해."

## 원칙 (어기면 안 되는 것)
- **웹(pagzly.com)의 화면·동작·마크업은 바뀌면 안 된다.** 523차 골든 마크업 테스트가 그대로 통과해야 한다. 공용 부품에 손대야 하면 **선택 속성 추가만** 허용(기본값=지금과 동일).
- 판정 로직·규칙 JSON·서버 라우트 수정 금지. 루트 `package.json` 의존성 추가 금지.
- 토스 규칙: 자체 뒤로가기 버튼 금지(토스 내비게이션과 중복), 라이트 모드 전용, 외부 사이트로 나가는 링크 금지, `eval`/`new Function` 새로 들이지 말 것(`scan-bundle-eval.mjs` 통과).
- 고객 화면 문구에 `무료`, `요금`, `1분`, `위반입니다`, `적법`, `완벽`, `보장`, `안전합니다`, `100%` 금지. `법적 판단이 아닙니다` 고지는 시작 화면에 **계속 보인다**.
- 설명에 쓰는 숫자·주장은 **PC에 이미 있는 것만** 쓴다(규칙 개수 `labelRuleCounts514()` 값, "점검 후 보관하는 원본 파일 0", "PDF·사진·문구"). 새 주장 금지. 특히 **"법령 변경을 매일 확인"** 같은 문구는 쓰지 않는다(아직 자동 확인 검증 전).
- 사용자 파일·글자 원문을 로그·화면 진단에 남기지 않는다. 토스 번들에 서버 전용 모듈(`fs`, `node:`)이 들어가면 실패.
- 524차의 PDF→OCR 분기, 523차 오류 카드·결과 화면 동작은 **그대로 유지**.

## A. 먼저 조사 (코딩 전, 보고서에 3줄로)
1. PC 랜딩의 `LandingStage519`, `LandingBelt515`, `FixShowcase519`, `labelRuleCounts514`가 **토스(Vite) 번들에서 그대로 import 가능한지** 확인한다(`next/*`, `fs`, 서버 전용 의존 여부). 가능하면 **재사용**, 안 되면 필요한 부분만 `toss-app/src/ui/`에 **새로 작은 부품**으로 만든다(복사 붙여넣기 금지: 시각 값은 PC의 CSS 변수/색을 따른다).
2. `labelRuleCounts514()`가 클라이언트에서 불가능하면, 빌드 시점에 숫자만 뽑아 상수로 넣는 방식(`vite define` 또는 생성 스크립트)을 쓴다. 규칙 JSON 전체를 번들에 넣지 않는다.
3. 지금 시작 화면 390px 기준 사진: `/tmp` 아니라 `review/525-baseline/`에 먼저 찍어 둔다(변경 전).

## B. 시작 화면 구성 (위→아래, 390px 기준)
토스 상단 바가 앱 이름을 이미 보여 주므로 **자체 헤더(Pagzly 로고·내 결과·로그인)는 넣지 않는다.**

1. **히어로** (유지): "라벨을 올리면, 바로 읽어서 점검해요" + 보조 한 줄. 보조 문구를 PC와 맞춰 한 줄 설명으로 확장: 화장품 라벨의 표시사항·광고 문구를 올리자마자 읽어서 고칠 곳을 알려 준다는 취지(해요체, 금지어 없이, `INTRO_ONE_LINE_486`과 같은 뜻).
2. **업로드 카드** (유지, 탭: 파일 올리기 / 문구 붙여넣기).
3. **점검 설정을 화면 안으로** (시트 제거 또는 대체):
   - PC 오른쪽 카드와 같은 내용을 **업로드 카드 바로 아래 카드**로 둔다: `판매 국가` 두 칸 선택(한국/미국, 큰 터치 영역 48px↑), `해당하는 제품` 칩(안 씻어내는 / 씻어내는 / 기능성화장품 / 스크럽 / 팩 / 샴푸 / 더 보기), 칩 아래 도움말 "고르면 해당하지 않는 항목을 빼서 결과가 더 깔끔해져요"(PC 문구의 해요체).
   - 선택 상태가 한눈에 보이게(검정/흰 칩 규칙은 523차 부품 표 재사용). 기본 선택은 지금과 같다(한국 · 안 씻어내는 제품).
   - 기존 `toss-settings-summary` 행과 하단 시트(`settingsOpen`)는 **시작 화면에서는 쓰지 않는다.** 시트 코드는 다른 곳에서 안 쓰이면 정리하고, 쓰이면 남긴다(어느 쪽인지 보고서에 적기). 키보드·스크롤 잠금 관련 기존 효과가 깨지지 않게.
   - "더 보기"가 칩을 더 펼치는 방식이라면 같은 동작을 유지한다.
4. **주 버튼(점검하기)**: 파일/문구가 준비되면 나타나는 하단 고정 바(523차 방식 유지). 준비 전에는 숨김. 설정 카드가 인라인이 되었으므로 **버튼 위 여백으로 내용이 가려지지 않는지** 확인.
5. **예시 보기 행** (유지): "결과가 어떻게 나오는지 먼저 볼까요".
6. **설명 구역** (신규, 아래로 스크롤하면 나옴. 시작 화면에서만 보이고 결과·확인 화면에서는 숨김):
   - (a) **"이렇게 점검해요" 3단계 카드**: ① 파일이나 사진을 올려요 ② 필수 표시사항·알레르기 성분·주의가 필요한 광고 문구를 읽어서 확인해요 ③ 고칠 곳과 이유를 카드로 보여 줘요. (PC `INTRO_LINES_486`·랜딩 설명과 같은 뜻만.) 아이콘은 523차 `ui/icons.tsx` 재사용(이모지 금지).
   - (b) **숫자 3~4칸**: PC `lc514-stats`와 같은 항목(한국 기준 표시·광고 항목 N개 / 미국 기준 라벨 항목 N개 / 입력 방식 PDF·사진·문구 / 점검 후 보관하는 원본 파일 0). 값은 A-2 방식으로.
   - (c) **"이런 걸 찾아 줘요" 미니 예시**: PC `LandingStage519` 또는 `FixShowcase519`를 재사용/축소해 **가상 브랜드 예시 1~2개**(원문 → 고친 문구). 가상 예시임을 한 줄로 표시. 재사용이 무거우면(번들·레이아웃) 정적 카드 1장으로 대체하고 사유를 적는다.
   - (d) **믿을 근거 3줄 체크**: 파일은 점검 후 저장하지 않아요 / 참고용 사전 점검이며 법적 판단이 아니에요 / 읽은 글자는 확인하고 고칠 수 있어요(OCR 확인 화면이 있다는 사실). 체크는 SVG.
   - (e) 맨 아래: "법적 판단이 아닙니다" 고지 + 문의 이메일 복사 버튼(기존 동작). 법령 확인 기준일 줄은 서버 응답이 쉽게 오면 붙이고, 어렵거나 CORS가 막히면 **붙이지 않는다**(하지 말고 보고서에 사유).
7. 설명 구역 전체가 **한 화면 분량을 넘기지 않도록**(스크롤 2~3화면 이내) 간결하게. 카드 간 간격·모서리·그림자는 523차 부품 표(카드 20px, 행 16px, 칩 40px 등)를 따른다.

## C. 전반 다듬기 (화면 전체에 적용)
- **PC와 같은 인상**: 배경 워시(옅은 파랑·살구 번짐), 제목 굵기/자간, 파랑 강조 `#1D4ED8`, 카드 흰 바탕+옅은 그림자. 지금 토스 화면과 PC의 색·그림자·글자 크기를 나란히 놓고 **차이 3가지 이상을 골라 맞춘다**(어떤 값을 맞췄는지 표로 보고).
- 글자 크기 최소 14px(보조 문구 포함), 터치 영역 44px 이상, 대비 4.5:1 이상(옅은 회색 설명 글자 확인).
- 위아래 리듬: 구역 사이 간격 일관(24~32px), 카드 안 여백 일관. 마지막 구역 아래에 **안전 영역 + 하단 고정 바 높이만큼** 여백.
- 점검 중(busy) 오버레이, 오류 카드, OCR 확인 화면, 결과 화면은 **구조 변경 금지**. 단 시작 화면과 색·간격이 어긋나면 값만 맞춘다.
- 시작 화면 진입 애니메이션은 과하지 않게(페이드/살짝 올라옴 정도). `prefers-reduced-motion`이면 끈다.
