## 1. 항목
### A. 데이터 교체와 기준선
- 사용자 원본 규칙표·알레르기 파일·진짜 샘플 PDF 3개로 교체하고, 현재 코드로 그대로 돌려 결과를 `review/484-notes.md`에 표로 기록(샘플 × 기대 결과 × 실제 결과 × 일치 여부).
- 기대 결과: A = 사용기한 없음, "재생/완전 제거" 확인 필요, 리모넨·리날룰 확인 필요, 알레르기 성분 글자가 4pt로 작음(5pt 미만 확인 필요). B = 기능성 표기·제조번호 확인 필요. C = 대부분 통과 + "피부 장벽 강화" 확인 필요.

### B. 글자 추출 품질 점검 (핵심)
1. 한글 정규화: 추출 텍스트를 NFC로 통일(PDF에 따라 자모 분리·공백 삽입이 있다). 항목명 사이 공백/줄바꿈 변형("내 용 량", "내용량 :")에도 찾도록 비교 전 공백·콜론 정규화.
2. 줄 순서: 2단 배치·글상자 순서가 섞여도 항목 존재 검사는 되는지 확인(순서에 의존하지 말 것).
3. 글자 크기: 현재 `/Tf` 추정은 Chromium PDF에서 변환 행렬 때문에 틀릴 수 있다. pdfjs의 텍스트 아이템 transform(실제 렌더 크기)으로 계산해 샘플 A의 4pt 글자(리모넨, 리날룰)와 9pt 전성분을 구분하는지 확인. 못 읽으면 "확인 불가"(절대 통과 처리 금지).
4. 서로 다른 생성기의 PDF 3종 추가 시험: (a) Chromium(Playwright page.pdf, 샘플과 같은 방식), (b) LibreOffice로 .docx/.html→PDF 변환(있을 때), (c) Python reportlab 또는 pdfkit 등으로 한글 TTF 임베드 PDF. 같은 문구를 넣어 각각 추출 결과를 `484-notes.md`에 비교. 추출이 안 되는 생성기가 있으면 어떻게 "확인 불가"로 안내하는지 기록.

### C. 판정 오류 점검
- 오탐/누락 점검: 정상 문구가 "없음"으로 나오는 경우, 없는 항목이 "통과"로 나오는 경우를 찾는다. 특히 "제조번호"(LOT 표기 변형), "사용기한(개봉 후 12개월 / 까지 / 년월일)", "책임판매업자 주소" 판별. 발견한 것은 수정하되 임의로 규칙을 새로 만들지 말고 notes에 근거를 적는다.
- "위반" 단정 문구, 내부 id 노출 0 재확인.

### D. 회귀·검증
- `scripts/regression/label-check-483.ts`를 진짜 PDF 3개 + 추가 생성기 PDF 기준으로 갱신(기대 결과 표 자동 비교). run-all 통과, 기존 상세페이지 회귀 변화 없음, 가로 넘침 0(320/390/750).
