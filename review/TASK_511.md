# 511차 — 사이트 전체 화면 리디자인 (교정지 컨셉, 한 번에)

> 순서: 510차 완료 후(보고서 있음). 이번은 **화면(표현)만** 바꾼다. 점검 로직·판정·API·DB·결제는 건드리지 않는다.
> 디자인 시안 원본(HTML)이 저장소에 있다: `review/design-511/landing.dc.html`, `check.dc.html`, `result.dc.html`. **반드시 세 파일을 처음부터 끝까지 읽고** 색·간격·문구·움직임을 그대로 옮긴다. (`<x-dc>`, `{{ }}`, `sc-if`, `sc-for` 같은 문법은 시안 도구용이니 React로 번역한다. `<helmet><style>`의 CSS 규칙과 `class Component`의 상태 로직이 번역 대상이다.)

## 0. 절대 규칙
1. 실제 OCR·네트워크 호출, 키·`.env*` 열람/생성/커밋 금지. main push 금지, 코드 삭제 금지, **새 npm 의존성 추가 금지**(움직임은 CSS와 React 상태로만). `package.json`·`package-lock.json` 변경 금지.
2. 아래는 **절대 수정 금지**: `lib/label-check/**`(판정·OCR·규칙), `app/api/**`, `supabase/**`, `review/data/**`, `middleware`/인증 로직, `app/billing/**`. 컴포넌트의 props·함수 시그니처·데이터 흐름·저장 규칙(`unreadable` 저장 안 함 등)·`DETAIL_PAGE_ENABLED` 분기는 그대로 둔다. 바꾸는 것은 마크업·className·CSS·문구(아래 §4)뿐이다.
3. 상세페이지 생성 기능(플래그로 숨겨진 쪽)의 화면은 바꾸지 않는다. 새 색·글꼴·애니메이션 CSS는 **라벨 점검 화면에만 적용되도록 범위를 좁힌다**(최상위 래퍼에 `lc-site` 같은 클래스를 두고 그 아래에서만 CSS 변수·규칙 사용). `app/globals.css`의 기존 토큰 값은 바꾸지 않는다(추가만 가능).
4. 고객 화면 금지어: "위반입니다/적법/완벽/보장/안전합니다/100%". 상태 이름은 **고칠 것 / 확인할 것 / 확인 못 함 / 문제 없음 / 직접 확인** 그대로. "참고용 사전 점검이며 법적 판단이 아닙니다" 문구는 시안대로 랜딩·점검·결과·푸터에 반드시 유지.
5. 마무리 전: `npx tsc --noEmit`, `npm run build`, `npm run regression:label-check`. **커밋 최대 6개**. 보고서 `review/511cha-report.md`(맨 위 "확인하지 못한 항목"). 커밋 해시는 push 후 `git log --oneline`의 실제 값만.
6. 먼저 `node_modules/next/dist/docs/`에서 이번에 쓰는 기능(font 로딩, 클라이언트 컴포넌트, metadata)의 설명을 읽고 시작한다(이 Next는 기존과 다르다).

## 3. 화면별 작업
### 3-1. 랜딩 `/` (`app/page.tsx`의 `LabelCheckLanding`) — 시안 `landing.dc.html`
- 진한 청록 첫 화면: 76px 제목(모바일에서는 clamp로 줄임), "빨간펜" 밑 선 그리기, 줄별 순차 등장, 점 깜빡임, 주황 버튼 "무료로 점검하기"(→ `/label-check`), "샘플 결과 보기".
- 오른쪽 샘플 라벨: **클라이언트 컴포넌트**(`LandingProofDemo`). 5.2초마다 3개 샘플(한국 크림 / 미국 세럼 / 한국 앰플)이 바뀌고 빨간 밑줄·배지·요약이 다시 재생. 아래 탭 클릭 시 해당 샘플로 이동하고 자동 전환 정지. `setInterval`은 언마운트 때 정리. 시안 문구를 그대로 쓰되 **샘플 제품명·문구는 가짜 예시임이 분명해야 하므로 실제 브랜드명을 쓰지 않는다**(시안 그대로 OK).
- 흐르는 띠(`ReviewBelt`): 시안의 7개 문구×2 반복, 마우스 올리면 멈춤, `overflow-x:hidden`으로 가로 스크롤이 생기지 않게.
- "직접 해 보기"(`TryItPicker`, 클라이언트): 문구 4개 버튼 → 오른쪽 패널(상태 배지·제목·이유·고친 문구). 시안의 `slideA/slideB` 교대 애니메이션 방식 유지. 접근성: 버튼은 `<button>`, 선택 상태 `aria-pressed`.
- 이어서 "올리고 보고 고쳐서" 3칸, "점수 대신 해야 할 일" 4칸, 마지막 CTA 띠, 푸터 — 시안 순서·문구 그대로.
- 기존 `LabelCheckLanding`의 **사실 문구**(PDF·사진 지원, 저장하지 않음, 국가별 기준 등)가 시안과 다르면 시안 쪽 문구를 쓰되, 서비스 동작과 다른 표현이 있으면 쓰지 말고 보고서에 적는다.
- `metadata`(title/description)·noindex는 그대로.

### 3-2. 점검 시작 `/label-check` (게스트) — 시안 `check.dc.html`
- 대상: `app/label-check/page.tsx`와 `components/label-check/ui-507/UploadCard.tsx`, `OcrReviewCard.tsx`, `OcrLimitBanner.tsx`.
- 진한 청록 헤더 + 단계 표시(1 올리기 / 2 결과 보기 / 3 고쳐서 다시 점검: 알약 모양), 제목 46px(모바일 축소), 판매국 선택 큰 버튼 2개(선택 시 청록 채움), 점선 업로드 칸(아이콘이 떠다니는 움직임, 호버 확대), "또는 문구만 붙여넣기", 글자 수 표시(IBM Plex Mono), 라디오 2개, 주황 "무료로 점검하기".
- **점검 중 오버레이**: 실제 점검이 진행되는 동안(기존 로딩 상태에 연결) 시안처럼 단계(글자를 읽는 중 → 필수 표시사항 확인 → 광고 문구 확인 → 결과 정리)를 보여 준다. **실제 진행 신호가 없으면 시간 기반 연출이 아니라, 로딩 중임을 알리는 스피너와 같은 단계 문구를 고정 순환으로만 쓰고**, 점검이 끝나면 즉시 닫는다(가짜로 오래 붙잡지 않는다). 서버 응답이 오면 연출 중이라도 바로 결과로 이동.
- 기존 동작(OCR 읽은 글자 편집, 한도 안내, 붙여넣기로 이동 버튼, 읽기 상태 문구)은 모두 그대로 두고 **겉모양만** 바꾼다. 510차 문구(쉬운 말 안내, 부분 읽음 안내)는 유지.

### 3-3. 점검 결과 (게스트 결과 + 회원 `/label-check/new`, `history/[id]`) — 시안 `result.dc.html`
- 대상: `components/label-check/ui-507/ResultView.tsx`, `components/label-check/ResultPanel.tsx` 및 이를 쓰는 화면.
- 맨 위 요약 4칸(고칠 것/확인할 것/확인 못 함/문제 없음, 큰 숫자 IBM Plex Mono, 칸마다 위쪽 6px 색 줄). **점수·"발견된 항목이 없어요"류 문구는 쓰지 않는다**(기존 규칙 유지: `unreadable`이면 요약 대신 508 안내).
- 항목 카드: 왼쪽 8px 색 줄, 배지, 제목, 설명, 발견 문구(색 배경 표시), 고칠 문구 예시(+ 문구 복사). 위에서 아래로 순차 등장.
- "고쳤어요" 토글: 시안의 로컬 상태 기능을 넣는다. **저장하지 않고 화면에만 반영**하며, 문구 "고쳤다고 표시한 문구는 다시 점검하면 확인됩니다"를 함께 보인다. 남은 건수 막대도 시안대로. 이 상태가 점검 결과 데이터·DB·`label_check_runs` 저장에 **절대 섞이지 않게** 한다. (이 기능이 기존 구조에서 위험하면 넣지 말고 보고서에 이유를 적는다.)
- 하단 "고친 문구로 다시 점검" 버튼, 면책 문구.

### 3-4. 그 밖의 화면 (같은 틀·토큰 적용, 시안 스타일에 맞춤)
`app/label-check/history/page.tsx`(목록), `app/login`, `app/signup`, `app/forgot-password`, `app/reset-password`, `app/privacy`, `app/terms`, `app/not-found.tsx`, `app/error.tsx`.
- 헤더·푸터·바탕·글꼴·버튼(주황 강조 또는 청록)을 공통 틀로 통일. 약관·방침은 **본문 글(조항)을 한 글자도 바꾸지 말고** 겉모양만(본문 폭 최대 65~70글자, 행간 넉넉히, 조항 제목 굵게).
- 로그인·가입 폼의 동작·검증·문구는 그대로. 소셜 로그인 버튼 모양만 토큰에 맞춘다.
- 상세페이지 전용 화면(`/create` 등 숨겨진 기능)은 건드리지 않는다.

## 4. 움직임 원칙 (시안 그대로, 더 늘리지 않는다)
허용: 첫 화면 순차 등장, 밑줄 그리기, 샘플 라벨 순환, 띠 흐름, 점검 중 단계, 결과 카드 순차 등장, 숫자 갱신 팝, 스크롤 등장, 카드·버튼 호버 떠오름. 금지: 시안에 없는 패럴랙스·커서 효과·자동 재생 영상·소리·깜빡이는 배경. 모든 움직임은 `prefers-reduced-motion`에서 꺼진다.

## 5. 반응형·접근성 (필수)
- 320px·390px에서 **가로 스크롤이 없어야** 한다(띠·샘플 라벨·표 모두). 정적 CSS 점검으로 확인하고, 확인 못 하면 보고서에 적는다(이 세션은 실제 브라우저를 쓰지 않는다 — `docs/phone-session-rules.md` 준수).
- 눌리는 것은 높이 44px 이상. 아이콘만 있는 버튼은 `aria-label`. 장식 SVG는 `aria-hidden`. 입력칸은 `<label>` 연결. 탭 이동 순서가 시각 순서와 같게. 자동 전환 샘플은 탭으로 멈출 수 있어야 한다.
- 이미지 파일을 새로 추가하지 않는다(아이콘은 인라인 SVG 또는 기존 lucide).

## 6. 테스트
- 새 파일 `scripts/regression/label-check-511-ui.ts`(파일만 읽는 정적 검사, `label-check-suites.ts`에 등록):
  1. 새·수정한 라벨 화면 파일에 금지어 없음.
  2. `label-site-511.css`에 `prefers-reduced-motion` 규칙이 있고, 모든 `@keyframes` 애니메이션 클래스가 그 안에서 꺼짐.
  3. 새 CSS 변수가 `lc-site` 범위 안에서만 정의됨(`:root`에 라벨 색 변수 추가 금지).
  4. `package.json` 의존성 변경 없음(스냅샷 비교).
  5. 랜딩·결과·점검 시작에 면책 문구 존재, 상태 이름 5종 존재.
  6. `DETAIL_PAGE_ENABLED` 분기와 `lib/label-check/**`가 이번 커밋 범위에서 변경되지 않았음(파일 해시 또는 git diff 이름 검사).
- 기존 묶음이 옛 클래스명·옛 문구를 검사해서 깨지면: **금지어·면책·상태 의미를 검사하는 가드는 절대 약화하지 말고**, 순수 모양(className)·옛 문구만 새 화면에 맞게 고친다. 고친 목록을 보고서에 적는다. 판단이 애매하면 고치지 말고 멈춰서 보고서에 적는다.
