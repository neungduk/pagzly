# 485차 — 업로드 안전장치 + 글자가 없는 PDF 안내 + 1장 결과 인쇄

## 0. 규칙
- 유료 호출·Production·main 금지. 기존 상세페이지 코드 변경 금지(`/label-check`, `lib/label-check`, 해당 API만).
- 새 검사 규칙 추가 금지. 목표는 `review/485-targets.md`에 코드 전에 기재. 파일은 Read 후에만 Write/Edit.
- 이번 차수의 배경: 484차에서 진짜 Chromium PDF 3종은 기대대로 판정됨. 아직 확인되지 않은 위험은 (1) 디자인 툴(일러스트레이터/인디자인)에서 글자를 도형으로 바꿔(아웃라인) 내보낸 PDF는 글자가 0자로 읽힌다 (2) 로그인 없는 공개 업로드 API라 악성·대용량 파일 방어가 필요하다.

## 1. 항목
### A. 업로드 안전장치
- 파일 형식은 확장자가 아니라 **파일 앞부분 `%PDF-` 시그니처**로 확인. 아니면 거절 문구.
- 10MB 초과 거절(서버에서도 확인), **페이지 수 상한 10쪽**, 추출 **시간 제한 20초**(초과 시 "처리 시간 초과, 확인 불가"). 암호화/손상 PDF는 "열 수 없음" 안내(내용·경로·스택 노출 금지).
- IP당 단순 호출 제한(예: 분당 10회, 메모리 기반이면 충분. 서버리스에서 한계가 있으면 한계를 report에 기재).
- 서버 로그에 파일명·본문 금지(회귀로 검사). 응답 에러에 내부 경로·id 노출 0.

### B. 글자가 없는/부족한 PDF 안내
- 추출 글자 0자 또는 극소(예: 한글 10자 미만)면 판정을 하지 말고 전용 안내: "글자가 도형으로 변환된 PDF일 수 있어요. 디자인 파일에서 '글자 포함(아웃라인 해제)' 상태로 PDF를 다시 내보내 주세요." + 확인 불가 항목 없이 이 안내만(모든 항목이 '위반 가능'으로 쏟아지지 않게).
- 글자는 읽히지만 한글이 거의 없고(영문만) 제품이 한글 표시 대상일 수 있으면: "한글 표시사항이 읽히지 않았어요" 안내 + 판정은 보류.
- 시험 PDF: `review/data/samples/generators-484/gen_empty_notext.pdf`, `gen_helvetica_nohangul.pdf`로 검증(새로 만들지 말고 이 파일 사용).

### C. 1장 인쇄 결과
- 결과 화면을 A4 1~2장에 맞는 인쇄 레이아웃으로(`@media print`): 상단에 제품명(업로드한 파일 이름이 아닌, 사용자가 입력한 제품명 칸 — 선택 입력), 점검일, 요약 4칸, 항목 표, 하단 면책 문구("참고용 사전 점검이며 법적 판단이 아닙니다"). 한글 라벨만, 내부 id 0.
- 화면 UI에서 "인쇄/PDF로 저장" 버튼(브라우저 인쇄 호출). 320/390/750 가로 넘침 0.

### D. 회귀
- `scripts/regression/label-check-483.ts`에 추가: 시그니처 불일치, 11쪽 PDF, 빈 PDF, 영문 PDF, 로그 무본문. 기존 상세 회귀 변화 없음.
