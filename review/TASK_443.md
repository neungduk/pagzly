# TASK_443 — 이전 섹션 "쌍둥이 수정" 방식으로 v4 디자인 언어 확장 + 토큰 단일화 (코딩 중심, 유료 API 0회)

사용자 요청(2026-10-23, 오늘의 마지막 차수): 데이터만으로 코딩 위주, 디자이너/후킹 전문 제작사 수준. 선행: 442차 완료(442cha-report.md가 없으면 먼저 작성).

## 배경 (442차 결과로 결정된 방향)
- 442차 인벤토리: 라이브(React·Tailwind·컨테이너 쿼리·편집 UI)와 export(인라인 스타일 문자열·`@media`)는 **한 문자열로 공용화할 수 없다**(편집 UI 19종, 인터랙션·결제 근접 2종, 컨테이너 쿼리 반응형). 공용 빌더 방식은 **폐기**한다.
- 대신 **쌍둥이 수정(twin edit)** 방식: 라이브와 export를 **각각** 고치되, ① 값은 **단일 토큰 소스**(`lib/design-tokens-v4.ts` 등)에서만 읽고 ② 섹션 하나마다 **패리티 검사 + off 문자열 diff 0**을 통과해야 커밋한다.
- 눈 검수(442) 결과 441차 항목 대부분 합격, 결함 3건(구분선↔모티프 겹침, 신뢰 스트립 중복 문장, 배너 속 글자)은 수정 완료. 구매 카드(이름 → 가격 → 훅 → 칩 → 신뢰 스트립 → 구매)는 정돈됨.
- 남은 시각 문제: **이전 섹션(강조 카드·페르소나·FAQ·표·고지·구매 카드 하단)의 위계·여백·행간**, 배송 안내와 "AI 생성 콘텐츠 안내" 사이 약 110px 빈 간격, 제목 위계 잔여 8페이지(강조 카드 제목 24/700·페르소나 라벨 18/600).

## 0. 규칙
- **유료 API 0회**, push 금지, 마이그레이션 없음, 결제 코드·보호 파일 미수정(`cta_price`의 `data-pz-buy`·스티키 바 참조 마크는 절대 건드리지 않는다: 스타일 값만 변경), .env* 열지 않기, 새 로그인/계정 생성 금지, 항목마다 커밋 1개.
- **새 문구·수치·사실 생성 금지.** 편집 UI(`EditableText`, `ImageReplaceHit`, `elementSelectProps`, `edit?.`)·인터랙션 동작 변경 금지. 고지(AI 생성 콘텐츠 안내) 문구 고정 규정 준수.
- 변경은 모두 `NEXT_PUBLIC_DESIGN_V4` 안. **off = 438차 상태와 동일**(export 문자열 diff 0 + 라이브 off 스냅샷 diff 0), 패리티 0, export 금지 기법(`:has()`, container query, `text-wrap`, `mix-blend-mode`, `clip-path`, `-webkit-text-stroke`) 금지(라이브 전용 Tailwind 컨테이너 쿼리 클래스는 기존대로 라이브에만 존재), 대비 4.5:1, 본문 14px·라벨 12px, Noto Sans KR만, 회귀 80+ 통과, tsc, next build, launch-smoke 53/53, 428 DOM 24/24, 750폭 가로 넘침 0.
- **정규식은 `Write`로 파일에 직접 작성**(heredoc 금지, 역슬래시 소실 방지).
- 시작 문장: "443차 시작: 이전 섹션 쌍둥이 수정과 토큰 단일화".

## 1. 단일 토큰 소스 (`lib/design-tokens-v4.ts`)
- 441·442차에 흩어진 v4 값(제목 위계 3단 크기·굵기, 여백 스케일 32·48·64, 반경 2~3단, 그림자 none/soft/float, hairline, 카드 면 규칙, 행간 단계)을 **한 파일에서 export**하는 객체로 모으고, 기존 v4 코드가 그 값을 import하도록 정리(값 불변 — off·on 렌더 문자열 diff 0으로 증명).
- 라이브(React 클래스/스타일)와 export(인라인 문자열)가 같은 토큰 키를 쓰게 **헬퍼 2개**(`tokenStyle(key)`: 인라인 스타일 문자열 / `tokenClass(key)` 또는 style 객체: 라이브용)를 제공. 이후 항목은 이 헬퍼만 사용(하드코딩 신규 금지).
- 회귀: 토큰 키 누락·타입 검사, 라이브·export 같은 키가 같은 값을 내는지.

## 2. 이전 섹션 쌍둥이 수정 (섹션 하나당 커밋 1개, 순서대로)
각 섹션: ① 라이브 `case`와 export 함수의 현재 값 목록화 → ② v4 on에서만 토큰 헬퍼로 교체(제목 위계 3단, 여백 스케일, 행간·반경·그림자 토큰) → ③ 패리티(라이브↔export) 불일치 0, off diff 0, 회귀 통과 확인 후 커밋. **하나라도 어긋나면 그 섹션만 되돌리고 사유 기록 후 다음 섹션으로.**
1. **highlight_box(강조 카드)**: 제목 24/700 → 위계 3단(중 20~22·800), 카드 면·깊이 토큰.
2. **target_persona**: 라벨 18/600 → 위계 3단(소 16~18·700), 말풍선/카드 반경·여백 토큰.
3. **faq**: 카드형(Q 번호/아이콘 + 답, 정적 펼침 마크는 기존 동작 유지), 행간·간격 토큰.
4. **spec_table / comparison_table**: 헤더 면 + 줄무늬 + 숫자 우측 정렬·단위 작게, 행 높이·반경 토큰(`comparison_table`은 라이브 제목 변수 매핑이 필요하면 v4에서만 `--pz-t-*` 단일 변수 CSS 추가).
5. **caution / ai_disclosure(고지 문구 불변)**: 441차 새 스타일을 라이브에도 일치.
6. **usage_steps / step_card / brand_story / review_highlight**: 제목 위계와 여백만(구조·편집 훅 불변).
7. **cta_price 하단**: 스타일 값(여백·글자 크기·깊이)만 토큰화. **`data-pz-buy`·스티키 바 연결·결제 관련 마크업 구조는 변경 금지**(애매하면 건너뛰고 기록).
- 각 섹션 전환 후 **R16(제목 위계) 잔여·R17(여백)** 수치를 기록(목표: R16 잔여 8페이지 → 0, 한 페이지 제목 스타일 ≤3종, R17 info 0).
