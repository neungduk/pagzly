# 498차 노트

## 수정 전 한도 (실측)
| 항목 | 값 |
|------|-----|
| 서버/클라 `MAX_PDF_BYTES_483` | 10MB |
| Vercel Hobby 요청 본문 | ~4.5MB (플랫폼이 먼저 413 가능) |
| 쪽수 | 10 |
| 추출 타임아웃 | 20s → 408 |
| `maxDuration` | 미설정 |

## 수정 후
| 항목 | 값 |
|------|-----|
| 서버/클라 | **4MB** (`MAX_PDF_BYTES_483`) — 플랫폼보다 작음 |
| 안내 | `ERR_TOO_LARGE_485` + 권장 4MB |
| `maxDuration` | 30s |
| 오류 | `{ error, code }` |

## B. 큰 파일 대안 (구현 금지 — 기획 판단용)
| 방식 | 장점 | 단점 | 개인정보("저장하지 않음") | 난이도 |
|------|------|------|--------------------------|--------|
| 클라 pdfjs → 텍스트·글자크기만 전송 | 본문 용량↓, 플랫폼 413 회피 | 클라 번들↑·기기 편차·위조 가능·이미지 PDF는 여전히 실패 | 서버에 PDF 미전송 → 약속과 잘 맞음 | 중 |
| 임시 스토리지 업로드 후 서버 처리 | 대용량·동일 서버 로직 | 저장 구간 생김, 삭제 보장·TTL 필요 | **"저장하지 않음"과 충돌** (일시 저장이라도 설명 변경 필요) | 중~상 |
| **권장(메모)** | 단기: 4MB 한도+저해상도 안내 유지. 중기: 클라 추출 검토(저장 약속 유지). 스토리지는 약속 문구 개정 후에만. | | | |

## C. 암호 PDF
- qpdf / pdf-lib 미설치 → **합성 암호 PDF 시험 미실시**.
- 손상·암호 계열은 `countPdfPages`/`withExtractTimeout`에서 `UNREADABLE` 문구로 수렴(경로·스택 비노출).

## D. 동시성·메모리
- 인메모리 레이트 리밋(`SlidingWindowLimiter`)은 **서버리스 인스턴스마다 분리** → 우회 가능. **수정 금지**(한계 기록만).
- `extract-pdf` / `countPdfPages`: `doc.destroy()` 호출로 핸들 해제.
