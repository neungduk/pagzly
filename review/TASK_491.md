# 491차 — 공개 전 점검: 개인정보처리방침·이용약관을 검수 서비스 실제 동작에 맞추기

## 0. 규칙
- 유료 호출·Production·main 금지. 코드 삭제 금지. 새 기능·새 검사 규칙 금지. 목표는 `review/491-targets.md`에 코드 전에 기재. 파일은 Read 후에만 Write/Edit. 마무리 전 `npx tsc --noEmit`, `npm run build` 통과 필수. 커밋은 최대 3개.
- 문구는 **코드가 실제로 하는 일만** 적는다(과장·보증 금지). 법률 자문이 아니므로 보고서에 "공개 전 전문가 검토 권장"을 적는다.

## 1. 배경
`/label-check`는 사용자가 PDF 시안을 올리는 서비스인데, `app/privacy`·`app/terms`는 상세페이지 생성 서비스(사진 업로드·AI 생성·결제) 기준일 가능성이 높다. 영업 메일을 받은 사람이 업로드 전에 읽는 문서이므로, 실제 동작과 맞아야 한다.

## 2. 항목
### A. 동작 감사 (읽기 전용 → `review/491-notes.md` 표)
다음을 코드에서 직접 확인해 "사실 / 근거 파일·줄"로 기록:
1. 업로드된 PDF가 디스크·DB·스토리지(R2/Supabase)에 저장되는가(저장 0이어야 함).
2. PDF 본문이 외부 서비스(AI/OCR/로그/분석 도구)로 전송되는가(0이어야 함). 서버 로그·에러 로그·모니터링에 파일명/본문이 남는가.
3. 쿠키·분석 스크립트·광고 픽셀 등이 `/label-check`에서 로드되는가.
4. 검수 결과가 서버에 저장되는가(저장 0이어야 함). 샘플 결과는 정적 JSON.
5. 호출 제한을 위해 IP를 메모리에 임시 보관하는가(보관 시 보관 방식·기간).
6. 위 중 하나라도 "저장/전송 있음"이면 **문구를 바꾸지 말고 멈추고 보고**한다(소개 문구의 "저장하지 않고 폐기" 주장이 틀리면 안 되므로).

### B. 문서 수정 (플래그 꺼짐 상태 기준)
- `app/privacy/page.tsx`: 검수 서비스 항목 추가 — 처리하는 정보(업로드한 PDF, IP 일시 처리), 저장 여부(A 결과 그대로), 외부 제공 여부, 문의 방법(`NEXT_PUBLIC_LABEL_CONTACT_EMAIL` 있을 때만 표시, 없으면 문의 항목 숨김, 임의 주소 금지). 상세페이지 생성 관련 문단은 플래그 꺼짐일 때 숨김(켜짐이면 기존 그대로).
- `app/terms/page.tsx`: 검수 서비스 항목 추가 — "참고용 사전 점검이며 법적 판단이 아님", 결과의 정확성·완전성 보증 없음, 최종 확인 책임은 이용자(책임판매업자)에게 있음, 업로드 시안의 권리는 이용자에게 있음. 결제·요금 조항은 현재 결제 기능이 닫혀 있으므로 플래그 꺼짐일 때 숨김.
- 작성일/시행일 표기는 사용자가 정하도록 **자리표시자 금지** → 기존 문서에 날짜 체계가 있으면 따르고, 없으면 "시행일: (사용자 확정 후 표기)" 같은 임시 문구를 만들지 말고 해당 줄을 생략하고 보고서에 알린다.
