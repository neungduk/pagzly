# 480차 — 원본 실사 유료검증 (뷰티 1개 섹터, 1세트만)

## 0. 승인 확인 (가장 먼저)
- 이 지시서를 붙여 넣은 메시지 안에 **"유료 승인 2026-11-03"** 문구가 있을 때만 유료 단계(C)를 실행한다.
- 문구가 없으면 A, B(준비·점검)만 하고 멈춘 뒤 "승인 문구가 없어 유료 단계는 실행하지 않음"이라고 보고한다.

## 1. 범위 (이보다 넓히지 말 것)
- 카테고리: **뷰티 1개만** (미스트). 전자기기/패션/식품/극단 팔레트는 이번에 하지 않는다.
- 세트: **1세트**, 실제 상품 사진 2~4장(사용자가 직접 올린다).
- 확인할 섹션: hero / points / phototext / bleed / spec / timeline / purchase.
- 검증 대상은 프리뷰 `https://pagzly-h4zrcmwnv-pagzly.vercel.app` (cloud-work 빌드, V4/UP1/V5 켜짐). 코드 변경 없이 점검과 기록 중심.
- main push 금지. 새 카피·새 기능 금지. 키/토큰을 채팅이나 파일에 적지 말 것.

## 2. 항목
### A. 사전 점검 (무료)
1. 프리뷰 환경 변수 존재 여부만 확인(값 출력 금지): `STORAGE_PROVIDER=r2`, `NEXT_PUBLIC_STORAGE_PUBLIC_BASE_URL`, Supabase pagepick-3 연결, V5 플래그 3종.
2. 이번 생성 1회에 실제로 일어나는 외부 호출 종류를 코드에서 찾아 `review/480-notes.md`에 표로 정리: (호출처, 제공사, 1회 생성당 최대 호출 수, 재시도 횟수, 이미지 업로드 대상). 재시도가 자동으로 일어나는 곳이 있으면 최대 횟수를 적는다.
3. 호출 횟수 상한 확인: 생성 1회당 비전/역할 태깅/합성 호출이 사진 장수 × 1을 넘는 경로가 있는지 확인하고, 있으면 어디인지 기록(코드는 고치지 말고 보고).

### B. 로그 준비 (무료)
- 생성 직후 확인할 항목을 `scripts/verify-480.ts`(읽기 전용)로 준비: 방금 생성된 상품의 이미지 URL 접두사가 모두 `https://img.pagzly.com/`인지, 업로드된 파일 수, 섹션별 사진 배정, 생성 상태/오류 필드. DB는 읽기만 한다.

### C. 유료 실행 (승인 문구가 있을 때만)
- 사용자가 프리뷰에서 직접 사진 2~4장으로 **딱 1번** 생성한다. Cursor는 생성하지 않는다.
- 사용자가 "생성 끝"이라고 알리면 `scripts/verify-480.ts`를 실행해 결과를 기록한다.
- **오류가 나면 재시도하지 말고 멈춰서** 오류 메시지(키 값 제외)와 어느 호출에서 났는지만 보고한다.
- 어떤 경우에도 2번째 생성, 다른 카테고리, 자동 재시도 루프를 실행하지 않는다.

### D. 기록
- `review/480cha-report.md`: 맨 위에 승인 여부와 실제 실행한 유료 호출 종류·횟수, 이미지 URL 접두사 점검 결과, 섹션별로 눈에 띈 문제(가짜 사진에서 안 보이던 것: 사진 크롭, 글자 가독성, 사진 위 스크림, 장식 겹침), 오류가 있었다면 원인, 다음 후보. `git log -1`/`git status`로 push 확인 후 커밋 해시 기재.
