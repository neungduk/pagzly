# 501차 — 규칙 갱신 절차서 + 데이터 버전 표시 + 회귀 통합 실행

## 0. 규칙
- 유료 호출 금지. Production·main 금지. 코드 삭제 금지. 규칙 데이터 내용 수정 금지(데이터 소유는 기획 담당). "위반" 단정·"완벽/보장" 금지.
- `review/501-targets.md`에 코드 전 기재. 마무리 전 `npx tsc --noEmit`, `npm run build`. 커밋 최대 3개. 보고서 `review/501cha-report.md`.

## 1. 배경
법령·지침은 바뀐다. 규칙 데이터를 코드와 분리해 둔 이유다. 규칙이 바뀔 때 비개발자(운영자)가 안전하게 갱신할 수 있어야 한다. 또 결과 화면에 어떤 기준(날짜)으로 점검했는지 보여야 사용자가 오래된 기준에 속지 않는다.

## 2. 항목
A. **`docs/label-check-rules-update.md`**(한글, 비개발자용, 1~2쪽): 규칙 파일 5개(`kr_label_rules`, `ad-phrases-kr`, `fix-suggestions-kr`, `us_label_rules`, `us-ad-phrases`)의 위치·역할, 각 필드 의미, 규칙 추가/수정/삭제 시 순서(데이터 수정 → 회귀 실행 → 빌드 → 푸시), 흔한 실수(JSON 쉼표·따옴표, id 중복, 제안 파일 id 누락), 되돌리는 방법(git revert). 코드에서 실제로 읽는 필드만 근거로 쓰고, 읽지 않는 필드는 "참고용"으로 표기.
B. **데이터 검증 스크립트** `scripts/validate-label-rules.ts`(+ npm script `validate:rules`): 5개 파일의 JSON 유효성, id 중복, 필수 필드 존재, 제안 파일 커버리지, 패턴 빈 문자열/한 글자 패턴 경고(오류 아님), 광고 파일의 `condition` 허용값 검사. 오류는 exit code 1, 경고는 출력만. 이 스크립트를 `scripts/regression/run-all.ts`에 포함.
C. **기준 날짜 표시**: 각 규칙 파일의 `meta.version`/`date`(없으면 파일 최종 수정 커밋 날짜를 쓰지 말고 "미표기")를 읽어 결과 화면 하단 작은 글씨에 "점검 기준: 규칙표 v0.1 (2026-11-09)" 형태로 한 줄만 표시(시장별). 새 카피는 이 한 줄에 한정. 파일에 날짜 없는 경우의 표시를 시험.
D. **회귀 통합 보고**: `npm run regression`(없으면 추가) 한 번으로 모든 회귀가 순서대로 돌고 마지막에 통과/실패 표를 출력하게 정리. 현재 회귀 목록과 각 소요 시간을 보고서에 표로.

## 3. 시험
- 검증 스크립트가 일부러 깨뜨린 사본(중복 id, 누락 필드, 잘못된 JSON)에서 실패를 내는지 확인(원본은 건드리지 않고 임시 사본 사용).
- 날짜 표시 시험(있음/없음).
- 기존 회귀 전부 유지.

## 4. 보고서
