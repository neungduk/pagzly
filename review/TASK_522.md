# TASK 522 — 토스 미니앱 화면 개편 ("구글폼 같다" → 앱처럼)

## 왜 하는가
- 521차 번들이 토스 앱 안에서 실제로 뜬다(사용자 폰 캡처 확인). 다만 지금 화면은 한 페이지에 체크박스·버튼·글상자가 세로로 나열된 **폼**이라 앱 같지 않고 구글폼처럼 보인다.
- 방향: **한 화면에 결정 하나**, 큰 터치 영역, 하단 고정 버튼, 단계가 넘어가는 흐름. 토스 앱 안에 들어 있어도 어색하지 않게. 색·분위기는 Pagzly 토큰(밝은 바탕 `#F3F5FB` 계열, 검정 `#111214`, 포인트 `#1D4ED8`, 상태색 `#D6402B` / `#B7791F` / `#6B7A74` / `#1F7A56`)을 따른다.
- 이번 차수는 `toss-app/` **화면만** 바꾼다. 판정 로직·규칙·서버·웹 사이트(`app/`, 기존 `components/`)는 건드리지 않는다.

## 원칙
- 루트 `package.json`·웹 사이트 동작 변경 금지. 새 npm 패키지는 `toss-app/package.json`에만, **그리고 정말 필요할 때만**(기본은 추가 없음). TDS(`@toss/tds-mobile`)는 이번에 도입하지 않는다(번들에 `eval`이 들어 반려됐던 전례가 있고, 문서상 권장일 뿐 필수가 아니다). 도입 여부는 보고서에 한 줄로 근거만 적는다.
- 라이트 모드만. 이모지 금지. 새 글꼴 파일 추가 금지(시스템 글꼴 스택만).
- 고객 문구는 해요체. `무료`, `요금`, `1분`, `위반입니다`, `적법`, `완벽`, `보장`, `안전합니다`, `100%` 금지. 외부 링크(`href="http…"`) 금지. `법적 판단이 아닌 사전 점검 도구입니다` 고지는 결과 화면과 홈에 둔다.
- 사용자 파일·글자 원문을 로그에 남기지 않는다.
- 진단용 "실험 화면"(`LabPanel`)은 그대로 두고, 제목을 3초 안에 5번 누르거나 `?lab=1`이면 열리는 기존 방식을 유지한다. 새 UI 때문에 가려지면 안 된다.

## A. 화면 흐름 (단계별 한 화면)
화면 전환은 **브라우저 기록**(`history.pushState` + `popstate`)에 쌓는다. 토스 내비게이션의 뒤로가기가 한 단계 전으로 돌아가고, 첫 화면에서는 앱이 종료된다. **자체 뒤로가기 버튼은 만들지 않는다**(토스 규칙: 이중 노출 금지).

1. **홈**
   - 큰 제목(해요체): `인쇄 넣기 전에 라벨을 먼저 훑어봐요`, 설명 한 줄.
   - 제목 아래에 **작은 그림 하나**(CSS·SVG만): 랜딩 첫 화면의 "라벨 종이 + 색 태그 두 개(`고칠 것`, `확인할 것`)"를 작게 재현. 훑는 선이 한 번 지나가는 CSS 애니메이션(약 3초, `prefers-reduced-motion`이면 정지).
   - 시작 방법을 **큰 행(row) 3개**로 보여 준다(각 행: 아이콘, 제목, 한 줄 설명, 오른쪽 화살표, 높이 72px 이상):
     1. `사진으로 점검해요` — 라벨 사진을 골라요
     2. `PDF로 점검해요` — 상세페이지 PDF를 골라요
     3. `문구를 붙여넣어요` — 광고 문구를 직접 넣어요
   - 행의 종류는 `toss-app/src/config.ts`의 상수(`TOSS_START_KINDS = ["photo", "pdf", "text"]`)로 켜고 끈다. **PDF·HEIC 지원 여부는 아직 실측 전**이라, 상수 하나로 `pdf`를 빼도 화면이 어색하지 않아야 한다.
   - 맨 아래: `법적 판단이 아닌 사전 점검 도구예요` 고지(작은 글씨).
2. **준비** (파일을 골랐거나 `문구를 붙여넣어요`를 눌렀을 때)
   - 사진/PDF: 파일 이름·크기, 사진이면 **썸네일**(작게). 문구 붙여넣기: 글상자 하나(자동 높이, 글자 수 표시).
   - 옵션 두 개는 체크박스가 아니라 **칩/스위치 행**: `씻어내는 제품이에요`, `기능성화장품이에요`(각각 한 줄 설명).
   - 하단 고정 버튼 `점검하기`(높이 56px, 꽉 찬 폭, 모서리 16px, 검정 `#111214`, 활성 전에는 회색). 홈 인디케이터·안전 영역(`env(safe-area-inset-bottom)`) 반영.
3. **읽는 중 / 점검 중**
   - 전체 화면, 가운데에 작은 라벨 그림 + 훑는 선 반복. 진행 문구는 기존 `PROGRESS_READ_507`·`PROGRESS_RULES_507`을 해요체 한 줄로 보여 준다. 취소 버튼은 두지 않고 토스 뒤로가기로 처리해도 되지만, 진행 중 뒤로가기가 요청을 방치하지 않도록 `AbortController`를 쓰거나, 안 되면 결과를 버리기만 한다(어느 쪽인지 보고서에 적는다).
4. **글자 확인** (사진·PDF를 글자로 읽은 경우만)
   - 제목 `이렇게 읽었어요. 틀린 글자는 고쳐 주세요`, 글상자(읽은 글자), 글자 수.
   - 낮은 신뢰도 안내(`avgConfidence`)가 있으면 한 줄 안내. 하단 고정 버튼 `이대로 점검할게요`.
5. **결과**
   - 맨 위 요약: 큰 숫자 세 개(`고칠 것 N` 빨강 점, `확인할 것 N` 노랑 점, `문제 없음 N` 초록 점)를 가로로. 숫자는 `result.summary` / 상태 분류(`statusToBucket507`)에서 온다(하드코딩 금지).
   - 아래 항목 카드(세로 목록). 항목은 **고칠 것 → 확인할 것 → 직접 확인할 것(manualItems) → 문제 없음(접힘)** 순. 번호는 연속 번호.
   - 카드 한 장: `01` 모노 숫자 + 상태 색 점 + 제목, `이 문구`(걸린 문장, 있으면), `이유` 한 줄, `이렇게 고쳐 보세요`(고쳐 쓴 문구 예시) + **`복사` 버튼**(복사가 막히면 선택 가능한 글상자로 대체). 카드 모양은 웹 518차 `FindingBody518`과 같은 계열(취소선·안쪽 흰 상자 없음). 기본은 접힌 한 줄 요약, 누르면 펼쳐지는 방식도 좋다.
   - `문제 없음`은 한 줄로 접어 두고 누르면 목록. `해당 없어 뺀 항목`(`skippedItems513`)도 접힘.
   - 하단 고정 버튼 `다른 라벨 점검하기`(홈으로). `OCR_LIMIT`(429) 응답이면 기존 안내 문구와 같은 뜻의 한 장짜리 안내 화면 + `문구 붙여넣기로 점검해요` 버튼.
   - 결과 맨 아래: `법적 판단이 아닌 사전 점검 도구예요` + `result.rulesBasis`가 있으면 점검 기준 한 줄.

## B. 느낌 (앱처럼 보이게 하는 디테일)
- 터치 영역 48px 이상, 본문 글자 16px 이상(제목 26~30px, 800), 줄간격 1.45, `word-break: keep-all`.
- 카드 모서리 20px, 그림자는 옅게. 회색 테두리 흰 상자 나열 금지(구분은 배경색 차이와 간격으로).
- 화면 전환: 새 단계는 오른쪽에서 24px 슬라이드 + 페이드(0.22초), 뒤로 가면 반대. `prefers-reduced-motion`이면 전환 없음.
- 누를 때 살짝 눌리는 느낌(`:active` 스케일 0.98), `-webkit-tap-highlight-color: transparent`, 버튼·행은 `user-select: none`, 가로 스크롤 없음, `overscroll-behavior: none`.
- 페이지 배경은 `#F3F5FB` + 위쪽에 옅은 번짐 한두 개(CSS 그라디언트만). 토스 내비게이션 바 아래 여백은 기본 16~20px.
- 오류는 빨간 글자 한 줄이 아니라 화면 안의 작은 안내 카드(`다시 시도해 볼까요`처럼 해요체)로.

## D. 번들 검사 가드 (반려 재발 방지)
- 토스 번들 검사는 `eval(`을 찾으면 반려한다(521c에서 pdfjs 복사본은 정리했다). 이제 **빌드 후 `toss-app/dist` 전체를 훑어** `eval(` 또는 `new Function(`이 있으면 빌드를 실패시키는 스크립트 `toss-app/scripts/scan-bundle-eval.mjs`를 만들고, `ait:build`가 `vite build` 직후·`ait build` 직전에 실행하게 한다(현재 `ait:build`는 `node scripts/copy-label-check-pdfjs.mjs && vite build && ait build`).
- 새로 의존성을 추가했다면 그 코드가 `eval`을 끌어오는지 이 스크립트로 확인한다.

- `scripts/regression/label-check-522.ts`를 만들고 `regression:label-check`에 넣는다.
