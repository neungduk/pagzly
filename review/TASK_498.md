# 498차 — 실제 고객 파일 대비 견고성(용량·암호·쪽수·시간 제한)

## 0. 규칙
- 유료 호출 금지. Production·main 금지. 코드 삭제 금지. 규칙 데이터 수정 금지. "위반" 단정·"완벽/보장" 금지.
- `review/498-targets.md`에 코드 전 기재. 마무리 전 `npx tsc --noEmit`, `npm run build`. 커밋 최대 3개. 보고서 `review/498cha-report.md`.

## 1. 배경 (중요)
인쇄용 패키지 PDF는 5~100MB가 흔하다. Vercel Hobby의 서버리스 함수는 **요청 본문 약 4.5MB 제한**이 있어, 현재 구조(브라우저→`/api/label-check` 직접 업로드)는 큰 파일에서 플랫폼이 먼저 거부할 수 있다(우리 코드의 오류 문구가 아닌 플랫폼 오류가 뜸). 현재 코드의 업로드 한도·실행 시간 설정(`maxDuration`, 최대 용량 상수)을 먼저 읽고 표로 기록하라.

## 2. 항목
A. **업로드 한도 정합성**: 서버 한도 상수 = 플랫폼 한도보다 작게 설정, 클라이언트에서 업로드 전 파일 크기 검사 → 초과 시 한글 안내 ("PDF가 너무 큽니다. 이미지 해상도를 낮추거나 점검용으로 저해상도 PDF를 내보내 주세요" + 권장 한도 숫자). 플랫폼이 413 등을 반환할 때(JSON 아님) 화면이 깨지지 않고 같은 안내가 뜨게 응답 파싱 방어.
B. **큰 파일 대안 설계(구현 금지, notes에만)**: 브라우저에서 PDF를 읽어 텍스트·글자 크기만 추출해 보내는 방식(클라이언트 pdfjs) vs 임시 저장소 업로드 후 서버 처리 방식의 장단점, 개인정보("저장하지 않음" 약속과의 충돌), 구현 난이도, 권장안을 `498-notes.md`에. 판단은 기획 담당이 한다.
C. **비정상 PDF**: 암호 걸린 PDF, 손상된 PDF, 0바이트, 확장자만 pdf인 파일, 쪽수 과다(예: 50쪽 이상)에서 각각 한글 안내가 나오고 서버가 예외로 죽지 않는지. 쪽수 상한 상수와 시간 제한 초과 시 처리(중간에 끊고 안내)를 확인. 합성 시험 파일은 스크립트로 생성(예: qpdf/pdf-lib 없으면 notes에 미실시 기재).
D. **동시성·메모리**: 인메모리 레이트 리밋이 서버리스 인스턴스마다 따로라 우회 가능함을 notes에 한계로 기록(수정 금지). pdfjs 사용 시 메모리 해제 확인.
E. **응답 형식 통일**: 모든 오류가 `{error, code}` 형태 JSON인지 점검, 화면이 code별 문구를 쓰는지 표로.

## 3. 시험
`scripts/regression/label-check-498.ts`: C의 비정상 입력 5종 이상(코드 레벨에서 만들 수 있는 것) 기대 `code` 고정. 기존 회귀(483·493·494·495·496·497) 유지.
