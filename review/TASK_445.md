# TASK_445 — 클라우드에서 라이브 화면 띄우기(더미 환경값) + 라이브↔export 시각 대조 + 리듬·색·섹션 마감 (코딩 중심, 유료 API 0회)

실행 환경: 클라우드 세션(`cloud-work` 브랜치). 선행: 444차 완료(`review/444cha-report.md`).
시작 문장: "445차 시작: 라이브 화면 클라우드 구동과 시각 대조".

## 배경
444차로 export 정적 캡처는 실제 Noto Sans KR로 볼 수 있게 됐다. 남은 가장 큰 구멍은 **라이브(React/Tailwind) 화면을 한 번도 못 본 것**이다(문자열 패리티만 통과). 라이브 화면 경로 `/dev/detail-preview?capture=session`은 저장 세션 JSON만 있으면 렌더되는 개발용 경로이므로, **진짜 비밀값 없이 더미 환경값으로 `next dev`를 띄워** 클라우드의 Chromium으로 라이브 화면을 직접 캡처해 볼 수 있는지 시도한다.

## 0. 규칙
- **유료 API 0회, 실제 키·토큰·비밀값은 어디에도 쓰지 않는다.** `.env*` 파일을 열거나 만들거나 커밋하지 않는다. 환경값이 필요하면 **명령어 앞에 인라인**으로 줄 것(예: `NEXT_PUBLIC_SUPABASE_URL=http://127.0.0.1:54321 NEXT_PUBLIC_SUPABASE_ANON_KEY=dummy ... npx next dev`). 값은 의미 없는 더미(로컬 주소·`dummy` 문자열)만. 더미 값 목록은 보고서에 적되 키처럼 보이는 문자열 생성 금지.
- 새 로그인/계정 생성 금지, 외부 네트워크 호출이 필요한 기능(AI·결제·Supabase)은 호출하지 않는다(실패해도 되는 경로만 연다).
- 마이그레이션 없음, 결제 코드·편집 UI·인터랙션 변경 금지(`cta_price` 구조 불변).
- **새 문구·수치 생성 금지.** 고지 문구 불변.
- 모든 변경 `NEXT_PUBLIC_DESIGN_V4` 안, **off = 444차 끝(`eee0bdd`) 출력과 문자열 diff 0**(export·라이브·섹션 단독), 문자열 패리티 유지, export 금지 기법(`:has()`, container query, `text-wrap`, `mix-blend-mode`, `clip-path`, `mask`, `-webkit-text-stroke`) 금지, 대비 4.5:1, 본문 14px·라벨 12px, 회귀 91+ 통과, tsc(기존 1건 외 신규 0).
- 스크립트·정규식은 heredoc 말고 Write/Edit로 파일 작성. Playwright 리비전 불일치는 444차 방식(`/opt/pw-browsers` 링크, 저장소 변경 금지). 폰트는 `node scripts/build-detail-fonts.mjs`로 생성(gitignore 대상).
- 항목마다 커밋하고 `cloud-work`에 push. main push 금지. push가 403이면 보고서 맨 위에 쓰고 계속.

## 1. 라이브 화면 클라우드 구동 (먼저, 상한 40분)
- 더미 환경값 인라인으로 `next dev`(또는 `next start`)가 뜨는지 시도. 부팅이 안 되면 어떤 모듈이 어떤 환경값을 요구하는지 에러 메시지로 정리하고, **개발 전용 경로가 그 값 없이도 렌더되도록 코드를 고치는 것은 하지 않는다**(보고만). 단, 공개/개발 경로가 환경값 부재로 죽는 것이 실제 취약점이면 보고에 별도 표시.
- 뜨면 `/dev/detail-preview?capture=session`에 저장 세션 대신 **합성 픽스처 21종**을 넣을 수 있는지 확인(저장 세션 6종이 저장소에 없음). 기존 캡처 스크립트(`scripts/_440-cap.ts` 계열 또는 eye-capture)가 라이브 경로를 쓰는지 확인하고, 없으면 `scripts/live-capture.ts`를 새로 작성(서버 주소·픽스처 선택은 인자로).
- 뜨면 라이브 캡처 21종 × 390px(+750px 6종)를 만들고 export 캡처(444차 시트)와 **같은 섹션끼리 나란히 비교 시트**(`review/445-verify/live-vs-export/`). 비교 항목: 제목 크기·굵기, 여백, 카드 반경·그림자, 배너 스크림, 표/FAQ/고지 모양, 구매 띠, 사진 오버레이, 줄바꿈.
- 차이가 있으면 원인을 분류(라이브 전용 Tailwind/컨테이너 쿼리 vs 토큰 불일치 vs 편집 훅 마크업)하고 쌍둥이 수정(토큰 한 곳)으로 맞춘다. 맞출 수 없는 차이(반응형 방식 차이)는 표로 남긴다.
- 구동 자체가 불가능하면 그 사실과 에러, 시도한 더미 값 조합을 보고하고 2번 이후 항목(라이브 비교)은 건너뛴 뒤 3번 이후로 진행.

## 2. next build 시도
- 더미 환경값 인라인으로 `npx next build`를 시도하고 성공/실패와 소요 시간·에러를 기록. 실패하면 환경값 문제인지 코드 문제인지 구분(코드 문제면 수정 후보를 보고서에, 환경값 문제면 PC에서 재실행 항목으로). 빌드 산출물(`.next`)은 커밋 금지.

## 3. 리듬 확장 (444차 한계 해소)
- 444차 `lib/rhythm-v4.ts`는 임팩트 블록만 대상이었고, **임팩트가 아닌 이전 섹션(표·FAQ·주의·강조 카드·페르소나 등)은 면 정보가 없어 규칙 밖**이었다. 이전 섹션도 배경 면 색을 계획 단계에서 읽을 수 있게(섹션 타입 → 면 키 매핑 표를 한 곳에 두고 라이브·export가 같이 읽음) 해서 같은 면 이웃 간격 규칙(앞 아래 + 뒤 위 ≤ 96, 3단 스케일)을 적용. 라이브 Tailwind 클래스 쌍과 export 변수가 같은 값을 내도록 쌍둥이 수정.
- 측정: gapBig·gapUneven·3단 밖 여백을 합성 21종 export(+가능하면 라이브) DOM으로 전/후, 눈 검수 시트로 리듬 확인.

## 4. 히어로 색 중복·퀵포인트 틈
- 444차 관찰: 뷰티 합성 히어로가 **같은 파란 면으로 3종 이상 겹침**. `heroFaceColor` 입력 신호(사진 지배색 → 상품명 색상어 → mood 색 → 대표색)가 합성 픽스처에서 같은 대표색으로 수렴하는지 확인하고, 합성 픽스처의 대표색 입력을 카테고리·mood별로 다르게 부여하거나(픽스처 문제) 규칙에 브랜드명·키워드 해시 기반 보조 신호를 더하는 방안(규칙 문제)을 판단해 최소 변경으로 해결. 같은 면 색 중복 ≤ 2/21 목표. 입력 신호가 없으면 현재 동작 유지.
- 뷰티 퀵포인트 줄 사이 좁은 흰 띠(관찰): 원인 확인 후 v4 안에서 수정.
