## 1. 디자인 방향
"실제 제품 화면이 주인공." 설명 카드 3개 대신, 첫 화면에서 라벨 위에 걸린 문구를 표시하고 옆에 판정 카드를 보여 준다. 시안의 구조를 따른다.
섹션 순서: 떠 있는 상단 바 → 히어로(큰 제목+부제+버튼 2개+한 줄 안내) → 제품 화면(왼쪽 라벨/오른쪽 판정 카드) → 어두운 숫자 띠 → 전/후 문장 예시 → 파란 마무리 영역 → 푸터.

### 토큰 (lc-site 범위, 기존 511 토큰 교체)
- 배경 #F7F7F5, 카드 #FFFFFF, 선 #E6E6E1, 본문 #111214, 보조 #4A4D54, 흐린 #6A6D74(글자 4.5:1 미만이면 #5F6269로)
- 강조색은 파랑 하나만: #1D4ED8 (어두운 배경 위 글자는 #7FA2FF)
- 상태색 고정: 고칠 #D6402B / 확인할 #B7791F / 직접확인·확인못함 #6B7A74 / 문제없음 #1F7A56. 기존 코랄(#FF6B52) CTA와 진초록(#0F3D36) 포인트는 제거.
- 주 버튼: 검정 #111214 알약(radius 999px, 상단 바 안 버튼은 10px). 호버 #2A2C30.
- 둥글기는 3단계만: 10 / 14·16 / 20·28. 그 외 값 금지.
- 글꼴: 본문·제목 Pretendard(자체 호스팅, 가능하면 `pretendard` 대신 필요한 굵기 400/500/700/900 woff2 subset만 `public/fonts`에 두고 next/font/local 사용; 용량이 커지거나 라이선스 파일 누락 시 Noto Sans KR 유지하고 보고서에 사유 기재), 숫자·파일명·"이 문장/이렇게" 라벨은 기존 IBM Plex Mono(또는 JetBrains Mono 중 이미 쓰는 것) 유지. 글꼴 2종 초과 금지.
- 제목 letter-spacing -0.04em, 굵기 900, `text-wrap: balance`. 본문 줄간격 1.7 이상.

### 상단 바
- 가운데 정렬 max-width 1040, 흰 바, 둥근 16, 약한 그림자, `position: sticky; top: 14px`.
- 메뉴는 한 줄: 검사 항목 / 수정 안내 / 시작하기(시안의 "요금"은 결제가 없으므로 **"요금" 쓰지 않는다**). 오른쪽: 로그인(테두리), "점검하기"(검정). 시안의 "무료로 점검"은 쓰지 않는다(과금 정책 미확정) → "점검하기".
- 모바일(<720px): 메뉴 링크 숨기고 로고 + 점검하기 버튼만.

### 히어로
- 제목 2줄: "화장품 라벨, 인쇄 전에 / **틀린 문구**부터 잡으세요" ("틀린 문구"만 #1D4ED8). 모바일 폰트 36~40px.
- 부제 2줄 이내 (시안 문구 사용). 버튼 2개: "내 라벨 점검하기"(검정 알약, `/label-check/check`로 연결 — 실제 점검 시작 경로 사용) / "결과 예시 보기"(테두리). 결과 예시가 현재 없으면 두 번째 버튼은 아래 제품 화면으로 스크롤하는 앵커로 한다.
- 한 줄 안내 3개는 **실제 동작과 일치하는 것만** 쓴다. 코드로 확인 후: 로그인 없이 시작 가능한지, 점검 후 원본 파일/텍스트를 저장하지 않는지(서버 저장·로그 여부), 지원 시장(한국·미국). 하나라도 사실이 아니면 그 문구는 빼고 보고서에 기재.

### 제품 화면 (핵심)
- 왼쪽 "예시 라벨" 카드: 가상 제품(시안의 "비타 브라이트닝 앰플") 문구 위에 표시 3종: 빨강 밑줄(고칠 것), 노랑 밑줄(확인할 것), 형광 노랑(수정 후 문구). 카드 상단에 작은 글씨로 **"예시 화면입니다"** 를 반드시 표기(실제 고객 결과로 오해 금지).
- 스캔 선 애니메이션은 1개(파랑 선, 글로우 약하게)만. `prefers-reduced-motion`이면 정지.
- 오른쪽 판정 카드 3개(고칠/확인할/문제 없음). 카드 문구는 실제 엔진 결과 카드 규칙(TASK_512)과 같은 구조("이 문장 → 이렇게")로, 하드코딩 데이터는 `components/label-check/ui-511/landing-demo-514.ts` 한 곳에 모은다. 예시 문구는 금지어 목록에 걸리지 않게 하고 "예시 문구입니다 · 법적 판단이 아닙니다" 표기.
- 호버: 카드가 왼쪽으로 4px 이동 + 그림자. 입장 애니메이션은 순차 fade-up(0.5s) 한 번만.
- 모바일: 한 열로 쌓고 라벨 카드가 먼저, 판정 카드가 아래.

### 숫자 띠 (어두운 #111214 배경)
- 4칸: 한국 기준 항목 수 / 미국 기준 항목 수 / 입력 방식 3종 / 보관 원본 0. **숫자는 하드코딩하지 말고** `review/data`의 규칙 JSON에서 실제 개수를 읽어 표시한다(현재 KR 35, US 13이지만 규칙이 바뀌면 같이 바뀌어야 함). "0 보관"은 위 한 줄 안내와 같은 사실 확인을 통과했을 때만 표시.
- 모바일은 2열.

### 전/후 문장 + 마무리
- 시안대로. BEFORE는 빨강 밑줄, AFTER는 형광 노랑. 이전 TASK_512 원칙대로 BEFORE 취소선 금지.
- 마무리 파란 영역(#1D4ED8, radius 28): 제목 + 버튼 1개(흰색 알약). 문구는 "지금 올려 보세요. 1분이면 끝납니다." → **"1분이면 끝납니다"는 실제 소요시간을 확인할 수 없으므로 "지금 올려 보세요"로 줄인다.**
- 푸터: "참고용 사전 점검이며 법적 판단이 아닙니다" · 이용약관 · 개인정보처리방침 · 문의 이메일(`NEXT_PUBLIC_LABEL_CONTACT_EMAIL` 사용, 하드코딩 금지).

## 2. 디자인 규칙 (taste-skill에서 필요한 것만 뽑음, 이 TASK 범위 안에서 지킨다)
AI 티 금지:
1. 똑같은 카드 3개 나열 금지(섹션마다 구조가 달라야 한다).
2. 섹션 번호("01", "02"), 장식용 알약 라벨/뱃지, 그라데이션 배경, 글로우(스캔 선 제외), 이모지 아이콘, 긴 줄표(—)를 본문에 쓰지 않는다.
3. 같은 문장 구조 반복("~하세요 / ~하세요 / ~하세요") 금지. 문구는 짧고 구체적으로.
4. 일반 문구("혁신적인", "스마트한", "원스톱") 금지. 화장품 라벨 용어를 쓴다(전성분, 사용기한, 제조번호, 내용량).
레이아웃:
5. 히어로 제목 2줄 이내, 부제 2줄 이내, 버튼은 첫 화면(1440x900)에서 보여야 한다. 내비는 한 줄.
6. 한 화면 강조색은 파랑 하나. 상태색은 상태 표시에만 쓴다.
7. 최대 너비 1040, 좌우 여백 24(모바일 16).
점검(자동으로 가능한 범위):
8. 글자/배경 대비 4.5:1 이상(큰 글자 3:1). 정적 테스트로 토큰 조합을 계산해 검사한다.
9. 360/390/768/1440 폭에서 가로 스크롤 없음 — CSS 정적 점검(고정 width, 100vw 사용 여부)으로 대체하고, 실브라우저 캡처는 하지 않는다(폰/클라우드 규칙).
10. 버튼·링크 터치 영역 최소 44px.
11. `prefers-reduced-motion` 대응, 모든 이미지/아이콘에 의미 있는 `aria-label` 또는 장식이면 `aria-hidden`.
