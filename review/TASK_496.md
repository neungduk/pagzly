# 496차 — 한국 수정 제안 데이터 연결 + 공개 전 점검 + 접근성

## 0. 규칙
- 유료 호출·Production·main 금지. 코드 삭제 금지. 상세페이지·결제 코드 변경 금지. "위반" 단정, "완벽/보장" 표현 금지. 규칙 데이터 파일(`kr_label_rules`, `ad-phrases`, `us_label_rules`)은 수정하지 않는다.
- `review/496-targets.md`에 코드 전 기재. 마무리 전 `npx tsc --noEmit`, `npm run build`. 커밋 최대 4개. 보고서 `review/496cha-report.md`.

## 1. 한국 수정 제안 연결
- `review/data/fix-suggestions-kr_draft_v0.1.json`(기획 담당 작성, 49개 id)을 로드해 한국 결과의 항목 아래 "수정 제안" 영역에 `fix_ko`, `fix_example`(있을 때만, 494차 `FIX_EXAMPLE_NOTE_494` 동반)을 표시한다. 같은 id가 없으면 영역을 숨긴다(빈 문구 금지).
- `fix_kind`가 `evidence`인 항목은 "근거 자료 확인" 라벨, `soften`은 "표현 완화 예시", `fix`는 "수정 제안"으로 구분 표시.
- "수정 제안 모아 보기"에 한국 항목 포함. `review/data/fix-suggestions-kr_todo.md`는 삭제하지 말고 맨 위에 "완료(496차): 초안 파일 생성" 한 줄만 추가.
- 규칙 id가 파일에 없는 경우를 알리는 단위 시험: 규칙표 id 전체 대비 제안 파일 커버리지 테스트(누락 0 확인, 누락되면 실패).

## 2. 공개 전 점검 (코드로 가능한 범위만)
- 모든 화면/응답에 "위반", "완벽", "보장", "합법", "승인" 단어가 단정 문맥으로 나오는지 정적 검색 스크립트 `scripts/regression/forbidden-words-496.ts` 추가. 면책 문구 속 "위반 여부를 판단하지 않는다" 같은 부정 문맥은 허용 목록으로 처리하고 목록을 보고서에 표로.
- `noindex`/robots: `/label-check/new`, `/label-check/history*`는 noindex. 공개 `/label-check` 인덱싱 여부는 현행 유지(기획 담당·사용자 결정 대기)하고 현재 상태만 보고.
- 오류 처리: 저장 실패·로그인 만료·업로드 중 새로고침 시 화면이 멈추지 않는지 코드 경로 점검 후 표로.

## 3. 접근성·모바일 (정적 점검)
- 업로드 영역·시장 선택·체크박스·삭제 확인 창에 키보드 접근(Tab/Enter/Esc)과 레이블 연결을 점검, 부족하면 수정.
- 320px 폭에서 가로 넘침 가능 요소(표, 긴 문구) 점검. 실제 렌더링 시험은 불가하면 "미실시"로 기재.
