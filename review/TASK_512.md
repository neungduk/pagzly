# 512차 — 결과 카드: "무엇이 틀렸는지"와 "이렇게 수정"을 정확하게 보여 주기

> 순서: 511차 완료·배포 후. 사용자 지적(실제 화면): 카드에 `관련 표기를 찾지 못함 → [수정문구]`처럼 **"없다"는 상태 문구에 취소선**이 그어져 나오고, **무엇이 어떻게 틀렸는지**가 보이지 않는다. 이번 작업은 `ResultView` 카드 구조를 고치는 **화면 작업**이다.

## 0. 절대 규칙
1. 실제 OCR·네트워크 호출, 키·`.env*` 금지. main push 금지, 코드 삭제 금지, 새 의존성 금지.
2. 수정 금지: `lib/label-check/**`(판정·규칙), `app/api/**`, `supabase/**`, `review/data/**`, `package*.json`. `Finding` 타입·API 응답 모양은 그대로 둔다. 새 코드는 `components/label-check/ui-511/` 안에 만든다.
3. 고객 화면 금지어: "위반입니다/적법/완벽/보장/안전합니다/100%". "법적 판단이 아닙니다" 문구 유지.
4. 마무리 전: `npx tsc --noEmit`, `npm run build`, `npm run regression:label-check`. 커밋 최대 3개. 보고서 `review/512cha-report.md`(맨 위 "확인하지 못한 항목"), 해시는 push 후 `git log --oneline`의 실제 값만.

## 1. 지금 문제 (코드 원인)
`components/label-check/ui-511/`·`ui-507/ResultView.tsx`의 `evidenceBefore(f)`가 `f.found`를 "고치기 전 문구"로 쓴다. 그런데 `f.found`에는 `관련 표기를 찾지 못함`, `원산지 표기를 찾지 못함`, `내용량(숫자+단위)을 찾지 못함`, `전성분 영역 크기(pt): 4, 5` 같은 **상태·측정 설명**도 들어온다. 이걸 취소선으로 그리고 → 수정문구를 붙이니 말이 안 된다. 또 카드 어디에도 **왜 문제인지(기준)**가 따로 없다.

## 2. 카드를 3가지 종류로 나눠 보여 준다
새 순수 함수 `classifyFinding512(f: Finding): "missing" | "wording" | "measure" | "other"`를 만든다(`components/label-check/ui-511/finding-kind-512.ts`). 판단 규칙(문자열 기반, `lib` 수정 없이):
- **missing(표기 없음)**: `f.found`가 `찾지 못`·`없음`·`부족`·`구분할 수 없`·`읽지 못`으로 끝나거나 포함되고 `f.evidence`가 비어 있다.
- **wording(문구 문제)**: `f.evidence?.length`가 있거나, 광고 계열(`checkKey`가 `MFDS-`/`USAD-`로 시작)이고 `f.found`가 실제 원문 조각이다.
- **measure(측정값 문제)**: `f.found`에 `pt`·`크기`·숫자 나열이 있다(예: `전성분 영역 크기(pt): 4, 5 — 5pt 미만 1건`).
- 그 외는 other(기존 모양에 "무엇이 문제인가요"만 추가).

### 2-1. 공통 구조 (고칠 것·확인할 것 카드 모두)
카드 안을 세 줄로 나눈다. 제목 한 줄은 지금처럼 항목 이름.
1. **무엇이 문제인가요** — 한 문장. 종류별 문장은 §2-2. 항상 맨 위, 굵게.
2. **라벨에서 확인한 내용** — 종류별 표시는 §2-2. 이 줄이 취소선의 유일한 자리다.
3. **이렇게 수정해 보세요** — 종류별 표시는 §2-2.
기준 근거가 있으면(`f.basis`) 카드 아래에 작은 글씨로 "기준: {law} — {source}"(접이식 아님, 한 줄). 없으면 생략.

### 2-2. 종류별 표시
**missing**
- 문제: `"{f.label}"을(를) 라벨에서 찾지 못했어요.` (예: "영업자의 상호 및 주소"를 라벨에서 찾지 못했어요.)
- 확인한 내용: 취소선 없이 회색 안내 한 줄 — "사진/PDF에서 읽은 글자 안에는 이 표기가 없어요." (OCR로 읽은 경우 `readStatus`가 partial이면 "일부만 읽어서 놓쳤을 수도 있어요. 읽은 글자를 확인해 주세요."를 덧붙인다.)
- 수정: 제목을 **"이렇게 넣어 보세요"**로 바꾼다. 예시(`templates`/`alternatives`)는 **"추가할 문구"** 한 줄씩(고치기 전 없음, 화살표 없음, 취소선 없음), 각 줄에 "문구 복사". 예시가 없으면 `f.suggest`를 "넣는 방법"으로 쓴다.

**wording**
- 문제: `f.suggest`가 있으면 그 문장을, 없으면 `"{f.label}"에 해당할 수 있는 표현이에요.`
- 확인한 내용: **문제가 된 문장 전체**(`evidence[0].sentence`)를 보여 주고 그 안의 걸린 말(`evidence[0].found`)만 빨간 배경으로 표시한다. 문장이 없으면 `f.found`를 따옴표로 한 줄. 여러 건이면 최대 3개 + "더 보기".
- 수정: 제목 **"이렇게 고쳐 보세요"**. "고치기 전(취소선) → 고친 뒤(초록)" 한 쌍은 **걸린 말 → 대체 문구** 형태로 한다(문장 전체를 취소선으로 긋지 않는다). `exception`(예외 가능성)이 있으면 "예외가 될 수 있어요: …" 한 줄을 추가한다.

**measure**
- 문제: `f.suggest` 또는 `"기준보다 작거나 확인이 필요해요."`
- 확인한 내용: `f.found`를 **그대로 값 표**로 — 왼쪽 "읽은 값", 오른쪽 "기준"(기준값이 문자열에 `5pt` 등으로 들어 있으면 뽑아 쓰고, 없으면 생략). 취소선 없음.
- 수정: **"이렇게 확인해 보세요"** + `f.suggest` 또는 `f.fix.note`.

**other**: 문제 줄 + 기존 표시.

### 2-3. 공통 규칙
- "예시 문구입니다. 제품에 맞게 고치고, 최종 확인은 판매자가 합니다." 줄은 **예시 문구가 실제로 1개 이상 보일 때만** 표시한다(예시가 없는데 보이는 지금 상태 수정).
- 하나 마나 한 문장("해당 항목을 확인해 주세요")은 쓰지 않는다. `f.suggest`·`f.fix.note`·`f.fix.headline` 어느 것도 없으면 이 "수정" 줄 자체를 숨긴다(빈 안내보다 낫다).
- "고쳤어요" 토글·복사 버튼·탭·요약·진행 막대는 그대로.
- `fixSheet`(일괄 복사 텍스트)와 저장 데이터는 건드리지 않는다.
- 접근성: 줄 제목은 `<h3>`/`<p>`+`aria-label` 없이 읽히는 순서로, 빨간 강조에 의존하지 않도록 "문제가 된 말"을 굵게도 처리.
- 모바일 320/390에서 가로 스크롤 없음(긴 문장은 줄바꿈, 값 표는 2열 → 1열).

## 3. 테스트
- `scripts/regression/label-check-512-card.ts`(등록): (a) `classifyFinding512` 표 — 아래 입력이 기대 종류로 나옴: `"관련 표기를 찾지 못함"`→missing, `"원산지 표기를 찾지 못함"`→missing, `"전화·이메일 등 연락처를 찾지 못함"`→missing, `"내용량(숫자+단위)을 찾지 못함"`→missing, `"전성분 영역 크기(pt): 4, 5 — 5pt 미만 1건"`→measure, evidence가 있는 광고 finding→wording. (b) 정적 검사: missing 경로에서 `before`(취소선) 클래스를 렌더하지 않음, "예시 문구입니다" 줄이 예시 존재 조건 안에서만 나옴, 하나 마나 한 문구 문자열("해당 항목을 확인") 없음, 금지어 없음. (c) 기존 묶음 전부 통과.
- 기존 테스트를 고쳐야 하면 금지어·면책 가드는 약화하지 말고, 고친 목록을 보고서에 적는다.

## 4. 보고서에 포함
1. 맨 위 "확인하지 못한 항목".
2. 종류별로 화면 모양(마크업 요약)과 `classifyFinding512`가 실제 샘플 결과(`label-check`의 샘플 버튼 결과)의 카드 몇 개를 어떤 종류로 분류했는지 표.
3. 분류가 모호해 `other`로 남긴 항목 목록(다음 차수에서 데이터로 보강할 후보).
