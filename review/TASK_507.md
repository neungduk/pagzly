# 507차 — 고객용 화면 전면 개편 (쉬움·간편함·상품성)

> 순서: **506차 완료 후**. 시안 파일: `review/mockups/label-check-ui-507.html` (브라우저로 열어 먼저 볼 것). 이 시안의 구조·위계·문구 톤을 따른다. 픽셀 단위 복제가 아니라 **구조와 우선순위**가 기준이다.

## 0. 절대 규칙
1. 유료 호출 금지. Production·main push 금지. 코드 삭제 금지(기존 컴포넌트는 교체하되 사용하지 않게 된 파일은 남겨 두고 보고). 상세페이지·결제 화면 변경 금지.
2. 판정 로직·규칙 데이터 변경 금지(이번 차수는 화면만). 화면에 표시하는 설명·수정 문구는 전부 서버 결과(506차 구조)에서 온다. UI 라벨(버튼·탭·안내)만 코드에 둔다.
3. 금지 표현: "위반입니다", "적법", "완벽", "보장", "안전합니다", "100%". 496차 금지어 검사 통과 필수(새 라벨 포함).
4. 먼저 `node_modules/next/dist/docs/`의 관련 안내를 읽는다(AGENTS.md). 새 의존성 추가 금지(아이콘은 인라인 SVG 또는 이모지 최소 사용).
5. `review/507-targets.md`에 코드 전 화면 구성표(화면·컴포넌트·상태)를 적는다.
6. 마무리 전 통과: `npx tsc --noEmit`, `npm run build`, `npm run regression:label-check`. 커밋 최대 5개. 보고서 `review/507cha-report.md`(맨 위 "확인하지 못한 항목"), push 확인 후 해시 기재.

## 1. 고객 관점 목표
화장품 브랜드 담당자(비전문가)가 **설명 없이 1분 안에**: 올린다 → 무엇을 고칠지 안다 → 고칠 문구를 복사한다 → 고쳐서 다시 확인한다.

## 2. 용어(화면 표기) — 내부 상태와 매핑
| 내부 상태 | 화면 표기 | 색 |
|---|---|---|
| possible(위반 가능) | **고칠 것** | 빨강 계열 |
| attention(확인 필요) | **확인할 것** | 호박색 |
| unknown(확인 불가) | **확인 못 함** | 회색 |
| pass | **문제 없음** | 녹색 |
| manual | **직접 확인** (확인할 것 탭 하단에 묶음) | 회색 테두리 |
- 색만으로 구분하지 말고 **칩 글자**를 함께 쓴다. 본문 글자 대비 4.5:1 이상.
- "위반 가능"이라는 단어는 화면에서 쓰지 않는다(내부 코드·데이터는 그대로).

## 3. 화면 구성

### 3-1. 올리기 (게스트 `/label-check`, 회원 `/label-check/new` 공통 컴포넌트)
위에서 아래 순서로 한 장의 카드:
1. 제목 한 줄(시안 문구) + 3단계 표시(1 올리기 → 2 결과 보기 → 3 고쳐서 다시 점검).
2. **판매 국가 선택**: 큰 버튼 2개(한국/미국), 기본 한국. 라디오 그룹 접근성.
3. **PDF 놓기 영역**: 끌어다 놓기 + 클릭 + 키보드(Enter/Space). 선택 후 파일명·크기 표시와 "다른 파일" 버튼.
4. "또는 문구만 붙여넣기" 구분선 + 입력칸(506차 텍스트 모드). PDF와 텍스트 중 하나만 활성(둘 다 있으면 PDF 우선, 안내 한 줄).
   - 텍스트 입력 시 범위 선택: "광고 문구만"(기본) / "라벨 전체 문구".
5. **제품 정보 선택**(접힘, 기본 닫힘): 기존 옵션(씻어내는 제품, 기능성, 수입품, 전문가용 등 시장별)과 제품 유형(504차). 시장을 바꾸면 해당 시장 옵션만 보인다.
6. 큰 버튼 "무료로 점검하기". 진행 중에는 버튼 자리에 단계 문구("글자 읽는 중…" → "규칙과 비교하는 중…") 표시, 중복 클릭 방지.
7. 면책 한 줄.
- 샘플 결과 보기(기존)는 카드 아래 텍스트 링크로 축소.
- 회원/비회원 차이: 회원은 제품명(선택) 입력 1칸 추가, 상단에 "내 결과" 링크.

### 3-2. 결과
1. **한 줄 결론**(가장 크게): 고칠 것 n>0 → "먼저 고칠 곳이 n군데 있어요" / 고칠 것 0·확인할 것 n>0 → "확인할 곳이 n군데 있어요" / 둘 다 0 → "이번 점검에서 발견된 항목이 없어요"(+ 작은 글씨 "최종 확인은 직접 하셔야 합니다"). 그 아래 작은 글씨: 제품명 · 시장 · 점검 기준(501차 문구).
2. **숫자 4칸**(고칠 것/확인할 것/확인 못 함/문제 없음). 누르면 해당 탭으로 이동.
3. **탭**(가로 스크롤 가능): 기본 선택은 건수가 있는 가장 심각한 탭. 탭 전환은 키보드 좌우 화살표 지원.
4. **항목 카드**(탭 안 목록, 심각도·규칙 순 정렬):
   - 칩 + 제목(사용자 말투: "사용기한이 보이지 않아요" 형태가 데이터에 없으면 기존 제목 그대로 — 임의 의역 금지).
   - **찾은 문구**: `evidence.sentence`에서 `found`를 `<mark>`로 강조(최대 3개, 긴 문장은 앞뒤 40자).
   - **수정 영역**(항상 펼침): `fix.kind`별 소제목 — fill "이렇게 넣으세요" / replace "이렇게 바꿔 보세요 (예시)" / delete "이 표현은 빼는 걸 권해요" / evidence "근거 자료가 있으면 쓸 수 있어요" / functional_only "기능성화장품만 쓸 수 있어요" / manual "직접 확인해 주세요". `templates`·`alternatives` 각 줄 오른쪽에 **복사 버튼**(복사됨 표시 1.5초, clipboard 실패 시 텍스트 선택 폴백). `kind: guideline_exception` 대체 문구에는 작은 꼬리표 "지침 예외 조건".
   - `exception`이 있으면 연한 안내 줄 "예외에 해당할 수 있어요: …".
   - **근거**(접힘): `basis.law` + `basis.source`.
5. "문제 없음" 탭은 제목만 한 줄 목록(카드 아님). "확인 못 함"은 이유 한 줄 + 해결 방법.
6. **하단 고정 바**(결과가 있을 때만): 왼쪽 안내 한 줄, 오른쪽 "수정안 모두 복사"(506차 `buildFixSheet`). 모바일에서 본문을 가리지 않게 본문 아래 여백 확보, 화면 하단 안전 영역 반영.
7. **다시 점검 카드**(목록 아래): "고친 문구를 붙여넣고 다시 점검" 입력칸 + 버튼. 재점검 후 결과 상단에 비교 띠 "2개 해결 · 1개 남음 · 새로 생김 0"(506차 `compare`).
8. 회원: "이 결과 저장됨" 표시와 "내 결과" 링크. 비회원: "가입하면 결과를 다시 볼 수 있어요" 한 줄(+가입 링크).
9. 텍스트 모드 ad_only 결과에는 상단에 "광고 문구만 점검했어요" 표시, 숫자 칸의 "문제 없음"은 광고 항목 기준.

### 3-3. 오류·빈 상태 (모두 한글, 다음 행동 1개 제시)
이미지 PDF, 용량 초과, 쪽수 초과, 읽기 실패, 요청 제한, 로그인 만료, 서버 오류, 영어 라벨 아님(미국), 클립보드 실패. 기존 문구 상수 재사용, 새 문구는 최소.

## 4. 디자인 기준
- 색·간격·모서리는 시안의 CSS 변수 값을 기준으로 프로젝트 방식(기존 Tailwind/CSS 방식 유지)으로 옮긴다. 폰트는 프로젝트 기존 폰트 유지.
- 폭: 본문 최대 760px 가운데 정렬. **320px·390px에서 가로 스크롤 0**, 탭만 자체 가로 스크롤.
- 터치 대상 최소 44px. 포커스 링 보이게. 애니메이션은 탭 전환·복사 표시 정도만(`prefers-reduced-motion` 존중).
- 한 화면에 강조색은 1개(브랜드 녹색) + 상태색. 그림자 남용 금지.
- 다크 모드는 이번 범위 아님(기존 사이트 정책 따름).

## 5. 접근성
- 탭: `role="tablist/tab/tabpanel"`, `aria-selected`. 시장 선택: 라디오 그룹. 복사 결과: `aria-live="polite"`. 오류: `role="alert"`. 결과 도착 시 결론 문장으로 포커스 이동.
- 모든 입력에 label. 색 대비 검사 결과를 보고서에 기재(계산값).

## 6. 시험
- `scripts/regression/label-check-507.ts`(정적·렌더 문자열 수준): 상태→표기 매핑, 결론 문장 3분기, 탭 기본 선택 규칙, fix.kind별 소제목, 금지어 0, "위반 가능" 문자열이 화면 컴포넌트에 없음, noindex 유지(new/history), 빈 `fix`일 때 수정 영역 미표시.
- 저장된 결과(`/label-check/history/[id]`)도 새 카드로 보이되 저장본에는 문장 원문이 없으므로 "찾은 문구" 영역은 표시하지 않음 — 시험 포함.
- 브라우저 실측(폭 320/390, 키보드, 복사)은 가능하면 하고, 못 하면 "미실시"로 기재(추정으로 통과 처리 금지).
