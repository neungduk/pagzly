# TASK_447 — PC 원커맨드 검증 도구 + 남은 코딩 후보 정리 (코딩 중심, 유료 API 0회)

실행 환경: 클라우드 세션(`cloud-work`). 선행: 446차 완료(`review/446cha-report.md`).
시작 문장: "447차 시작: PC 검증 도구와 남은 후보 정리".

## 배경
445·446차까지로 합성 데이터·플레이스홀더 기준의 디자인 품질은 상당히 올라왔고, **이제 남은 위험은 전부 PC에서만 확인 가능한 것**(실사진, 저장 세션 6종, 실제 환경값 빌드, `launch-smoke`, 438차 원본 대비 off 증명, 실제 폰트 라이브 화면)이다. 클라우드 코딩을 더 쌓아도 실사진 검증 없이 합성에만 맞추면 과적합 위험이 있다. 그래서 이번 차수는 (1) **PC에서 한 번에 돌릴 검증 도구**를 만들어 PC 확인 비용을 줄이고, (2) 446차가 남긴 코딩 후보 중 **실사진 없이도 판단 가능한 것**만 처리한다.

- **유료 API 0회**, 실제 키·토큰 0, `.env*` 열람·생성·커밋 금지(환경값은 명령어 앞 인라인 더미만), 외부 호출 금지, 새 로그인/계정 금지.
- **새 문구·수치 생성 금지.** 고지 문구 불변. 마이그레이션 없음.
- **결제 코드·`cta_price` 구조·`data-pz-buy`·스티키 바·편집 UI·인터랙션 불변.**
- 모든 디자인 변경은 `NEXT_PUBLIC_DESIGN_V4` 안, **off = 446차 끝 코드(`601c481`) 출력과 문자열 diff 0**(export·라이브·섹션 단독, 기준 = 그 커밋 worktree + 현재 픽스처), 문자열 패리티 유지, export 금지 기법(`:has()`, container query, `text-wrap`, `mix-blend-mode`, `clip-path`, `mask`, `-webkit-text-stroke`) 금지, 대비 4.5:1, 본문 14px·라벨 12px, 회귀 98+ 통과, tsc 오류 0.
- 스크립트·정규식은 heredoc 말고 Write/Edit. Playwright는 `/opt/pw-browsers` 링크, 폰트는 `node scripts/build-detail-fonts.mjs`.

## 1. PC 원커맨드 검증 도구 (`scripts/pc-verify.ts` + `docs/pc-verify.md`)
목표: PC에서 `npx tsx scripts/pc-verify.ts`(또는 `npm run pc-verify`) 한 줄로 아래를 **순서대로 실행하고 요약표를 `review/pc-verify-<날짜>/summary.md`로 저장**한다. 실패한 단계가 있어도 **다음 단계는 계속**하고(의존 단계 제외) 최종에 합격/불합격/건너뜀을 표로 낸다. 각 단계는 **실행 명령·소요 시간·종료 코드·로그 경로**를 남긴다.
1. 환경 점검(Node 버전, `public/fonts` 존재, 환경값 존재 **여부만**(값은 읽지 않고 출력도 하지 않음), `git status` 요약).
2. `npx tsc --noEmit`
3. `npx tsx scripts/regression/run-all.ts` (Playwright 리비전 오류를 감지하면 `npx playwright install chromium` 안내 문구를 요약에 남김)
4. `check-v4-off`·`check-v4-off-live`(기준 스냅샷 경로가 없으면 **건너뜀 + 기준 만드는 명령 안내**; 438차 원본 worktree에서 기준을 저장하는 보조 명령 `scripts/pc-verify.ts --make-baseline <commit>` 제공: 임시 worktree를 만들고 기준을 저장한 뒤 정리, `node_modules`는 링크하지 말고 `npm ci` 또는 경로 인자로 재사용 방법을 안내)
5. `npx next build`(환경값은 PC의 기존 환경에서; 이 스크립트는 **환경 파일을 열지 않고** 자식 프로세스가 상속하게만 둔다)
6. 저장 세션 6종 자동 탐색: `review/*-live/**/session.json` 등 알려진 경로 패턴으로 찾고(없으면 건너뜀) 각 세션에 대해 export 패리티·428 DOM 지표·750폭 가로 넘침·린트(R7·R16·R17·R18)를 실행해 표로.
7. `launch-smoke`(저장소의 기존 명령을 `package.json`/스크립트에서 찾아 호출, 못 찾으면 건너뜀 + 안내).
8. 눈 검수용 캡처: 저장 세션 6종 + 합성 21종을 390·750으로 캡처해 `review/pc-verify-<날짜>/eye/`에 844px 단위 시트와 첫 화면 접촉 시트로 저장(실사진·실폰트). 캡처가 오래 걸리면 `--skip-capture` 옵션.
9. 요약에 **눈으로 볼 체크리스트**(446차 §10의 10~12번 항목: 색 응집력, 고스트 안 잘림·프레임 3종, 번호 배지, 750폭 간격, 후기 캡션 12px, 노랑~초록 사진 대비 등)를 시트 경로와 함께 출력.
- 도구 자체의 회귀(`scripts/regression/pc-verify-447.ts`): 단계 목록·건너뜀 규칙·요약 생성(모의 실행 `--dry-run`으로 명령만 출력)·**환경 파일을 읽지 않는지**(소스에 `.env` 읽기 호출이 없는지 정적 검사)·값 출력 금지.
- `docs/pc-verify.md`: 사용법 1페이지(순서, 옵션, 실패 시 해석, 소요 시간 어림).
- 클라우드에서는 `--dry-run`과 가능한 단계(2·3·6의 합성 부분)만 실제로 돌려 도구가 동작함을 확인하고 보고서에 어떤 단계를 실제로 돌렸는지 표시.

## 2. 446차 남은 후보 중 실사진 없이 판단 가능한 것
1. **긴 한글 상품명 고스트 대체**: 한글 9자 이상이면 고스트가 꺼지는 현재 설계(잘림 방지 우선)를 개선 — 상품명의 첫 어절·영문 보조줄·브랜드명 중 **폭 맞춤이 가능한 가장 짧은 후보**를 고스트 문구로 재선택(입력 문구만, 새 문구 금지). 후보가 모두 넘치면 현재처럼 끔. 라이브·export 같은 함수, 회귀(실제 글자 상자가 화면 안, 후보 선택 결정성).
2. **모티프 블록 위 여백 112 간격**: 모티프 안전 영역 때문에 줄이지 못하던 구조를 **앞 블록 아래 여백을 줄이는 쪽**으로 해결(3단 스케일 안), 모티프-글 겹침 회귀(R9) 유지. 느슨한 스캔 750px 96 초과 8 → 목표 ≤4, 390px 4 → ≤2.
3. **포화 히어로 면 채도 상한**: B형 포화 면이 진한 파랑·마젠타에서 과하게 강한 문제 — 대비 4.5:1만 보장하던 것에 **면 채도·명도 상한**(색상별 고정 상한이 아니라 정규화된 지각 채도 상한 + 사진 영역과의 균형)을 추가. 실사진 판단은 PC 몫이므로 **상한 값은 토큰 한 곳**에 두고 보고서에 눈으로 본 근거(합성 5색상)와 "실사진 확인 필요" 표시.
4. **페이지 끝 검색용 평문 블록 접기/축소**: 문구는 유지(접힘 표시는 정적 HTML에서 항상 펼친 상태로 보이되 시각적으로 작게·옅게, `details` 같은 인터랙션 도입 금지). 라이브·export 같은 마크업.
- 항목별 전/후는 라이브 캡처 샘플(변경 섹션만) 또는 export 시트로 눈 검수 후 결함은 즉시 수정.
