# 483차 — 화장품 표시사항 PDF 자동 검수 MVP (코드 검사만, AI 호출 없음)

## 0. 규칙
- 유료 호출(AI/OCR API)·Production·main 금지. 기존 상세페이지 기능은 건드리지 말고 새 경로(`/label-check`)에만 추가한다.
- 키/토큰을 채팅이나 파일에 적지 말 것. 업로드된 PDF는 검수 직후 서버에 남기지 않는다(메모리 처리 후 폐기, 로그에 본문 금지).
- 결과 문구는 "참고용 사전 점검, 법적 판단 아님"을 항상 표시. 단정 표현 금지: "위반"이 아니라 "위반 가능/확인 필요".
- 글자가 없는 PDF(이미지뿐)는 검수하지 말고 "텍스트를 읽을 수 없어 확인 불가"로 안내(OCR은 다음 차수).
- 목표는 `review/483-targets.md`에 코드 전에 기재. 파일은 Read 후에만 Write/Edit.

## 1. 입력 자료
- 규칙표: `review/data/kr_label_rules_draft_v0.1.json` (사용자가 전달; 35개 규칙. check_type=code 인 것만 이번에 구현, ai/manual 은 "수동 확인 필요"로 목록만 표시)
- 알레르기 25종: `review/data/allergens-kr-25_draft.json` (한글명은 미검증 → 화면에 "초안" 표시)
- 테스트 PDF 3개: `review/data/samples/sample_A_moari_toner.pdf`, `sample_B_rovan_sun.pdf`, `sample_C_salt_bodywash.pdf` (글자 있는 PDF, 가상 브랜드)

## 2. 항목
### A. 업로드와 글자 추출
- `/label-check` 페이지: PDF 1개 업로드(최대 10MB), 제품 유형 선택(씻어내는/안 씻어내는, 기능성 여부 체크박스).
- 서버에서 PDF 텍스트 추출(pdfjs-dist 또는 pdf-parse 등 무료 라이브러리). 글자 수가 너무 적으면 "확인 불가".

### B. 코드 검사 (규칙표 check_type=code)
- 필수 항목 존재 검사: 명칭, 책임판매업자 상호·주소, 내용량, 사용기한(또는 개봉 후 사용기간), 제조국, 전성분, 주의사항, 제조번호.
- 전성분 안에 알레르기 25종이 있는지 매칭(향료 포함 시 확인 필요 표시).
- 금지 표현 키워드(의약품 오인: 재생/치료/완전 제거 등)는 "확인 필요"로만 표시. 키워드 목록은 규칙표에서 읽는다(코드에 박지 말 것).
- 글자 크기(5pt 이상) 검사는 PDF에서 폰트 크기를 읽을 수 있을 때만 수행, 못 읽으면 "확인 불가".

### C. 결과 화면
- 요약(위반 가능/주의/확인 불가/통과 개수) + 항목 표(구분·항목·찾은 내용·제안). 한글 라벨만, 내부 id 노출 금지.
- 결과를 1장짜리 인쇄용 화면으로 보여주기(PDF 저장은 다음 차수).
- 로그인 없이 동작해도 됨. 결과는 DB에 저장하지 않는다.

### D. 검증
- 테스트 PDF 3개로 기대 결과 확인: A는 사용기한 없음·"재생/완전 제거" 확인 필요·알레르기 성분(리모넨, 리날룰) 확인 필요, B는 기능성 표기 및 제조번호 확인 필요, C는 대부분 통과(+"피부 장벽 강화" 확인 필요 정도).
- 회귀: 기존 상세페이지 테스트 전부 통과, 가로 넘침 0(320/390/750).
- `scripts/regression/label-check-483.ts` 추가(run-all 등록).
