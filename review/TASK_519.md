# TASK 519 — 랜딩 첫 화면 재구성 (제품이 일하는 장면을 첫 화면으로)

## 왜 하는가
- 지금 첫 화면은 "가운데 정렬 제목 → 버튼 → 그 아래 데모" 순서다. 제목만 보이고 제품은 스크롤해야 보인다. 사용자는 이 구도를 "구글폼 같다, AI가 만든 티가 난다"고 본다.
- 참고 사이트를 직접 열어 보고 정한 방향은 세 가지다.
  1. **구도(Harvey 방식)**: 밝은 바탕, 왼쪽 정렬 큰 제목, 오른쪽에 짧은 설명과 검은 버튼. 그 바로 아래에 큰 "무대" 하나가 화면 폭을 거의 다 쓰고, 무대 안에 제품 화면이 들어간다. 어두운 면은 결과 카드 하나뿐이다.
  2. **태그(DeepL Write 방식)**: 라벨 글자 위에 작은 색 태그가 붙어 튀어나온다. "무엇을 짚어 주는지"가 그림으로 보인다.
  3. **톤(뤼튼 방식)**: 밝은 바탕 + 검은 알약 버튼. 지금 토큰 그대로다.
- 색·글꼴·버튼 토큰은 바꾸지 않는다. **바꾸는 것은 첫 화면의 구도와 연출뿐이다.**

## 범위
- 대상: 랜딩(`/`)의 머리말 아래 ~ 예시 문구 띠 위까지. 즉 `lc514-hero` 영역과 `LandingProofDemo511`의 `#demo` 영역.
- 건드리지 않는 것: 판정 로직, 규칙 JSON, `/label-check` 화면, 결과 화면, 그 아래 섹션(숫자 띠, 고친 문장, CTA 띠, 푸터), 예시 문구 띠(`lc515-belt-section`).
- 새 파일은 `components/label-check/ui-519/`에 둔다. 기존 `ui-511` 컴포넌트는 지우지 말고, 랜딩에서 쓰는 부분만 새 것으로 바꿔 끼운다.
  - `ui-519/LandingStage519.tsx` (첫 화면 전체: 제목 줄 + 무대)
  - `ui-519/landing-519.css` (접두사 `lc519-`, `.lc-site` 범위 안)
  - 데모 문구는 계속 `ui-511/landing-demo-514.ts`에서 가져온다. 새 문구가 필요하면 그 파일에 `_519` 상수로 추가한다(하드코딩은 그 파일에만).

## A. 제목 줄 (무대 위)

### A-1 구도
- 데스크톱(≥1024px): 2단. 왼쪽 약 60%에 제목, 오른쪽 약 40%에 설명·버튼·힌트. 아래쪽 기준선을 맞춘다(`align-items: end`).
- 전체 왼쪽 정렬. 가운데 정렬 금지.
- 제목 줄 위아래 여백은 지금보다 줄인다. 1440×900 화면에서 **스크롤 없이 무대 윗부분이 최소 280px 보여야 한다.**
- 모바일(<768px): 1단. 제목 → 설명 → 버튼 → 무대 순.

### A-2 문구 (그대로 쓸 것)
- 제목(h1): `인쇄 넣기 전에,` 줄바꿈 `라벨과 광고 문구를` 줄바꿈 `{kr}개 기준으로 먼저 훑어 드립니다`
  - `{kr}`은 `labelRuleCounts514().kr` 값이다. 숫자를 직접 적지 않는다.
  - `{kr}개 기준` 부분만 파란색 `#1D4ED8`. 그 아래에 손으로 그은 듯한 밑줄(SVG path 한 줄, 처음 한 번 왼쪽에서 오른쪽으로 그려짐).
  - 숫자는 처음 한 번 0에서 `{kr}`까지 올라간다(0.9초 안팎). `prefers-reduced-motion`이면 바로 최종 숫자.
- 설명: `화장품 라벨 사진이나 상세페이지 PDF를 올리면, 고칠 문구와 빠진 표시사항을 근거와 함께 보여 드립니다. 고쳐 쓴 문구 예시도 함께 나옵니다.`
- 주 버튼(검은 알약, `/label-check`로 이동): `내 라벨 점검해 보기` + 오른쪽 화살표. 올리면 살짝 뜨고 화살표가 오른쪽으로 4px 이동.
- 보조 링크(글자만, 밑줄): `결과 예시 보기` → `#demo`
- 힌트 3개(작은 모노 글씨, 가운뎃점으로 구분): `로그인 없이 시작` · `점검 후 파일 저장 안 함` · `한국 · 미국 기준`
- 버튼 아래 작은 글씨: `법적 판단이 아닌 사전 점검 도구입니다`

### A-3 글자
- 제목: Noto Sans KR 800~900, `clamp(38px, 5.2vw, 76px)`, 줄간격 1.16, 자간 -0.035em, `word-break: keep-all`.
- 세리프 글꼴은 쓰지 않는다(한글에서는 무거워 보인다).

## B. 무대 (첫 화면의 중심)

### B-1 틀
- 제목 줄 바로 아래, 좌우 여백만 남기고 화면 폭을 거의 다 쓰는 큰 판 하나. 모서리 28px(모바일 20px).
- 판 바탕: 기존 번지는 색(#D5DEFF, #FFDCCB, #CFEFE0)을 **판 안쪽에서 더 진하게** 쓴다. 판 밖 페이지 배경(#F3F5FB + 옅은 번짐)은 그대로 둔다. 판 안의 번짐은 천천히 움직인다(20초 이상 주기).
- 판에 흰 카드 테두리(1px 회색 선)를 두르지 않는다. 구분은 색과 그림자로만 한다.
- `id="demo"`는 이 판에 둔다(기존 `결과 예시 보기` 링크가 여기로 온다).

### B-2 판 안 구성 (데스크톱)
- 왼쪽 약 45%: **라벨 종이.** 기존 `lc514-label-card` 내용을 재사용한다(제품명, 내용량, 광고 문구, 전성분, LOT). 3도쯤 기울인다. 종이 느낌의 밝은 면.
- 오른쪽 약 55%: **검은 결과 카드(#111214) 하나.** 기존 `lc517-land-hero` 결과 묶음을 재사용한다. 카드가 판의 오른쪽·아래쪽 가장자리를 12~24px 넘어서 걸쳐 나오게 한다(판 밖으로 살짝 튀어나옴). 판이 `overflow: hidden`이면 안 된다.
- 라벨 종이와 결과 카드는 40px쯤 겹친다(결과 카드가 위).
- 결과 카드 안: 번호 `01`~`03` 모노 숫자, 상태 색 점, `BEFORE` / `AFTER` 두 블록. 518차 `FindingBody518`의 모양과 같은 계열로 맞춘다(취소선 없음, 안쪽 흰 상자 없음).

### B-3 연출: 훑는 선과 태그 (DeepL 방식)
순서대로 한 바퀴(약 6초) 돌고, 2초 쉬었다가 반복한다.
1. 훑는 선이 라벨 위에서 아래로 내려간다(기존 `lc-scan514` 재사용 가능).
2. 선이 지나간 자리의 문구에 형광펜 표시가 생긴다(기존 `lc515-mk`).
3. 표시된 문구에서 **태그가 튀어나온다.** 태그는 작은 알약 모양, 색 점 + 글자, 살짝 기울어짐(-2~2도), 그림자.
   - `피부 주름을 완전히 없애 주는` → 빨강 점 `고칠 것`
   - `피부 재생` → 노랑 점 `확인할 것`
   - 사용기한 자리(`표기 없음`) → 노랑 점 `확인할 것 · 사용기한`
   - 전성분 → 초록 점 `문제 없음`
4. 태그가 나올 때마다 결과 카드의 해당 줄이 차례로 켜진다(투명도 0.35 → 1, 아래에서 6px 올라옴).
- 태그 위치는 문구 요소에 대한 상대 위치로 잡는다. 화면 폭이 바뀌어도 문구에서 떨어지지 않아야 한다.
- 태그 글자에 `위반입니다`, `적법`, `완벽`, `보장`, `안전합니다`, `100%`를 쓰지 않는다.
- `prefers-reduced-motion: reduce`이면 선은 멈추고, 표시·태그·결과 줄은 처음부터 다 보이는 상태로 둔다.
- 자바스크립트 타이머 대신 CSS `animation-delay`로 순서를 만든다. 클라이언트 컴포넌트가 꼭 필요하면 숫자 올라가기 부분만 분리한다.

### B-4 판 아래 한 줄
- 판 왼쪽 아래 바깥에 모노 작은 글씨: `예시 화면입니다 · 실제 결과는 올린 파일에 따라 달라집니다`
- 516차 `법령 확인 기준일` 줄은 지금 위치(푸터 위) 그대로 둔다.

### B-5 모바일(<768px)
- 판 안을 1단으로: 라벨 종이(기울기 1.5도로 줄임) → 결과 카드가 라벨 아랫부분에 24px 겹쳐서 이어짐.
- 태그는 라벨 안쪽에 머문다. 화면 밖으로 나가서 가로 스크롤이 생기면 안 된다(360px, 390px에서 확인).
- 결과 카드가 판 밖으로 튀어나오는 것은 모바일에서는 아래쪽만.
