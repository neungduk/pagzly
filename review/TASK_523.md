## 1. 절대 규칙
1. **웹 화면(pagzly.com)은 글자 하나, 클래스 하나 달라지면 안 된다.** 2-A의 "기준 출력 비교" 테스트로 매 커밋마다 확인한다.
2. 판정 로직·규칙 JSON·서버(`app/api/**`)·`lib/label-check`의 판정 관련 파일은 건드리지 않는다.
3. 루트 `package.json` 변경 금지. `toss-app`에도 **npm 패키지를 추가하지 않는다**(TDS 포함). 글꼴 파일·이미지 파일 추가 금지. 그림은 CSS와 인라인 SVG로만.
4. 번들에 `eval(`·`new Function(`이 들어가면 토스가 반려한다. `scripts/scan-bundle-eval.mjs`가 항상 통과해야 한다.
5. 토스 규칙: 라이트 모드만. 화면 안에 **자체 뒤로가기 버튼 금지**(토스 내비게이션과 이중 노출). **진입하자마자 뜨는 바텀시트·팝업 금지.** 외부 이동(`href="http…"`, `window.open`, `location.href =`) 금지. 가입·앱 설치 유도 금지.
6. 문구: `무료`, `요금`, `1분`, `위반입니다`, `적법`, `완벽`, `보장`, `안전합니다`, `100%` 금지. 가짜 후기·가짜 수치·가짜 진행률(%) 금지. 고지 문장 **`참고용 사전 점검이며 법적 판단이 아닙니다.`** 는 결과 화면에 그대로 남긴다.
7. 사용자 파일·글자 원문을 콘솔·로그에 남기지 않는다.
8. 이모지 금지. 화살표 글자(`→`, `↓`)·체크 글자(`✓`)를 아이콘 대신 쓰지 않는다(토스 화면에서는 인라인 SVG로 바꾼다. 5-C).
9. 확인하지 않은 것을 "확인함"으로 적지 않는다. 못 본 것은 "못 봄"으로 적는다.

## 3. 검수자가 이미 찾은 흠 (라운드 1에서 전부 고친다)
`review/523-baseline/` 그림 기준.
1. **제목 줄바꿈이 어색하다**: `라벨을 올리면, 바로 / 읽어서 점검해요`처럼 파란 글자가 두 줄로 갈라진다. 뜻 단위로 끊는다(`라벨을 올리면,` 줄바꿈 `바로 읽어서 점검해요`). 쉼표 뒤 띄어쓰기도 확인.
2. **파일을 고른 뒤 아래 알약이 잘린다**: `준비 완료 · 아래 점검하기를 눌러요`가 오른쪽에서 잘린다. 파일 이름 알약과 `다시 고르기`도 맞닿는다.
3. **쓸 수 없는 회색 큰 버튼이 화면을 가린다**: 파일을 올리기 전에도 `파일을 올리면 시작할 수 있어요` 회색 막대가 하단에 고정돼 설정 카드를 가린다. 준비되기 전에는 막대를 띄우지 않고, 준비되면 검은 버튼이 아래에서 올라온다.
4. **`샘플 결과 보기`가 맨 아래 작은 글씨다**: 처음 온 사람이 결과가 어떻게 나오는지 볼 수 있는 가장 좋은 입구인데 눈에 띄지 않는다.
5. **결과 필터가 두 줄로 깨진다**: `확인할 / 것 5`, `직접 확 / 인 1`. 한 줄 칩으로, 넘치면 그 줄만 가로로 민다.
6. **PC용 안내 문구가 남아 있다**: `문구 위치를 찾지 못한 항목은 오른쪽 목록에서 확인해 주세요`(폰에서는 "아래 목록").
7. **요약 카드의 날짜가 줄 중간에서 끊긴다**: `점검일 2026- / 11-11`.
8. **항목 제목이 상태 칩 때문에 좁아져 두 줄이 된다**: `사용기한 또는 개봉 후 / 사용기간`, `영업자의 상호 및 / 주소`.
9. **결과를 다 본 뒤 갈 곳이 없다**: `다른 라벨 점검하기`가 없다(뒤로가기만 있다).
10. **`가상 브랜드 예시입니다`가 설명 없이 맨 위에 붙어 있다**: 예시 결과임을 알리는 띠로 정리한다.
11. 점검 중 화면이 `✓`·`·` 글자를 아이콘처럼 쓴다. 화살표도 글자(`→`, `↓`)다.
12. 아래쪽에 빈 바탕이 길게 남는다(시작 화면 하단, 결과 화면 하단).

## 4. 화면별 설계 (라운드 1~2)
공용 부품의 **구조를 바꾸지 않고**, 토스 쪽에서 감싸거나 CSS로 보정한다. 문구·작은 표시를 바꿔야 하면 522차 방식(선택 속성 `touch`, `embedded`. 기본값은 웹과 동일)을 확장한다. 새 선택 속성을 추가할 때마다 2-A 테스트가 통과하는지 확인한다.

### A. 시작 화면 — "한 화면에 들어오는 첫인상"
- 목표: **390×844에서 스크롤 없이** 제목, 파일 올리는 카드, 예시 보기, 설정 요약이 모두 보인다. 360×740에서는 한 번의 짧은 스크롤 안에 끝난다.
- 구성(위에서 아래로)
  1. 제목 2줄(28~30px, 900) + 설명 한 줄(15px).
  2. 파일 올리는 카드: 탭(`파일 올리기` / `문구 붙여넣기`) + 누르는 영역. 누르는 영역은 폰에서 **높이 200~230px**로 줄이고, 문서 그림은 작게(훑는 선 움직임 유지). 용량 안내(`PDF 100MB · 사진 10MB`)는 카드 아래쪽 작은 글씨로.
  3. **예시 결과 보기 행**: 작은 미리보기 그림(빨강·노랑·초록 점 세 줄) + `결과가 어떻게 나오는지 먼저 볼까요` + 오른쪽 화살표 아이콘. 누르면 예시 결과.
  4. **점검 설정**: 폰에서는 카드 전체를 펼쳐 두지 말고 **요약 행 하나**(`점검 설정` · `한국 · 안 씻어내는 제품` · 화살표)로 접는다. 누르면 그 자리에서 부드럽게 펼쳐지거나 아래에서 올라오는 시트로 연다(사용자가 눌러서 여는 시트는 허용. 진입 즉시 뜨면 안 된다). 시트로 만들면: 위쪽 손잡이, 바깥을 누르거나 아래로 밀면 닫힘, 닫을 때 선택값 유지, 뒤로가기(토스 내비게이션)로도 닫힘, 초점 가두기, `aria-modal`.
  5. 맨 아래 작은 글씨: `파일은 점검 후 저장하지 않아요` · 문의 이메일(눌러서 복사).
- 하단 버튼: 준비 전에는 없음. 파일을 고르거나 문구를 넣으면 검은 버튼 `점검하기`가 아래에서 0.25초에 올라온다. 안전 영역 반영.
- 파일을 고른 뒤: 미리보기 카드(사진은 `object-fit: contain`, 최대 높이 화면의 45%), 위에 파일 이름 알약(말줄임)과 `다시 고르기`(서로 8px 이상 떨어짐), 아래 안내는 카드 **안쪽**에 한 줄로(잘리지 않게).

### B. 점검 중 화면
- 화면 전체를 덮는 차분한 화면. 가운데에 문서 그림과 훑는 선, 그 아래 단계 4개(`글자를 읽는 중` → `필수 표시사항 확인` → `광고 문구 확인` → `결과 정리`).
- 단계 표시는 글자 기호 대신 아이콘: 끝난 단계는 초록 체크(SVG), 진행 중은 도는 고리, 남은 단계는 옅은 점. 가짜 퍼센트는 쓰지 않는다(지금처럼 단계 기준).
- 8초가 넘으면 한 줄 추가: `사진이 크면 조금 더 걸려요`. 30초가 넘으면: `연결이 느려요. 잠시만 기다려 주세요`.

### C. 글자 확인 화면
- 제목 `이렇게 읽었어요` + 설명 `틀린 글자는 고쳐 주세요`.
- 썸네일은 접힌 작은 띠(누르면 크게), 글상자가 화면의 중심. 글자 16px 이상, 줄간격 1.7.
- 낮은 신뢰도 줄 표시·안내 문구는 지금 부품이 주는 것을 그대로 쓴다.
- 하단 고정 버튼 두 개: 주 버튼 `이 글자로 점검` / 보조 `취소`. 키보드가 올라오면 버튼이 입력을 가리지 않는다.

### D. 결과 화면 — 가장 공들일 곳
1. **요약 카드(어두운 면)**
   - 한 줄 정보(제품명 · 기준 · 점검일)는 줄 중간에서 끊기지 않게(`white-space: nowrap` 묶음 단위, 넘치면 항목 단위로 줄바꿈).
   - 큰 문장(`고칠 것 3개, 확인할 것 6개가 있어요`)은 26px 안팎, 숫자만 상태색.
   - 비율 막대는 화면에 들어올 때 왼쪽에서 0.6초에 차오른다. 숫자 4칸은 0에서 올라간다(0.7초, 한 번만). `prefers-reduced-motion`이면 바로 최종값.
   - 숫자 4칸은 2×2 유지하되 칸 높이를 줄여(약 84px) 요약 카드가 첫 화면의 **60%를 넘지 않게** 한다. 첫 화면에서 필터 줄이나 첫 항목 머리가 보여야 한다.
2. **읽은 라벨 패널**: 폰에서는 기본 3줄만 보이고 `펼쳐 보기`. 펼치면 안쪽 스크롤(최대 높이 화면의 50%). 안내 문구는 `아래 목록`으로.
3. **필터 줄**: 한 줄 칩(`전체 20`, `고칠 것 3`, `확인할 것 5`, `직접 확인 1`, `문제 없음 11`). 넘치면 그 줄만 가로 스크롤(스크롤 막대 숨김, 오른쪽 끝에 옅은 흐림으로 "더 있음" 표시). 스크롤해 내려가도 **위에 붙어 있다**(`position: sticky`, 반투명 바탕 + 흐림). 선택된 칩은 검정 바탕 흰 글씨.
4. **항목 카드**
   - 머리: 번호 동그라미 + 제목(전체 폭 사용, 최대 2줄) / 그 **아래 줄**에 상태 칩. 오른쪽에 펼침 아이콘(SVG, 펼치면 180도 회전).
   - 펼침은 높이가 부드럽게 열린다(`grid-template-rows: 0fr → 1fr`, 0.25초).
   - 펼친 내용: 이유 한 문단, `라벨에서`(걸린 문구) 상자, `이렇게 고쳐 보세요` 상자 + `복사` 버튼. 복사하면 버튼이 1.5초 동안 `복사했어요`로 바뀌고 화면 아래에 짧은 알림(토스트)이 뜬다.
   - `고쳤어요` 버튼은 지금 동작 유지.
   - 카드 사이 간격 10px, 카드 모서리 20px, 그림자는 한 단계만.
5. **문제 없음 / 해당 없어 뺀 항목 / 참고**: 접힌 행. 펼치면 목록. 지금 구조 유지하되 여백·글자 크기를 본문 체계에 맞춘다.
6. **하단 고정 막대**: `수정 문구 한꺼번에 복사`(기존 `lc507-bar`). 한 줄 설명은 폰에서는 숨기고 버튼만 꽉 차게. 고칠 문구가 없으면 막대 없음.
7. **맨 끝**: `고친 문구로 다시 점검` 영역(지금 구조) → **`다른 라벨 점검하기`** 버튼(시작 화면으로, 입력 초기화) → 고지 문장 → 법령 확인 기준일 줄(있을 때).
8. **예시 결과일 때**: 맨 위에 옅은 띠 `예시 결과예요 · 가상 브랜드로 만든 화면이에요` + `내 라벨 점검하기` 버튼.
9. **결과가 깨끗할 때(`result-clean`)**: 요약 문장 `고칠 것을 찾지 못했어요`. 과장 금지(`문제없습니다`, `통과` 같은 단정 금지). 아래에 `규칙으로 확인한 범위예요. 최종 확인은 직접 해 주세요` 한 줄.
10. **글자를 못 읽었을 때(`unreadable`)**: 이유 한 줄 + 할 수 있는 일 두 가지 버튼(`다른 사진으로 다시` / `문구를 붙여넣어 점검`).

### E. 안내·오류 화면
- 오류(`error`): 빨간 테두리 상자 대신 카드 하나 — 아이콘, `연결이 잠시 끊겼어요`, 한 줄 설명, `다시 시도` 버튼. 원인 코드를 그대로 보여 주지 않는다.
- 한도(`limit`): `오늘 사진 읽기는 여기까지예요` + `문구를 붙여넣어 점검해요` 버튼(기존 문구의 뜻 유지. `무료`·`요금` 금지).
- HEIC(`heic`): 기존 안내 문구의 뜻을 유지하되 카드 모양으로.

## 5. 마감 품질 (라운드 2~3)

### A. 글자 체계 (토스 화면 한정, `.toss-app` 범위)
| 쓰임 | 크기 / 굵기 / 줄간격 |
|---|---|
| 화면 제목 | 28~30px / 900 / 1.25 |
| 카드 제목·요약 문장 | 20~26px / 800~900 / 1.3 |
| 항목 제목 | 17px / 800 / 1.4 |
| 본문 | 15~16px / 400~500 / 1.65 |
| 보조 | 13~14px / 400 / 1.55 |
| 가장 작은 글씨 | **12.5px 미만 금지** |
- 숫자는 `font-variant-numeric: tabular-nums`. 한글은 `word-break: keep-all`, 제목은 `text-wrap: balance`. 글자 사이는 제목만 `-0.03em` 안팎.
- 글자색 대비: 본문·보조 글씨는 흰 바탕에서 4.5:1 이상. `#8A8D94`는 흰 바탕에서 부족하므로 12.5~14px 글씨에는 `#6A6D74` 이상 진한 색을 쓴다(토스 화면 한정 보정).

### B. 간격·모양 체계
- 간격은 4의 배수(4, 8, 12, 16, 20, 24, 32). 화면 좌우 여백 20px(360px에서는 16px).
- 모서리: 카드 20px, 버튼·입력 14~16px, 칩 999px. 그림자는 두 단계만(떠 있는 것 / 살짝 뜬 것).
- 구분은 선보다 여백과 바탕색 차이로. 얇은 회색 테두리 상자를 줄줄이 늘어놓지 않는다.
- 같은 종류는 같은 모양(모든 주 버튼 56px 검정, 모든 보조 버튼 48px 흰 바탕 등). 보고서에 "부품 표"(버튼·칩·카드·행·입력 각각의 크기·색)를 적는다.

### C. 아이콘
- `toss-app/src/ui/icons.tsx`에 인라인 SVG로 필요한 것만(화살표 오른쪽, 펼침, 체크, 복사, 사진, 문서, 글자, 경고, 닫기, 새로고침). 선 굵기 1.75, 24px 기준, `currentColor`.
- 공용 부품이 글자 화살표를 그리는 곳은 토스에서 CSS로 숨기고 아이콘으로 대체하거나, 선택 속성으로 아이콘을 넘긴다(웹 기본 출력 불변).

### D. 움직임
- 원칙: 짧고(0.15~0.3초), `transform`·`opacity`만, 의미가 있을 때만.
- 넣을 것: 화면 전환(새 화면은 12px 아래에서 올라오며 나타남 0.22초, 뒤로는 반대), 카드 펼침, 누름(`:active` 0.98배), 하단 버튼 등장, 토스트, 요약 숫자·막대 한 번, 결과 항목이 0.04초 간격으로 차례로 나타남(최대 8개까지만).
- 넣지 않을 것: 계속 도는 장식, 튀는 스프링, 시차 스크롤.
- `prefers-reduced-motion: reduce`이면 전부 즉시.
- 터치 후 남는 hover 효과 제거(`@media (hover: none)`).

### E. 촉각·시스템 연동 (가능할 때만)
- `@apps-in-toss/web-framework`에 진동(햅틱) 기능이 있으면 `점검하기`·`복사` 성공 때 가볍게 쓴다. **공식 문서에서 이름과 쓰는 법을 확인한 뒤에만** 넣고, 토스 밖(브라우저)에서 열어도 오류가 나지 않게 감싼다. 확인이 안 되면 넣지 않고 보고서에 적는다.
- 토스 내비게이션 뒤로가기: 시트가 열려 있으면 시트 닫기 → 결과면 시작 화면 → 시작 화면이면 종료. `history` 기록으로 처리한다.

### F. 문구 (토스 화면 한정 해요체)
- 토스 화면에 보이는 문구를 해요체로 통일한다. 웹 문구는 그대로다(선택 속성으로 토스에서만 바꾼다).
- `toss-app/src/copy.ts` 한 파일에 토스용 문구를 모은다. 보고서에 "웹 문구 → 토스 문구" 표를 적는다.
- 판정 결과 안의 문구(규칙 제목, 이유, 고쳐 쓴 예시)는 서버가 주는 값이므로 **바꾸지 않는다.**
- 고지 문장 `참고용 사전 점검이며 법적 판단이 아닙니다.`는 그대로 둔다.

## 6. 견고함 (라운드 3)
1. 긴 내용: 파일 이름 60자, 제품명 40자, 항목 제목 3줄, 고쳐 쓴 문구 400자, 항목 30개 — 넘침·겹침 없음.
2. 좁은 화면 360px, 큰 글씨 설정(브라우저 글자 크기 120%)에서도 겹치지 않음.
3. 키보드: 글상자에 초점이 가면 하단 고정 요소가 입력을 가리지 않음. 초점이 간 입력이 화면 안에 보임.
4. 연속 누름: `점검하기`를 빠르게 두 번 눌러도 요청이 한 번만 나감. 점검 중 뒤로가기를 누르면 화면만 돌아가고 늦게 온 결과가 화면을 바꾸지 않음.
5. 사진 주소(`URL.createObjectURL`)는 화면을 떠날 때 해제.
6. 접근성: 모든 누를 수 있는 것 44px 이상, `:focus-visible` 표시, 버튼에 이름(`aria-label`), 펼침에 `aria-expanded`, 토스트에 `aria-live`, 시트에 초점 가두기.
7. 성능: `dist`의 JS는 gzip 120KB 이하, CSS는 gzip 12KB 이하를 목표로 한다(넘으면 이유를 적는다). 움직임은 60fps(레이아웃을 건드리는 속성 애니메이션 금지).
