# 502차 — 회귀 분리·재확인 (표시사항 전용 빠른 회귀 + 기존 NG 25건 원인 분류)

## 0. 규칙
- 유료 호출 금지. Production·main 금지(원인 분류 시 main은 **읽기/임시 체크아웃만**, push 금지). 코드 삭제 금지. 규칙 데이터 수정 금지. 상세페이지 로직 수정 금지(NG 원인이 우리 변경이라면 보고하고 최소 수정 여부는 판단 요청).
- `review/502-targets.md`에 코드 전 기재. 마무리 전 `npx tsc --noEmit`, `npm run build`. 커밋 최대 3개. 보고서 `review/502cha-report.md`.

## 1. 항목
A. **`npm run regression:label-check`** 추가: 표시사항 스위트(483·488·489·492~501 및 규칙 검증)만 실행, 총 시간 1~2분 내 목표. 기존 `npm run regression`(전체)은 그대로 유지하고 이름이 혼동되지 않게 `package.json`에 설명 주석 불가하면 docs에 한 줄. 표시사항 스위트 목록은 한 파일(`scripts/regression/label-check-suites.ts`)에서 관리.
B. **496 재확인**: 501차에서 496이 금지어(`ad-phrases-us.ts` 주석의 「위반」)로 NG였고 주석 수정 후 단독 재실행만 했다. 표시사항 전용 회귀를 **전체 한 번 재실행**해 전부 OK인지 보고. 금지어 검사의 허용 범위가 소스 주석에 영향받는 구조라면, 코드 주석은 검사 대상에서 제외하고 화면 문구·응답 문자열만 검사하도록 바꿀지 notes에 판단(변경은 최소).
C. **기존 NG 25건 원인 분류**: 보고서에 NG로 나온 25개를 (1) 우리 표시사항 작업(485~501) 이후 새로 깨진 것, (2) 그 이전부터 깨져 있던 것으로 분류. 방법: 표시사항 작업 직전 커밋(상세페이지 작업 마지막 커밋, `git log`로 특정)을 임시 worktree로 체크아웃해 **NG였던 스위트만** 실행. 오래 걸리는 것(10분 이상)은 건너뛰고 "미실시"로 기재. 결과 표: 스위트명 / 직전 커밋 결과 / 현재 결과 / 분류.
   - 특히 「무거운 도구 가드 — 전수 적용·진입 파일만 검사」와 「DB 주소 교체 SQL」, 「v4 off 동일」 3건은 우리 변경(플래그 489, vercel 설정, 새 API 라우트)이 영향을 줬을 가능성을 먼저 확인.
D. **무거운 도구 가드와 label-check**: 새 API(`/api/label-check`, `runs`)가 이 가드의 "전수 적용" 대상인지 확인하고 사실만 보고.
