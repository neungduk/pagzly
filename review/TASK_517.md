## 2. 점검 시작 화면 (`/label-check`)
구조: 큰 제목 → 2열(왼쪽 "라벨 무대" 1.6 : 오른쪽 "점검 설정" 패널 1, 패널은 sticky). 모바일(<860px)은 1열, 설정 패널이 무대 아래, 점검 버튼은 화면 하단 고정 바.
1. 제목: "라벨을 올리면, **바로 읽어서** 점검해요"(강조만 파랑), 부제 "파일 하나면 충분해요. 설정은 오른쪽에서 고르세요."
2. 무대 상단 탭: "파일 올리기 / 문구 붙여넣기"(세그먼트). 붙여넣기 탭에 기존 textarea + 글자 수 + "광고 문구만 / 라벨 전체 문구" 선택을 **칩 2개**로(기존 radio 값 그대로 연결).
3. 빈 상태: 점선 무대 가운데 라벨 모양 일러스트(CSS 막대로 그린 문서 + 스캔 선) + "라벨 PDF나 사진을 여기에 놓으세요" + 용량 안내. 드래그 중에는 테두리 파랑·배경 #F7F9FF.
4. **파일 선택 후 상태(핵심)**: 무대가 미리보기로 바뀐다. 사진은 `URL.createObjectURL` 썸네일(브라우저 안에서만, 업로드·저장 없음, 언마운트 시 revoke), PDF는 기존 pdfjs 경로로 1페이지 캔버스 미리보기가 **이미 가능하면** 사용하고 불가하면 문서 아이콘 카드로 대체(보고서에 명시). 미리보기 카드는 살짝 떠 있고(bob), 좌상단 파일명·용량 칩(pop), 우상단 "다시 고르기", 하단 "준비 완료 · 오른쪽에서 점검하기를 누르세요".
5. 설정 패널: "판매 국가" 2칩(선택 시 파랑 테두리+#EEF2FF), "해당하는 제품(선택)" 칩 묶음 — 기존 제품 정보 옵션(productTypes, rinseOff, functional, export_only, set_product 등 **현재 있는 옵션 전부**)을 칩으로 노출하되 6개 초과분은 "더 보기"로 접기. 값·전송 형식은 기존과 동일. 안내 한 줄 "고르면 해당하지 않는 항목을 빼서 결과가 더 짧아져요."
6. 점검 버튼: 입력 없으면 회색 #9AA0AC + "파일을 올리면 시작할 수 있어요"(disabled, aria-disabled), 입력 있으면 검정 + "점검하기" + pulse(1.6s). 아래 "참고용 사전 점검이며 법적 판단이 아닙니다".
7. 점검 중 오버레이: 흰 카드 + 스피너 + 진행 바 + 단계 체크(기존 CheckBusyOverlay의 실제 단계/상태값을 그대로 사용, 가짜 진행률 금지: 단계 수 기준으로만 채움).
8. 기존 오류·한도·OCR 확인 UI는 새 스타일로 감싸되 문구·조건 변경 금지. "샘플 결과 보기" 링크와 문의 메일은 푸터로.

## 3. 결과 화면
구조: 어두운 요약 띠 → 2열(왼쪽 "읽은 라벨" sticky .9 : 오른쪽 항목 목록 1.1). 모바일은 1열(요약 → 목록 → 라벨은 접이식).
1. **요약 띠**(#111214, 둥글기 28): 파일 정보(시장), 큰 제목 "고칠 것 N개, 확인할 것 M개가 있어요"(숫자만 색; 둘 다 0이면 기존 결론 문구 규칙을 따름 — 507의 결론 문구 로직 재사용, 새 단정 문구 금지), 판정 비율 막대(4색, flex 비율), 4개 큰 숫자, "고친 항목 x / y" 진행 막대(기존 "고쳤어요" 로컬 토글과 연결, 저장 없음).
2. **읽은 라벨 패널**: 이번 점검에서 읽은 텍스트(클라이언트가 가지고 있는 rawText/붙여넣은 문구)를 보여 주고, finding의 `evidence`/걸린 말을 **문자열 검색으로 찾아** 밑줄 + 번호 핀을 붙인다. 규칙:
   - 일치 검색은 공백·줄바꿈 정규화 후 첫 일치만. 못 찾으면 핀을 만들지 않는다(추측 위치 금지).
   - 핀 클릭 → 해당 항목 펼침 + 스크롤, 항목 펼침 → 해당 문구 배경 강조.
   - 텍스트는 React 텍스트 노드로만 렌더(dangerouslySetInnerHTML 금지), 길면 최대 높이 + 내부 스크롤.
   - **저장된 결과(내 결과/히스토리)에는 원문이 없다**(save-run이 원문 저장 금지). 이 경우 패널 자체를 숨기고 목록을 한 열 전체 폭으로. 원문을 새로 저장하지 말 것.
3. **항목 목록**: 필터는 밑줄 탭(전체/고칠 것/확인할 것/직접 확인/문제 없음 + 개수). 항목은 **한 줄 행**(번호 원, 제목, 상태 알약, 화살표)이고 한 번에 하나만 펼친다. 기본으로 가장 심각한 첫 항목이 펼쳐져 있다.
   - 펼친 "고칠 것" 항목은 검정 바탕 강조 카드. 나머지 상태는 흰 바탕 + 상태색 테두리.
   - 펼친 본문은 512의 종류별 본문을 그대로 사용하되 표현만 교체: wording → BEFORE(걸린 문장, 걸린 말 밑줄) / AFTER(대체 문구 + 복사), missing → "라벨에서"(찾지 못했어요) / "이렇게 넣어 보세요", measure → 읽은 값 / 기준 2칸. 예시가 없으면 AFTER 블록을 만들지 않는다. 취소선 금지 유지.
   - 하단: 기준(법령·출처), "고쳤어요" 토글. 키보드: 행은 button 역할, Enter/Space로 토글, aria-expanded.
   - 513 구역("판매자가 꼭 확인할 것", "해당하지 않아 뺀 항목", "참고")은 목록 아래 별도 묶음으로 유지하되 같은 행 스타일.
4. 맨 아래: 법령 확인 기준일(516 조건 그대로) + 고지 문구. 우상단 "다시 점검".
5. 움직임: 행 hover 3px 이동, 펼침 시 배경·테두리 전환 .25s, 진입 fade-up 1회. `prefers-reduced-motion` 시 전부 정지.
