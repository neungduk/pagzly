# 483차 목표 (코드 전)

## 성공 기준
1. **경로**: `/label-check`만 추가. 기존 상세페이지·생성 파이프라인 무변경.
2. **입력**: PDF 1개(≤10MB) + 씻어내는/안 씻어내는 + 기능성 여부. 서버 메모리 추출 후 폐기, 본문 로그 금지, DB 저장 없음.
3. **추출**: 무료 라이브러리(pdf-parse). 글자 수 과소 → "텍스트를 읽을 수 없어 확인 불가"(OCR 없음).
4. **검사**: `kr_label_rules_draft_v0.1.json`의 `check_type=code`만 자동. `ai`/`manual`은 "수동 확인 필요" 목록. 단정 "위반" 금지 → "위반 가능/확인 필요/확인 불가/통과".
5. **알레르기**: `allergens-kr-25_draft.json` 매칭 + 화면 "초안" 표기. 향료 포함 시 확인 필요.
6. **금지 표현**: 규칙표 키워드만 사용(하드코딩 금지), 결과는 "확인 필요".
7. **글자 크기 5pt**: 폰트 크기 메타를 읽을 수 있을 때만, 아니면 "확인 불가".
8. **UI**: 면책 문구 상시, 요약 카운트 + 한글 라벨 표, 인쇄용 1장. 내부 rule id 비노출.
9. **샘플**: A=사용기한 없음·재생/완전 제거·리모넨/리날룰, B=기능성·제조번호 확인 필요, C=대부분 통과(+피부 장벽 강화 확인 필요 가능).
10. **회귀**: `label-check-483.ts` run-all 등록, 기존 상세 회귀·가로 넘침 불변.
