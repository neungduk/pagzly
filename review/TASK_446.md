# TASK_446 — 색 응집력·대비 결함(노랑~초록)·히어로 마감·후킹 흐름 (코딩 중심, 유료 API 0회)

실행 환경: 클라우드 세션(`cloud-work`). 선행: 445차 완료(`review/445cha-report.md`). 라이브 화면은 더미 환경값 `next dev`로 클라우드에서 캡처 가능(445차 방식 `scripts/live-lib.ts`·`live-capture.ts` 재사용).
시작 문장: "446차 시작: 색 응집력과 히어로·후킹 마감".

## 배경 (445차 결과)
- 라이브·export 시각 대조까지 했고 구조 차이는 거의 해소됐다. 남은 것은 **실사용에서 바로 드러날 디자인 품질 문제**다.
  1. **대비 결함(실사용 위험)**: 대표색이 노랑~초록(약 45~135°)이면 가격 기호·"POINT 1" 칩 등이 4.5:1 미달(3.0~4.3:1). 실제 상품 사진 지배색이 이 색상대면 그대로 난다(레몬·녹차·식품·아웃도어 카테고리에 흔함).
  2. **색 응집력**: 한 페이지에 연두·분홍·연보라·하늘 파스텔이 4~5색 섞여 "알록달록해서 싸 보이는" 인상. 제작사 페이지는 포인트 1계열 + 중립 + 보조 1이 보통이다.
  3. 히어로 고스트 글자가 사진 가장자리에서 반쯤 잘림, 아치+스티커 문법 반복.
  4. 750px 같은 면 간격 10건, 페이지 끝 서식 없는 긴 평문, "한눈에 보기" 체크 아이콘 반복.
  5. step_card STEP 칩 크기·v3 폰트 쌍 자간의 export 반영.

- **새 문구·수치 생성 금지.** 고지 문구 불변. 마이그레이션 없음.
- **결제 코드·`cta_price` 구조·`data-pz-buy`·스티키 바 마크업 불변**(가격 색은 색 토큰/규칙만 조정, 마크업 구조·속성·버튼 동작 변경 금지). 편집 UI·인터랙션 불변.
- 모든 변경 `NEXT_PUBLIC_DESIGN_V4` 안, **off = 445차 끝 코드(`580976c`) 출력과 문자열 diff 0**(export·라이브·섹션 단독, 기준은 그 커밋 worktree + 현재 픽스처), 라이브↔export 문자열 패리티 유지, export 금지 기법(`:has()`, container query, `text-wrap`, `mix-blend-mode`, `clip-path`, `mask`, `-webkit-text-stroke`) 금지, 대비 4.5:1(큰 글자 3:1 허용은 R7 규칙 기준), 본문 14px·라벨 12px, 회귀 94+ 통과, tsc 오류 0.

## 1. 노랑~초록 대표색 대비 결함 (먼저, 실사용 위험)
- 재현: 픽스처 대표색을 H 30·45·60·75·90·105·120·135·150°(채도·명도 상·중·하 3단)로 바꿔 `buildThemeFromHueWithNeutral` 등 실제 theme 파생 함수로 theme을 만들고 export+라이브에서 린트 R7(대비)·눈으로 확인. 위반 요소 목록(가격 기호, POINT 칩, 강조 글자, 아이콘 등)을 표로.
- 수정 원칙: 팔레트 파생 단계(`lib/palette-v4.ts`·`palette-harmony.ts` 등)에서 **글자·칩 전경색(ink)을 면 색 대비 4.5:1로 자동 보정**하는 규칙을 한 곳에 두고(`readableInk(face, preferred)` 류 기존 함수가 있으면 재사용·확장) 위반 지점이 그 함수를 쓰게 한다. 노랑~초록에서 밝은 면 위 글자가 연해지는 것이 원인이면 **어두운 쪽으로 명도 보정(색상 유지)**, 어두운 면이 필요하면 면 자체를 deep 톤으로.
- 가격 기호: 색 값만 보정(마크업 구조·속성 불변), 회귀로 구매 섹션 `data-pz-buy` 수·구조가 그대로인지 확인.
- 회귀 신규: H 12단계 × 명도·채도 3단에서 R7 위반 0(합성 theme 생성기로 전수), off 불변.

## 2. 색 응집력 (페이지 단위 색 예산)
- 현재 면 색 수집: 합성 21종 export DOM에서 **면(배경) 색의 색상군 수**·포화도 분포를 표로(`review/446-verify/color-budget.md`). 한 페이지 면 색이 몇 색상군을 쓰는지 측정하는 DOM 지표(`design-metrics-dom.ts` 확장: 색상군 수, 채도 상위 면 수)를 추가해 린트 규칙 **R18(색 응집력)** 로 승격(warn: 면 색상군 > 3).
- 규칙: v4에서 한 페이지의 **면 색상군을 최대 3**(포인트 1계열 = 대표색 계열, 보조 1계열 = 하모니 규칙의 세컨더리, 중립 = 흰/웜 뉴트럴)으로 제한. 임팩트·섹션 면 배정(`assignFaces`)과 palette-v4 면 역할 표가 허용 집합 안에서만 고르게 하고, 파스텔 연두·분홍·연보라·하늘이 한 페이지에 동시에 나오지 않게. 패션 `photo-tonal`(430B: 사진 톤 ≤2 색상군) 규칙과 뷰티 파스텔 소프트 면 규칙은 유지(교차 시 더 엄격한 쪽).
- **다양성은 페이지 사이**에서 유지: 제품마다 포인트 계열이 다르면 충분(히어로 면 색 중복 ≤2/21 유지).
- 눈 검수: 전/후 5종 첫 3화면 + 750 전체 시트(`review/446-verify/color-before-after/`), "정돈됐다/단조롭다" 평가를 표로. 단조로우면 허용 집합에 채도 변주(같은 계열 명도 사다리 5단 활용)를 더한다.
- 회귀: 면 색상군 ≤3(합성 21종), 대비·반전 예산(428 하드 면 ≤6) 유지, off 불변.

## 3. 히어로 마감
- 고스트 글자 잘림: 444차 페이드를 거쳤는데도 "사진 가장자리에서 반쯤 잘림" 관찰. 고스트 글자 폭을 컨테이너 안(좌우 안전 여백 8%)에 들어가게 **글자 수·폰트 크기 기반 폭 계산으로 축소**(`statFitEm` 류 재사용)하고, 계산상 넘치면 고스트 자체를 끈다. 라이브·export 같은 값. 사진 위에서는 고스트 불투명도를 낮춰 가독성 확보.
- 아치+스티커 문법 반복: 히어로 변형 B·E 외에 **카테고리별 프레임 변주 2종**(원형 컷, 직사각 오프셋 이중 프레임)을 v4 히어로 레이어 규칙에 추가하되 변형 선택은 결정적 시드 유지, 같은 카테고리 안 연속 동일 프레임 금지. 새 문구 없음. 입력 사진 없음/실패 폴백 유지.
- 회귀: 고스트 폭 안전 여백, 프레임 변주 결정성, off 불변.

## 4. 후킹 흐름·밀도
1. **"한눈에 보기" 아이콘 반복**: 445차 아이콘 매핑이 근거 없으면 체크로 폴백하던 것을 **번호·큰 숫자 칩·세로 구분선 스트립 등 비아이콘 변주**로 폴백(키워드 근거 없을 때). 새 문구 금지.
2. **페이지 끝 서식 없는 긴 평문 정리**: 길이 180자 초과 평문 블록을 규칙으로 감지해 v4에서 **문단 분리·여백·작은 제목 라벨·좌측 인용선** 중 하나로 서식 부여(문구 불변, 문장 단위 줄바꿈만). 린트 R4(긴 글) 위반 수 전/후.
3. **750px 같은 면 간격(10건)**: 445차 규칙이 넓은 폭에서 3단 밖 값(`@media`)으로 남은 부분 — 750px에서도 3단 스케일 안으로 스냅(라이브·export 같은 CSS 한 줄), 눈 검수.
