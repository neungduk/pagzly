# 486차 — 파일럿 공개 준비: 소개 영역 · 샘플 결과 보기 · 문의 안내 · 검색 제외

## 0. 규칙
- 유료 호출·Production·main 금지. 기존 상세페이지 코드 변경 금지(`/label-check`, `lib/label-check`, 해당 API만). 새 검사 규칙 추가 금지.
- 목표는 `review/486-targets.md`에 코드 전에 기재. 파일은 Read 후에만 Write/Edit.
- 배경: 기능은 동작하나 처음 보는 사람이 "무엇을 해주는 서비스인지, 올려도 안전한지, 결과를 어떻게 믿어야 하는지" 알 수 없다. 영업 메일을 받은 사람이 업로드 없이도 결과 모양을 볼 수 있어야 한다.

## 1. 항목
### A. 소개 영역 (페이지 상단, 짧게)
- 한 줄 설명: "화장품 패키지 시안(PDF)의 표시사항을 인쇄 전에 사전 점검합니다."
- 3줄 안내: ① PDF를 올리면 필수 표시사항·알레르기 성분·주의가 필요한 광고 문구를 확인합니다 ② 업로드한 파일은 점검 직후 저장하지 않고 폐기합니다 ③ 참고용 사전 점검이며 법적 판단이 아닙니다.
- 새 카피를 길게 만들지 말 것(위 문구 범위). 가로 넘침 0(320/390/750).

### B. 샘플 결과 보기
- "샘플 결과 먼저 보기" 버튼: 업로드 없이 **가상 브랜드 샘플 A(모아리 토너)** 의 결과를 보여준다. 결과는 `review/data/samples/sample_A_moari_toner.pdf`를 기존 검사기에 돌려 만든 **정적 JSON**(`lib/label-check/sample-result-a.json`)을 쓴다(실시간 서버 호출·파일 업로드 없음). 화면 상단에 "가상 브랜드 예시입니다" 표시.
- 정적 JSON은 스크립트로 재생성 가능하게(`scripts/build-label-sample-result-486.mjs`). 실제 브랜드명·실제 상품 데이터 사용 금지.

### C. 문의 안내
- `NEXT_PUBLIC_LABEL_CONTACT_EMAIL` 환경 변수가 있으면 "문의: (이메일)"을 표시(텍스트로 보여주고 복사 버튼, mailto 의존 금지). **없으면 문의 영역 자체를 숨긴다**(임의 주소·자리표시자 금지). 값은 코드·로그에 적지 말 것.

### D. 검색 제외
- `/label-check`에 `noindex`(metadata robots) 적용. 사이트맵·내비게이션 링크 추가 금지. 정식 공개는 사용자가 결정.

### E. 회귀
- `scripts/regression/label-check-483.ts`에 추가: 소개 문구 존재, 샘플 결과 JSON이 스키마와 일치·"위반" 단정/내부 id 0, 이메일 env 없을 때 문의 영역 없음, noindex 존재, 320/390/750 가로 넘침 0. 기존 회귀 변화 없음.
