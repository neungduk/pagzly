# 481차 — 실사 결과가 픽스처만큼 안 나오는 격차 추적과 수정

## 0. 규칙
- 유료 호출·새 생성·Production·main 금지. 이번에는 **이미 만들어진 결과(DB 행)를 읽기만** 한다. 사진은 공개 주소(img.pagzly.com)에서 읽기만(무료).
- V5 off는 480차와 바이트 동일, V4 off 락과 기존 회귀 통과. 새 카피 금지.
- 목표는 `review/481-targets.md`에 코드 전에 기재. 파일은 Read 후에만 Write/Edit.

## 1. 배경 (기획 담당이 실사 결과를 직접 본 판정)
사용자가 480차 실사 결과(product `e8c1c270-dc6a-435d-a915-efab06ab6dd1`, 뷰티 미스트, 사진 9장)를 보고 **"폰트도, 사진 배치도, 이미지 뒤 배경색도 이전보다 나아진 게 하나도 없다"**고 했다. 기획 담당이 같은 프리뷰에서 DOM을 재 본 결과:
1. 이 결과에 적용된 시그니처가 **`editorial` 하나**(`data-pz-vsig`, `data-pz-bsig` = editorial). 470~479차에서 만든 8종 분화가 실사에서는 보이지 않는다.
2. 렌더된 글꼴이 **Noto Sans KR 858곳 + Gowun Batang 32곳, 둘뿐**. 제목 서체(474차 7종 체계)가 거의 안 쓰이고, Gowun Batang은 뒤쪽 3개 섹션 제목에만 쓰였다. 첫 화면 제목은 일반 고딕.
3. 첫 화면이 큰 병 사진 위/아래에 연보라 면 + 일반 제목 블록으로, 471차 "첫 화면 시각 서명(hero-stack)"과 달라 보인다.
4. 사진 뒤 배경이 AI 배경(backdrop) 파스텔 한 가지 톤이고, 사진 가장자리와 배경 면이 어긋나 보이는 곳이 있다.
5. 섹션 제목·목록에 `seller_trust_evi`, `ingredient_circl` 같은 내부 이름이 노출된다. 포인트1 제목 밑줄이 글자와 겹친다. 타겟 알약 일부는 사진이 빈 칸. 상품과 무관한 시계 그림.
결론: **픽스처(가짜 사진·정돈된 데이터)에서 통과한 것이 실제 생성 결과에서는 재현되지 않는다.** 이번 차수는 그 격차의 원인을 찾아 고친다.

## 2. 항목
### A. 실사 결과를 픽스처로 재현 (최우선, 읽기 전용)
- `scripts/capture-live-fixture-481.ts`: 위 product의 저장된 섹션 JSON·이미지 URL·팔레트·분석 결과를 DB에서 읽어 `scripts/fixtures/live-481.json`으로 만든다(개인정보 없음, 키 없음). 이미지 URL은 그대로 쓰고 로컬 렌더에서 불러온다(네트워크는 img.pagzly.com만 허용, 읽기).
- 같은 데이터로 **8종 아키타입 × (750, 390)** 로컬 렌더 + 프리뷰 실제 화면과 같은 조건의 `editorial` 렌더를 만들어 `review/481-captures/`에 저장(커밋 금지). 프리뷰 실제 화면과 로컬 `editorial` 렌더가 같은지 먼저 확인(다르면 그 차이가 첫 번째 원인).

### B. 격차 원인 규명
다음을 각각 확인해 `review/481-notes.md`에 표로 기록한다(가설 → 실측 → 결론):
1. **아키타입 선택**: 이 상품이 왜 `editorial`로 정해졌나(자동 선택 로직·`NEXT_PUBLIC_V5_ARCHETYPE` 값·카테고리/톤 기준). 뷰티 상품이 항상 editorial로 가는지.
2. **제목 서체**: 첫 화면/섹션 제목에 474차 서체 체계(type-system-v5)가 왜 안 걸렸나(폰트 파일 미로드, 조건 미충족, 실사 데이터에서 role이 달라서 등). 실제로 로드된 폰트 목록과 기대 목록을 비교.
3. **hero-stack 미적용**: 실사 첫 화면에서 471차 구조가 안 쓰인 이유(조건: 사진 비율, 섹션 슬롯 이름, 데이터 필드 부재 등).
4. **실사 섹션 구성**: 실사 결과의 섹션 종류가 픽스처에 없는 종류(seller_trust_evi, ingredient_circle 등)라서 V5 변형이 안 걸리는 것이 있는지 → 목록화.
5. **사진 뒤 배경**: AI 배경(backdrop)이 만드는 파스텔 면과 V5 색 역할(color-roles-v5)이 따로 놀아서 생기는 톤 충돌 여부. 사진 주변 면 색을 V5 면 색으로 통일할 수 있는지.

### C. 수정 (효과가 큰 순서, 사용자가 "눈으로 보이는" 것 위주)
1. 위 B에서 밝힌 원인 중 **"실사에서 V5가 안 걸리는 경로"를 수정**: 슬롯 이름·섹션 종류 별칭 매핑, 조건 완화(안전 하한 유지).
2. 뷰티·화장품 같은 카테고리가 editorial 한 가지로 고정되지 않게 선택 규칙 보강(상품 톤·팔레트 명도/채도·카테고리로 8종 중 선택, 같은 상품은 항상 같은 결과로 결정적). 선택된 아키타입 이름을 결과 화면 어딘가(개발용 옵션 또는 data 속성)에 노출해 확인 가능하게.
3. 제목 서체가 첫 화면 제목과 섹션 제목에 실제로 적용되게. 폰트 로드 목록에 아키타입 제목 서체가 포함되는지 시험 추가.
4. 사진 주변 면 색: 사진 뒤 파스텔 면을 V5 색 역할의 면 색으로 맞추고, 사진 가장자리 마감(그림자·테두리·마스크)을 아키타입 어휘로 통일.
5. 내부 섹션 이름(slug) 노출 제거: 화면·섹션 목록에는 한글 라벨만. 매핑이 없는 종류는 안전한 일반 라벨.
6. 포인트 제목 밑줄 겹침 수정, 빈 알약(사진 없음)은 숨기거나 텍스트 알약으로 폴백, 상품과 무관한 범용 일러스트(시계 등)는 해당 근거 없으면 쓰지 않기.

### D. 회귀·검증
- `scripts/regression/live-481.ts`(run-all 등록): live-481 픽스처를 8종 모두 렌더해 ① 아키타입별 로드된 제목 서체가 2종 이상 분화 ② slug 문자열(`seller_trust` 등 영문 내부 이름) 화면 노출 0 ③ 대비 실패 0 ④ 가로 넘침 0.
- 4 픽스처 + live-481 전체의 이전 회귀(463~480) 통과, 가로 넘침 0(320/390/750), fold·폴백·가격·고지·탭 앵커 불변.
