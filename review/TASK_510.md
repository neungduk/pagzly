# 510차 — 판정 정확도 보강 3건(의약품 효능 문구·사용기한·읽은 글자 확인 화면)

> 순서: 509차 완료 후. 실제 사진 시험에서 발견된 문제를 고치는 **작은 보강**이다. 새 기능 추가 금지.
> 참고: `scripts/regression/label-check-ocr-fix-510.ts`는 내가 먼저 만든 OCR 보정 시험이다(이름이 같은 510이지만 별개). 수정하지 않는다.

## 0. 절대 규칙
1. 실제 OCR·네트워크 호출, 키·`.env*` 열람/생성/커밋 금지. 테스트는 fixture·가짜 fetch만. main push 금지, 코드 삭제 금지, 새 의존성 금지.
2. `review/data/*` 수정 금지(규칙 데이터 원문). 판정 로직·문구 사전 코드(`lib/label-check/*`)만 수정한다.
3. 고객 화면 금지어: "위반입니다/적법/완벽/보장/안전합니다/100%". 금지어 검사 통과.
4. 마무리 전: `npx tsc --noEmit`, `npm run build`, `npm run regression:label-check`. 커밋 최대 4개. 보고서 `review/510cha-report.md`(맨 위 "확인하지 못한 항목"). **커밋 해시는 push 후 `git log --oneline`의 실제 값만 적는다.**

## 1. 발견된 문제(실사용 시험 결과)
| # | 입력 | 지금 결과 | 원하는 결과 |
|---|------|-----------|-------------|
| A | "치료에 효과", "재생", "완전 제거" 등 명백한 의약품 효능 문구 | 확인할 것 | **고칠 것** |
| B | 사용기한 칸에 "별도 표기 없음" | 문제 없음(키워드만 보고 통과) | **확인할 것/고칠 것** |
| C | 미국용 "Reduces wrinkles permanently. Cures acne." | 확인할 것 | **고칠 것** |

## 2. 작업
### 2-1. 명백한 의약품 효능 문구는 "고칠 것"으로 (KR: `ad-phrases.ts`, `ad-exceptions.ts`, `run-check.ts`)
- 먼저 현재 `ad-phrases.ts`와 `ad-exceptions.ts`를 읽고, 어떤 문구가 왜 "확인할 것"으로 떨어지는지(예외 안내가 붙는 구조인지) 보고서에 적는다.
- **예외가 적용될 수 없는 문구**만 골라 고칠 것으로 올린다: 치료, 완치, 치유, 질병 이름과 결합한 개선·예방(아토피·여드름 "치료" 등), "재생"(피부 재생), "영구적으로", "완전 제거/완전 제거됨". 
- 일반 화장품 허용 표현(보습, 피부 결 개선, 주름 개선 *기능성 심사 품목*, "윤기" 등)은 **올리지 않는다.** 반대 시험(올라가면 안 되는 문구)을 반드시 넣는다.
- 확신이 없는 문구는 "확인할 것"으로 그대로 두고 보고서에 목록으로 적는다(추측으로 올리지 않는다).

### 2-2. 사용기한은 값이 있어야 통과 (`run-check.ts` expiry 모드)
- 지금은 "사용기한" 같은 단어만 있어도 pass. 아래처럼 바꾼다:
  - 날짜(연월일·연월), 개월/M(개봉 후 기간), EXP+연도, "제조일로부터 N" 중 **하나라도 있어야** pass.
  - 키워드만 있고 값이 없거나 "별도 표기 없음/없음/해당 없음"이 붙으면 **확인할 것**, 문구: "사용기한 또는 개봉 후 사용기간의 값을 찾지 못했어요."
  - "사용기한: 제조일로부터 36개월"은 통과 유지, "개봉 후 12M"은 통과 유지.
- 기존 시험이 깨지면 **시험을 고치지 말고** 왜 깨졌는지 보고서에 적고 멈춰서 알린다(규칙 회귀일 수 있음).

### 2-3. 미국용 효능 문구 (`ad-phrases-us.ts`, `run-check-us.ts`)
- 같은 원칙을 적용: cure(s), treat(s) disease/acne, heal(s), permanently, "clinically proven to cure", "FDA approved"(화장품에는 승인 개념 없음) → **고칠 것**. 
- "reduces the appearance of wrinkles" 같은 외형 표현은 올리지 않는다(반대 시험 포함).

### 2-4. "읽은 글자 확인" 화면 다듬기(고객용)
- 파일: 508/509에서 만든 공용 OCR 확인 컴포넌트.
- 안내 문구를 쉬운 말로: "사진에서 읽은 글자예요. 틀린 곳을 고친 뒤 점검하세요." + 고친 글자가 점검에 쓰인다는 한 줄.
- 읽기 상태(`partial`)일 때 "일부만 읽었어요. 빠진 부분은 직접 붙여넣어 주세요" 안내와 붙여넣기 이동 버튼.
- 320px·390px 가로 스크롤 없음(CSS 정적 점검).

### 2-5. 테스트
- `scripts/regression/label-check-510b-accuracy.ts`(새 파일, `label-check-suites.ts` 등록): A·B·C 각각 올라가야 하는 문구 / 올라가면 안 되는 문구 / 사용기한 4가지 경우 / 읽기 상태 문구 정적 검사. 기존 묶음 전부 통과.
