# 513차 — "직접 확인" 항목 대폭 줄이기 (해당 여부 자동 감지 + 코드 판정)

> 순서: 512차(결과 카드 구조) 완료 후. 사용자 요구: "직접 확인할 것이 너무 많다. **판매자가 꼭 확인해야 하는 것만 남기고 AI·코드로 할 수 있는 건 전부 하자.**"
> 이번은 점검 로직 일부를 **새로 만든다**. 단, 원칙은 보수적이다: **긍정적 증거가 있을 때만 "문제 없음"**, 모르면 "확인할 것"이나 "확인 못 함"으로 둔다. 거짓 통과는 이 서비스에서 가장 큰 사고다.

## 0. 절대 규칙
1. 실제 OCR·네트워크 호출, 키·`.env*` 금지. 외부 AI(LLM) 호출 **금지**(이번 차수는 코드 판정만). main push 금지, 코드 삭제 금지, 새 의존성 금지.
2. 수정 금지: `review/data/**`(규칙 원문 JSON), `app/api/**`의 요청·응답 형식, `supabase/**`, `package*.json`. 새 판정은 **새 파일**(`lib/label-check/gating-513.ts`, `lib/label-check/checks-513.ts` 등)에 만들고 `run-check.ts`·`run-check-us.ts`에서 호출만 연결한다(기존 판정 결과를 바꾸는 부분은 최소로, 보고서에 위치 명시).
3. 고객 화면 금지어("위반입니다/적법/완벽/보장/안전합니다/100%") 금지, 면책 유지.
4. 마무리 전: `npx tsc --noEmit`, `npm run build`, `npm run regression:label-check`. 커밋 최대 5개. 보고서 `review/513cha-report.md`(맨 위 "확인하지 못한 항목", 해시는 `git log --oneline` 실제 값만).

## 1. 지금 문제의 원인
`run-check.ts`는 규칙의 `check_type`이 `code`가 아니면(`ai` 11건·`manual` 2건 — 한국, `manual` 6건 — 미국) **상황과 무관하게 전부** "수동 확인이 필요합니다."로 `manualItems`에 넣는다. 게다가 `addenda-kr.ts`가 확인 질문 카드를 더 붙인다. 그래서 세트 상품이 아닌 라벨에도 "세트 상품…", 색조가 아닌 제품에도 "색조 착색제…", 수출 제품이 아닌데도 "수출 전용 제품…"이 항상 나온다. **대부분은 "해당할 때만" 봐야 하는 항목**이다.

## 2. 핵심 설계: ① 해당 여부 감지 → ② 해당하면 코드로 판정 → ③ 해당 안 하면 숨김 → ④ 꼭 사람이 봐야 하는 것만 남김
새 모듈 `gating-513.ts`: 규칙 id(또는 라벨)별로 `{ applicable(text, input, extracted): "yes" | "no" | "maybe", check?(…): Finding | null }`를 정의한다. 결과는 세 갈래다.
- `no`(해당 없음): 목록에서 뺀다. 대신 결과 화면 맨 아래 접이식 "이 제품에는 해당하지 않아 뺀 항목 N건"에 이름만 모아 보여 준다(이유 한 줄 포함, 예: "세트 상품 표시가 없어 점검하지 않았어요"). 사용자가 "제품 정보"에서 해당 옵션을 체크하면 점검 대상이 된다고 안내.
- `yes`: 코드로 판정해 일반 finding(고칠 것/확인할 것/문제 없음)으로 낸다.
- `maybe`: 판정 근거가 모자란 것만 "직접 확인"(판매자 확인)으로 남긴다.

### 2-1. 제품 정보 옵션 추가 (`product-type-options-504.ts`는 클라이언트 안전 파일이므로 **같은 방식으로 새 옵션을 추가**, 기존 옵션 id·동작은 바꾸지 않는다)
`export_only`(수출 전용), `set_product`(세트 상품), `soap`(비누), `professional`(전문가용·US), `hazardous`(US, 기존 `hazardous` 입력과 연결). 한국 `color_makeup`(색조)은 이미 있음. UI는 기존 "제품 정보 선택" 접힘에 체크박스로만 추가(문구는 쉬운 말).
- `export_only` 체크 시: 한국 표시 규칙을 적용하지 않고 맨 위에 안내("수출 전용은 한국 표시 규정 대신 수출국 기준을 따르기 때문에 한국 기준 점검을 줄였어요").

### 2-2. 한국 항목별 처리 (현재 "직접 확인"으로 나오던 것)
| 항목 | 해당 여부 감지 | 코드 판정 | 남는 직접 확인 |
|------|----------------|-----------|----------------|
| 수출 전용 제품 | 사용자 옵션 `export_only` | 위 2-1 | 없음(옵션으로 대체, 목록에서 제거) |
| 주의사항·알레르기 유발성분 표시 규정 개정안 (KR-PEND-001) | 해당 없음 | 점검 항목이 아니라 **동향 안내**이므로 결과 맨 아래 "참고" 한 줄로 옮긴다 | 없음 |
| 세트 상품 제조번호·사용기한 표기 / 세트 상품 표시 | 텍스트에 `세트|SET|set|구성품|증정|기획` 또는 옵션 `set_product` | 제조번호·사용기한이 각각 1회 이상 있는지, 통합 표기라면 "제품에 별도 표시" 류 안내 문구가 있는지 | 해당 여부 `maybe`일 때만 |
| 색조 제품 착색제 ± 표기 | 옵션 `color_makeup` 또는 전성분에서 `CI \d{5}`·`적색\s*\d+호` 등 착색제 패턴 | 착색제가 있고 `±`/`+/-`/`+/−`/`（±）` 표기가 있는지 | 착색제가 있는데 표기가 없으면 "고칠 것" 후보(수정 예시: ± 뒤에 착색제 나열) |
| 제조번호와 사용기한 구별 표시 | 항상 점검(이미 일부 코드 있음, `run-check.ts` 516·546 행 참고) | `제조번호|LOT|Lot|L/N`과 `사용기한|개봉 후|EXP|PAO`가 서로 다른 항목 이름으로 따로 있으면 문제 없음, 한 줄에 합쳐진 `LOT/EXP`류면 확인할 것 | 없음 |
| 중화·비누화 성분 표기 | 전성분에서 중화제(`수산화나트륨|수산화칼륨|트리에탄올아민|아르기닌|소듐하이드록사이드|potassium hydroxide|sodium hydroxide|triethanolamine`)나 비누화 단서(`비누`, 지방산염) 감지 시에만 | "중화 반응 생성물로 표시 가능"이라는 안내 카드(확인할 것) | 해당 없으면 아예 안 나옴 |
| 기타 성분 (식약처 인정 시에만) | 전성분에 `기타 성분`/`기타성분` 문구가 있을 때만 | 있으면 "식약처 인정을 받은 경우에만 쓸 수 있어요" 확인할 것 카드 | 해당 있을 때만(인정 여부는 판매자 몫) |
| 기능성화장품 문구 위치·크기 | `기능성화장품` 단어 감지 또는 옵션 `functional` | PDF(글자 크기 `sizePt`가 있을 때)에서 `기능성화장품` 글자와 바로 아래 문구의 크기를 비교(같거나 큼 → 문제 없음, 작음 → 고칠 것). 사진·OCR(`sizePt`=0)이면 "확인 못 함" | **위치(바로 아래 여부)**는 좌표가 없어 직접 확인으로 남김 |
| 표준 국문 성분명 사용 | 항상 | 전성분 목록에서 **영문 INCI만 있는 성분**(한글 없이 영문 전용 토큰)과 오타 의심(숫자·특수문자 혼입)을 감지해 "표준 국문명으로 바꿔 보세요: 영문 {n}개" 카드(확인할 것)로 낸다. 표준명 사전이 없으므로 **정확성 판정은 하지 않고** | **"표준 국문 성분명이 맞는지"**는 직접 확인으로 남김(사전 필요, 이유 문구 포함) |

### 2-3. 미국 항목별 처리 (US manual 6건)
| 항목 | 처리 |
|------|------|
| 제품명(주 표시면) US-001 | PDF에서 가장 큰 글자 줄(`sizePt` 최대)을 "제품명 후보"로 보여 주고 확인할 것 카드(영문이면 후보 표시). 크기 정보 없으면 확인 못 함 |
| 영어 표기 US-007 | 이미 있는 한글 비율 판정(`run-check-us.ts`)을 이 항목의 코드 판정으로 정식 연결. 영문 필수 문구(내용량·성분·상호) 각각 영문 여부 확인 |
| 안전성 미입증 경고 US-008 | `The safety of this product has not been determined` 문구가 있으면 문제 없음. 없으면 판매자가 안전성 근거를 갖고 있는지에 달려 있으므로 **직접 확인(이유: "안전성 근거 자료는 서비스가 알 수 없어요")** 로 남김 |
| 위험 제품 경고 US-009 | 옵션 `hazardous`/`aerosol` 또는 텍스트에 `aerosol|pressurized|flammable|spray`가 있을 때만 점검: 경고·"Keep out of reach of children" 문구 확인. 해당 없으면 숨김 |
| 전문가용 US-011 | 옵션 `professional` 또는 텍스트에 `professional`이 있을 때만 점검: `for professional use only` 문구 확인. 해당 없으면 숨김 |
| 향료 알레르기(MoCRA, 규칙 미확정) US-012 | 점검 항목이 아니라 **동향 안내**(결과 맨 아래 "참고")로 이동. 목록에서 제거 |

## 3. 결과 화면 (직접 확인 영역 개편, `ResultView` / `ResultPanel`)
- 제목을 **"판매자가 꼭 확인할 것"**으로 바꾸고, 항목마다 한 줄 이유를 붙인다: "왜 직접 봐야 하나요: …"(표준 국문명 사전 없음, 안전성 근거 자료는 서비스가 알 수 없음, 글자 위치 정보 없음 등).
- 이 목록은 보통 **0~3건**이어야 한다. 5건을 넘으면 보고서에 샘플별 건수와 이유를 적는다.
- 맨 아래 접이식 두 개: ① "이 제품에는 해당하지 않아 뺀 항목 N건"(이름+이유) ② "참고: 개정 예정·동향"(KR-PEND-001, US-012). 둘 다 기본 접힘.
- 요약 숫자(`summary.manual`)와 저장 데이터(`label_check_runs`)의 `manual` 값은 **새 건수 기준**으로 계산되게 한다(스키마 변경 없이 숫자만).

## 4. 테스트
- `scripts/regression/label-check-513-gating.ts`(등록). 반드시 포함:
  1. 세트·색조·수출·비누·기능성·전문가용·에어로졸 **없는** 평범한 라벨 → 직접 확인 목록에 해당 항목이 **나오지 않음**, "해당하지 않아 뺀 항목"에는 이름이 있음.
  2. 세트 문구가 있는 라벨 → 세트 항목 판정이 일반 finding으로 나옴.
  3. 착색제(`CI 77891`)+`±` 표기 있음 → 문제 없음, 없음 → 고칠 것 후보.
  4. 전성분에 영문 INCI만 있는 줄 → "표준 국문명으로" 카드.
  5. `수산화나트륨`이 있는 전성분 → 중화 안내 카드, 없으면 없음.
  6. US: 한글만 있는 라벨 → 영어 표기 문제, `aerosol` 문구 → 경고 점검.
  7. **거짓 통과 방지**: 증거 없이 "문제 없음"으로 나오는 경로가 없음(각 새 check는 증거 문자열이 있을 때만 pass).
  8. 기존 묶음 전부 통과. 기존 테스트가 "manual 개수"를 옛 값으로 검사하면 **새 값으로만** 고치고 고친 목록을 보고서에 적는다. 금지어·면책 가드 약화 금지.
- 파일럿 샘플 PDF(`review/data/samples`)가 있으면 그 결과를 전후 비교해 보고서에 표로(직접 확인 건수: 이전 → 이후, 새로 나온 고칠 것/확인할 것).

## 5. 보고서에 포함
1. 맨 위 "확인하지 못한 항목".
2. 항목별 처리 결과표(위 2-2, 2-3 표를 실제 구현 기준으로 채움: 자동화됨 / 숨김 / 남김).
3. 샘플별 "직접 확인" 건수 전후 비교.
4. 사람이 봐야 해서 남긴 항목과 이유(고객 화면 문구 그대로).
5. 거짓 통과 방지를 위해 둔 조건 목록.
