# 리듬 확장 측정 (445차 3)

변경: `lib/rhythm-v4.ts`에 섹션 타입 → 면·여백 표(`LEGACY_SECTION_V4`)를 두고 계획(`applyDisplayRules`)이 이전(비임팩트) 섹션의 면 키를 읽어
같은 면 이웃의 위 여백을 `topPads`(섹션 번호 → 32|48px)로 내보낸다. 라이브는 래퍼 `data-pz-top`, export는 `<section data-pz-top>` 표식 + 같은 CSS 한 줄(`topPadCssV4`)로 적용.
임팩트 쪽은 같은 면 키 조회(`faceKeysFor`)를 통해 앞이 이전 섹션인 경우도 `rhythm:"tight"` 대상이 된다. v4 off = 표식·CSS 없음(444차 끝과 문자열 diff 0).

## 면 규칙(표)
- 본문 순번의 패턴(`getSectionPattern`): A·D = 흰 면, B·E = 옅은 색 면(눈으로 같은 파스텔이라 한 키), boldBlock = 어두운 면(항상 구획), cta_price = 자기 면.
- 위·아래 여백 출처: y = 카테고리 `padY`, ty = `padTy`(FAQ·주의·표), cy = `padCy`(구매), 고정 32(AI 안내·갤러리 위), 갤러리 아래 0.
- 표 밖(히어로·배너·사진 중심 image_text·tradeoff_card 등)은 면을 판정하지 않는다(그대로).

## 측정 (합성 픽스처 21종, export DOM)
| 지표 | 전 | 후 |
|---|---|---|
| gapBig / gapUneven / 3단 밖 여백 / 급변 (저장소 지표, 390px) | 0 / 0 / 0 / 0 | 0 / 0 / 0 / 0 |
| 같은 면 이웃(색 거리 ≤ 6) 사이 간격 96 초과, 390px | 3 | 3 |
| 같은 면 이웃 간격 96 초과, 750px | 14 | 10 |
| 이전 섹션 위 여백을 줄인 곳 | 0 | 7곳(7 픽스처, 값은 모두 32) |

- 저장소 지표는 면 색이 정확히 같은 쌍만 세므로 이미 0이었다. 느슨한 스캔(색 거리 ≤ 6)에서 390px 3건은 임팩트↔임팩트(옅은 색 두 종류 `v4:bgB`↔`tint:faqcards`가 거의 같은 색, 모티프 블록 위 여백 면제)라 이번 표의 범위 밖이다.
- 750px 4건 감소는 넓은 폭에서도 같은 위 여백 32/48이 적용돼서다(넓은 폭 여백은 3단 스케일 밖이라 규칙 대상 아님, 최선 노력).
- 눈 검수: `fx-*-before-after.png`(왼쪽 전 | 오른쪽 후). 줄어든 곳은 같은 흰 면 사이 위 여백이 32로 줄어 16px 좁아진 정도이고 구획·위계는 유지된다.
- 라이브: 같은 6개 픽스처를 라이브↔export 대조(`scripts/live-vs-export.ts`)해 위 여백·높이 차이 없음(표식 달린 섹션의 `pt` 일치).
