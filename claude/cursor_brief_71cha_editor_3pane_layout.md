# 71차 — 결과 페이지 3분할 편집 레이아웃 (후커블 편집 화면 대응)

생성: 2026-09-02

## 배경

사용자가 후커블(hookable.ai) 실제 상품 생성 편집 화면 스크린샷을 보여주며 질문:

> "상세페이지 제작이 되면 이렇게 화면이 전환 되면서 옆에 사진 텍스트 등 내가 넣을 수 있고
> 재작업이 가능하게 되거든 그다음에 오른쪽에 분석 추출 이런식으로 나오고 중간에 상세페이지
> 작업물이 나오게 보여주는 레이아웃인데 이건 만들 수 있을까 ?"

후커블 화면 구성: 좌측 페이지/섹션 목록(썸네일), 중앙 실시간 캔버스, 우측 "이미지 분석 완료 / 톤앤매너 추출 완료 / 레이아웃 디자인 완료 / 콘텐츠 제작 완료" 체크리스트 + 채팅 입력창.

코드 확인 결과, **Pagzly는 이미 이 화면의 핵심 기능을 대부분 갖고 있습니다** — 없는 건 화면 배치뿐입니다.

| 후커블 요소 | Pagzly 현황 |
|---|---|
| 우측 채팅창 (자연어로 섹션 수정 요청) | 이미 있음 — `app/create/result/page.tsx`의 "섹션 채팅"(patch) 탭, `/api/patch-section`, 섹션별 채팅 히스토리(`patchHistories`) |
| 중앙 실시간 캔버스 | 이미 있음 — `DetailSectionRenderer`가 최종 페이지를 그대로 렌더링, `editMode`에서 텍스트/이미지 인라인 수정 가능 |
| 사진 교체, 섹션 순서/숨김 | 이미 있음 — "업로드" 탭, "구조" 탭 |
| 우측 "분석/추출 완료" 체크리스트 | **일부만 있음** — `app/create/draft/page.tsx`에서 `GeneratingOverlay`가 실제 파이프라인 단계(uploading/backdrop/enhancing/generating, 섹션별 완료)를 보여주지만, `/create/result`로 넘어오면 이 정보가 사라짐 (아래 작업 B) |
| 좌측 페이지 썸네일 목록 | 없음 — Pagzly는 여러 "페이지"가 아니라 스크롤형 단일 상세페이지라 1:1 대응은 아님. 이번 라운드에서는 섹션 목록(텍스트 위주)으로 대체, 썸네일 이미지는 다음 라운드로 미룸 |

즉 이번 라운드는 **새 기능을 만드는 게 아니라, `app/create/result/page.tsx`에 이미 있는 도구들(`DetailActionBar`의 탭들)을 후커블처럼 상시 3분할 화면으로 재배치**하는 작업입니다.

## 작업 A — result 페이지 3분할 레이아웃 (핵심 작업)

`app/create/result/page.tsx` + `components/DetailActionBar.tsx` 대상.

- 데스크톱 폭(예: `lg:` 브레이크포인트 이상)에서 3열 그리드로 재배치:
  - **좌측**: 지금 "구조" 탭 안에 있는 섹션 목록(순서 변경/숨기기, `onReorder`/`onToggleHidden`)을 상시 사이드바로 승격. 섹션 클릭 시 가운데 캔버스에서 해당 섹션으로 스크롤 이동.
  - **중앙**: 기존 `DetailSectionRenderer` 캔버스 그대로 유지 (editMode의 `EditableText`/`ImageReplaceHit`/`onRequestAiPatch` 로직 변경 없음).
  - **우측**: "섹션 채팅"(patch) 탭 내용을 상시 노출로 승격 (`patchIndex`/`patchInstruction`/`handlePatchSection`/`patchMessages` 그대로 재사용). 그 위에 작업 B의 요약 카드. 업로드/AI 재생성(1688 붙여넣기)/블로그/인스타그램 등 나머지 도구는 우측 패널 안에서 서브탭이나 접이식 아코디언으로 축소.
  - 좁은 화면(모바일 등)에서는 **기존 `DetailActionBar` 탭 방식 그대로 유지** — 반응형 폴백. 모바일까지 3분할로 억지로 만들지 않음.
- 상태/핸들러는 전부 재사용, 새 배치 컴포넌트(레이아웃 wrapper)만 추가하는 방식으로 작업 — `handleSectionChange`, `handlePatchSection`, `handleReorder`, `handleToggleHidden` 등 기존 로직 변경 없음.

## 작업 B — 우측 패널에 "완료된 생성 단계" 요약 카드

`components/GeneratingOverlay.tsx`가 이미 실제 파이프라인 진행 상황(단계별 메시지, 섹션별 완료 여부, 경과 시간, 비용)을 잘 보여주고 있는데, 이 정보가 `/create/draft`를 벗어나면 사라집니다. `/create/result` 우측 패널 상단에, 후커블의 "이미지 분석 완료/톤앤매너 추출 완료/레이아웃 디자인 완료/콘텐츠 제작 완료" 같은 **접힌 요약 카드**를 하나 남겨주세요.

- **새 실시간 스트리밍 파이프라인을 만들 필요 없음** — draft 단계에서 이미 갖고 있던 stage/progress 정보를 result로 넘기기만 하면 됩니다 (`DraftSessionPayload`나 `GenerateResponse`에 실어 보내는 방식으로, 정확한 전달 방법은 기존 데이터 흐름 보고 판단해주세요).
- 이미 끝난 일을 사후 요약해서 보여주는 정적 카드면 충분합니다. 실시간 애니메이션/진행바 다시 만들 필요 없음.
- draft 단계 자체(`GeneratingOverlay`)는 이미 잘 동작하고 있으므로 **건드리지 마세요** — result 쪽에 요약만 추가하는 작업입니다.

## 작업 C (있으면 좋음, 우선순위 낮음)

좌측 섹션 목록에 슬롯별 짧은 라벨 정도 표시 (`GeneratingOverlay`의 `slotDisplayLabel` 함수 재사용 가능). 썸네일 이미지까지는 이번 라운드에서 하지 않음 — 시간 남으면만.

## 하지 않는 것

- `GeneratingOverlay`/draft 페이지 자체 로직 변경 없음.
- 백엔드 생성 로직, AI 프롬프트, `/api/generate`, `/api/patch-section` 로직 변경 없음 — 순수 프론트 레이아웃 재배치.
- "여러 페이지" 개념 도입 안 함 — Pagzly는 단일 스크롤 상세페이지 유지.
- 새로운 실시간 스트리밍 API 만들지 않음.

## 검증 방법

- 데스크톱 폭에서 실제(또는 기존 fixture) 상품 1건으로 result 페이지 3분할 렌더 스크린샷.
- 모바일/좁은 화면 폭에서 기존 탭 방식이 그대로 유지되는지 스크린샷.
- 섹션 채팅(patch), 이미지 교체, 순서 변경/숨기기 등 기존 기능이 레이아웃 변경 후에도 정상 동작하는지(회귀 없는지) 확인.
- 우측 요약 카드가 실제 draft 단계에서 어떤 단계를 거쳤는지 정확히 반영하는지 확인 (지어낸 문구 금지).
