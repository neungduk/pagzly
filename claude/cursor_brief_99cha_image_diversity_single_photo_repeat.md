# 99차 — 상세페이지 전체가 사진 1장을 30번 재사용하는 문제 (이미지 다양성)

생성: 2026-09-03
전제: 사용자가 실제 판매용 상세페이지 레퍼런스(글로위스트/마유에스테/버가못 BB/이어폰/락토핏)를 보내며 "우리 결과물과 비교해 모자란 점을 고쳐달라"고 요청. 레퍼런스들의 가장 큰 공통점은 **한 페이지에 서로 다른 사진이 10~20컷 들어간다**는 점(정면컷, 텍스처 매크로, 모델컷, 패키지컷, 성분컷, 사용장면 등). Pagzly 결과물을 DOM 레벨에서 실측해 비교한 결과, 특정 상품에서 이 격차가 매우 크게 벌어지는 것을 확인했습니다.

## 실측 데이터

Chrome에서 `document.querySelectorAll('img')`로 렌더링된 실제 이미지를 집계했습니다(둘 다 "상세정보 더보기" 펼친 상태, 23개 섹션 전체).

| 상품 | 총 `<img>` | **고유 이미지** | 최다 사용 1장의 반복 횟수 | 업로드 사진 수(교체 패널 기준) |
|------|-----------|----------------|------------------------|------------------------|
| 히알루론 딥 모이스처 세럼 (`7dca0930-…`) | 36 | **10** | 6회 | 9장 |
| **글로위스트 드림글로우 카멜리아 에센스 미스트 v3 (`49f8192b-2d17-4650-adac-12941f86487a`)** | 36 | **4** | **30회** | 5장 |

글로위스트 v3는 고유 이미지가 4개뿐이고, 그중 `…-enhanced-fx-moisture.png` **1장이 30번** 반복됩니다(나머지 3개는 illustration 1장 + compare-before/after 2장). 즉 히어로·미니포인트 3개·성분·질감·패키지·작용원리·용량·데일리루틴 등 거의 모든 섹션이 **같은 사진 한 장**을 쓰고 있습니다. 반면 히알루론 세럼은 상품 사진 7종이 고르게 분산되어 정상입니다.

사용자가 직접 후커블로 만든 같은 제품(glowiest) 레퍼런스와 나란히 놓으면 이 차이가 결과물 품질 차이의 가장 큰 원인입니다 — 레이아웃·카피가 아니라 **같은 사진이 계속 나오는 것**이 "AI로 대충 만든 티"의 핵심입니다.

## 조사해야 할 것 (근본 원인 확정)

글로위스트 v3는 사진을 5장 업로드했는데 고유 상품 이미지가 1장뿐입니다. 두 갈래 중 어느 쪽인지 먼저 확정해 주세요.

1. **enhance 단계 실패**: `lib/photo-pipeline-client.ts` / `lib/photo-enhance.ts`가 업로드 5장 중 1장만 enhanced 산출물을 만들고 나머지 4장은 실패(타임아웃·Replicate 오류·컷아웃 품질 미달로 폐기)했는지. Supabase `product_images`(또는 해당 상품의 이미지 테이블)에서 `product_id = 49f8192b-2d17-4650-adac-12941f86487a` 행을 조회해 **enhanced 산출물이 몇 개 저장돼 있는지** 확인해 주세요.
2. **배정 단계 폴백**: enhanced가 여러 장 있는데도 `lib/assign-section-images.ts`가 섹션별 imageIndex를 해석하는 과정에서 유효하지 않은 인덱스를 만나 계속 0번으로 폴백하고 있는지. `resolveImage(imageUrls, n)` 계열 헬퍼가 범위를 벗어난 인덱스에서 조용히 0번을 반환하는 경로가 있는지 확인해 주세요.

DB에 enhanced가 1개뿐이면 (1)번, 여러 개인데 화면엔 1개만 나오면 (2)번입니다.

## 작업 A — 근본 원인 수정

확정된 원인에 따라 고쳐 주세요.

- (1)번이면: enhance 실패 시 **원본 업로드 사진이라도 해당 슬롯에 쓰이도록** 폴백을 넣어 주세요. 지금은 실패한 사진이 통째로 사라져 배정 풀에서 빠지는 것으로 보입니다. "보정 실패 → 원본 사용"이 "보정 실패 → 다른 사진 1장을 30번 반복"보다 훨씬 낫습니다. 실패 건수는 로그로 남겨 주세요.
- (2)번이면: 인덱스 폴백이 항상 0번으로 수렴하지 않도록, **이미 사용된 이미지를 피해 다음 미사용 이미지를 고르는** 방식으로 바꿔 주세요.

## 작업 B — 반복 사용 상한 가드

원인과 무관하게, 배정 단계에 안전장치를 넣어 주세요.

- 사용 가능한 고유 이미지가 N개일 때, **한 장이 전체 이미지 슬롯의 절반을 넘게 차지하지 않도록** 균등 분배(round-robin)합니다.
- 고유 이미지가 1~2장뿐이라 반복이 불가피한 경우에는, 같은 사진을 **연속된 섹션에 붙여 쓰지 않도록** 최소 간격을 둡니다(바로 위아래 섹션에 같은 컷이 나오면 가장 티가 납니다).
- 배정 결과를 로그로 남겨 주세요: `[assign-images] unique=4 slots=30 maxRepeat=30` 같은 형태 — 이번 같은 케이스를 다음엔 로그만 보고 바로 잡을 수 있게.

## 작업 C — 사용자 안내

고유 이미지가 슬롯 수에 비해 크게 부족하면(예: 고유 3장 이하로 23개 섹션을 채워야 하는 경우) 결과 화면에 안내를 노출해 주세요. 결과 페이지 상단 안내 영역이나 생성 단계 카드 근처에 한 줄이면 충분합니다:

> 사용 가능한 사진이 N장뿐이라 일부 섹션에서 같은 사진이 반복됩니다. 사진을 추가하면 더 다양한 구성으로 만들 수 있어요.

지금은 판매자가 "왜 이렇게 밋밋하지?"의 원인을 알 방법이 전혀 없습니다.

## 하지 않는 것

- 부족한 컷을 AI로 새로 만들어 채우는 것(생성형 이미지 증강)은 이번 범위 밖입니다 — 비용·환각 리스크가 크고 별도 논의가 필요합니다.
- 섹션 레이아웃/디자인 변경은 이번 범위 밖입니다.
- 이미 저장된 과거 페이지를 소급 재생성하지 않습니다.

## 검증 방법

- `npx tsc --noEmit` 에러 0건.
- 글로위스트 v3(`49f8192b-…`)를 **재생성**한 뒤, 결과 페이지에서 아래 스니펫으로 고유 이미지 수를 실측해 4 → 5 이상으로 늘어났는지 확인:

```js
// 결과 페이지에서 "상세정보 더보기"를 누른 뒤 콘솔에 붙여넣기
const l = [...document.querySelectorAll('img')].map(i => (i.currentSrc||i.src).split('/').pop());
const c = {}; l.forEach(s => c[s] = (c[s]||0)+1);
console.log({ total: l.length, unique: Object.keys(c).length, counts: c });
```

- 사진 2장만 올린 상품을 하나 만들어, 반복 상한 가드가 동작하는지(같은 컷이 연속 섹션에 붙지 않는지) + 안내 문구가 뜨는지 확인.
- 히알루론 세럼(`7dca0930-…`)처럼 이미 정상인 상품이 회귀하지 않는지(고유 10개 유지) 확인.
