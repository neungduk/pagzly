## 1. 범위 — 110차와 동일한 원칙, 카테고리만 확장

110차의 설계 원칙을 그대로 따릅니다. 다시 적지 않고 참조만 합니다: **AI 이미지 생성 금지, 코드 SVG 템플릿만, 입력값 없으면 미렌더, 카테고리 테마 색상만 사용, 컴플라이언스 가드 통과.**

### 만들 것

1. **식품/건강기능식품 — 원재료 구성 비율** (`lib/food-ratio-diagram.ts` 또는 유사 신규 파일 + 컴포넌트)
   - 입력: 판매자가 입력한 배합비/원재료 비율 데이터가 있을 때만.
   - 형태: 도넛 또는 스택 바.
   - 입력 없으면 **미렌더**(예시 수치 채우기 금지 — 110차와 동일 규칙).
   - `food-compliance.ts` 가드 통과 확인.

2. **전자제품 — 구성품 배치도**
   - 입력: 판매자가 입력한 구성품 목록(박스 구성품 텍스트 등 기존 데이터).
   - 형태: 아이콘 + 라벨 배치. 새 아이콘을 AI로 생성하지 말고 기존 `concept-icons.ts` 또는 심플한 SVG 도형(원/사각형 + 텍스트)으로 처리하세요.
   - `SizeComparisonDiagram.tsx`가 이미 있으니 **크기 비교와는 별개**로, 구성품 "무엇이 들었는지"를 보여주는 배치도만 새로 만드세요.

3. **생활용품/패션 — 재사용 확인**
   - `SizeComparisonDiagram.tsx` / `FashionSizeDiagram.tsx`가 이미 이 카테고리들을 커버하는지 코드로 확인만 하고, 빠진 게 있으면 알려주세요. **중복 구현 금지**(110차와 동일 지침).

4. **화장품 — 3번째 다이어그램 검토 (선택)**
   - 110차는 용량 비교·사용 순서 2종만 했습니다. 레퍼런스(마유에스테)의 "지방산 비교표"류처럼 **성분 배합비를 시각화할 입력 데이터**(예: 판매자가 입력한 주요 성분 함량 %)가 실제로 존재하는지 먼저 확인하세요.
   - 데이터가 있으면: 성분 비율 바 차트 정도로 제한하고, **효능·기능성 주장으로 읽히지 않게** 문구를 "함유 성분"류로만 표기하세요(`cosmetics-compliance.ts` 가드 필수 — 97차 라벨 환각, 110차 효능 필터와 같은 계열의 위험입니다).
   - 데이터가 없으면 **만들지 마세요.** 억지로 3번째를 채우는 것보다 2종을 정확히 유지하는 게 낫습니다.

## 2. 하지 않는 것

- 상품 생성 실행 금지. `TEST_MODE=true` 유지.
- AI 이미지로 다이어그램 생성 금지(110차 2절과 동일).
- 입력 없는 항목을 예시 수치로 채우기 금지.
- 효능·임상 주장 시각화 금지.
- 새 섹션 타입 남발 금지 — 가능하면 기존 `stat_infographic`/`spec_table` variant로 얹으세요.

## 3. 검증 방법 (무비용)

- 각 신규 다이어그램: (a) 입력 충분 (b) 입력 일부 누락 (c) 입력 없음 3종 픽스처로 렌더/미렌더 확인.
