# 197차 — "어떤 사진이 들어와도 같은 품질" 감사: 브랜드색 스크림이 사진과 충돌하는 다른 자리 점검 (API 0)

생성: 2026-09-15

## 하드 가드레일 (반복 — 사용자 재확인)

> "api 토큰은 사용 하면 안돼"

Replicate/Claude/DeepSeek 등 **어떤 생성 API도 호출 금지**. `/api/generate` 실행 금지.
이번 라운드는 **이미 있는 세션 데이터(`review/181cha-live/{cat}/`, 6카테고리 전부 이미
생성 완료)로 로컬 재렌더링·스크린샷만** 합니다. 새 이미지·카피 생성 없음.

## 배경 — 사용자 지적 (원문)

> "후커블과 똑같이 나와야해 그렇다고 소비자가 매번 다른사진 넣을텐데 항상 같게가 아니라
> 퀄리티가 똑같이 나와야해"

정확한 지적입니다. 지금까지 195/196차는 "지금 손에 있는 샘플 사진 1~2장이 예쁘게
나오는가"만 확인했는데, 실제 판매자는 매번 다른 사진을 올립니다. **특정 사진에서만
운 좋게 괜찮아 보이고 다른 사진(다른 색감·구도)에서는 깨지는 로직**이 있다면, 그건
"품질이 낮다"가 아니라 "품질이 사진마다 들쑥날쑥하다"는 훨씬 나쁜 문제입니다. 196차가
고친 문제(`getHeroGradient`가 카테고리 브랜드색을 스크림으로 써서, 그 색과 사진 색이
우연히 부딪히면 탁하게 오염됨)가 정확히 이 종류의 버그였습니다 — 식품 샘플에서는
초록빛으로 오염됐지만, 다른 사진이었다면 안 그랬을 수도 있습니다. 즉 **"사진 의존적으로
결과가 흔들리는 다른 자리가 더 있는가"**를 이번에 전수 점검합니다.

**코드 전체에서 `getHeroGradient(theme)`를 쓰는 자리를 grep으로 찾아보니 4곳**입니다:

| 자리 | 박스 크기 | 위험도 |
|------|-----------|--------|
| `case "hero"`(1340행) | `min-h-[70~85svh]`(거의 풀뷰포트) | 낮음 — 196차 분석대로 박스가 커서 브랜드색 비중이 작음 |
| `case "image_text"` 에디토리얼 풀블리드(1805행) | `aspect-[4/5]` | **196차에서 이미 수정 중** |
| `case "illustration_banner"`(2793행) | `aspect-video`(16:9) | **미점검** — hero보다 훨씬 짧은 박스, 게다가 이중 그라데이션까지 겹침 |
| `case "custom_gif"`(2879행) | `aspect-video`(16:9) | **미점검** — 테스트용 세션 데이터에 없어(GIF 미사용) 코드 검토만 가능 |

`illustration_banner`는 6개 카테고리 세션(`review/181cha-live/{cat}/session.json`) **전부에
실제로 존재**합니다(food 11번, fashion 19번, beauty 10번, electronics 19번, living 11번,
pet 11번 섹션) — 6장 전부 스크린샷으로 실사 검증이 가능합니다.

## 작업

### A. 196차부터 먼저 — 6카테고리 전부로 확장 검증

196차가 고친 에디토리얼 풀블리드 스크림(`getEditorialBleedScrim`)을 food/fashion
2개만이 아니라 **아래 6개 섹션 전부**로 검증 범위를 넓히세요(같은 코드가 카테고리마다
다른 사진에도 안전한지 확인하는 것이 이번 라운드의 핵심입니다):

- beauty: 23번 섹션(`customer_scenario`, "아침 루틴 한 방울")
- electronics: 11번(`usage_scenario`, "침실 협탁 위, 밤새 조용히"), 23번(`install_scenario`, "책상 한쪽, 22cm 폭")
- living: 9번(`usage_scenario`, "욕실 한 켠에"), 22번(`usage_scenario_extra`, "드레스룸 정리")
- pet: 9번(`usage_scenario`, "매일 같은 시간의 한 끼"), 21번(`usage_scenario_extra`, "남은 사료 소분 보관")

사진이 탁해지거나 가려지는 카테고리가 하나라도 있으면, 그 카테고리의 실제 사진 색감을
근거로 `getEditorialBleedScrim()`의 정지점(0%/24%/42%/55%)이나 최대 불투명도(0.82)를
조정하세요 — 색 자체는 이미 중립(`BRAND.ink`)이라 190차식 "판단 오류" 없이 순수 수치
조정만으로 끝날 가능성이 높습니다.

### B. `illustration_banner` — 이중 그라데이션 실사 재확인 (신중하게, 섣불리 고치지 않기)

`illustration_banner`는 `getHeroGradient(theme)` + 별도 `linear-gradient(180deg, ...)`를
겹쳐 씁니다(2842~2851행). 주석에 "모델이 가끔 넣는 가짜 UI/깨진 글자를 가린다"라고 돼
있어 **의도적으로 강하게** 만든 것입니다 — 이번엔 무조건 고치지 말고, 먼저 6개 카테고리
섹션(위 표의 섹션 인덱스)을 전부 스크린샷으로 찍어 실제로 탁하게 오염되는지 **눈으로
먼저 확인**하세요.

- 문제가 없다면(이 섹션의 원본 이미지가 애초에 흐리게 처리돼(`blur-2xl`, `opacity-55`)
  들어가는 구조라 195차 문제와 다를 수 있음 — 코드 2810~2815행 참고) **그대로 두고
  "이상 없음"으로만 보고**하세요.
- 실제로 탁해지는 카테고리가 있다면, `getHeroGradient(theme)` 자리만 196차와 같은
  기법(`theme.deepAccent`/`accent` → `BRAND.ink` 중립색 교체)으로 바꾸되, **주석에 적힌
  "가짜 UI 가리기" 목적을 약화시키지 않도록 불투명도는 유지**하세요(색상만 중립화, 강도는
  그대로).

### C. `custom_gif` — 코드만 선제적으로 정리 (실사 데이터 없음)

`custom_gif`는 판매자가 직접 GIF를 올려야 나오는 섹션이라 지금 세션 데이터엔 없습니다
(실사 스크린샷 불가). 하지만 구조가 195차 수정 전 에디토리얼 풀블리드와 동일합니다
(`getHeroGradient(theme)` 하나만 이미지 위에 인라인으로, aspect-video 박스). 같은 버그가
분명히 재현될 구조이니, **실사 확인 없이도 선제적으로** `getHeroGradient(theme)` →
196차가 만든 중립 스크림 함수(박스 비율이 다르니 percentage 정지점만 aspect-video에 맞게
재조정 — 4:5보다 세로가 짧으니 좀 더 안쪽으로 당기세요, 예: `0%/20%/38%/50%`)로
교체하세요. `tsc`만 통과하면 되고, 스크린샷은 생략 가능(테스트 데이터 없음을 보고서에
명시).

## 하지 않는 것

- 생성 API 호출 전부 금지(0회).
- `case "hero"`는 미수정(196차 분석대로 박스가 커서 위험도 낮음 — 이번 라운드에서도
  문제 신고 없으면 그대로 둠).
- `illustration_banner`는 실사로 문제 확인 전에는 코드를 먼저 고치지 않음(섣부른 재사용
  방지 — 195차의 실수를 반복하지 않기 위함).
- EDITORIAL_BLEED_SLOTS 슬롯 목록, split/compact/annotated/callout 레이아웃, 154/156/183/
  188~196차 완료 항목 재작업 없음.
