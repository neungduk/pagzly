# 50차 — 실제 쇼핑몰 판매 페이지 벤치마킹 품질 개선 (코드 전용, 비용 절감)

생성: 2026-09-01

## 방향 전환 (중요)

지금까지(29·45·48차) 조사는 "AI 상세페이지 제작 툴"(후커블·크리에이지·GENCY 등) 경쟁사
위주였습니다. 이번엔 방향을 바꿔서 **AI 툴이 아니라 실제로 잘 팔리는 진짜 쇼핑몰 판매
페이지**(올리브영·무신사 등 실제 상품 상세페이지)를 직접 둘러보고, 우리 결과물과
비교했을 때 **구조적으로 부족한 부분**을 찾았습니다.

**이번 라운드는 실제 유료 생성 테스트를 돌리지 않습니다.** API 비용이 계속 들어가는
문제 때문에, 이번엔 전부 코드 리뷰 + 정적 검증(`tsc`, 기존 픽스처/스냅샷)으로만 확인하고,
실제 앱에서 눈으로 봐야 하는 항목은 "제안만 하고 실제 생성 없이 로컬 스토리북/목업 데이터로
확인"하는 방식으로 범위를 좁혀주세요. 새로 실제 상품 생성을 여러 번 돌리는 방식의 QA는
이번 브리프에서는 하지 마세요.

## 조사 방법 및 발견 (직접 확인함)

올리브영 실제 판매 1위 상품(이즈앤트리 참마 비건 밀크 클렌저, 리뷰 12,914건)과 무신사
실제 판매 상품(무신사 스탠다드 우먼 스웨트셔츠, 좋아요 36만) 상세페이지를 브라우저로 직접
열어서 스크롤하며 확인했습니다. 우리 결과물과 비교해 눈에 띄는 차이 6가지를 찾았습니다.

### 발견 1 — 상세 콘텐츠를 처음부터 다 펼쳐 보여주지 않는다 ("더보기" 접기)

올리브영·무신사 둘 다 상세설명 탭을 열면 처음엔 브랜드 배지/짧은 배너만 보이고,
**"상품설명 더보기" 버튼을 눌러야** 전체 이미지 시퀀스가 펼쳐집니다. 우리는 지금 생성된
모든 섹션을 처음부터 끝까지 한 번에 다 렌더링합니다 — 처음 스크롤에서부터 페이지가
과도하게 길어 보이고, 이탈 여지가 큽니다.

### 발견 2 — 페이지 최상단에 "신뢰 신호"가 밀도 높게 몰려 있다

올리브영 예시엔 하나의 화면 안에 별점(4.8)+리뷰수(12,914건)+실시간 조회자 수("572명이
보고 있어요")+베스트/오늘드림 배지+쿠폰 할인율이 동시에 보입니다. 우리 히어로는 헤드라인+
사진+가격 정도만 있고 이런 신뢰/긴급성 신호가 없습니다. (단, 우리는 실제 리뷰·조회수
데이터가 없으므로 가짜 숫자를 만들면 안 됩니다 — 아래 "하지 않는 것" 참고.)

### 발견 3 — 본문 진입부에 "판매 랭킹/수상" 같은 임팩트 있는 증거 그래픽이 먼저 나온다

실제 상세설명 콘텐츠의 첫 화면이 제품 소개가 아니라 "올리브영 판매랭킹 1위" 같은 굵고
큰 타이포 증거 배너입니다. 우리는 이런 "증거를 먼저 보여주는" 섹션 패턴이 없습니다.

### 발견 4 — 카피가 "고객 pain point 인용구 → 감성 해시태그 헤드라인 → 수치 기반 감각 스탯"
3단 구조로 짜여 있다

"민감한 피부를 위한 1차 세안제가 있었으면 좋겠어요"(고객 목소리 인용) → "#참마장벽밀크"
(짧은 해시태그형 벤치마크 카피) → "자극감 없는 부드러운 롤링감 48%"(수치+감각 표현, 텍스처
클로즈업 사진과 페어링) 순서로 이어집니다. 우리 카피는 대체로 바로 효능 설명으로
들어가고, 이런 "문제 제기 → 감성 훅 → 수치 근거"의 3단 스토리텔링 구조가 약합니다.

### 발견 5 — 텍스처/사용 장면 클로즈업 사진의 스타일링 수준이 높다

원료(참마 뿌리)를 크래프트지·끈 같은 소품과 함께 배치한 에디토리얼 스타일 사진, 제품
텍스처가 눌려 나오는 순간의 매크로 클로즈업 등 — 우리 AI 배경 합성 결과보다 훨씬
공들인 소품 연출입니다.

### 발견 6 — 패션 카테고리는 컬러 배경보다 "화이트/뉴트럴 배경 + 사진 자체의 힘"으로 승부한다

무신사 상세페이지는 우리처럼 섹션마다 컬러 그라데이션 배경을 쓰지 않습니다. 배경은 거의
흰색/뉴트럴이고, 대신 큼직한 편집숍풍 모델 사진과 초대형 타이포(브랜드명급 크기의 제품명)로
고급스러움을 만듭니다. 우리 패션 카테고리도 다른 카테고리와 똑같은 accent 그라데이션
패턴(A/B/C/D/E)을 쓰는데, 패션에는 안 맞을 수 있습니다.

## 이번 라운드 수정 사항 (코드 전용, 자동 진행 — 순서대로, 각 항목 완료 후 다음으로)

### A. 상세 콘텐츠 "더보기" 접기 UX (신규 UI, API 비용 없음)

결과 페이지(`app/create/result/page.tsx`, 미리보기 렌더러)에서 히어로 + 본문 처음
1~2개 섹션까지만 기본으로 보이게 하고, 그 아래는 "상세정보 더보기" 버튼을 눌러야
펼쳐지도록 하세요.
- 버튼 클릭 시 나머지 섹션이 자연스럽게 펼쳐지는 애니메이션(높이 트랜지션 정도만).
- 마켓 업로드용 정적 HTML export(`lib/export-detail-html.ts`)에서는 이 접기 기능이
  꼭 필요하지는 않습니다 — 정적 다운로드본은 처음부터 전체를 다 보여줘도 됩니다(마켓
  업로드 후엔 마켓 자체 UI가 페이지 길이를 조절하는 경우가 많음). **미리보기 화면
  (result 페이지)에만 적용**하세요.
- 검증: 실제 생성 없이, 기존 세션에 저장된 목업/픽스처 데이터(있다면) 또는 하드코딩된
  더미 섹션 배열로 로컬에서 접기/펼치기 동작만 확인하면 됩니다.

### B. "증거 먼저 보여주기" 섹션 — 판매자 입력 기반 신뢰 배지 (가짜 숫자 절대 금지)

새 섹션 타입을 만들지 말고, 기존 `highlight_box` 또는 `stat_infographic` 슬롯을
재활용해서 "판매자가 실제로 가진 근거"만 넣을 수 있는 입력 필드를 하나 추가하세요.
예: "네이버 랭킹 O위", "누적 판매 O개", "재구매율 O%" 같은 문구를 판매자가 직접
입력하면 그 문구를 굵은 타이포 배너 형태(올리브영 "판매랭킹 1위" 배너 느낌)로 페이지
상단 근처(히어로 바로 다음)에 강조 렌더링합니다. **입력이 비어 있으면 이 섹션 자체를
아예 생성하지 마세요** — AI가 임의로 숫자나 "베스트셀러" 같은 근거 없는 문구를 만들어내면
절대 안 됩니다(과대광고·전자상거래법 이슈).

### C. 카피 구조 개선 — "고객 인용구 → 해시태그 헤드라인 → 수치 감각 스탯" 3단 프롬프트 반영

`app/api/generate/route.ts`(또는 카피를 만드는 DeepSeek 프롬프트 부분)에서, checklist나
image_text 같은 본문 섹션 중 최소 1곳에 이 3단 구조를 시도하도록 프롬프트 지시문을
추가하세요:
1. (선택적) 판매자가 입력한 원본 설명에 고객 반응/고민이 있으면 그걸 인용구 톤으로 짧게
   재구성
2. 짧은 해시태그형 헤드라인 1개 (예: "#OO케어")
3. 숫자 근거가 있는 경우에만 "OO% 개선/차이" 같은 감각적 수치 문구 — **숫자는 판매자가
   입력한 값이나 성분표에서 나온 값만 사용, 지어내지 마세요.**
이건 프롬프트/템플릿 수정이라 기존 생성 흐름 안에서 처리되고 별도 API 호출이 추가되지
않습니다 — 코드 리뷰로 프롬프트 문구가 제대로 들어갔는지만 확인하면 됩니다.

### D. 패션 카테고리 배경 미니멀리즘 옵션 검토

`lib/design-tokens.ts`의 `getCategoryRhythm("의류/패션")`에 배경 강도를 낮추는 옵션을
검토하세요. 지금처럼 A/B/C/D/E 그라데이션 패턴을 그대로 쓰되, 패션 카테고리에 한해
`getSectionBackground()`가 참조하는 알파값을 지금보다 낮춰서(예: 패턴 A/B/D의 accent
알파를 다른 카테고리 대비 절반 수준으로) 배경이 사진을 방해하지 않고 뉴트럴에 가깝게
보이도록 튜닝하세요. **3색 구조·슬롯 자체는 건드리지 마세요** — 알파(투명도) 값만
패션 카테고리 한정으로 조정하는 겁니다. 튜닝 후 스크린샷 1장 정도로(기존에 이미 있는
`review/qa-screenshots/`류 픽스처 활용, 새로 생성 안 해도 됨) 눈으로 확인.

### E. 텍스처 클로즈업 슬롯 안내 문구 보강

`lib/image-roles.ts`(업로드 힌트) 또는 사진 슬롯 가이드 문구에, "질감이 잘 보이는
매크로/클로즈업 사진을 올리면 감각적 카피와 자연스럽게 매칭됩니다" 같은 안내를
`texture_closeup`/`detail_zoom` 슬롯에 한해 추가하세요. 이미 업로드된 사진 중
클로즈업으로 보이는 게 있으면 우선 배치하는 로직이 있다면 그대로 재사용하고, 없다면
이번 범위에서 새로 만들 필요는 없습니다 (안내 문구만).

## 하지 않는 것 (이번 라운드 범위 밖)

- **실제 앱으로 여러 번 재생성해서 스크린샷 비교하는 QA는 이번엔 하지 마세요** — 비용
  문제로 보류 중입니다. 코드 리뷰 + `tsc` + 기존 픽스처로만 검증하세요.
- 가짜 리뷰 수·평점·조회자 수(실시간 "N명이 보고 있어요" 같은) 등 **판매자가 실제로
  갖고 있지 않은 데이터를 지어내서 넣는 것은 절대 금지**입니다. 이번 브리프의 B 항목은
  판매자가 "직접 입력한" 근거만 다룹니다.
- 무신사에서 본 "사진 안 핫스팟 클릭 → 다른 상품 카드" 같은 크로스셀 기능, AI 가상 피팅
  아이콘 — 둘 다 흥미롭지만 Pagzly는 단일 상품 페이지 생성 툴이라 범위 밖입니다.
  `review/upgrade-proposals.md`에 아이디어로만 기록해 두세요.
- 색상 추출 로직(`color-extract.ts`) 재수정 — 49차에서 이미 다뤘고 이번 범위 밖입니다.
