# 109차 — 히어로 브랜드 워드마크 / 로고

생성: 2026-09-03
전제: 107차 로드맵의 "109차 예정" 항목입니다. 108차와 독립적이므로 순서를 바꿔 진행해도 됩니다.

---

## 1. 현재 상태

레퍼런스(후커블 glowiest 페이지, 마유에스테, 버가못)는 모두 상단에 **브랜드명이 로고처럼 조판**되어 있습니다. 이게 "누가 파는 물건인지"를 즉시 각인시키고 페이지 전체의 격을 올립니다.

우리 쪽은 리포 전체 검색 결과 **워드마크·로고 관련 코드가 0건**입니다. 브랜드명이 나오는 곳은 `DetailSectionRenderer.tsx:2572-2574`의 브랜드 스토리 kicker(`font-mono text-[11px] uppercase tracking-[0.32em]`)뿐이고, 히어로에는 아예 없습니다.

---

## 2. 방향 — 로고 업로드가 1순위입니다

두 갈래가 있는데 **우선순위가 분명합니다.**

**(A) 판매자 로고 파일 업로드 — 이걸 기본으로 하세요.**
실제 브랜드에는 이미 로고가 있습니다. 그걸 받아 쓰는 게 가장 정확하고 기술적으로도 단순합니다.

**(B) 타이포그래피 워드마크 — 로고가 없을 때의 대체안.**
브랜드명을 선택된 서체·자간으로 조판합니다.

**중요 — (B)에서 지켜야 할 선**: 심볼·아이콘·엠블럼을 **생성하지 마세요.** 실존 브랜드의 로고를 AI가 지어내는 것은 97차의 가짜 라벨, 103차의 재생성된 제품과 같은 계열의 문제입니다. (B)는 어디까지나 **브랜드명 텍스트의 조판**이어야 하고, 판매자가 "이건 우리 로고가 아니라 텍스트 조판"임을 알 수 있어야 합니다.

---

## 3. 작업

### 3-1. 로고 업로드 (A)

- `CreateProductForm.tsx`의 "참고 자료" 영역에 **브랜드 로고 (선택)** 슬롯을 추가하세요. PNG/SVG, 배경 투명 권장이라고 안내하세요.
- 저장: products에 `logo_url` 컬럼 추가(마이그레이션은 `add column if not exists`, 적용은 사용자가 수동).
- 히어로 렌더에서 로고가 있으면 표시합니다. 제약:
  - 최대 너비 히어로 폭의 **25~30%**, 최대 높이 고정(예: 64px 상당)
  - 위치는 상단 중앙 또는 상단 좌측 — 기존 히어로의 카테고리 kicker/배지와 겹치지 않게
  - 배경 사진 위에 올라가므로 **기존 히어로 그라디언트 오버레이 안쪽**에 배치해 대비를 확보하세요(`getHeroGradient` 재사용)
  - 투명 배경이 아닌 로고(흰 배경 JPG 등)가 올라올 수 있으니, 흰 배경 감지 시 여백을 주거나 밝은 영역에 배치하는 정도의 완충을 두세요

### 3-2. 타이포 워드마크 (B) — 로고가 없을 때

- 브랜드명을 히어로 상단에 조판합니다. 카테고리 테마(`category-theme.ts`)와 `design-tokens.ts`의 기존 토큰을 쓰고 **새 서체를 추가하지 마세요.**
- 영문 브랜드명(예: `glowiest`)과 한글 브랜드명은 조판이 달라야 합니다. 영문은 소문자 + 넓은 자간이 잘 맞고, 한글은 자간을 과하게 벌리면 깨져 보입니다. 최소한 두 갈래로 분기하세요.
- 브랜드명이 없거나 상품명과 동일하면 **아무것도 표시하지 마세요.**

### 3-3. 내보내기 포함

로고/워드마크는 판매자가 실제로 게시하는 결과물에 들어가야 의미가 있습니다. `lib/export-detail-html.ts`와 이미지 다운로드 경로에 **반드시 포함**되도록 하세요. (108차 장식 배경과 달리, 이건 내보내기에 들어가야 합니다.)

---

## 4. 하지 않는 것

- 상품 생성 실행 금지. `TEST_MODE=true` 유지.
- **로고 심볼·아이콘 생성 금지** (2절).
- 새 웹폰트 추가 금지 — 기존 토큰 범위 안에서 해결하세요.
- 브랜드 스토리 kicker의 기존 표시는 건드리지 마세요(중복 표시가 되지 않도록 히어로에 로고가 나올 때의 처리만 정하면 됩니다).

## 5. 검증 방법 (무비용)

- `npx tsc --noEmit` 0건, 기존 스모크 PASS.
- 픽스처 4종으로 렌더 단위 테스트: (a) 투명 PNG 로고 (b) 흰 배경 JPG 로고 (c) 로고 없음 + 영문 브랜드명 (d) 로고 없음 + 한글 브랜드명. 각각 의도한 대로 나오는지 확인.
- 브랜드명 없음 / 상품명과 동일한 케이스에서 아무것도 렌더되지 않는지 확인.
- `export-detail-html` 출력 문자열에 로고 마크업이 **포함되는지** 확인.
- 극단 케이스: 가로로 매우 긴 로고, 세로로 긴 로고에서 레이아웃이 깨지지 않는지.
