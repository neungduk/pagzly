## 1. 확인해 줄 것 (수정 아님)

`119cha-food-diagram.png`와 `119cha-living-pattern.png` 스크린샷 **왼쪽 아래**에 빨간 알약 모양 배지가 찍혀 있습니다 — `N` 로고 아이콘 + "1 Issue" 텍스트 + X 버튼. Next.js 개발 서버가 브라우저에 띄우는 dev overlay 인디케이터로 보입니다(런타임 에러/경고 카운트).

확인해 주세요:

1. 이게 **`next dev` 로컬 서버에서만 뜨는 오버레이**가 맞는지 — 즉 실제 배포 빌드(`next build && next start`)나 `export-detail-html.ts`로 만든 정적 export에는 안 나오는 게 맞는지.
2. 맞다면, 그 "1 Issue"가 **무엇을 가리키는지**만 클릭해서 확인해 주세요(콘솔 에러? React 경고? 특정 컴포넌트 hydration 이슈?). `npx tsc --noEmit`은 0건이었으니 타입 에러는 아닐 텐데, 런타임 콘솔 경고가 계속 쌓이고 있었다면 다음 브리프에서 원인을 봐야 할 수도 있습니다.
3. 이번 차수에서 그 경고 자체를 고치라는 게 아닙니다 — **무엇인지만 보고**해 주세요. 진짜 배포에 영향 없는 dev-only 노이즈면 그걸로 종결하면 됩니다.

## 2. 119차 반영 재채점 (118차와 같은 방식 재사용)

118차에서 6개 카테고리를 채점했고 전부 4.5 미만이었습니다(화장품 4.48 / 패션 4.42 / 식품 4.34 / 전자 4.42 / 생활 4.22 / 반려동물 4.24). 119차가 고친 게 **대비**(워드마크, 식품 다이어그램)와 **색 분리**(생활용품 패턴)이므로, 특히 이 세 카테고리·두 항목이 얼마나 올랐는지 확인이 필요합니다:

- 화장품/뷰티: 대비 4.3 → ?
- 식품: 대비 4.2 → ?
- 생활용품: 색 분리 4.3 → ?

### 할 것

1. `scripts/capture-58cha-preview.ts` + `review/quality-log.md` 채점 기준, 118차와 **완전히 동일한 프로세스**로 6개 카테고리 재캡처·재채점 1사이클 진행하세요. 새 기준 만들지 마세요.
2. 결과를 `review/120cha-report.md`에 118차와 같은 표 형식(항목별 점수 + 코멘트 + 카테고리별 평균 + 6개 카테고리 요약표)으로 정리하세요.
3. **정보** 항목은 118차에서 이미 "픽스처가 카테고리마다 안 달라서 구조적으로 낮게 나온다"고 정확히 진단됐고, 119차 브리프에서 이번엔 안 고치기로 한 부분입니다. 이번 재채점에서도 정보 점수가 낮게 나오면 그건 **회귀가 아니라 원래부터 있던 픽스처 한계**라는 걸 표에 다시 명시해 주시면 됩니다(새로 손대지 마세요).
4. 4.5를 넘긴 카테고리가 있으면 표에 표시해 주세요 — `quality-log.md` 기준상 "4.5+ 3회 연속"이 목표인데, 지금까지 채점된 라운드는 118차 1회뿐이라 이번이 2회차입니다. 3회 연속 조건은 아직 안 채워져도 괜찮습니다, 그냥 추이만 정확히 보고해 주세요.
5. 재채점 중 118차 §3에서 실측했던 4개 조합 가설 중 뭔가 **새로** 눈에 띄는 게 있으면(없으면 없다고) 짧게 적어주세요. 없으면 "특이사항 없음"이라고만 써도 됩니다 — 억지로 찾지 마세요.

### 하지 않는 것

- 118차 §4의 3번(픽스처 카테고리 정합), 5번(세리프×고딕 톤) — 계속 보류. 이번 재채점 결과에서 이 두 가지 외의 **새로운** 문제가 뚜렷하게 보이면 그것만 보고해 주세요(고치지 마세요).
