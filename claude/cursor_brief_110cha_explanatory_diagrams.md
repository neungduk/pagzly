# 110차 — 설명형 다이어그램 (SVG 템플릿 라이브러리)

생성: 2026-09-03
전제: 107차 로드맵의 "110차 예정" 항목입니다. 레퍼런스와의 격차 중 **가장 난이도가 높지만, 제대로 하면 임팩트도 가장 큰** 항목입니다.

---

## 1. 현재 상태

레퍼런스(마유에스테)는 피부 장벽 구조도, 지방산 비교표, 성분 구조식 같은 **그림형 설명 다이어그램**으로 "이 제품이 왜 좋은지"를 시각적으로 논증합니다. 이게 페이지를 "만든 것"처럼 보이게 하는 핵심 장치입니다.

우리 인포그래픽은 `DetailSectionRenderer.tsx:1935-2093` `stat_infographic`이 전부이고, 렌더 형태가 **숫자 카드 · 원형 게이지 · 막대**뿐입니다. 그림으로 개념을 설명하는 다이어그램은 없습니다.

---

## 2. 접근 방식 — AI 생성이 아니라 SVG 템플릿입니다 ★

세 가지 선택지 중 **(b)를 택합니다.**

- (a) 다이어그램을 AI 이미지로 생성 → **채택하지 않음.** 비용이 들고, 글자가 깨지고(97차 라벨 환각과 동일 계열), 무엇보다 **없는 과학적 주장을 그림으로 만들어낼 위험**이 큽니다. 화장품에서 "피부 장벽 구조도"를 AI가 그리면 그건 근거 없는 효능 표현이 됩니다.
- (b) **카테고리별 SVG 템플릿 라이브러리를 코드로 만들고, 검증된 입력값만 채워 넣기** → 채택.
- (c) 하이브리드(AI가 템플릿 선택 + 라벨 채움) → (b)를 먼저 만든 뒤 선택 로직만 얹으면 되므로, (b)의 후속으로 둡니다.

**(b)의 이점**: 추가 API 비용 **0원**, 글자 깨짐 없음, 벡터라 확대해도 선명, 내보내기 HTML에 그대로 들어감, 편집 가능.

---

## 3. 절대 규칙 — 데이터가 없으면 그리지 않습니다

리포에는 이미 같은 철학의 가드가 있습니다: `lib/comparison-chart-guard.ts`, 그리고 `section-templates.ts`의 "실측 근거가 있을 때만", "가짜 % 금지" 지시.

다이어그램도 동일하게 갑니다.

- **판매자가 입력한 사실**(용량, 성분명, 사용 순서, 구성품, 크기)만 라벨과 수치로 씁니다.
- 입력이 없으면 **그 다이어그램을 렌더하지 않습니다.** 빈 껍데기나 예시 수치로 채우지 마세요.
- 효능·임상 수치를 다이어그램으로 표현하지 마세요. 화장품은 `lib/cosmetics-compliance.ts`, 식품은 `lib/food-compliance.ts`를 통과시키세요.

---

## 4. 만들 다이어그램 (1차 범위)

카테고리당 1~2종만 먼저 만드세요. 전부 **입력값이 있을 때만** 렌더됩니다.

### 화장품/뷰티
1. **용량 비교** — 이 제품(예: 35mL)과 일반적인 규격(100mL 등)을 병 실루엣 높이로 비교. 필요한 입력: 용량. 이번 glowiest 케이스에 바로 적용됩니다.
2. **사용 순서 다이어그램** — `usage_steps` 데이터를 원형/화살표 흐름도로. 이미 `step_card`가 있지만 텍스트 나열이라, 흐름이 보이는 형태로 재구성.

### 식품/건강기능식품
3. **원재료 구성 비율** — 입력된 배합비가 있을 때만 도넛/스택 바. 없으면 미렌더.

### 전자제품
4. **구성품 배치도** — 입력된 구성품 목록을 아이콘+라벨 배치로.
5. **크기 비교** — 이미 `SizeComparisonDiagram.tsx`가 있으니 **재사용**하고, 없는 것만 새로 만드세요.

### 생활용품/패션
6. 기존 `FashionSizeDiagram.tsx` / `SizeComparisonDiagram.tsx` 재사용 여부를 먼저 확인하고, 중복 구현하지 마세요.

---

## 5. 구현 지침

- **인라인 React SVG**로 구현하세요. 이미지 생성·업로드 경로를 타지 마세요.
- 색상은 `design-tokens.ts`의 카테고리 테마(`accent`, `deepAccent`, `baseNeutral`)를 쓰고 새 팔레트를 만들지 마세요. 페이지 전체와 톤이 맞아야 합니다.
- 새 섹션 타입을 남발하지 말고, 가능하면 **기존 `stat_infographic`에 `variant: "diagram"` 같은 형태로 얹으세요.** 섹션 타입이 늘어나면 템플릿·배정·렌더 전부에 파급됩니다.
- 텍스트가 들어가는 SVG는 반응형에서 잘리기 쉽습니다. 모바일 폭(360px 기준)에서 라벨이 겹치지 않는지 반드시 확인하세요.
- 내보내기(`export-detail-html.ts`)에 인라인 SVG가 그대로 실려야 합니다. 외부 참조 금지.

## 6. 하지 않는 것

- 상품 생성 실행 금지. `TEST_MODE=true` 유지.
- 다이어그램 AI 이미지 생성 금지(2절).
- 없는 데이터를 예시값으로 채우기 금지(3절).
- 효능·임상 주장 시각화 금지.
- 카테고리 6종 전부에 대해 한 번에 만들지 마세요. **화장품 2종부터** 만들고 검증 후 확장합니다.

## 7. 검증 방법 (무비용)

- `npx tsc --noEmit` 0건, 기존 스모크 PASS.
- 픽스처 단위 테스트: 각 다이어그램별로 (a) 입력값 충분 (b) 입력값 일부 누락 (c) 입력값 없음 → 각각 정상 렌더 / 축소 렌더 또는 미렌더 / **미렌더**가 되는지.
- 컴플라이언스: 효능 문구가 라벨로 들어간 픽스처에서 걸러지는지.
- 반응형: 360px / 768px / 860px 폭에서 라벨 겹침 없는지 (스냅샷 또는 수동 확인).
- `export-detail-html` 출력에 SVG가 인라인으로 포함되고 외부 URL 참조가 없는지.
