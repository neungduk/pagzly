# 48차 — 상세페이지 "우와" 퀄리티 업그레이드 (자동 진행형 백로그)

생성: 2026-08-31

## 배경 (사용자 원문)

> "자 그러면 다시 상세페이지로 돌아 와서 상세페이지 업그레이드를 지속적으로 이어가보자.
> 모든 AI상세페이지 기업들의 견본 혹은 만들어져있는 상세페이지들을 전부다 찾고 정말 MVP모델
> 이여도 사람들이 우와 하고 쓸 수 있게 끔 퀄리티를 높여보자 지시사항줘
> 최대한 너가 아니라 커서가 자동으로 돌아가면서 업그레이드를 할 수 있게 지원 해야해"

이 브리프는 29차(대규모 리서치 디렉티브)·45차(경쟁사 실사 2라운드)의 3번째 라운드입니다.
기존 두 라운드가 만든 `review/reference-patterns.md`, `review/upgrade-proposals.md`,
`review/competitor-gap-2026.md`를 무시하고 처음부터 다시 하는 게 아니라 이어서 확장합니다.

**이번 라운드의 차이점**: 지금까지는 "문제 하나 → 브리프 하나 → 보고 → 다음 브리프" 리듬으로
진행했습니다. 이번엔 사용자가 명시적으로 "커서가 자동으로 돌아가면서" 진행하길 원합니다. 그래서
이 브리프는 **여러 트랙과 하위 항목으로 구성된 백로그**입니다. Cursor는 아래 "작업 방식" 절의
규칙에 따라 사람 확인 없이 순서대로 진행하고, 막히는 항목만 표시해두고 넘어간 뒤, 전체를 끝내고
한 번에 종합 보고하면 됩니다.

### 1-2. 크리에이지의 "채팅으로 수정하기" — 가장 구체적인 벤치마크

지금까지 3번의 리서치(29차 P1-4, 45차, competitor-gap-2026.md "다음 우선순위 1번")에서
**"채팅형 섹션 편집"이 계속 최우선 미해결 항목으로 반복 등장**했습니다. 이번에 크리에이지의
실제 튜토리얼 페이지(`creazy.app/ko/tutorial/features/ai-chat`)를 확인해 정확한 UX 구조를
파악했습니다:

- **3단계 요청 granularity**: (1) 전체 페이지 채팅 — 섹션 생성·이미지 생성·문구 수정 뭐든
  자유 입력, 막막하면 "추천 후속 채팅" 제안 3개 제공. (2) 섹션 단위 — 섹션 툴바의 "채팅에서
  수정하기"를 누르면 그 섹션만 채팅에 컨텍스트로 들어가서 정확히 그 섹션만 변경. (3) 요소
  단위 — 이미지/텍스트를 클릭하면 그 요소만 채팅에 추가.
- **레퍼런스 활용**: 디자인 이미지를 업로드하고 적용 위치를 선택하면 AI가 참고.
- **번역**: 외국어 상세페이지를 "디자인은 그대로, 텍스트만" 한국어로 변환.
- **승인 메커니즘**: 크레딧 소모 작업(이미지·비디오 생성)은 실행 전 승인 필요, 프로젝트
  단위로 "항상 승인" 설정 가능.

**Pagzly 현재 상태**: `app/api/patch-section/route.ts` + `app/create/result/page.tsx`
(160~330행대, `patchIndex`/`patchInstruction`/`handlePatchSection`)에 이미 "섹션 하나 골라서
지시 한 줄 넣고 버튼 누르면 DeepSeek이 그 섹션 JSON을 고쳐준다"는 **기능적으로 크리에이지의
2단계(섹션 단위)와 동일한 백엔드가 이미 있습니다.** 다만 UI가 드롭다운+텍스트박스+버튼
한 번짜리라 "채팅"으로 안 느껴지고, 대화 이력도 없고, "추천 후속 질문" 같은 안내도 없습니다.
즉 **엔진은 있는데 껍데기가 "우와" 포인트를 못 살리고 있는 상태** — 이번 라운드에서 가장
비용 대비 효과가 큰 지점입니다 (Track 3 참고).

## 2. 작업 방식 — 자동 진행 규칙 (이번 라운드 핵심)

1. **아래 Track 1 → 2 → 3 순서로 진행**하되, 같은 트랙 안의 하위 항목은 순서 상관없이 진행
   가능합니다.
2. **각 항목을 끝낼 때마다** `npx tsc --noEmit`을 돌려 0건인지 확인하고, 그 항목만 커밋
   단위로 남기세요(한 번에 여러 항목을 뭉쳐서 큰 diff로 만들지 않기 — 지금까지 지켜온 원칙).
3. 항목을 진행하다가 **설계 판단이 필요한 지점**(예: 새 슬롯 타입이 필요해 보인다, 기존
   컴포넌트 구조를 크게 바꿔야 한다)을 만나면, **그 항목은 구현하지 말고 "승인 필요" 표시만
   남긴 채 다음 항목으로 넘어가세요.** 전체를 막지 않는 게 목적입니다.
4. **사람 승인 없이는 진행하지 않는 것**: 슬롯 신설, 3색 규칙/히어로-only 장식 규칙 변경,
   새 유료 이미지 생성 API 호출 추가, 섹션 타입 구조(JSON 키) 변경. 이런 게 필요하다고
   판단되면 반드시 제안만 남기세요.
5. **전체 백로그를 다 돌고 나서 한 번에 종합 보고**하세요. 중간에 끊어서 보고할 필요 없습니다
   (사람이 매번 확인하지 않아도 되도록 하는 게 이번 라운드의 목적).
6. Track 3(채팅형 편집)은 이번 라운드에서 **Phase 1만** 구현합니다 (아래 3절 참고). Phase 2/3는
   제안만 남기고 다음 라운드로 넘깁니다 — 한 번에 다 만들면 회귀 재현이 어려워집니다.

## Track 2 — 시각적 "우와" 폴리시 (저비용, UI/문구 중심)

### 2-A. 여백·미니멀리즘 감사 (트렌드 ⑤)

`lib/design-tokens.ts`와 실제 렌더러(`components/` 안의 섹션별 렌더 컴포넌트)를 훑어서,
섹션 간 여백(margin/padding)이 지금 기준으로 "여백이 부족해 답답해 보이는" 곳이 있는지
점검하세요. 3색 규칙이나 슬롯 구조를 바꾸는 게 아니라 **spacing 값만** 조정 대상입니다.
`review/qa-screenshots/`의 최근 캡처(화장품/전자기기/생활)를 실제로 열어보고 판단하세요.
구체적으로 어디를 얼마나 바꿨는지 스크린샷 전/후 비교를 보고에 포함하세요.

### 2-B. GIF/모션 기능 노출 강화 (트렌드 ⑥)

`custom_gif` 섹션(판매자 GIF 삽입) 기능이 이미 있는데 사용자가 잘 못 찾는다면, 업로드 UI
(`CreateProductForm.tsx` 또는 result 페이지의 GIF 업로드 버튼 근처)에 "동영상처럼 움직이는
사용 장면을 넣으면 체류시간이 올라갑니다" 같은 안내 문구를 추가하세요. **새 기능 개발이
아니라 기존 기능의 발견성(discoverability) 개선**입니다.

### 2-C. 인터랙티브 컬러 스와치 재검토 (트렌드 ④, `upgrade-proposals.md` P2-2)

기존 문서에 "마켓플레이스 HTML export의 script 정책 미검증으로 보류"라고 남아있습니다. 이번
라운드에서 실제로 확인하세요:
- 스마트스토어/쿠팡 상세페이지 HTML 등록 시 `<script>` 태그가 실제로 제거되는지, 아니면
  CSS만으로 만드는 인터랙션(예: `:hover`, `<details>/<summary>`, radio 버튼 트릭)은
  살아남는지 실제 테스트하거나 각 마켓 공식 가이드에서 근거를 찾으세요.
- **스크립트 없이 순수 CSS로 구현 가능하다고 확인되면** `color_variation` 섹션 렌더러에
  스와치 클릭 시 이미지가 바뀌는 인터랙션을 CSS-only로 구현하세요 (예: radio + `:checked`
  선택자).
- 스크립트가 반드시 필요하거나 마켓 정책상 위험하다고 판단되면, 구현하지 말고 결론만
  `upgrade-proposals.md` P2-2에 업데이트하세요.

### 2-D. `upgrade-proposals.md` P0 항목 잔여 처리

29차에서 만든 P0-1~4 중 아직 구현 안 된 게 있으면 이번 라운드에 처리하세요 (각 항목이 이미
파일/위치까지 명시돼 있으니 그대로 따르면 됩니다). 이미 구현됐으면 문서에서 "구현 완료"로
옮기세요.

## Track 3 — 채팅형 섹션 편집 Phase 1 (이번 라운드 최대 항목)

**목표**: 크리에이지의 3단계 중 **"섹션 단위"(2단계)에 해당하는 부분을, 이미 있는
`/api/patch-section` 백엔드를 그대로 재사용하면서, UI만 진짜 "채팅"처럼 느껴지게 업그레이드**
합니다. 새 AI 기능이 아니라 기존 기능의 UX 재포장이라 리스크가 낮습니다.

### 지금 상태 (변경 전)

`app/create/result/page.tsx`: `patchIndex`(드롭다운으로 섹션 선택) + `patchInstruction`
(텍스트박스 1개) + `handlePatchSection`(버튼 누르면 1회성 API 호출) — 대화 이력 없음, 이전
지시가 뭐였는지 안 보임, 실패해도 왜 실패했는지 UI에 잘 안 남음.

### 목표 상태 (Phase 1)

1. **대화 이력 상태 추가**: 섹션별로 `{ role: "user" | "assistant"; text: string; timestamp }[]`
   배열을 유지하세요 (섹션을 바꾸면 그 섹션의 이력을 보여주고, 새 섹션은 빈 이력으로 시작).
   서버에 영구 저장할 필요는 없습니다 — 페이지 세션 동안 클라이언트 상태로 충분합니다(추후
   필요하면 별도 라운드에서 DB 저장 검토).
2. **UI를 채팅 버블 스타일로 교체**: 기존 드롭다운+텍스트박스 자리를, 위에 대화 버블 리스트
   (사용자 지시 → "수정했어요" 같은 짧은 확인 메시지), 아래 입력창+전송 버튼으로 바꾸세요.
   기존 `patch-section` API 응답 구조는 그대로 씁니다 — API 변경 없음.
3. **"추천 후속 질문" chip 2~3개**: 처음 섹션을 열었을 때, 그 섹션 type에 맞는 미리 정의된
   제안 문구를 chip 버튼으로 보여주세요 (예: checklist 섹션이면 "포인트를 더 짧게",
   "숫자를 강조하는 톤으로" 같은 정적 문구 — **AI가 매번 새로 생성할 필요 없이 섹션
   type별로 하드코딩된 2~3개 문구면 충분**합니다. `lib/types/generate.ts`의 `DetailSection`
   타입별로 짧은 매핑 테이블을 만드세요). 클릭하면 바로 그 문구가 입력창에 들어가거나 바로
   전송되게 하세요.
4. **여러 차례 수정이 누적되는지 확인**: 사용자가 "이거 더 짧게" → 결과 확인 → "그런데
   숫자는 남겨줘" 처럼 연속으로 여러 번 수정할 때, 매번 최신 섹션 JSON을 기준으로 API를
   호출하는지 확인하세요 (`handlePatchSection`이 최신 `data.generated.sections[patchIndex]`를
   참조하는지 — 지금 코드 313~317행 기준으로는 맞는 것 같지만, UI를 채팅으로 바꾸면서
   회귀시키지 않도록 재확인).
5. **에러 처리 명확화**: API 실패 시 채팅 버블에 "수정에 실패했어요, 다시 시도해 주세요"처럼
   사용자에게 명확히 보이게 하세요 (지금은 실패 시 UI 반응이 불명확할 수 있음 — 실제 코드
   확인 후 필요하면 개선).
