# 117차 — 헤드라인 전용 타이포그래피 도입 (후커블 격차 해소)

생성: 2026-09-04
전제: 116차(카피 톤) 완료·검증됨. 프로가 "후커블과 비슷한 퀄리티가 무조건 나오게" 계속 다음 지시를 정하라고 해서, 제가 코드를 직접 감사해 다음 격차를 찾았습니다.

---

## 1. 확인한 것 — 폰트가 카테고리·용도 구분 없이 전부 하나

`lib/detail-typography.ts`를 열어보니 페이지 전체(미리보기 + HTML export 공통)가 **Noto Sans KR 고딕 하나**로만 되어 있습니다.

```
sans: '"Noto Sans KR", ...'
heading: '"Noto Sans KR", ...'   ← 헤드라인도 본문과 같은 서체
label: '"Noto Sans KR", ...'
```

`lib/design-tokens.ts`(27KB)와 `lib/category-theme.ts`를 전체 검색해봐도 `font`/`typeface`/`serif` 관련 토큰이 **버튼의 `font-semibold` 유틸리티 클래스 외엔 전혀 없습니다.** 카테고리별로 색상 테마(`accent`/`deepAccent`/`baseNeutral`)는 이미 갈라놨는데, **타이포는 화장품이든 전자제품이든 반려동물이든 전부 똑같은 고딕 한 가지**입니다.

레퍼런스(후커블 결과물, 마유에스테, 버가못)를 보면 헤드라인에 본문과 다른 서체 — 특히 뷰티 계열은 세리프나 존재감 있는 디스플레이 서체 — 를 써서 "손으로 디자인한 느낌"을 만듭니다. 지금 구조로는 카피(116차)가 아무리 좋아져도, 그걸 담는 글자 자체가 밋밋해서 "생성됐다"는 인상이 남습니다. 이게 다음으로 손대야 할 항목입니다.

---

## 2. 방향 — 헤드라인 전용 서체를 카테고리 테마에 얹기

### 2-1. 원칙

- **본문은 지금 그대로 Noto Sans KR 유지**(가독성 최우선 — 건드리지 않음).
- **`h1`/`mainHeadline`/주요 섹션 헤드라인만** 카테고리별 전용 서체로 교체.
- Google Fonts 무료 한글 폰트만 사용(신규 비용 없음). 아래 후보 중 카테고리 무드에 맞게 골라 매핑하세요 — 정확히 이 목록에 얽매이지 말고, 실제 렌더링해보고 눈으로 판단해서 조정하세요:
  - **화장품/뷰티**: `Noto Serif KR`(우아한 세리프) — 클린 뷰티 계열에 흔한 조합
  - **패션/의류**: `Noto Serif KR` 또는 얇은 굵기의 에디토리얼 느낌 서체
  - **식품/건강기능식품**: 따뜻한 느낌의 라운드 고딕(예: `Gowun Batang`은 세리프 계열이니 고딕 쪽 대안도 검토)
  - **전자제품**: 타이트한 트래킹의 굵은 고딕(존재하는 Noto Sans KR Black/Bold를 더 존재감 있게 — 새 폰트 없이 weight/letter-spacing만 조정도 방법)
  - **반려동물/생활용품**: 부드러운 라운드 고딕
  - 카테고리 무드에 안 맞는 조합이면 무리해서 전부 다른 폰트를 쓰지 말고, **1~2종만 우선 도입하고 나머지는 기존 Noto Sans KR weight 강화로 대체**해도 됩니다. 폰트 개수가 늘수록 로딩 비용·일관성 리스크가 커지니 과하게 벌리지 마세요.

### 2-2. 구현

- `lib/detail-typography.ts`에 `DETAIL_HEADLINE_FONT_STACK`(카테고리별 맵) 추가, `DETAIL_GOOGLE_FONTS_URL`에 선택한 폰트 family를 추가.
- 미리보기(`DetailSectionRenderer.tsx`)의 `h1`/히어로 헤드라인/주요 섹션 타이틀에 카테고리 테마 기반으로 헤드라인 폰트를 적용.
- **`export-detail-html.ts`에도 동일하게 반영**(109·110차와 같은 원칙 — 실제 산출물에 들어가야 의미가 있음). `DETAIL_EXPORT_FONT_CSS`를 카테고리 인자를 받도록 확장하거나, export 시점에 카테고리별 CSS 블록을 주입하세요.
- 폰트 로딩 실패/느림 대비: `font-display: swap` 유지, 폴백은 항상 기존 Noto Sans KR 고딕으로.

### 2-3. 적용 범위를 좁게 시작하세요

한 번에 전체를 바꾸지 말고 **히어로 `mainHeadline` + `h2` 섹션 제목**만 우선 적용하세요. `stat_infographic`/`spec_table` 같은 정보 밀도 높은 섹션의 라벨·숫자는 지금 고딕을 유지하세요(가독성 우선 — 110차와 같은 원칙).

## 3. 하지 않는 것

- 본문(body) 서체를 바꾸지 마세요.
- `stat_infographic`/`spec_table`/`faq`/`caution` 등 정보 전달 섹션의 숫자·라벨 서체를 바꾸지 마세요(가독성).
- 카테고리마다 전부 다른 폰트를 무리하게 늘리지 마세요 — 1~2종 우선, 근거 없이 6종 다 바꾸지 마세요.
- 유료 이미지 생성과 무관한 작업입니다. `TEST_MODE`는 그대로 두세요.
- 새 유료 API 없음(Google Fonts는 무료).
