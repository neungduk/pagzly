# 70차 — 사진 기반 AI 자동입력 (제목+사진만으로 초안 생성)

생성: 2026-09-02

## 배경

사용자 요청: "후커블은 제목과 사진만 넣어도 그 사진과 제목만 보고 AI가 자체
글을 생성해준다 — 이런 기능 넣을 수 없나?"

먼저 확인한 사실부터 정리합니다 — **이 기능의 핵심 부분은 이미 존재합니다.**
`app/api/generate/route.ts`의 `analyzeImagesWithClaude()`가 업로드된 사진
최대 10장을 실제로 Claude Vision(`CLAUDE_MODEL`, 프로덕션 기준)으로 분석해서
`imageAnalysis` 텍스트를 만들고, 이게 `generateCopyWithDeepSeek()` 프롬프트에
"## AI 이미지 분석 결과"로 그대로 주입됩니다. 즉 **최종 상세페이지 본문 카피는
이미 사진 내용을 실제로 보고 쓰입니다** — 이름만 보고 짐작하는 게 아닙니다.
또한 `CreateProductForm.tsx`에서 "핵심 특징/강조 포인트"는 원래 **선택
필드**라서, 지금도 제목+카테고리+사진(7~10장)+가격만 입력하고 나머지를
비워도 최종 페이지는 생성됩니다.

**그런데 진짜 체감 격차는 "폼을 채우는 단계"에 있습니다.** 후커블은 사진을
올리는 즉시(생성 버튼을 누르기 전에) 그 사진을 보고 뭔가 채워주는 느낌을
주는데, 63차에서 만든 "AI 자동입력" 버튼은 **상품명 텍스트만 보고**
(DeepSeek, Vision 아님) 핵심특징/타겟고객을 추측합니다. 즉 최종 결과물은
이미 사진을 보고 쓰이지만, **입력 단계의 자동입력 미리보기는 아직 사진을
안 봅니다.** 이번 라운드는 이 간극을 메웁니다.

## 작업 A — "AI 자동입력"이 사진도 보게 확장

`lib/autofill-draft.ts`의 `generateAutofillDraft()`를 확장(또는 새 함수
`generateAutofillDraftFromPhotos()`)해서, 이미 업로드된 사진 URL 목록을 받아
Claude Vision으로 가볍게 분석한 뒤 그 결과를 초안 생성에 반영해주세요.

- Vision 분석은 `analyzeImagesWithClaude()`를 그대로 재사용하기보다는, 폼
  단계 전용으로 **더 가볍게**(예: 대표 사진 2~4장만, `max_tokens`도 축소)
  만들어주세요 — 폼에서 누를 때마다 10장 풀 분석을 돌리면 비용도 크고
  느립니다. 정식 생성 시점의 `analyzeImagesWithClaude()`는 그대로 두고
  건드리지 마세요.
- Vision 프롬프트는 "이 사진들에서 실제로 보이는 색상/소재/형태/디자인
  요소만 짧게 나열"하도록 해서, 63차와 마찬가지로 **사진에서 확인 불가능한
  사실(성분/인증/수치)은 언급하지 않게** 안전장치를 유지하세요.
- 이 Vision 결과를 63차 DeepSeek 초안 프롬프트에 "## 사진에서 확인된 특징"
  블록으로 추가 주입해서 "핵심 특징" 초안이 실제 사진 근거를 담게 해주세요.
- **성분/인증 필드는 여전히 자동입력 대상에서 제외**(63차 원칙 불변) —
  사진에 성분표가 찍혀 있어도 임의로 읽어내 채우지 마세요(오독 리스크).

## 작업 B — 폼에 "사진만으로도 충분하다" 안내 추가

`CreateProductForm.tsx`에 이미 "핵심 특징/강조 포인트" 등이 선택 필드라는
걸 사용자가 잘 모를 수 있습니다. 상품 사진 업로드 섹션 근처에 짧은 안내문을
추가해주세요: "사진과 상품명만으로도 AI가 상세페이지를 생성합니다. 아래
선택 항목은 채우면 더 정확해집니다" 같은 문구로, 후커블처럼 "최소 입력으로도
동작한다"는 인상을 주도록 해주세요.

## 작업 C — 검증: 정말 사진+제목만으로 괜찮은 결과가 나오는지 확인

이건 새 기능이 아니라 **기존 기능이 실제로 잘 동작하는지 검증**하는
작업입니다. 핵심 특징/성분/타겟고객/인증을 전부 비워두고, 상품명+카테고리+
사진 7~10장+가격만 입력한 상태로 실제 생성을 1회 진행해서, 완성된 페이지의
카피가 여전히 구체적이고(추상적 형용사 나열이 아니라) 실제 사진 내용과
맞는지 육안으로 확인해주세요. 만약 결과가 부실하면, 그건 이번 작업 A의
동기를 더 강하게 뒷받침하는 근거가 됩니다 — 있는 그대로 보고해주세요.

## 하지 않는 것

- `analyzeImagesWithClaude()`(정식 생성용 Vision 분석) 변경 없음
- 성분/인증 필드 자동입력 (63차 원칙 그대로 불변)
- 사진에서 텍스트(라벨/성분표)를 읽어서 필드를 채우는 것 (OCR 오독 리스크,
  이번 범위 아님)

## 검증 체크리스트

- [ ] `npx tsc --noEmit` 에러 0건 (관련)
- [ ] 폼 단계 Vision 분석 — 대표 사진 2~4장만 사용, 정식 생성용 분석과 분리 확인
- [ ] "AI 자동입력" 클릭 시 핵심특징 초안에 사진 근거 반영 확인 (실제 클릭 테스트 스크린샷)
- [ ] 성분/인증 필드 여전히 미변경
- [ ] 폼 안내 문구 노출 확인
- [ ] 작업 C: 사진+제목만으로 실제 생성 1회, 결과 카피 품질 육안 평가(솔직하게)
- [ ] 비용 기록 (폼 단계 Vision 호출 비용 별도 표기)
