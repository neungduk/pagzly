# 118차 — 통합 시각 QA 재실행 (97~117차 누적 반영 점검)

생성: 2026-09-04
전제: 97~117차(이미지 사이즈/중복/역할/합성, 인포 다이어그램, 장식 배경, 로고, 카피 톤, 헤드라인 서체)가 각각 개별로는 검증됐지만, **전부 합쳐진 상태로 한 번에 본 적이 없습니다.**

---

## 1. 왜 필요한가

지금까지 20개 가까운 라운드를 개별 항목 단위로 고쳐왔습니다. 각 라운드는 자기 항목만 검증했고, 다른 항목과 같이 있을 때 어떻게 보이는지는 아무도 확인하지 않았습니다. 예를 들면:

- 117차 세리프 헤드라인이 108차 장식 배경(글리터/텍스처) 위에 올라갔을 때 대비가 충분한지
- 116차로 길어지거나 짧아진 헤드라인이 117차 세리프 서체·`word-break: keep-all`과 만났을 때 줄바꿈이 어색하지 않은지
- 110/113차 다이어그램의 라벨 서체가 117차 헤드라인 서체와 톤이 맞는지(다이어그램은 기존 고딕 유지 원칙이었으니 서체가 2종 섞이는 지점)
- 109차 로고/워드마크가 히어로에 있을 때 108차 장식 배경, 97차 그라디언트 오버레이와 겹치지 않는지

이런 조합 문제는 각 라운드의 개별 스모크 테스트로는 절대 안 잡힙니다. `review/quality-log.md`에 이미 있는 **기존 자체 QA 사이클 방식**(Claude/Replicate/DeepSeek 호출 0원, `/dev/detail-preview` 또는 `/iteration-fixtures` 같은 로컬 렌더 기반 반복 스코어링)을 그대로 재사용해서, 지금 상태를 처음부터 다시 채점하세요.

---

## 2. 할 것

1. **기존 방식을 찾아 재사용하세요** — `scripts/qa-visual-check.ts`, `scripts/capture-iteration.ts`, `scripts/capture-category-cycle.ts`와 `review/quality-log.md`의 채점 기준(항목별 점수 + 코멘트, 목표: 항목당 4.5 이상을 3회 연속)을 확인하고 **같은 프로세스로** 진행하세요. 새 채점 기준을 만들지 마세요 — 이미 있는 걸 재사용하는 게 이번 브리프의 핵심입니다.
2. **6개 카테고리 전부**(화장품/뷰티, 의류/패션, 식품, 전자제품, 반려동물, 생활용품)에 대해 픽스처 상품 데이터로 렌더 → 스크린샷 → 채점을 1사이클 진행하세요. 실제 API 호출(Claude/Replicate/DeepSeek) 없이 **기존 고정 픽스처/더미 데이터**로 렌더만 하세요.
3. 항목당 점수가 4.5 미만이거나, 조합 문제(1절에 나열한 것들)가 실제로 관찰되면 **구체적으로 어디서 어떻게 나쁜지**(섹션 이름, 스크린샷 좌표 설명) 적어주세요. "괜찮아 보인다" 같은 뭉뚱그린 평가 말고, 이전 quality-log.md 사이클처럼 항목별 점수+코멘트 표로 남기세요.
4. **점수가 낮은 항목이 있으면 그 자리에서 고치지 말고, 무엇이 문제인지만 정확히 보고하세요.** 수정은 이 결과를 보고 제가 다음 브리프로 지시하겠습니다(원인 진단과 수정 지시를 분리 — 지금까지의 작업 방식과 동일).

---

## 3. 하지 않는 것

- 상품 생성(Claude/Replicate/DeepSeek) 실행 금지 — 이 QA 사이클은 원래도 0원으로 설계된 방식입니다. 실제 호출이 필요하면 진행 전에 먼저 보고하세요.
- 발견된 문제를 이번 브리프 안에서 임의로 고치지 마세요. 진단만 하세요.
- 새로운 채점 기준/스크립트를 새로 만들지 마세요 — 기존 것을 재사용하세요(찾을 수 없으면 그 사실부터 보고하세요).

## 4. 검증 방법

- 6개 카테고리 × 기존 채점 방식 1사이클.
- 카테고리별 스크린샷을 `review/118cha-<카테고리>.png`로 저장.
- 점수표 + 조합 문제 목록을 `review/118cha-report.md`에 정리.
