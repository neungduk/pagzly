# 68차 — 인물/제품 합성 브랜드·라벨 보존도 개선

생성: 2026-09-02

## 배경

사용자가 후커블과 재비교하며 명시적으로 요청: "제품사진 누끼 따서 인물사진과
함께 잘 합성이 후커블처럼 됬으면 좋겠고" — 지금 수준으로는 부족하다는 뜻입니다.

64차/66차 자체 QA에서 이미 정확히 이 문제를 발견해뒀습니다 (`review/64cha-report.md`):

> 잘 된 부분: 원본 손·조명·배경 유지, 제품이 손에 자연스럽게 쥐어짐...
> 어색한 부분: **제품 라벨이 원본과 다른 디자인으로 재해석됨** (브랜드 정확도 이슈)

## 왜 이런 일이 생기는가

`lib/lifestyle-product-composite.ts`의 `compositeProductOnLifestylePhoto()`는
`google/nano-banana`에 자연어 지시문(`"Edit the lifestyle photo so the person
naturally holds..."`) + 이미지 2장(라이프스타일 원본, 제품 컷아웃)을 함께 주고
**장면 전체를 새로 생성**하게 합니다. 이런 지시-기반 이미지 편집 모델은 참조
이미지를 그대로 "붙여넣기"하는 게 아니라 "이해하고 다시 그리기" 때문에, 제품에
적힌 로고·라벨 텍스트·색상이 미묘하게 재해석될 수 있습니다.

반면 우리 기존 히어로 배경 파이프라인(`lib/photo-enhance.ts`, flux 경로)은
전혀 다른 전략을 씁니다: AI는 **빈 배경만** 생성하고, 실제 상품 컷아웃 픽셀은
`sharp`로 그 위에 그대로 **합성(paste)**합니다 — AI가 상품 자체를 그리지
않으므로 라벨/로고가 100% 원본 그대로 보존됩니다. 이게 바로 히어로 컷이
"PM급 단독 컷"으로 안정적인 이유입니다. 라이프스타일 합성은 지금 이 원칙을
안 따르고 있는 게 근본 원인입니다.

## 이번 라운드 접근 — 2단계로 나눠서 진행

**1단계(먼저 시도, 저비용)를 먼저 해보고, 결과가 여전히 부족하면 2단계로
넘어가는 순서로 진행해주세요. 2단계는 상당한 엔지니어링 투자가 필요하니
1단계 결과를 보고 판단하는 게 좋습니다.**

### 1단계 — 프롬프트 강화로 라벨 보존 유도 (먼저 시도)

`compositeProductOnLifestylePhoto()`의 nano-banana 프롬프트에 라벨/브랜드
보존을 명시적으로 강하게 지시하는 문구를 추가해주세요. 예:

```
"Do NOT redraw, redesign, or alter the product's packaging, label text, logo,
or brand colors in any way — preserve the exact appearance of the reference
product image pixel-for-pixel where visible. Only change the surrounding
hand/pose/scene."
```

프롬프트 안에서 제품 컷아웃 이미지를 "참조 이미지"로 더 명확히 지칭하는 표현
(`the exact product shown in the second reference image`)도 시도해볼 가치가
있습니다. `image_input` 배열 순서를 바꿔보거나(제품 이미지를 먼저 배치), 더
고해상도 컷아웃을 넘기는 것도 시도해보세요.

**검증**: 같은 상품으로 최소 2~3회 실제 합성을 돌려서, 라벨 텍스트/로고 부분을
확대 비교한 전후(before/after) 스크린샷을 남겨주세요. "이전보다 나아졌다"가
아니라 "라벨 텍스트가 원본과 일치하는가"를 구체적으로 육안 비교해주세요.

### 2단계 — 실제 컷아웃 재합성 (1단계로 부족할 때만, 사용자 확인 후 착수)

1단계로도 라벨이 계속 재해석되면, 히어로 파이프라인과 같은 원칙을 적용하는
더 근본적인 방법을 검토합니다:

1. nano-banana에게는 "사람이 제품 모양의 무언가를 들고 있는 장면"만 생성하게
   하고 (제품 라벨을 정확히 그리라고 요구하지 않음),
2. Claude Vision으로 생성된 이미지에서 제품이 놓인 위치/회전/크기(대략적인
   바운딩 박스 + 각도)를 감지하고,
3. 그 영역에 **실제 상품 컷아웃**을 원근 변형(perspective warp)해서
   `sharp`로 다시 합성하고,
4. 기존 `compositeDecorOnBackdrop` 근처에 있는 접지 그림자/그레인 보정과
   비슷한 방식으로 경계를 자연스럽게 블렌딩합니다.

**이 2단계는 손가락에 의한 가림, 원근/각도 오차, 조명 불일치 등 자체적인
새로운 실패 모드가 있는 상당히 어려운 문제입니다.** 무리해서 한 번에
완성하려 하지 마시고, 1단계 결과가 명확히 부족하다고 판단될 때만, 그리고
가능하면 저에게 먼저 "1단계로는 한계가 있다"는 결과를 보고한 뒤 착수해주세요.

## 하지 않는 것

- AI로 가짜 인물을 새로 생성하는 것 (64차와 동일 원칙 — 여전히 범위 밖)
- 1단계를 건너뛰고 바로 2단계로 가는 것
- 실패 시 원본 폴백 로직(`composited: false`) 변경 — 그대로 유지

## 검증 체크리스트

- [ ] `npx tsc --noEmit` 에러 0건 (관련)
- [ ] 1단계: 프롬프트 개선 후 동일 상품 2~3회 재합성, 라벨 확대 전후 비교 스크린샷
- [ ] 1단계 결과가 충분한지 스스로 솔직하게 판단해서 보고 (여전히 라벨이 틀리면 "부족함"이라고 명시)
- [ ] 2단계 착수 시(1단계 부족 확인된 경우만): 위 4단계 파이프라인 구현 + 스크린샷
- [ ] 비용 기록 (QA 계정 토큰은 기존 67차 방식대로 필요 시 알아서 충전)

## 완료 보고 형식

1단계로 충분한지에 대한 솔직한 결론.
