# 127차 — 라이프스타일 합성 실사진 유료 검증 (실제 폼 경로, 1회)

생성: 2026-09-07
전제: 126차까지 코드 레벨 배선(폼 입력 필드 → formSnapshot → draft → photo-pipeline → /api/lifestyle-composite → compositeProductOnLifestylePhoto)이 diff·tsc·스크린샷·로그로 교차 검증 완료됨. 이번 127차는 새 코드 작업이 아니라 **그 경로가 실제로 눈으로 보기에 올바른 합성을 만들어내는지** 확인하는 라이브 테스트입니다.

## 0. 승인 범위 — 정확히 이만큼만

- 유료 Replicate 호출 **1회**만 승인합니다. 추가 재시도가 필요하면 진행 전에 먼저 알려주세요(임의로 재시도해서 비용 늘리지 말 것).
- `TEST_MODE`를 끄고 진행해야 하는 지점(실제 합성 호출)에서만 끄고, 그 외 경로는 기존처럼 유지합니다.
- 이번 테스트는 **CLI 스크립트로 값 주입해서 함수만 호출하는 방식이 아니라**, 126차에서 스크린샷으로 확인한 실제 `/create/detail` 폼을 브라우저로 열어서 사람이 쓰는 것과 동일한 경로로 진행해주세요. (요청 바디를 손으로 조립해서 API를 직접 찌르는 것도 금지 — 폼 제출 → draft → 파이프라인 순서 그대로)

## 1. 테스트 절차

1. 로컬 dev 서버에서 `/create/detail` 폼을 엽니다.
2. 라이프스타일 사진(사람 손 또는 신체가 나오는 실제 사진)과 제품 사진을 업로드합니다. 사람 손이 뚜렷하게 보이는 사진을 골라주세요 (손 대비 크기 비교가 목적이므로).
3. **제품 높이(선택, cm)** 필드에 `9`를 입력합니다 (126차 스크린샷과 동일한 값 — 실제 제품 실측 높이와 맞는 값이면 더 좋습니다. 실측값이 있으면 그 값을 우선 사용해주세요).
4. 폼을 제출해 draft를 생성하고, 배경/보정 단계를 거쳐 실제로 라이프스타일 합성이 실행되는 지점까지 진행합니다.
5. 합성이 완료되면 결과 이미지를 저장합니다.

## 2. 확인할 것

- 합성된 이미지에서 제품 크기가 손(또는 신체 다른 부위) 대비 물리적으로 말이 되는지 육안으로 판단합니다. (예: 9cm 제품이 손바닥보다 훨씬 크거나 작게 보이면 실패)
- `requirePixelPaste: true` 게이트가 실패해서 합성을 스킵한 경우, 스킵도 정상 동작이니 그 자체를 실패로 보고하지 마세요. 다만 왜 스킵됐는지(로그) 그대로 첨부해주세요.
- 콘솔에 찍히는 `[125cha]`/`[126cha]` 계열 로그에 실제 `productHeightCm=9`가 API 요청까지 그대로 실려가는지 확인합니다.

## 3. 리포트에 원문 그대로 첨부할 것 (요약 금지)

1. 실제로 저장된 **합성 결과 이미지 파일** (성공이든 스킵이든, 스킵이면 스킵 직전 상태의 스크린샷).
2. 폼 제출부터 합성 완료(또는 스킵)까지 콘솔에 찍힌 로그 전체 — 특히 `productHeightCm`, `requirePixelPaste`, `shouldAttempt` 관련 라인.
3. 이번에 실제로 발생한 Replicate 호출 횟수와 대략적인 비용(가능하면 대시보드 캡처 또는 로그).
4. 합성 이미지에 대한 본인(Cursor)의 육안 판단 한 줄 — "손 대비 제품 크기가 자연스러움 / 여전히 과대·과소함" 중 하나로 명확히. 애매하게 쓰지 말고 어느 쪽인지 분명히 밝혀주세요.

## 하지 않는 것

- 추가 유료 호출 (실패 시 재시도 전 반드시 먼저 보고)
- CLI/스크립트로 값을 주입해 API를 직접 호출하는 방식
- mL→cm 환산이나 임의의 기본 높이값 사용
- 코드 수정 (이번 라운드는 순수 검증 전용 — 만약 검증 중 실제 버그를 발견하면 고치지 말고 리포트에만 남겨주세요. 다음 라운드에서 별도로 지시하겠습니다)
