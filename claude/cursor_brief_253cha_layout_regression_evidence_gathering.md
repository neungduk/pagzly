# 253차 — "글/사진 배치가 이상하다" 증거 수집 + 251차 회귀 여부 확인 (코드 수정 전, 조사만)

## 배경

사용자가 "글 배치나 사진도 정말 이상하게 배치가 되고 있다"고 보고했습니다(구체적 스크린샷
없이). 타이밍상 의심되는 지점: **251차(`illustration_banner`를 AI 일러스트에서 실사진
기반으로 전환)가 이미 실행 완료된 상태**(`review/251cha-report.md`, `lib/assign-section-images.ts`
diff +213줄)이고, 이 파일은 `illustration_banner`뿐 아니라 **모든 섹션의 사진 배정을
담당하는 공용 로직**입니다. Claude가 PC의 현재 코드를 직접 읽어 `illustration_banner`가
`image_text`와 동일한 중복방지 풀(`uniqueAmongImageText`)을 공유하도록 통합된 것까지는
확인했고, 겉보기엔 스펙대로 짜여 있습니다 — 하지만:

1. **실제 화면으로 시각 검증된 적이 없습니다** — 251차 자체 검증 스크립트는 "배너가
   hero/image_text와 인덱스 충돌하지 않는다"는 것만 프로그램적으로 확인했지, 페이지
   전체를 스크린샷으로 찍어 다른 섹션들까지 눈으로 본 적이 없습니다.
2. **기존에 이미 저장된 상품**(251차 이전에 생성돼 `illustrationUrl`은 있고 `imageIndex`는
   없는 레거시 데이터)을 지금 코드로 다시 열었을 때 다른 섹션들의 이미지가 재배정되며
   흔들리는지도 아직 아무도 확인하지 않았습니다.

**이번 라운드의 목적은 코드를 고치는 게 아니라, 어디가 어떻게 이상한지 구체적 증거
(스크린샷 + 어느 섹션인지)를 모으는 것입니다.** 증거 없이 코드부터 고치지 마세요 — 원인이
251차가 아닐 수도 있습니다.

## 조사 절차

### 1) 기존 상품을 "다시 열기" — 레거시 데이터 회귀 확인

로컬 개발 서버(`npm run dev` 등 기존 방식)를 켜고, **DB에 이미 저장된, 251차 이전에
생성된 상품**(가능하면 여러 카테고리에서 하나씩 — 화장품/뷰티는 247/248차 상품 재사용
가능)을 상품 편집/미리보기 화면에서 그냥 열어보세요(재생성 버튼 누르지 말 것 — 그냥
기존 데이터를 화면에 띄우는 것). 다음을 스크린샷으로 남기세요:

- 페이지 전체(풀스크롤 또는 Playwright fullPage — 249차부터 있는 텍스트 안전장치가
  아직 유효한지, 252차가 지적한 `position:sticky` 캡처 버그를 피하려면 새로 만든
  `scripts/lib/neutralize-sticky.ts`의 `neutralizeStickyForScreenshot()`를 캡처 직전에
  호출하세요 — 안 그러면 `cta_price`가 또 안 보여서 헷갈립니다).
- 특히 `image_text` 섹션들(quick_points·feature_callout·ingredient_highlight 등)과
  `illustration_banner` 섹션이 **서로 다른 사진을 쓰는지**, 혹시 **같은 사진이 중복되거나
  엉뚱한 사진(제품과 무관한 컷)이 배정됐는지** 확인.
- `illustrationUrl`이 남아있는 레거시 상품이라면 배너에 그 URL이 그대로 나오는지(§1
  하위호환 규칙 유지 여부), 혹시 실사진(`imageIndex`)으로 잘못 바뀌어버렸는지 확인.

### 2) 텍스트 배치 — 별도 축으로 확인

"글 배치도 이상하다"는 언급이 있었으니, 이미지와 별개로 다음도 같이 스크린샷에서
확인해주세요:
- 헤드라인/본문이 clamp 없이 카드를 뚫고 나오거나, 반대로 말줄임(ellipsis)이 과도하게
  걸려 원래 있어야 할 문장이 잘리는 곳.
- 249차가 `illustration_banner`에 추가한 2줄 clamp + 다크 패널 스크림이 실사진 전환
  이후에도 여전히 적용돼 있는지(251차 브리프 §4가 "그대로 유지"를 지시했었음 — 실제로
  지켜졌는지 코드가 아니라 렌더된 화면으로 재확인).

### 3) 신규 생성 1건 허용 여부는 사용자에게 별도 문의

기존 데이터만으로 재현이 안 되는 증상이면(즉 "새로 생성해야만 보이는 문제"로 보이면),
**임의로 생성하지 말고** 그 사실 자체를 보고서에 남기세요 — Claude가 사용자에게
정확한 건수를 확인받은 뒤 별도로 허가 여부를 전달하겠습니다.
