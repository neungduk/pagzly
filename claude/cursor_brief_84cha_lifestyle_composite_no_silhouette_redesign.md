# 84차 — 라이프스타일 합성 구조 변경: 실루엣 생성 단계 제거, 원본 사진에 직접 배치 감지 후 paste

생성: 2026-09-02

## 배경 — 왜 구조를 바꾸는가

81~83차를 거치며 계속 같은 계열의 문제가 반복됐습니다:

- 81차: nano-banana 실루엣 위에 진짜 컷아웃을 얹었더니 위치가 안 맞아 "붕 뜸"
- 82차: 중앙 정렬로 고쳤더니 실루엣 단계에서 AI가 그린 물체가 감지된 bbox 밖에 남아 "이중 객체"
- 83차: 그 잔상을 블러로 지우려 했더니, 손/셔츠 위에 각진 블러 박스가 덮이는 **더 눈에 띄는 시각적 결함**이 생김 (제가 스크린샷으로 직접 확인 — 82차보다 오히려 더 나빠 보임)

세 라운드 모두 원인이 같습니다: **nano-banana가 먼저 장면에 뭔가를 그려 넣고, 그 위에 진짜 컷아웃을 얹거나 지우려는 구조라서, AI가 그린 부분이 어떤 형태로든 남습니다.** 프롬프트를 아무리 다듬어도 지시 기반 이미지 모델은 결정적이지 않기 때문에(83차 진단에서도 확인 — 같은 라운드 안에서도 실루엣 생성 결과가 매번 다름), 이 구조 위에서는 계속 새로운 부작용이 나올 가능성이 높습니다.

그래서 이번엔 **AI가 장면에 물체를 미리 그려 넣는 단계 자체를 없앱니다.** 원본 라이프스타일 사진(사람이 아직 아무것도 안 든 상태)에 Vision으로 "여기에 상품을 놓으면 자연스럽게 들고 있는 것처럼 보이겠다"는 위치를 직접 찾아서, 그 자리에 진짜 컷아웃을 바로 붙입니다. 애초에 AI가 그리는 단계가 없으니 "잔상이 남는다"는 문제 자체가 원천적으로 발생할 수 없습니다.

## 새 파이프라인

`lib/lifestyle-product-composite.ts`의 `compositeProductOnLifestylePhoto()`를 아래 흐름으로 바꾸세요.

### 1단계 — (유지) 실제 상품 컷아웃

`removeProductBackground()` 그대로 사용.

### 2단계 — (신규) 원본 사진 + 상품 컷아웃을 함께 Vision에 보여주고 배치 감지

새 함수 `detectHandPlacementForProduct()`를 `lib/detect-held-object-placement.ts`에 추가하세요 (기존 `detectHeldObjectPlacement()`는 81~83차 경로가 없어지면 더 이상 안 쓰이므로, 이 파일 안에 새로 만들거나 기존 함수를 대체하는 형태로 정리해도 됩니다 — 어느 쪽이든 명확하게).

- 입력: **원본 라이프스타일 사진**(아직 아무것도 들지 않은 상태) + **상품 컷아웃 이미지**, 두 장 모두 base64로 Claude Vision에 전달 (지금 nano-banana 호출에서 `image_input: [lifestyleImageUrl, cutoutUrl]`처럼 두 장을 같이 주던 것과 같은 방식 — 상품의 실제 종횡비를 Vision이 참고해서 적절한 크기를 제안할 수 있게 하기 위함입니다).
- 프롬프트 취지: "이미지 1은 사람이 있는 라이프스타일 사진이고, 이미지 2는 실제로 판매할 상품입니다. 이미지 1의 사람 손 주변에 이미지 2의 상품을 자연스럽게 쥐고 있는 것처럼 보이게 하려면 상품을 어디에, 얼마 크기로, 몇 도 회전해서 놓아야 하는지 알려주세요."
- 출력 JSON: `{ xPct, yPct, wPct, hPct, rotationDeg, confidence: "high"|"low" }` — 기존 `HeldObjectPlacement`와 같은 모양을 재사용해도 됩니다.
- **중요한 차이**: 기존 `detectHeldObjectPlacement()`는 "이미 그려진 물체가 어디 있는지 찾기"였는데, 이건 "아직 없는데 어디에 놓으면 자연스러울지 제안하기"라 더 어려운 과제입니다. 손가락 사이 틈, 벌어진 손바닥, 손이 뭔가를 쥐려는 듯한 각도 등 "쥘 수 있을 법한 공간"이 실제로 있는지까지 판단하게 하고, 그런 공간이 안 보이면 반드시 `confidence: "low"`를 반환하도록 프롬프트에 명시하세요. 무리하게 아무 데나 좌표를 만들어내지 않는 게 중요합니다.
- 안전 범위 체크(`isHeldObjectPlacementReasonable` 재사용 가능)와 파싱 실패 시 안전 폴백 — 기존 패턴 그대로.

### 3단계 — (단순화) 원본 사진에 직접 paste

`pasteCutoutOnScene()`을 단순화하세요 — **더 이상 `maskSilhouetteObjectRegions()`로 뭔가를 지울 필요가 없습니다** (원본 사진은 AI가 손댄 적 없는 깨끗한 상태이므로). 감지된 위치에 `sharp.resize()` + `rotate()` + 중앙 정렬(82차 로직 재사용) + contact shadow만 적용해서 원본 위에 바로 합성하세요.

### 4단계 — (유지) 폴백

Vision이 `confidence: "low"`거나 배치를 못 찾으면 → 기존 64/68/82차 nano-banana 전체 재생성 폴백(이미 라벨 보존 + 브랜드 창작 방지 프롬프트 적용된 상태, 그대로 사용) → 그것도 실패하면 원본 그대로.

### 정리할 것 (dead code)

`SILHOUETTE_PROMPT`/`LIFESTYLE_SILHOUETTE_PROMPT`, `generateLifestyleSilhouetteScene()`, `maskSilhouetteObjectRegions()`는 이번 구조에서 더 이상 안 쓰입니다. 완전히 지우거나, 지우기 애매하면 파일 상단에 "83차까지 쓰이던 구식 경로, 84차부터 미사용"이라고 주석으로 명확히 표시해주세요 — 다음에 누가 봐도 헷갈리지 않게.

## 기대 효과 (참고용, 검증 대상)

- nano-banana 호출이 성공 경로에서 1회 줄어듭니다(실루엣 생성 단계 제거) — pixel-paste 성공 시 비용이 기존보다 낮아질 것으로 예상됩니다. 실제로 얼마나 줄었는지 QA에서 비용 비교로 남겨주세요.
- 구조적으로 "AI가 그린 잔상" 계열 버그(81~83차 반복) 자체가 발생할 수 없습니다.

## 새로 생길 수 있는 리스크 (미리 알고 가는 것 — QA에서 반드시 확인)

- 원본 사진의 손이 애초에 "뭔가를 쥐는" 자세가 아니라 다른 제스처(예: 손등 만지기, 팔짱 등)라면, 아무리 Vision이 위치를 잘 찾아도 "그냥 물체가 손 옆에 붙어있는" 부자연스러운 결과가 나올 수 있습니다. 이건 이전 구조에서 nano-banana가 손 포즈 자체를 다시 그려주던 것과 다른 부분이라, 완전히 새로운 실패 모드입니다. 감추지 말고 QA에서 있는 그대로 스크린샷 남겨주세요.
- Vision이 "쥘 공간이 없다"고 정확히 판단하지 못하고 무리하게 좌표를 낼 가능성 — `confidence: "low"` 기준을 보수적으로 잡아주세요.

## 검증 방법

- 82/83차에서 쓴 것과 같은 라벨 있는 실제 상품 2건(세럼/튜브)으로 재QA하고, 전체 비교 스크린샷을 남기세요.
- 라벨 확대 비교도 다시 시도하되, 이번에도 Vision 텍스트 감지가 라벨 영역을 못 찾으면 억지로 판단하지 말고 "여전히 불확실"이라고 솔직히 남기세요.
- 이중 객체/블러 박스 같은 이전 라운드의 결함이 구조적으로 사라졌는지 확인 (재발하면 안 되는 게 정상이므로, 재발 시 원인을 다시 짚어주세요).
- 손 제스처가 부자연스러워지는 새 실패 모드가 실제로 관찰되는지 최소 1건은 의도적으로 확인(제스처가 명확히 "쥐는 자세"가 아닌 라이프스타일 사진으로 한 번 테스트).
- 폴백 발동 빈도, 비용(기존 대비 절감분 포함), `npx tsc --noEmit` 에러 0건.

## 완료 보고 형식

기존과 동일 — 변경 파일, `tsc` 결과, 라벨 비교 스크린샷, 새 구조에서의 자연스러움/부자연스러움 스크린샷(정상 케이스 + 의도적으로 확인한 실패 모드 1건 이상), 비용 비교(구조 변경 전후), 폴백 발동 여부, **이번에도 솔직한 결론** — 이전 라운드들의 문제가 실제로 사라졌는지, 그리고 이번 구조에서 새로 드러난 한계는 무엇인지.
