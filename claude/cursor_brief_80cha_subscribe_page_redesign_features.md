# 80차 — 구독 페이지(`/billing/subscribe`) 리뉴얼 + 플랜별 기능 안내

생성: 2026-09-02
전제: 79차(결제 페이지 공통 톤 개선 — 스탯 카드, 추천 배지, 카드 호버)가 먼저 적용된 상태에서 진행. 79차가 아직이면 이번 라운드에 흡수해서 같이 반영해도 됩니다. 이번 라운드는 `/billing/subscribe`에만 해당하고 `/billing/packs`는 이번 범위 밖입니다(토큰 팩은 "플랜"이 아니라서 기능 체크리스트 개념이 안 맞음).

## 배경

사용자가 후커블 요금제 페이지 스크린샷을 보여주며 두 가지를 요청:
1. 화면을 저 스크린샷처럼 깔끔하게.
2. **플랜별로 실제 쓸 수 있는 기능을 나눠서 보여주자.**

두 가지를 사용자에게 직접 확인했습니다:

- **연간 결제 토글**: 이번엔 **UI만** 만듭니다. 실제 연간 결제(가격/청구 로직)는 이번 라운드에 안 함. 토글에서 "연간 결제"를 누르면 비활성 상태로 두고 "준비 중" 안내만 보여주세요.
- **플랜별 기능 차이**: 이번엔 **마케팅 문구(화면 표시)만** 합니다. 실제로 특정 기능을 코드로 막는 작업은 안 함.

## ⚠️ 중요 — 없는 차별화를 지어내지 않는다

지금 Pagzly는 **모든 유료 플랜에서 기능이 완전히 동일**합니다 — 차이는 오직 "매월 지급 토큰 수"와 "월 요금"뿐입니다(캔버스 에디터, GIF 생성, 섹션 채팅, 소셜 미니 생성 등 전부 스타터 사용자도 이미 다 씁니다). 후커블 스크린샷의 개별 문구("피그마에서 편집하기", "고객 댓글 분석 AI" 등)는 Pagzly에 없는 기능이니 그대로 베끼면 안 됩니다.

그래서 체크리스트는 **거짓 차별화 없이** 아래 원칙으로 구성합니다:
- 세 카드 모두 Pagzly의 실제 핵심 기능 목록을 보여줍니다(아래 §A 목록, 전부 이미 라이브 기능).
- 상위 플랜 카드는 "스타터의 모든 기능 포함" 한 줄로 하위 플랜 전체를 요약하고, 그 아래 **실제로 다른 것 — 월 지급 토큰 수**를 강조합니다.
- 코드로 확인되지 않는 기능 제한/우선순위(예: "우선 지원")는 이번 리스트에 넣지 않습니다. 지원 정책 같은 운영상의 차별화는 실제로 그렇게 운영하기로 확정되면 별도 라운드에서 문구를 추가합니다.

## 작업 A — 플랜별 기능 체크리스트 (신규)

`lib/cost/saas-pricing-config.ts`의 `PricingTier` 타입에 표시용 필드를 추가하세요:

```ts
export type PricingTier = {
  id: PricingTierId;
  label: string;
  monthlyPriceKrw: number;
  monthlyTokens: number;
  tagline: string;        // 카드 제목 아래 한 줄 설명
  inheritsFrom?: PricingTierId; // "OO의 모든 기능 포함" 표시용 (starter는 없음)
};
```

각 플랜의 `tagline`은 아래처럼(자유롭게 다듬어도 되지만 없는 기능을 넣지 마세요):

- 스타터: "이제 막 상세페이지 제작을 시작하는 셀러에게"
- 그로스: "여러 상품을 함께 운영하는 셀러에게"
- 프로: "상세페이지 제작을 본격적으로 늘리는 셀러에게"

공통 기능 목록(상수로 별도 정의, 모든 플랜 카드에서 공유):

```ts
export const PAGZLY_CORE_FEATURES = [
  "AI 상세페이지 자동 생성 (사진 보정 + 카피 + 배경 합성)",
  "레퍼런스 이미지로 초안 자동입력",
  "섹션별 AI 채팅 수정",
  "자유 캔버스 에디터 (텍스트 · 이미지 · 도형 · 표)",
  "GIF 자동 생성",
  "인스타그램 피드 · 블로그 미니 생성",
  "무제한 다운로드",
] as const;
```

카드에 표시하는 방식:
- **스타터 카드**: `PAGZLY_CORE_FEATURES` 전체를 체크마크 목록으로, 마지막에 "매월 {monthlyTokens.toLocaleString()}토큰 제공".
- **그로스/프로 카드**: 체크마크 1번째 줄에 "스타터의 모든 기능 포함"(그로스) / "그로스의 모든 기능 포함"(프로) — `tier.inheritsFrom`으로 이전 티어 라벨 참조, 그 아래 "매월 {monthlyTokens}토큰 제공"만 강조해서 보여줍니다. `PAGZLY_CORE_FEATURES`를 다시 나열하지 않습니다(반복 지양, 위계상 "이미 포함"이라는 게 핵심).

체크마크 아이콘 색상은 새 색상(초록 등) 도입하지 말고 `text-ink` 또는 `text-registration-red` 중 하나로 통일하세요(79차와 동일한 "기존 토큰만 사용" 원칙).

## 작업 B — 페이지 레이아웃 리뉴얼

`app/billing/subscribe/page.tsx` 대상. 참고 이미지를 저장소에 넣어뒀습니다: **`claude/reference/hookable-reference-pricing-page.png`** — 열어서 레이아웃(타이틀 위치, 토글, 카드 3장 배치, 배지, 체크리스트 위치)을 보고 작업하세요. 문구는 그대로 베끼지 말고 아래 내용대로:

- 타이틀 "구독 플랜 선택"은 유지하거나 "요금제 플랜"으로 바꿔도 무방 — 서브카피는 Pagzly 톤에 맞게 새로 쓰세요(후커블 원문 그대로 베끼지 않기).
- 타이틀 아래에 "월별 결제 / 연간 결제" 토글 UI 추가. 연간 결제는 비활성(클릭 시 "연간 결제는 준비 중입니다" 안내만, 실제 전환 없음). 토글 디자인은 기존 토큰(ink/registration-red/paper/line)으로.
- 카드 3장: 79차에서 이미 추천 배지 작업을 지시했다면 배지 문구를 **"인기"**로 통일해주세요(79차 브리프에는 "추천"이라고 썼는데, 이번 스크린샷 기준으로 "인기"가 더 자연스럽습니다 — 그로스 카드).
- 각 카드 순서: 플랜명 → 가격(`{price} 원 / 월`, 기존 표기 유지) → `tagline` → CTA 버튼("지금 시작하기" 또는 기존 "구독하기" 문구 유지, 자유 판단) → 구분선 → 체크마크 기능 목록(작업 A).
- 반응형: 모바일에서 카드 3장이 1열로 쌓일 때도 순서/여백 깨지지 않게.

## 하지 않는 것

- 연간 결제 실제 가격·청구 로직·토스페이먼츠 연동 변경 없음 — 토글은 시각 요소일 뿐.
- 특정 기능을 실제로 플랜별로 막는 접근 제어 코드 추가 없음.
- Pagzly에 없는 기능(피그마 편집, 댓글 분석 AI 등)을 카드에 넣지 않음.
- `/billing/packs` 페이지 변경 없음(79차 범위).
- 가격·토큰 수치(`PRICING_TIERS`) 자체는 변경하지 않음 — 표시 방식과 부가 필드(`tagline`, `inheritsFrom`)만 추가.

## 검증 방법

- 데스크톱/모바일 스크린샷으로 3카드 레이아웃, 토글, 체크리스트 확인.
- 그로스 카드 "인기" 배지 + 강조 테두리 확인.
- 연간 결제 토글 클릭 시 "준비 중" 안내만 뜨고 실제 결제 흐름/가격에 영향 없는지 확인.
- 스타터 카드에는 전체 기능 목록, 그로스/프로 카드에는 "이전 플랜 포함" 문구 + 토큰 수만 표시되는지 확인.
- 기존 구독 결제 플로우(카드 등록, success/fail 리다이렉트) 회귀 없는지 확인.
- `npx tsc --noEmit` 에러 0건.
