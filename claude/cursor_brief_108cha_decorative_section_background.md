## 1. 현재 상태

레퍼런스(후커블 glowiest 페이지의 골드 글리터 풀블리드 섹션, 마유에스테의 물 스플래시 배경)와 우리 결과물의 시각적 격차 중 마지막으로 큰 항목이 **장식적 배경**입니다.

`lib/design-tokens.ts:64-66` 주석에 **"그라데이션은 hero 전용"** 이라고 명시돼 있고, 본문 섹션에 허용된 것은:
- A/B/C/D/E 5종 옅은 그라디언트 순환
- 카테고리별 SVG 점·파형 패턴, **불투명도 4~6%** (`:133-139`)

뿐입니다. 사진형·질감형 배경은 **설계상 배제**돼 있어, 페이지 전체가 흰색~아주 옅은 톤으로만 흘러갑니다. 레퍼런스가 중간중간 강한 풀블리드 배경으로 리듬을 만드는 것과 대비됩니다.

## 2. 설계 원칙 (이걸 어기면 안 됩니다)

### 2-1. 새 이미지 생성 비용을 추가하지 마세요 ★가장 중요

사용자가 비용에 민감한 상태입니다. **장식 배경을 위해 Replicate 호출을 새로 추가하지 마세요.** 대신 **이미 생성되는 자산을 재사용**하세요.

재사용 가능한 후보:
- `illustration-*.png` — `illustration_banner`용으로 이미 생성됨
- 섹션 배경 파생본 `-texture`, `-ingredient` — 이미 생성됨
- 배경 후보 중 **사용자가 선택하지 않은 나머지 후보** — `BACKDROP_CANDIDATES` 개수만큼 이미 생성해 놓고 1장만 쓰고 버리는 중입니다. 이걸 블러·오버레이 처리해 장식 배경으로 돌리면 **추가 비용 0**입니다. 이 경로를 우선 검토하세요.

선택되지 않은 후보 URL이 지금 저장되지 않고 버려진다면, 저장만 추가하면 됩니다(`generateBackdrop`의 `candidateUrls`).

### 2-2. 남발 금지 — 페이지당 최대 2개

장식 배경이 여러 번 나오면 오히려 싸구려로 보입니다. **한 페이지에 최대 2개 섹션**까지만 적용하고, 서로 인접하지 않도록 최소 간격을 두세요.

### 2-3. 적용 슬롯 화이트리스트

아무 섹션에나 열지 마세요. 강조 목적이 명확한 슬롯만:
- `illustration_banner` (이미 배경 이미지를 지원하므로 가장 안전)
- `highlight_box` 중 `boldBlock === true` 인 것
- `feature_callout`
- `cta_price`

`spec_table`, `caution`, `faq`, `ai_disclosure`, `shipping` 등 **정보 전달 섹션에는 절대 적용하지 마세요.** 가독성이 최우선인 곳입니다.

### 2-4. 히어로에는 붙이지 마세요

97차에서 확인했듯 히어로에 장식 레이어를 얹으면 가짜 글자·라벨 왜곡 위험이 가장 큽니다. 히어로는 지금 구조를 유지하세요.

### 2-5. 텍스트 가독성 게이트

배경 위에 텍스트를 올릴 때 반드시 오버레이로 대비를 확보하세요. `DetailSectionRenderer.tsx:2146-2156`의 `illustration_banner`가 이미 **상·하단을 짙게 덮는 그라디언트**로 이 문제를 처리하고 있습니다(주석에도 "모델이 가끔 넣는 가짜 UI/깨진 글자를 가린다"라고 적혀 있음). **같은 패턴을 재사용**하세요. 새로 만들지 마세요.

가능하면 배경 이미지의 평균 휘도를 sharp로 계산해, 밝으면 어두운 오버레이 / 어두우면 밝은 오버레이를 선택하는 정도의 간단한 분기를 넣으세요.

### 2-6. 생성형 텍스처에는 `NO_TEXT_PROMPT` 가드 유지

재사용이 아니라 부득이 새로 만드는 경로가 생긴다면, `lib/concept-effects.ts:16-17`의 `NO_TEXT_PROMPT`("no product, no packaging, no text, no letters, no glyphs, …")를 반드시 적용하세요. 97차 라벨 환각과 같은 계열의 사고를 막는 장치입니다.

## 3. 작업

1. **미선택 배경 후보 저장** — `generateBackdrop`의 `candidateUrls` 중 선택되지 않은 것을 상품 데이터에 보관하세요(새 컬럼 또는 기존 JSON 필드 확장). 마이그레이션이 필요하면 `add column if not exists` 방식으로, 컬럼 추가만 하세요.
2. **장식 배경 배정 로직** — 2-2/2-3 규칙에 따라 페이지당 최대 2개 섹션을 고르고, 재사용 자산을 배정하는 함수를 추가하세요. 자산이 없으면 **아무것도 하지 않고 기존 동작 유지**(하위 호환).
3. **렌더링** — 선택된 섹션에 배경 이미지 + 2-5의 오버레이를 적용하세요. `illustration_banner`의 기존 구현을 최대한 재사용하고, 새 CSS 체계를 만들지 마세요.
4. **`design-tokens.ts` 주석 갱신** — "그라데이션은 hero 전용"이라는 주석이 더 이상 사실이 아니게 되므로, 새 규칙(화이트리스트 슬롯 한정, 최대 2개)을 주석에 반영하세요. 다음 사람이 헷갈리지 않도록.
5. **로그** — `[decor-bg] applied=<섹션 인덱스들> source=<reused-candidate|illustration|none>` 형태로 남기세요.
