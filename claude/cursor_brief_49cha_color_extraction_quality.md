# 49차 — 배경/포인트 색상 추출 품질 개선 (사용자 직접 승인)

생성: 2026-08-31

## 배경 (사용자 원문)

> "전반적으로 사진 퀄리티랑 뒤에 색상이 너무 좋지가 않은데 색상을 정말 잘 어울리고 다채롭게
> 배경색상을 구성 할 수 없을까 ?"

방금 화장품 카테고리로 돌린 Pixabay 테스트 생성 결과(스크린샷)를 사용자가 직접 봤습니다.
히어로는 탁한 갈색, 중간 섹션은 탁한 자주색/올리브색 계열로 색이 칙칙하고, 페이지 전체가
비슷한 톤 하나로만 반복돼서 "다채롭다"는 느낌이 없습니다.

**중요**: 지금까지 여러 브리프(29차·45차)에서 "디자인 토큰의 3색 규칙(accent/baseNeutral/
deepAccent)과 히어로-only 장식 규칙은 검증된 시스템 제약이니 승인 없이 바꾸지 말라"고
반복해서 못박아뒀습니다. **이번 건은 사용자가 이 메시지에서 직접 색상 구성 방식을 바꿔달라고
요청한 것이므로, 색상 관련해서는 이 브리프가 그 승인입니다.** 다만 "3개 필드 구조 자체"
(accent/accentSoft/accentText/baseNeutral/deepAccent)는 그대로 유지하고, **그 값을 뽑아내는
방식**만 개선하는 것으로 범위를 좁힙니다 — 슬롯 구조나 새로운 색상 필드(예: 네이비 밴드)를
추가하는 게 아닙니다.

## 원인 분석 (코드 확인함)

`lib/color-extract.ts`의 `extractProductTheme()`이 색상 추출을 담당합니다. 두 가지 구조적
문제를 찾았습니다.

### 원인 1 — 사진 3장 중 "가장 센 것 하나만" 채택 (프롭 색 오염에 취약)

`extractProductTheme()` 246~256행:

```ts
for (const sample of samples) {
  if (!sample) continue;
  if (sample.hue && sample.hue.weight > bestWeight) {
    bestWeight = sample.hue.weight;
    bestHue = sample.hue.h;
  }
  ...
}
```

사진 3장을 각각 분석한 뒤, **그중 채도 비중이 가장 강했던 사진 딱 한 장의 색상**을 페이지
전체의 기준색으로 씁니다. 방금 테스트에 쓴 Pixabay 사진들처럼 손·나뭇잎·나무 테이블 같은
소품이 섞인 스톡 사진에서는, 상품 자체가 아니라 **어쩌다 채도가 세게 잡힌 소품 색(피부톤,
식물 초록, 나무 갈색 등)이 전체 페이지 색을 결정**해버립니다. 상품 사진 3장에 걸쳐
꾸준히 나타나는 색이 아니라 단 한 장에서 우연히 세게 나온 색이 뽑히는 구조라 이런 오염에
취약합니다.

### 원인 2 — 모든 색상(hue)에 똑같은 채도/명도 공식을 적용 (특정 색상대에서 필연적으로 탁해짐)

267~269행:

```ts
const [ar, ag, ab] = hslToRgb(bestHue, 0.62, 0.32); // accent
const [sr, sg, sb] = hslToRgb(bestHue, 0.55, 0.96); // accentSoft
const [tr, tg, tb] = hslToRgb(bestHue, 0.55, 0.26); // accentText
```

뽑힌 hue가 몇 도든 상관없이 채도(S)·명도(L)를 고정값으로 씁니다. 그런데 색은 hue마다
"예쁘게 보이는 채도/명도 구간"이 다릅니다 — 특히 **주황~노랑~황갈색 대역(hue 30~90도
근처)은 S=0.62, L=0.32 조합이면 거의 항상 탁한 흙색/카키색으로 보입니다** (파랑·보라·
빨강 계열은 같은 공식으로도 상대적으로 봐줄 만하게 나오는데, 이 구간만 유독 안 예쁘게
나오는 구조적 이유입니다). 이번 테스트에서 뽑힌 색이 정확히 이 문제 구간에 걸린 걸로
보입니다.

## 이번 라운드 수정 사항

### A. 사진 여러 장에 걸쳐 "꾸준히 나오는 색"을 우선하도록 집계 방식 변경

`extractProductTheme()`의 hue 선택 로직을 "한 장의 최댓값"이 아니라 **여러 장에 걸친 누적
가중치**로 바꾸세요:

1. 각 사진에서 나온 hue 버킷(`sampleImage()`가 이미 15도 단위로 버킷팅하고 있음)을 사진
   경계 없이 하나로 합산하세요 — 지금은 `sampleImage()` 내부에서만 버킷별로 합산하고,
   `extractProductTheme()`은 사진별 "1등 버킷"끼리만 비교합니다. `sampleImage()`가 버킷
   전체(`Map<number, {weight, hueWeightedSum}>`)를 반환하도록 바꾸고, `extractProductTheme()`
   에서 3장의 버킷 맵을 합산한 뒤 최종 1등을 뽑으세요.
2. 이렇게 하면 상품 고유색처럼 여러 장에 걸쳐 반복 등장하는 색이, 한 장에서만 우연히 세게
   나온 소품 색보다 유리해집니다.
3. 사진이 1장뿐이거나 색상 정보가 거의 없으면 지금처럼 폴백(카테고리 기본 테마)하는 동작은
   그대로 유지하세요.

### B. hue별 맞춤 채도/명도 커브 — "탁한 색 방지 + 다채로움" 둘 다 해결

고정 공식(`hslToRgb(bestHue, 0.62, 0.32)`) 대신, **hue 구간별로 미리 튜닝된 채도/명도 값을
쓰는 룩업 함수**를 만드세요. `lib/color-extract.ts`에 새 함수를 추가:

```ts
// hue(0~360)를 받아 그 색상대에서 "예쁘게" 보이는 채도/명도 조합을 반환한다.
// 고정 공식 하나로는 주황~황갈색 대역이 항상 탁하게 나오는 문제를 막기 위함.
// 색상환을 8구간으로 나눠 각 구간마다 accent/accentSoft/accentText용 S·L을 따로 튜닝.
function getPaletteCurve(hue: number): {
  accent: { s: number; l: number };
  accentSoft: { s: number; l: number };
  accentText: { s: number; l: number };
} {
  // 예시 방향 — 실제 값은 아래 기준으로 렌더링해보면서 눈으로 튜닝할 것:
  // - 빨강(345~15): 지금 공식 유지 (이미 괜찮음)
  // - 주황/황갈색(15~50): 채도를 낮추고(S 0.5 이하) 명도를 살짝 올려서(L 0.4~0.45)
  //   "흙색"이 아니라 "따뜻한 테라코타/카멜"처럼 보이게
  // - 노랑(50~70): S를 크게 낮추고(0.4~0.5) L을 올려서(0.45~0.5) 겨자색 대신 부드러운 앰버
  // - 연두/초록(70~150): S 0.45~0.55, L 0.30~0.35 — 너무 쨍한 형광 초록 방지
  // - 청록/파랑(150~250): 지금 공식과 비슷하게 유지 (이미 무난함)
  // - 보라/자주(250~345): S 0.5~0.6, L 0.30~0.35
  // 8구간으로 나누되, 각 구간 경계에서 값이 급격히 튀지 않도록 인접 구간과
  // 자연스럽게 이어지는지 실제 렌더링으로 확인할 것.
}
```

`extractProductTheme()`에서 이 함수로 얻은 S/L 값을 `hslToRgb(bestHue, curve.accent.s,
curve.accent.l)` 식으로 적용하세요. **"다채롭게"는 이 커브 자체를 hue마다 다르게 튜닝하는
것으로 달성됩니다** — 상품마다 실제로 다른 hue가 뽑히니, 커브가 hue별로 잘 튜닝돼 있으면
상품마다 자연스럽게 다른(그리고 각각 예쁜) 배경색 조합이 나옵니다. 지금처럼 하나의 공식을
전체 hue에 강제 적용하는 게 아니라요.

### C. 실제로 여러 색상대로 테스트해서 눈으로 확인

B를 구현한 뒤, 최소 4~5가지 다른 hue 대역의 상품 사진으로 로컬에서 실제 생성을 돌려
비교하세요 (예: 화장품/뷰티 카테고리 유지한 채로 사진만 바꿔서 — 붉은 계열 립스틱류,
초록 계열 클렌저, 파란 계열 패키지, 방금 문제였던 갈색/베이지 계열 스킨케어). 각각
스크린샷을 찍어서 `review/qa-screenshots/color-curve-{hue명}.png`로 저장하고, 탁하게
나오는 대역이 남아있는지 육안으로 재확인하세요. 하나라도 여전히 탁하면 그 구간의 커브
값을 다시 조정하세요 — 이건 수학 공식보다 실제로 렌더링해서 눈으로 판단해야 하는 작업입니다.

## 하지 않는 것 (이번 라운드 범위 밖)

- `CategoryTheme`/`ExtractedTheme` 타입에 새 필드(예: 2차 accent, 그라데이션 전용 색)를
  추가하는 것 — 3개 필드 구조는 유지합니다.
- `design-tokens.ts`의 "네이비/신규 색 금지" 같은 다른 하드코딩 규칙 변경 — 이번엔
  `color-extract.ts`의 추출 공식만 손댑니다.
- 이미지 자체의 배경(스튜디오 백드롭) 생성 프롬프트 로직 변경 — 이건 별도 파이프라인
  (`lib/photo-enhance.ts`)이라 이번 범위 밖입니다. 색상 톤 추출/적용 로직만 다룹니다.
- 카테고리 고정 테마(`lib/category-theme.ts`)는 손대지 않습니다 — 상품 사진에서 색을 못
  뽑았을 때의 폴백 역할 그대로 유지.
