# 화장품 카테고리 테스트 생성 — Pixabay 목업 이미지로 실제 파이프라인 품질 확인

생성: 2026-08-31

## 목적

48차(우와 퀄리티 업그레이드) 작업을 계속하기 전에, 지금 파이프라인이 실제로 어떤 품질의
결과물을 내는지 화장품 카테고리로 직접 한 번 돌려서 눈으로 확인합니다. 실제 판매 상품이
아니라 **순수 QA 테스트**입니다. 로컬 개발 서버(`localhost:3000`)에서 진행하세요 —
`review/qa-report.md`를 만들 때 쓴 것과 동일한 환경입니다. 프로덕션 DB/Storage에 테스트
데이터를 남기지 마세요.

## 1. 가라(더미) 상품 정보 준비

실제 존재하는 브랜드명·제품명은 쓰지 마세요 (상표권 문제). 완전히 지어낸 가상 정보로
채우세요. 예시(그대로 써도 되고, 비슷한 수준으로 바꿔도 됩니다):

- 상품명: "글로우밤 수분 크림" (가상 브랜드)
- 카테고리: 화장품/뷰티
- 핵심 특징: "수분감 있는 텍스처, 산뜻한 마무리, 민감성 피부 사용 가능" 등 흔한 스킨케어
  문구 수준으로 자유롭게
- 가격: 임의 (예: 25,000원)
- 나머지 필드(브랜드명, 타겟 고객 등)도 그럴듯한 가라 값으로 채우세요

## 2. Pixabay에서 비슷한 상품 이미지 최소 7장 확보

- Pixabay(https://pixabay.com/)에서 "skincare cream", "cosmetics jar", "beauty product"
  같은 키워드로 검색해서, **같은 상품군으로 보이도록 일관성 있게** 최소 7장을 받으세요
  (크림 통, 클로즈업, 손에 바르는 컷, 패키지 등 다양한 앵글이 섞여 있으면 좋습니다 — 실제
  셀러가 여러 장 찍어 올리는 것과 비슷하게).
- Pixabay 라이선스는 출처 표시 없이 상업적 사용도 가능하지만, **이건 내부 QA 테스트 이미지일
  뿐 실제 판매·마케팅에 쓰면 안 됩니다.** 테스트 끝나면 로컬에만 남기고 프로덕션에 올리지
  마세요.
- Pixabay API(무료 API 키 발급 가능) 또는 웹에서 직접 다운로드, 편한 방법으로 진행하세요.

## 3. 실제 유저처럼 파이프라인 전체 실행

`localhost:3000`에서 `/create` → `/create/detail`로 들어가서, 실제 사용자가 쓰는 것과 똑같이:

1. 화장품/뷰티 카테고리 선택
2. 위에서 준비한 가라 상품 정보 입력
3. Pixabay 이미지 7장 이상 업로드
4. draft 생성 → 결과 확인 → 최종(final) 승인까지 끝까지 진행

중간에 새 코드를 짜지 마세요 — 지금 있는 파이프라인을 그대로 실행해서 결과만 보는 게
목적입니다. (돈이 드는 실제 API 호출입니다 — Claude Vision·DeepSeek·Replicate·Bria가 정상
과금되는 실제 경로이니, 이번 1회 실행 비용은 QA 목적상 감수하는 겁니다.)

## 4. 결과 캡처 및 보고

- `review/qa-report.md`와 같은 방식으로 최종 결과 화면을 풀페이지 스크린샷으로 저장하세요
  (`review/qa-screenshots/cosmetics-pixabay-test-full.png` 같은 이름으로).
- 보고에 포함할 것:
  - 입력한 가라 상품 정보 전체
  - 사용한 Pixabay 이미지 URL 7개 이상 목록
  - 최종 스크린샷
  - **직접 보고 느낀 품질 관찰** — 사진 합성이 자연스러운지(이중노출·유령 사각형 없는지),
    카피 톤이 괜찮은지, 섹션 배치가 답답하거나 어색한 곳은 없는지, 48차에서 다루고 있는
    "우와" 포인트 기준으로 부족해 보이는 지점이 있으면 구체적으로 적어주세요
