# 239차 — 솔직한 레벨 체크: "진짜 외주 업체급"인가?

생성: 2026-09-23 · 유료 API 0건 · 코드 변경 0(이번 문서는 기존 148~238차 벤치마크 증거 종합 + 정직한 판정)

## 질문

사용자 지시: "진짜 상세페이지 외주 업체가 만든급으로 나와야하는데 그급은 아직 힘들지? 우리
레벨 체크 해보자."

결론부터: **정보/레이아웃/카피 축은 후커블류 AI 템플릿 서비스급엔 근접했다고 볼 근거가 충분히
쌓였습니다. 하지만 "사람이 직접 만드는 외주 상세페이지"급의 사진 합성 폴리시는 아직 아닙니다
— 이게 정확히 우리가 8라운드 넘게(211~238차) 반복해서 스스로 확인해온 가장 약한 지점입니다.**
축별로 정직하게 나눠서 보겠습니다.

## 축 1: 정보구조·레이아웃·카피 — "후커블급"엔 근접 (근거 있음)

148차부터 238차까지, 후커블(hookable.ai)·Behance 디자이너 포트폴리오를 총 10회 넘게 재크롤링해
4축(레이아웃/타이포·여백/이미지 합성/정보 위계) + 3분류(버그/취향/입력부족) 규율로 대조해온
기록이 있습니다. 이 라운드들의 결과 추이를 보면:

| 라운드 | 벤치마크 대상 | 발견된 "진짜 코드 격차" | 나머지 |
|--------|---------------|--------------------------|--------|
| 148차 | 후커블 실사용 | 0건 — comparison_chart/stat_infographic/ingredient_circle 전부 **이미 구현돼 있었음**, 안 뜬 이유는 "입력 기근"(사진만 넣고 텍스트 입력 안 함) | — |

추이가 뚜렷합니다: 최근 갈수록 "레퍼런스에서 보인 패턴 중 진짜 새로운 코드 버그"는 점점
줄어들고, 나머지는 거의 다 "이미 구현돼 있었다" 또는 "의도적으로 안 한다"(컴플라이언스·
anti-hallucination 가드레일)로 수렴하고 있습니다. 즉 **정보 구조·섹션 다양성·타이포·레이아웃
리듬 자체는 실제 디자이너/AI 템플릿 서비스 레퍼런스와 나란히 놓아도 구조적으로 뒤처지는
지점이 거의 안 남았다**는 게 최근 10라운드의 일관된 증거입니다.

단, 이건 **"판매자가 입력을 충분히 채웠을 때"**라는 전제가 붙습니다. 148차가 증명했듯 사진만
올리고 성분·인증·후기 텍스트를 비워두면 고급 섹션(비교 차트·통계 인포그래픽 등)이 통째로
스킵됩니다 — 이건 시스템 한계가 아니라 "없는 걸 지어내지 않는다"는 anti-hallucination
원칙이 의도한 대로 작동한 결과입니다.

## 축 2: 사진 합성·비주얼 폴리시 — 아직 아님 (가장 약한 지점, 원 지시 그대로)

이게 사용자가 처음부터("사진합성 부분이 아직 미약한거 같으니 코딩으로 해결 하자") 지목했던
바로 그 축이고, 8라운드 넘게(64/81/211/214~218/233~235/238차) 다뤘지만 **한 번도 "완료"로
닫힌 적이 없는** 유일한 축입니다. 세부적으로:

- **hero 컷아웃**: 상대적으로 탄탄합니다 — rembg 최대 3회 재시도(`cropAttempts`), 투명도·코너
  알파·플레이트 리스크 3중 품질 게이트, 전부 기준 미달이면 원본 세이프크롭으로 폴백, 거기에
  Replicate clarity-upscaler 화질 보정까지. 디자이너 레퍼런스와 나란히 봐도 눈에 띄는 이질감은
  최근 라운드에서 보고되지 않았습니다.
- **라이프스타일 픽셀 페이스트(실사용샷)**: hero 대비 명백히 약합니다. rembg를 **1번만** 호출,
  재시도·손-오염 검사·화질 보정이 전무(235/238차가 각각 독립적으로 재확인). 매칭 3축(화이트
  밸런스·선명도·그레인, 211~218차)은 유닛 테스트 수치로는 개선됐지만, **"실제 사진으로 육안
  체감되는지는 아직 확인이 안 된 상태**로 §4에 정직하게 남아 있습니다(214~218차, 9건·$0.369
  유료 검증 이후 추가 검증은 보류 중).
- **그림자 방향(광원 각도) 매칭**: 아예 시도된 적이 없습니다 — AI 배경마다 광원 위치를 추정하는
  로직 자체가 없고, 실제 니즈가 있는지도 불확실해 의도적으로 보류 중입니다(§2).
- 이 축의 남은 격차를 hero 수준으로 메우려면(재시도·손-오염 검사·화질보정을 라이프스타일에도
  적용) **판매자가 라이프스타일 합성을 쓸 때마다 프로덕션 유료 API 호출이 늘어나는 구조적
  변경**이 필요합니다 — "허가 없이 유료 API 호출 금지" 원칙 때문에 지금까지 손대지 않고 §4에만
  쌓아뒀습니다.

## 축 3: "AI 템플릿 서비스"와 "사람이 만드는 외주 업체"의 근본적 차이

이 부분이 가장 솔직하게 짚어야 할 지점입니다. 지금까지의 벤치마크 대상(후커블, Behance
디자이너 포트폴리오)은 대부분 **완성된 정적 디자인 결과물**이거나, 후커블처럼 **우리와 같은
부류(반자동화 AI 생성 서비스)**입니다. 반면 사용자가 말하는 "진짜 외주 업체"는 보통:

- 사진마다 사람이 수작업으로 리터칭(그림자·반사·색온도를 눈으로 보면서 맞춤)
- 제품 특성에 맞춰 매번 새로 그리는 커스텀 일러스트·그래픽 요소
- 카피를 여러 번 다듬는 전담 카피라이터
- 레이아웃을 템플릿이 아니라 이 제품만을 위해 처음부터 설계

Pagzly는 구조적으로 "슬롯 + 템플릿 + 조건부 로직" 절차적 생성이라, 이런 **"이 제품 하나만을
위한 맞춤"** 수준은 애초에 코드만으로 도달할 수 있는 범위 밖입니다. 이건 버그가 아니라
아키텍처의 근본적 한계이고, 사진 합성 폴리시(축2)가 정확히 이 차이가 가장 크게 드러나는
지점입니다 — 사람 리터처가 만지면 사라질 "합성 티"가, 코드 기반 파이프라인에는 구조적으로
남습니다.

## 정직한 결론

- **정보·레이아웃·카피**: 후커블급 AI 템플릿 서비스와 나란히 놓아도 구조적 격차는 거의
  소진됐습니다(최근 6라운드 중 5라운드가 "이미 구현됨"/"의도적 제외"로 수렴). 입력을 충분히
  채운다는 전제 하에는 이 축에서 "부족하다"고 말하기 어려운 수준입니다.
- **사진 합성**: 아니요, 아직입니다. hero는 탄탄하지만 라이프스타일 합성 경로가 확실히
  약하고, 이걸 hero 수준으로 끌어올리려면 유료 API 호출 증가가 필요해 사용자 허가 없이는
  더 진행이 안 됩니다.
- **"사람이 만든 외주"급 맞춤 완성도**: 구조적으로 100% 도달은 어렵습니다 — 코드로 좁힐 수
  있는 한계까지는 계속 좁혀왔고(211~238차), 남은 격차의 상당 부분은 "사람이 눈으로 보고
  다듬는다"는 외주 업체의 본질적 강점이라 코딩만으로는 완전히 대체가 안 됩니다.

## 제안

축2(사진 합성) 격차를 실제로 더 좁히려면 다음 중 하나가 필요합니다:
1. 라이프스타일 픽셀 페이스트에 hero급 안전장치(rembg 재시도 3회 + 손-오염 검사 + clarity-
   upscaler) 추가 허가 — 판매자가 라이프스타일 합성을 쓸 때마다 유료 API 호출이 늘어납니다.
2. 211~218차가 유닛 테스트로만 확인한 매칭 3축 개선이 실제 사진에서 육안으로 체감되는지
   유료 재검증(§4에 이미 기록된 미결 항목).

두 항목 모두 사용자의 명시적 허가가 있어야 진행할 수 있어 지금은 §4에 대기 중입니다. 허가
여부는 이 문서와 별개로 판단해주시면 됩니다.
