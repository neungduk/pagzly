# 85차 — 84차 후속: Vision 배치 confidence 보정 + 얼굴/목 배치 하드 세이프가드

생성: 2026-09-02

## 배경 — 84차에서 발견한 문제 (스크린샷으로 직접 확인)

84차(실루엣 제거, 원본에 직접 paste)는 구조적 목표는 확실히 달성했습니다 — 82/83차의 "이중 객체·블러 박스" 문제가 스크린샷(`84cha-vs-82cha-serum.png`)으로도 확인될 만큼 완전히 사라졌고, 비용도 87% 줄었습니다. 다만 QA에서 훨씬 더 심각한 새 문제가 나왔습니다:

- `84cha-arms-crossed-serum-full-compare.png`: **손이 아예 안 나오는 얼굴 클로즈업 사진**인데 Vision이 `confidence: high`를 주고, 세럼 병이 **여성의 턱/목 부근에 붙어있는** 결과가 나왔습니다.
- `84cha-non-grip-rubbing-hands-full-compare.png`: 손을 비비는 동작(쥐는 자세가 아님)인데도 `high`가 나와서 손가락 사이에 병이 어색하게 끼워져 있습니다.

이건 "위치가 살짝 안 맞는다" 수준이 아니라 **실제 판매자 상세페이지에 나가면 안 되는, 눈에 바로 띄는 파손된 이미지**입니다. 지금 이 필터링을 `confidence` 필드 하나에만 의존하고 있는데, 프롬프트로 "손이 안 보이면 low를 반환하라"고 이미 지시했음에도(84차 브리프에 포함됨) Vision이 지키지 않았습니다. 이 프로젝트에서 여러 번 확인된 패턴이지만(81~84차 모두), **프롬프트 지시만으로는 모델이 결정적으로 지키지 않습니다.** 이번엔 프롬프트만 더 다듬는 게 아니라, 모델의 판단을 신뢰하지 않는 **코드 레벨의 강제 안전장치**를 같이 넣습니다.

## 지시 — 두 가지를 함께

### 1. Vision 응답에 판단 근거 필드 추가 (프롬프트 보정)

`lib/detect-held-object-placement.ts`의 `detectHandPlacementForProduct()` 프롬프트와 응답 스키마에 아래 필드를 추가하세요:

```json
{
  "xPct": 0-100, "yPct": 0-100, "wPct": 0-100, "hPct": 0-100,
  "rotationDeg": -45~45,
  "confidence": "high" | "low",
  "handsVisible": true | false,
  "gripSpaceVisible": true | false,
  "faceRegion": { "xPct": 0-100, "yPct": 0-100, "wPct": 0-100, "hPct": 0-100 } | null
}
```

- `handsVisible`: 이미지 1에 사람의 손이 실제로 보이는지 (얼굴 클로즈업처럼 손이 프레임 밖이면 false).
- `gripSpaceVisible`: 손가락 사이 틈, 벌어진 손바닥처럼 **실제로 물체를 끼우거나 쥘 수 있는 빈 공간**이 보이는지 — 손이 맞닿아 있거나 비비는 동작처럼 공간이 없으면 false.
- `faceRegion`: 이미지 1에 사람 얼굴/머리가 보이면 그 대략적인 bbox, 안 보이면 `null`. (이 필드는 Vision의 "confidence" 판단을 검증하기 위한 것이지, 이 값 자체를 신뢰해서 배치 여부를 결정하는 용도가 아닙니다 — 아래 2번 참고.)
- 판정 로직(코드): `reliable = confidence === "high" && handsVisible && gripSpaceVisible && isHeldObjectPlacementReasonable(placement)` — 기존 조건에 `handsVisible`/`gripSpaceVisible`를 AND로 추가.

### 2. 얼굴/목 영역 배치는 confidence와 무관하게 코드로 강제 차단 (하드 세이프가드)

프롬프트 보정만으로는 이번에도 100% 안 지켜질 수 있다고 가정하고, `pasteCutoutOnScene()` 또는 그 직전 단계에 **Vision이 뭐라고 하든 무조건 적용되는** 검증을 추가하세요:

- `faceRegion`이 존재하면, 제안된 배치 bbox가 `faceRegion`과 겹치거나 일정 여백(예: `faceRegion` 상하좌우로 `faceRegion` 높이의 20~30% 정도 패딩) 안에 들어오면 **`confidence`가 `high`여도 무조건 `reliable = false`로 강제**하세요. 즉 이 체크는 위 1번의 AND 조건에도 포함시키되, "Vision이 그렇게 말했으니 믿는다"가 아니라 **좌표 겹침을 코드로 직접 계산해서 기계적으로 거른다**는 게 핵심입니다 — `isHeldObjectPlacementReasonable`처럼 순수 함수로 만들어서 유닛 테스트하듯 검증 가능하게 해주세요(예: `overlapsExclusionZone(placement, faceRegion)`).
- 얼굴이 아예 감지 안 됐는데(`faceRegion: null`) 배치가 이미지 상단 30% 이내처럼 얼굴이 있었을 법한 위치라면 보수적으로 한 번 더 의심할 수 있지만, 이건 과설계일 수 있으니 이번 라운드는 "얼굴이 감지된 경우의 확실한 겹침 차단"까지만 하고, 필요하면 다음 라운드로 미루세요.

### 3. 회귀 확인 — 안전장치가 정상 케이스까지 막지 않는지

82~84차에서 이미 "성공"으로 분류됐던 라벨 있는 케이스(세럼/튜브, 실제로 손으로 쥐고 있는 정상 라이프스타일 사진)를 다시 돌려서, 이번 안전장치 때문에 정상적으로 됐어야 할 케이스까지 막혀버리는 건 아닌지 확인하세요. 과도하게 막히면 폴백행이 너무 잦아지는 것도 문제이니, 그 경우 있는 그대로 보고해주세요(억지로 통과시키지 말고).

## 하지 않는 것

- 원근 변형, 손가락 가림 처리 등은 여전히 스코프 밖.
- `faceRegion` 미감지 시의 추가 휴리스틱(위 2번 마지막 문단) — 이번엔 필요 시에만, 무리하게 확장하지 마세요.
- 라벨 문자 일치 검증 — 계속 "Vision 텍스트 미감지로 불확실" 상태 그대로 두고, 이번 라운드 목표가 아님을 명시.

## 검증 방법

- 84차에서 실패했던 두 케이스(`arms-crossed-serum`, `non-grip-rubbing-hands`)를 다시 돌려서 이번엔 **fallback으로 정상적으로 빠지는지** 확인 — 스크린샷 필수.
- 84차에서 성공했던 케이스(세럼/튜브, 정상 쥐는 자세)가 이번에도 정상 동작하는지 회귀 확인 — 스크린샷 필수.
- `overlapsExclusionZone()` 같은 순수 함수는 가능하면 대표적인 좌표 몇 개로 직접 계산해서 로그로 남겨주세요(겹침/비겹침 케이스 각 1개 이상) — Vision 호출 없이도 로직 자체가 맞는지 확인 가능하게.
- `npx tsc --noEmit` 에러 0건.
- 비용 기록.
