# 98차 — "핵심 3축"(highlight_box) 카드 0개일 때 페이지에 빈 공백 렌더링되는 버그

생성: 2026-09-03
전제: 사용자가 레퍼런스 상세페이지(글로위스트, 마유에스테, 버가못 BB크림 등) 스크린샷을 보내며 "우리가 만든 것과 비교해서 모자란 점을 고쳐달라"고 요청. 검증 삼아 사용자가 실제로 여러 번 재생성했던 "글로위스트 드림글로우 카멜리아 에센스 미스트 v3"(`id=49f8192b-2d17-4650-adac-12941f86487a`, 브랜드 glowiest — 사용자가 보낸 레퍼런스 이미지 중 하나와 동일한 제품)를 직접 Chrome으로 열어 확인하던 중, "미니 포인트"(카멜리아 오일/히알루론산) 섹션과 "사용 방법" 섹션 사이에 스크린샷 기준 **뷰포트 1개 분량 이상의 완전히 빈 공백**이 있는 것을 발견했습니다. 섹션 목록에는 10번 "핵심 포인트"(타입: **핵심 3축**)가 그 사이에 있어야 하는데, 실제 미리보기에는 헤딩조차 없이 장식용 구분선(점 하나)만 있고 그 외엔 아무것도 렌더링되지 않습니다.

## 원인

`components/DetailSectionRenderer.tsx:1769-1771`:

```ts
case "highlight_box": {
  const cards = section.cards.slice(0, 4);
  if (cards.length === 0) return null;
```

`section.cards`가 빈 배열이면 헤딩(`section.heading`)조차 렌더링하지 않고 `null`을 반환합니다. 문제는 `lib/section-templates.ts`에서 **모든 카테고리의 `highlight_box` 슬롯이 `required: true`이고 프롬프트 노트에 "카드 3장"을 명시적으로 지시**하고 있다는 점입니다(예: `section-templates.ts:75-78` 화장품 카테고리 — "핵심 효과/성분 3가지를 카드 3장으로 요약..."). 즉 이 섹션은 항상 카드 3장이 있어야 정상인데, 이번처럼 AI 생성 결과에서 `cards`가 비어버리는 케이스가 실제로 발생하고 있고, 그 결과가 서버 검증을 통과해 저장·노출까지 그대로 이어지고 있습니다. 렌더러가 아무 안내 없이 `null`만 반환하다 보니 최종 사용자(쇼핑몰 구매자)에게는 "페이지가 갑자기 뚝 끊기고 큰 흰 여백이 있다가 다음 섹션이 나오는" 것처럼 보입니다 — required 섹션 하나가 조용히 사라지는 게 아니라 **빈 자리만 남기고 사라지는** 게 더 나쁩니다.

## 작업 A — 렌더러 방어 처리 (즉시 눈에 보이는 버그 제거)

`components/DetailSectionRenderer.tsx`의 `case "highlight_box"` 처리를 수정합니다. 카드가 비어 있으면:
1. 섹션 자체를 완전히 건너뛰어야 합니다(빈 `<section>`이나 여백도 남기면 안 됨).
2. 이 섹션을 감싸는 상위 레이아웃(구분선 "•" 장식, `scroll-mt` 앵커 등)도 함께 스킵되는지 확인해 주세요 — 현재는 `highlight_box`가 `null`을 반환해도 상위 wrapper가 여전히 섹션 구분선을 그리고 있어서(이번에 관찰된 "점 하나만 있는 빈 공백"이 그 증거) 빈 자리가 남습니다. `null`을 반환하는 섹션은 섹션 목록/구분선 렌더링 루프에서도 완전히 제외되도록 상위 map/wrapper 로직을 확인하고 고쳐 주세요.
3. 개발 콘솔에 경고 로그를 남겨 주세요: `console.warn('[DetailSectionRenderer] highlight_box cards empty — section skipped', {index, heading: section.heading})` — 다음에 이런 케이스가 또 생기면 바로 원인 추적이 가능하도록.

이 방어 처리는 `highlight_box` 외에 카드/리스트 배열이 비어있을 때 `null`을 반환하는 다른 case(`checklist`, `stat_infographic`의 각 metric 그룹, `gallery` 등)에도 같은 문제가 있을 수 있습니다 — 시간이 되면 같은 패턴(배열 비었을 때 `null` 반환 + 상위가 빈 자리를 남기는지)을 한 번 훑어봐 주시고, 최소한 `checklist`(`section-templates.ts`상 모든 카테고리 필수 슬롯)는 꼭 같이 확인해 주세요.

## 작업 B — 생성 파이프라인에서 근본 원인 조사

`required: true`인 슬롯이 빈 배열로 나오는 것 자체가 생성/검증 단계의 문제입니다. `app/api/generate/route.ts`(또는 실제 콘텐츠 생성·검증 로직이 있는 파일)에서:
1. `highlight_box` 타입 섹션을 저장하기 전에 `cards.length >= 1`(이상적으로는 3) 검증이 있는지 확인해 주세요. 없다면 추가해 주세요.
2. 검증에 실패하면(카드 0개) 어떻게 처리되는지 확인 — 재시도(retry)하는지, 아니면 그냥 빈 채로 통과되는지. 지금 상태(빈 채로 통과)가 이번 버그의 근본 원인으로 보입니다.
3. 가능하면: 카드가 비어 있을 때 (a) 1회 재생성 시도, 그래도 실패하면 (b) 해당 섹션을 `hidden`으로 표시하거나 목록에서 아예 제외하고 로그를 남기는 방식으로 처리해 주세요. "필수 섹션인데 조용히 비어서 나가는" 상황 자체를 서버 단에서부터 막는 게 목표입니다.
4. 이번에 실제로 문제가 발생한 상품(`id=49f8192b-2d17-4650-adac-12941f86487a`)의 생성 로그가 남아있다면(로컬 콘솔 히스토리, DB의 원본 생성 응답 등) 어떤 단계에서 `cards`가 비었는지 확인해 근본 원인을 파악해 주세요 — DeepSeek/Claude 응답 자체가 비어서 온 건지, JSON 파싱 중 유실된 건지에 따라 대응이 달라집니다.

## 하지 않는 것

- `highlight_box`의 비주얼 디자인(카드 스타일, 강조 카드 로직 등)은 이번 범위 밖입니다 — 순수 "빈 카드일 때 빈 공백이 남는 버그"만 고칩니다.
- 다른 섹션 타입의 시각적 풍성함(장식 배경, 주석 콜아웃 등) 개선은 이번 라운드에 포함하지 않습니다 — 별도 라운드(99차 예정)에서 다룹니다.
- 이미 저장된 과거 페이지(이번에 발견된 글로위스트 v3 포함)를 소급 재생성하지 않습니다.

## 검증 방법

- `npx tsc --noEmit` 에러 0건.
- 문제의 상품(`id=49f8192b-2d17-4650-adac-12941f86487a`, "글로위스트 드림글로우 카멜리아 에센스 미스트 v3")을 다시 열어서, `cards`가 비어있는 상태가 재현되면(재현 안 될 수도 있음 — AI 생성이라 매번 다를 수 있음) 더 이상 빈 공백 없이 섹션이 완전히 스킵되는지 확인.
- 의도적으로 `cards: []`인 `highlight_box` 섹션을 목업 데이터로 만들어 렌더러 방어 로직이 실제로 동작하는지(빈 공백 없이 다음 섹션으로 바로 이어지는지) 확인.
- 신규 상품을 1개 이상 생성해 `highlight_box`가 정상적으로 카드 3장을 채워서 나오는지, 서버 검증 로그가 남는지 확인.
