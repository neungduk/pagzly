**지난 66차 E2E 테스트가 `/api/generate` 402(크레딧 부족)로 최종 페이지까지
도달하지 못하고 중단됐습니다.** 이번 라운드는 실제 유료 생성이 최소
4~6회(전자제품 1~2회 + 화장품 1~2회, 필요 시 재시도 포함) 예상되고, 앞으로도
QA 라운드마다 크레딧 부족으로 매번 사용자에게 충전을 요청하는 건 비효율적이라는
사용자 지시가 있었습니다. 그래서 **이번부터는 매 라운드 시작 전에 Cursor가
먼저 QA 테스트 계정에 토큰을 충전해두고 작업을 시작**하는 것으로 절차를
바꿉니다.

52차·57차에서 이미 쓴 것과 같은 방식입니다:

```
계정: pagelab-test@test.local (2f01ed61-ed80-465d-9c1a-712bbf01a658)
RPC:  grant_credits(2f01ed61-ed80-465d-9c1a-712bbf01a658, 100000, 'admin_adjustment', 'qa_topup_67cha')
```

`grant_credits`는 `security definer`이고 `service_role`에만 EXECUTE 권한이
있으므로 (`supabase/migrations/20260831100000_billing_credits_schema.sql`
233~236행), **반드시 서버 사이드에서 Supabase service-role 키로만 호출**해주세요
— 클라이언트/브라우저에서 호출하거나 authenticated 롤에 권한을 새로 부여하는
식으로 우회하지 마세요 (이건 실제 결제 없이 잔액을 조작하는 기능이라 원래도
service_role 전용으로 잠가둔 것이고, 이 제한은 그대로 유지돼야 합니다).

충전 후 잔액을 로그로 남기고, 그 다음에 아래 작업 A/B로 진행해주세요. 이후
라운드에서도 QA 계정 잔액이 부족해지면 같은 방식으로 알아서 충전 후 진행하시면
됩니다 — 매번 사용자에게 먼저 물어볼 필요 없습니다. (단, 이건 어디까지나
`pagelab-test@test.local` QA 테스트 계정 한정입니다. 실제 결제/구독 로직이나
다른 사용자 계정에는 손대지 마세요.)

## 배경

`pagzly-quality-baseline-2026.md`의 2차 채점(58~62차)에서 기준3·기준4는
**코드는 정확하지만 실제 화면에서 확인되지 않은 상태**로 남아 있습니다.

- **기준3 (화장품 시그니처 컷 = 텍스처 스와치)**: `cosmetics-texture-swatch.ts`
  로직 자체는 정확하고 서버 로그에 스와치 프롬프트도 실제로 찍히지만,
  `62cha-final-cosmetics-texture.png`에서 해당 섹션을 봤을 때 제품/소품이
  프레임을 많이 가려서 배경(스와치)이 뚜렷이 안 보였습니다.
- **기준4 (전자제품 주석형 콜아웃)**: `analyzeProductAnnotations` →
  `areAnnotationsReliable` → `applyElectronicsAnnotatedSections` →
  `AnnotatedImageOverlay` 코드 전 구간이 정확하고 안전 폴백도 잘 동작하지만,
  유일했던 실제 테스트에서 Vision이 신뢰도 `low`를 반환해 폴백이 발동됐고
  annotated 레이아웃이 화면에 렌더된 사례가 지금까지 0건입니다.

이번 라운드 목표는 새 기능을 만드는 게 아니라, **이 두 기준이 실제로 화면에
보이는 사례를 최소 1건씩 확보**하는 것입니다.

## 작업 A — 기준4: 전자제품 주석형 콜아웃 재시도

부품/기능 위치가 사진에서 비교적 명확히 구분되는 전자제품 1개로 실제 생성을
1~2회 진행해주세요 (예: 이어버드, 스피커, 소형 가전처럼 버튼/포트/그릴 같은
구분되는 부위가 있는 제품 — 지난번 실패 사례와 다른 상품으로 시도해보는 걸
권장합니다).

- `analyzeProductAnnotations`가 반환하는 신뢰도(`high`/`low`)를 로그로 반드시
  남겨주세요.
- `high`가 나오고 annotated 레이아웃이 실제로 렌더되면: 해당 섹션 스크린샷을
  캡처하고, 점·리더라인·라벨이 실제 부위와 육안으로 맞는지 확인해주세요.
- 이번에도 `low`가 나오면: 무리하게 재시도 횟수를 늘리지 말고 (1~2회 선에서
  멈추고) "이 기능이 실전에서 몇 % 확률로 발동하는지 아직 불확실하다"는
  결과를 있는 그대로 보고해주세요. 억지로 좌표를 만들어내거나 신뢰도 임계값을
  낮추는 식으로 "성공"을 만들어내지 마세요 — 안전 폴백을 훼손하는 수정은
  하지 않습니다.

## 작업 B — 기준3: 화장품 텍스처 스와치 재시도

이번엔 소품이 적고 제품 단독 컷 비중이 높은 화장품 상품(가능하면 크림/로션
계열 — 제형이 카메라에 잘 보이는 타입)으로 실제 생성을 1~2회 진행해주세요.

- `ingredient_highlight` 또는 `texture_feel` 슬롯에 배정된 섹션을 스크린샷으로
  캡처하고, 배경이 "크림을 짜서 펼친 스와치"처럼 육안으로 보이는지 확인해주세요.
- 여전히 제품/소품에 가려서 안 보이면, 무리하게 성공으로 보고하지 말고
  "배경 자체는 생성되지만 전경 요소에 가려 잘 안 보인다"는 정확한 원인을
  적어주세요 (예: 전경 상품 사진의 크롭 비율/배치 문제인지, 배경 자체가
  약한지 구분해서).
