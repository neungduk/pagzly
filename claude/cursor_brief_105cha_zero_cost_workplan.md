## 0. 비용 규칙 (작업 내내 지킬 것)

1. **작업 시작 전 `.env.local`의 `TEST_MODE`를 `true`로 되돌리세요.** 지금 `false`라서 무심코 생성 한 번이 돌면 그대로 과금됩니다.

3. Claude/DeepSeek 텍스트 호출은 상대적으로 저렴하지만, 필요할 때만 최소 단위 스모크로 쓰세요(아래 각 항목의 검증 방법 참고).
4. 모든 항목이 끝난 뒤, 마지막에 한 번만 `TEST_MODE=false`로 바꾸고 **6장**의 최종 프로토콜대로 1회 생성합니다.

## 3. 항목별 무비용 검증 방법

### 1번 — Vision 역할 배선 (102차)
근본 원인 후보 중 **draft→final 경로 유실**이 가장 유력합니다(100차 C에서 `imageAnalysis`가 같은 자리에서 새던 것과 동일 패턴).

무비용 검증:
- `analyzeImagesWithClaude`만 단독 호출하는 스모크 스크립트를 만들어(로컬 테스트 이미지 3~4장) **반환 JSON에 `roles`가 실제로 담기는지** 출력만 확인하세요. Vision 호출 1회는 이미지 생성 대비 무시할 수준입니다.
- 그 결과를 하드코딩한 픽스처로 `normalizeImageRoles` 병합 우선순위(사용자 지정 > Vision > 순서 기본값)를 **순수 함수 단위 테스트**로 검증하세요. 여기엔 API 호출이 전혀 없습니다.
- draft→final 전달은 `console.log`로 경계마다 값을 찍고 **코드 리뷰로** 유실 지점을 특정하세요.

### 2·3번 — before/after, ingredient circle
2절의 replay 스크립트로 검증합니다. before/after가 gallery에 강제 배정되지 않고, circle 섹션이 성분 섹션과 다른 인덱스를 받는지 표에서 바로 보입니다.

### 4번 — preferForSlot 우선순위 큐
replay 스크립트 출력의 **"prefer 미충족 슬롯 목록"** 이 비거나 크게 줄어야 합니다. 특히 `packaging_design`이 package 역할 인덱스를 받는지 확인하세요(1번이 선행돼야 의미 있음).

### 5번 — 스케일 프롬프트
**Replicate를 호출하지 말고 프롬프트만 출력하세요.** `buildHumanShots`가 만든 최종 프롬프트 문자열을 콘솔에 덤프하는 스모크를 만들어, `productSizeHint`가 실제 문장으로 들어갔는지 눈으로 확인합니다. `aspect_ratio`도 `replicateInput` 객체를 찍어서 `match_input_image`가 아닌 플래너 지정값이 들어가는지 확인하세요. **`replicate.run` 직전까지만 실행하고 return** 하는 dry-run 플래그를 두면 편합니다.

### 6번 — aHash dedup
sharp로 로컬 테스트 이미지들의 해시를 계산해 **해밍 거리 행렬만 출력**하는 스크립트로 검증하세요. 같은 병의 비슷한 컷끼리 거리가 작게 나오는지 확인하면 됩니다. 그다음 replay 스크립트에서 인접 배정 유사도가 개선되는지 봅니다.

### 7번 — Vision 검증 게이트
배선만 하고, **판정 함수는 저장된 기존 사용샷 이미지 URL로 단독 호출**해 "크기 이상/라벨 불일치"를 잡아내는지 확인하세요. 새 사용샷을 생성할 필요가 없습니다. 대상 URL은 상품 `a4e33e41-…`의 `…-lifestyle-ai-1.png`, `…-lifestyle-ai-2.png`입니다.

### 8번 — 부족 역할 경고
1번의 역할 판정 결과를 입력으로 받는 순수 함수로 만들고, 픽스처(병 컷만 9장 / 병+박스+매크로 섞인 세트)로 경고가 뜨는지 단위 테스트하세요.

### 공통
- 모든 단계에서 `npx tsc --noEmit` 0건 유지.
- 기존 스모크(`54cha-quick-points`, `99cha-assign-images-smoke`)가 계속 PASS하는지 확인.

## 6. 최종 유료 테스트 프로토콜 (사용자가 지시할 때만 실행)

**준비**: `.env.local`에서 `TEST_MODE=false`, `IMAGE_ROUTER_ENABLED=true` 확인 → dev 서버 재시작.

**입력**: 이전과 동일 조건으로 맞춰 비교 가능하게 합니다.
- 카테고리 화장품/뷰티, 긴 구성
- glowiest 실제 제품 사진 9장 (정면 / 캡분리 / 눕힌컷 / 박스2컷 / 각도 / 2개 / 3개×2)
- **역할 드롭다운은 건드리지 않음** (Vision 판정 검증을 위해)
- 상품명 "글로위스트 드림글로우 카멜리아 에센스 미스트", 브랜드 glowiest, 32000원, 타겟 20~30대 여성
- 핵심 특징에 2중 레이어·35mL·미세분사 등 기존과 동일하게
- **신규**: 용량/크기 입력란에 "35mL, 높이 약 9cm" 입력 (103차 A에서 추가한 필드)
- 인물 사진 슬롯은 비워둠

**측정 체크리스트** (한 번의 생성으로 전부 확인):

1. 저장된 `image_roles`가 업로드 순서 기본값(`hero,detail,lifestyle,package,other×5`)과 **다른가** — 102차
2. 눕힌 컷이 `lifestyle`이 아니고, 박스 컷이 `package`로 잡혔는가 — 102차
3. `packaging_design` 섹션에 **박스 사진**이 들어갔는가 — 104차 B
4. 사용샷의 병이 **손 안에 들어오는 크기**인가, 라벨이 원본과 일치하는가 — 103차 A·B
5. before/after가 gallery에 강제 배정되지 않았는가 — 104차 A-1
6. 인접 섹션에 시각적으로 같은 컷이 연속으로 오지 않는가 — 104차 A-3
7. 성분/질감 슬롯이 텍스트·일러스트로 대체됐거나, 부족 경고가 생성 전에 떴는가 — 104차 C
8. 생성 단계 4/4 유지, `npx tsc --noEmit` 0건
9. AI 비용 총액과 분해를 기록 (직전 기준값: 총 $0.3597, 이미지 $0.2034)

DB 조회는 102차 브리프의 콘솔 스니펫을, 고유 이미지 측정은 99차 브리프의 스니펫을 사용하세요.
