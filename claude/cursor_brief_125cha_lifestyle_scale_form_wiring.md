# 125차 — 라이프스타일 합성 사이즈: 실제 폼 경로 연결 (124차 후속, 필수)

생성: 2026-09-07
전제: `TEST_MODE=true` 유지. 유료 Replicate 라이브 합성은 승인 후에만(아래 A-3 제외 — A-3의 스케일-공식 스모크 1회는 이미 승인됨).

## 0. 배경 — 124차 검증 중 발견한 문제

124차 리포트는 "`lib/photo-pipeline-client.ts` | 높이 없으면 API 호출 스킵; 있으면 `productHeightCm`+hint 전달"이라고 보고했지만, 제가 직접 파일을 읽어 대조한 결과 **실제로는 그렇지 않습니다.**

- `lib/photo-pipeline-client.ts`의 `runPhotoEnhancementPipeline()` → `/api/lifestyle-composite` fetch 바디(626~636행 부근)에 `productHeightCm`/`productSizeHint`가 **전혀 포함되어 있지 않습니다.** 124차 이전과 코드가 동일합니다.
- 이 함수를 호출하는 유일한 실제 지점(`app/create/draft/page.tsx` 287행)에도 사이즈/높이를 받을 폼 필드 자체가 없습니다.
- `productSizeHint`라는 이름의 필드는 `lib/types/generate.ts` 80행에 있긴 한데, 이건 **문구/카피 생성 요청 타입**이고 사진 합성 파이프라인(`runPhotoEnhancementPipeline`)과는 전혀 연결돼 있지 않습니다.

즉 124차에서 새로 만든 게이트(`resolveLifestyleCompositeScale`, `requirePixelPaste`)는 정확히 잘 만들어졌지만, **그 게이트에 들어갈 입력값을 실제로 보내는 곳이 어디에도 없어서, 지금 상태로는 실제 사용자가 라이프스타일 사진을 업로드해서 합성을 시도하면 100%(예외 없이) 스킵됩니다.** "사이즈 버그 수정"이 아니라 "기능이 조용히 꺼짐"에 가깝습니다. 안전한 방향이긴 하지만, 사용자에게 쓸모 있는 기능이 되려면 이 라운드가 필요합니다.

## 1. 할 것

### A. 높이 입력 경로 확보

먼저 확인: 상품 등록/초안 폼(`app/create/draft/page.tsx` 또는 그 이전 단계인 `app/create` 폼)에 **용량/크기 필드가 이미 존재하는지** 찾아보세요(예: "35mL", "300ml" 같은 값을 받는 필드가 있다면 그게 실마리입니다). `lib/lifestyle-physical-scale.ts`의 `parseProductHeightCm()`은 "높이 약 9cm", "H: 9cm" 같은 **높이(cm) 문자열**만 파싱하고, "35mL" 같은 부피 단위는 못 씁니다(부피→높이 환산은 용기 형태를 몰라서 원칙적으로 불가 — 지어내기 금지 원칙상 억지로 변환하지 마세요).

두 가지 중 하나로 진행해주세요(직접 판단 후 근거와 함께 보고):

- **(A안, 권장)** 라이프스타일 사진을 업로드하는 UI 흐름에 **선택적** 입력 필드 하나를 추가: "제품 높이(선택, cm) — 입력하면 손 크기 대비 정확한 합성이 가능해요" 같은 짧은 안내 문구와 함께. 필수 아님, 비워두면 기존처럼 합성 생략(안전). 이 값이 `runPhotoEnhancementPipeline` params → `/api/lifestyle-composite` 바디 `productHeightCm`까지 그대로 흘러가게 배선.
- (B안) 이미 스펙 테이블 등에 실측 치수 데이터가 폼 어딘가에 있다면 새 필드 없이 그걸 재사용 — 있는지부터 확인하고, 없으면 A안으로.

어느 쪽이든 **없으면 그냥 스킵(옵션 1 유지)** 원칙은 그대로 둡니다 — 강제 입력으로 만들지 마세요.

### B. 실제 배선 확인

- `runPhotoEnhancementPipeline()` 파라미터에 새 필드 추가, `/api/lifestyle-composite` fetch 바디에 포함.
- `app/create/draft/page.tsx`(또는 실제 호출부)에서 이 값을 params로 전달.
- 이번엔 **실제로 값이 전달되는지** `console.log`나 임시 로그로 눈으로 확인하고 스크린샷/로그를 리포트에 남겨주세요 — 124차처럼 "연결했다"고만 쓰고 실제로 안 된 채 넘어가는 일이 없도록, 이 라운드는 특히 더 꼼꼼히 확인 부탁드립니다.

## 2. 검증

- 높이 입력 O: 요청 바디에 `productHeightCm` 포함 확인(네트워크 로그 또는 콘솔 로그 캡처).
- 높이 입력 X(기존과 동일): 여전히 안전하게 스킵.
