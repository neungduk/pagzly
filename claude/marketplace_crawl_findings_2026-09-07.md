## 1. 지마켓 실제 상세페이지 (뷰티 — 스네일 수분크림, 9,600원대 중저가)

관찰 순서: 히어로 제품컷 → **마켓 자체 프로모 배너(스타배송/빅세일)** → "도연 MD의 추천이유 3가지!"
(일러스트 아바타 + 손글씨풍 "하나!/둘!/셋!" 뱃지) → 성분/텍스처 컷 → **동일 판매자 다른 상품 교차판매
배너** → 상품정보제공고시(법정 표) → 주의사항.

**시사점**
- 저가 상품은 실제로 Pagzly의 25섹션보다 **훨씬 짧다** (이미지 블록 6~8개 수준). Pagzly의 정보 밀도는
  이미 이 구간 대비 우위 — 이번 라운드에서 "더 채워 넣기" 방향은 불필요.
- "MD 추천이유" 같은 **인격화된 캐릭터 + 손글씨 뱃지** 톤은 Pagzly의 컨셉 일관성/프리미엄 원칙
  (`reference-patterns.md` §1, §8.6 "미니멀·프리미엄")과 정면으로 배치됨 — **채택 비권장**으로 기록.
- 마켓이 강제로 끼워 넣는 배송/쿠폰 배너는 Pagzly가 안 만드는 게 오히려 강점(깔끔함) — 손댈 필요 없음.
- 법정 고시 표는 순수 HTML 테이블, 디자인 전무 — Pagzly의 `spec_table` 렌더링이 이미 더 나음.

## 2. 옥션 실제 상세페이지 (전자/생활가전 — 무선청소기, 11만원대)

관찰 순서: 히어로 제품컷 → 판매자 인기상품 교차판매 그리드 → 프로모 배너 → **풀블리드 라이프스타일 사진
위에 초대형 볼드 타이포 "귀찮고, 힘들었던 / 물걸레 청소까지"** (문제→해결 대비 카피) → (스크롤 생략)
→ 상품정보제공고시(품명/모델명/**KC 인증정보**/정격전압) → 교차판매 푸터.

**시사점**
- 헤드라인 타이포가 Pagzly 기준(`sectionTitle 2rem→2.75rem`, `reference-patterns.md` §8.4)보다 훨씬
  크고 대담하며, **불편함(pain point) → 해결**을 한 문장 대비로 박아 넣는 카피 패턴이 뚜렷함.
  Pagzly 카피가 상대적으로 얌전한 설명체일 가능성 — 헤드라인 카피 가이드에 pain-point-first 규칙을
  보강할 여지 있음 (입력된 제품 특징에서 도출, 지어내지 않음).
- **KC 인증정보**가 전자제품 법정 고시에 명시적으로 노출됨. Pagzly가 전자제품 카테고리에서 사용자가
  KC 인증번호를 입력했을 때 `spec_table`/`warranty_caution`에 그대로 노출하는지는 **코드 확인 필요**
  (식품의 `food-compliance.ts`와 같은 패턴으로 "electronics-compliance" 소규모 보강 후보).

## 3. 후커블(Hookable) — 실제 생성 예시 (랜딩페이지 내 스크린샷, 기존 랜딩-텍스트 크롤 이상의 신규 근거)

### 3.1 페르수전 태그 시스템
생성된 섹션 썸네일 위에 **"인증 / 비교 / 요약 / 문제제기 / 반박 제거 / 소구점 구체화 / 사회적 증거 /
나열"** 라벨을 붙여 마케팅. 즉 후커블은 "AI가 몇 장 만들어줌"이 아니라 **"검증된 설득 프레임워크를
섹션마다 적용했다"는 걸 판매자에게 투명하게 보여주는 것 자체를 신뢰 요소**로 판매 중.
→ Pagzly는 섹션이 왜 그 자리에 있는지(AIDA/슬롯 근거)를 **판매자에게 노출하지 않음**. 코드 변경 없이도
   문서화/온보딩 UX 아이디어로만 기록(이번 브리프 범위 아님).

### 3.2 "반박 제거" 예시 — 주의: 그대로 베끼면 위험
캡처 예시: "더욱 위험한 성분에 주의하는 이유입니다" / "안심하고 사용하실 수 있도록 꼭 필요한 것만
남겼습니다." → 익명의 "타 제품엔 위험 성분이 있다"는 프레이밍으로 불안을 조성한 뒤 자사 제품으로
안심시키는 구조. **Pagzly의 무근거 비교/타사 폄훼 금지 원칙과 충돌** → 그대로 채택 금지. 다만 "우려 →
안심" 구조 자체는, 판매자가 실제 입력한 `무첨가/무향료/성분` 필드에 근거해서만 재구성하면 안전하게
흉내 가능(예: 입력된 "파라벤 무첨가" 필드가 있을 때만 "불필요한 성분을 넣지 않았습니다" 식 카피 — 입력값
파생이라 지어내기 금지 원칙 위반 아님).

### 3.3 리뷰 기반 "근거 보기" — 가장 유력한 개선 후보
캡처 예시: "1000명의 고객 목소리를 담은 단 하나의 문장." + 펼치면 "근거 보기" UI에 실제 리뷰 인용
("아이와 같이 쓰려고 해요", "알코올이 안 좋다고 들었어요", "입 안이 예민한 편이에요")과 막대그래프
(안정성/효과/자극감 비율)가 나타남.
→ Pagzly의 `review_highlight`는 **입력된 실제 리뷰만 쓴다**는 원칙이 이미 있음(`marketplace-pdp-learning-2026.md`
   "근거 있는 신뢰만"). 하지만 지금은 리뷰를 그대로 나열/인용하는 수준이고, **입력 리뷰에서 파생된
   집계·근거 요약**은 아직 없음. 후커블처럼 "몇 명 중 몇 명이 이런 언급을 했다"는 식으로 입력 리뷰
   텍스트만으로 카운트를 뽑아 보여주면: (a) 지어내기 금지 원칙을 100% 지키면서 (b) 후커블의 핵심
   차별점(근거 있는 카피)을 따라잡을 수 있음. **신규 유료 API 호출 없이(결정론적 키워드 집계)** 가능한
   범위로 스코프를 좁힐 것.

## 4. 결론 — 다음 라운드(131차) 방향

0회, 지어내기 금지 유지). 나머지(전자제품 KC 인증 노출 확인, pain-point 헤드라인 카피 가이드 보강, MD

131차 스코프 밖.

## 5. 절대 원칙 재확인 (이번 조사에도 동일 적용)

1. 경쟁사 카피/디자인 복제 금지 — 구조·패턴만 참고.
2. 타사 폄훼·근거 없는 불안 조성 금지 (Hookable 3.2 패턴 채택 금지).
3. 입력되지 않은 리뷰·통계·인증 정보 날조 금지.
4. `section-templates` 슬롯 순서/종류 변경 금지 (승인 없이).
