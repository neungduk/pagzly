생성: 2026-09-23 · 유료 API 0건 · 코드 변경 0(조사·비교만)

## 배경 (사용자 원문)

> "이게 우리가 만든거고 쇼핑몰 디자이너들이 만든 상세페이지 혹은 AI가 자동으로 만들어주는
> 사이트들 견본 싹 찾아서 비교하고 보완해야할점 지시사항으로 만들어봐"

첨부된 스크린샷은 249차까지 독립 검증을 마친 실제 산출물(`review/248cha-export-full.png`,
"라이트 워터 히알루론 세럼", 화장품/뷰티 28섹션)입니다. 이 문서는 그 스크린샷을 기준으로
① 실제 판매 중인 디자이너 제작 화장품 상세페이지 1건, ② AI 자동생성 경쟁사 2곳(레이메이커·
후커블)을 이번에 새로 열람·크롤링해 비교한 결과입니다.

  다시 뒤집지 않고 이번에 새로 본 것만 보고합니다.

## 신규 크롤링 레퍼런스 3건

### (C) 후커블(hookable.ai) — 랜딩페이지 재방문, 실제 생성 예시("구강스프레이") 직접 확인

## 발견 · 코드 대조 · 분류

1. **(A) 토리든 — "시스템명"을 성분명 대신 강조하는 타이포**("5D H.A. Complex" 등) —
   Pagzly는 이미 `POINT 01 #수분3중레이어`/`POINT 02 맑은 결` 같은 뱃지+헤드라인 패턴으로
   같은 목적(성분 나열 대신 컨셉명 강조)을 구현하고 있음(248차 스크린샷 slice03에서 직접
   확인). **이미 해결됨, 재작업 불필요.**

2. **(A) 토리든 — 브랜드 컬러 하나로 전체 서사를 관통**(파란색 = "수분 이동 경로"를 히어로부터
   CTA까지 일관 적용) — `lib/design-tokens.ts`의 `extendTheme()`/`getSectionTheme()`를 읽어
   확인한 결과, Pagzly는 **의도적으로 다른 설계 철학**을 씁니다: 상품 사진에서 뽑은 기준색
   하나(`base`)에서 색상환상 규칙적으로 파생된 warm/cool/bold 3변형을 만들어 섹션마다
   `["base","warm","cool","bold","warm","cool"]` 순서로 순환시킵니다(스크롤 중 인접 섹션끼리
   너무 단조롭지도, 너무 튀지도 않게 하려는 기존 설계 — 무작위 색이 아니라 전부 **하나의 기준
   색상에서 파생**됨). 토리든처럼 "한 가지 색만 끝까지"가 아니라 "한 뿌리에서 나온 여러 색을
   순환"이 Pagzly의 현재 방향입니다. **이건 버그가 아니라 이미 존재하는 의도적 설계 — 둘 다
   유효한 디자인 철학이라, 코드를 임의로 바꾸지 않고 취향 차이로 기록만 합니다.**

3. **(B) 레이메이커 — 히어로/컨셉 섹션이 전부 "실제 제품 사진 + 그 위에 굵은 헤드라인
   타이포"**이고, **추상적인 AI 일러스트레이션 배경(소용돌이 패턴 등)을 쓰는 샘플이 35건 중
   단 하나도 없었습니다.** 텍스트가 배경과 겹치는 문제 자체가 애초에 생길 수 없는 구조 —
   왜냐하면 배경이 항상 "사진"이고 텍스트는 그 사진 위에 "고정된 색 박스"로 얹히기 때문입니다.
   이건 249차가 이미 고친 `illustration_banner` 가독성 버그(텍스트 전용 다크 패널 스크림 추가)
   의 **근본 방향성 질문**으로 연결됩니다 — 지금은 "AI가 그린 추상 배경 위에 텍스트, 문제 생길
   때마다 패치"인데, 경쟁사·레퍼런스는 애초에 "실사진 위에 텍스트, 구조적으로 안전"입니다.
   249차 패치로 당장의 가독성 버그는 해결됐으니 시급하지 않지만, **`illustration_banner`
   섹션 자체를 계속 쓸지, 아니면 실사진 기반 배너로 전환할지는 코드 버그가 아니라 제품 방향
   결정**이라 이번 라운드에서 임의로 바꾸지 않고 후보로만 남깁니다.

4. **(C) 후커블 — 성분 무첨가 배지를 제품 사진 주위에 원형으로 배치**(파라벤/합성착색료/
   벤조페논/실리콘/알콜/MIT 6개 배지) — `lib/apply-ingredient-circle-pair.ts`
   (`ingredient_circle_pair`/`ingredient_circle_solo` 슬롯)와 `lib/ingredient-ring-diagram.ts`
   (185차, 성분/균주 원형 곡선 텍스트 다이어그램)를 코드로 확인한 결과, **Pagzly는 이미 원형
   성분 시각화를 두 가지 형태로 갖고 있습니다** — 248차 스크린샷에서 본 "6개 성분명이 원형으로
   배치된 큰 다이어그램"(slice03, `ingredient-ring-diagram.ts`)과 "성분 2개의 클로즈업 사진을
   작은 원형 배지로 나란히"(slice05, `apply-ingredient-circle-pair.ts`)가 서로 다른 두 컴포넌트가
   같은 페이지 안에서 함께 쓰인 것이었습니다. **버그(중복/불일치)가 아니라 의도된 별개 기능 —
   248차 리뷰 때 남겨뒀던 "버그인지 의도인지 미확정" 항목을 이번에 코드로 확정 종결합니다.**

5. **(C) 후커블 — 비교 차트 수치를 실제 리뷰 인용구로 근거 제시**("아이와 같이 뿌리려고 해요"
   등 3개 인용구가 안정성/효과/자극감 막대 옆에 붙음) — `lib/types/generate.ts`의
   `ComparisonChartSection.evidenceQuotes`(137차, "축별 실제 매칭 리뷰 원문 최대 2개, 지어내지
   않음")를 grep으로 확인했고, `DetailSectionRenderer.tsx`(1198행)·`export-detail-html.ts`
   (412행) 양쪽에 실제 렌더링까지 이미 연결되어 있습니다. **이미 완전히 구현됨 — 249차
   스크린샷의 COMPARE 섹션에 인용구가 안 보인 건 버그가 아니라, 이번 생성에 쓰인 더미 입력에
   리뷰 파일이 없어서 `evidenceQuotes`가 빈 채로 나온 것(입력 부족)일 뿐입니다.**

6. **(C) 후커블 — 있다/없다 체크마크 그리드 비교** — `ComparisonChartSection.presentationStyle:
   "checklist"`(161차)로 이미 구현되어 있음을 코드로 재확인. **이미 해결됨.**

## 결론

이번 라운드도 **대부분 "정직한 null 결과"**입니다 — 새로 크롤링한 6개 패턴 중 4개는 이미
코드로 구현·렌더링까지 완료돼 있었고(POINT 배지, 원형 성분 시각화 2종, evidenceQuotes,
checklist 비교), 1개는 의도적 설계 차이(팔레트 순환 vs 단일색)로 확인됐습니다. **유일하게
남는 건 `illustration_banner`(추상 AI 일러스트 배경) 섹션 자체를 계속 쓸지에 대한 제품
방향 질문**입니다 — 이건 코드 버그가 아니라 "레이메이커·후커블 등 실제 서비스들은 애초에
이 방식을 안 쓴다"는 관찰이라, 자동으로 코드를 바꾸지 않고 사용자 결정을 기다립니다.

새 cursor_brief는 작성하지 않았습니다 — 이번 라운드에서 발견한 것 중 즉시 코드로 고칠 버그는
없었고(249차가 이미 그 섹션의 실제 버그를 고쳤음), 남은 1건은 사용자의 제품 방향 결정이
먼저 필요합니다.
