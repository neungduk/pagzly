# 57차 — 배경/합성 리얼리티 업그레이드 + 크기비교 다이어그램 일반화

생성: 2026-09-01

## 배경

"결과물이 MVP여도 퀄리티는 높아야 한다"는 요청으로 배경·합성·인포 세 가지에
집중해서 실제 마켓플레이스를 다시 크롤링했습니다. 이번엔 올리브영·마켓컬리 등
실제 판매 상세페이지를 직접 열어서 사진 스타일링 자체를 뜯어봤고, 우리
`lib/backdrop-prompt-templates.ts`와 대조해서 원인을 찾았습니다.

**핵심 발견**: 코드에 이미 이런 주석이 있습니다.

```ts
/**
 * 미니멀 — 구체적 사물(꽃잎·물방울·잎사귀) 없이 그라데이션·보케·비네트만.
 * 배경이 단순할수록 제품 합성 티(그림자·색온도 불일치)가 덜 도드라진다.
 */
```

즉 지금 배경 템플릿(화장품 제외 5개 카테고리: 패션/전자제품/식품/생활용품/
반려동물)은 전부 "smooth soft-focus gradient, no props" — 합성 티가 덜 나게
하려고 의도적으로 아무 사물도 없는 블러 그라데이션만 씁니다. 반면 실제 마켓컬리
와규 스테이크 상세페이지는 짙은 남색 세라믹 접시 + 소금 그릇 + 나무 소재 프롭을
써서 제품과 대비되는 색·질감으로 프리미엄하게 스타일링했고, 올리브영 클렌징폼도
녹두 알갱이를 실제로 흩뿌린 매크로샷이었습니다. 이게 사용자가 "결국 다 비슷한
베이지 톤"이라고 느낀 것과 같은 근본 원인입니다 — 안전하게 가려고 아무 개성 없는
배경을 쓰고 있는 것.

다만 코드 주석이 맞습니다 — 접시·캔 같은 뚜렷한 사물을 배경에 넣으면 제품이 그
위에 원근·그림자가 맞게 "놓인" 것처럼 보여야 하는데, 지금 합성 파이프라인
(`matchCutoutWhiteBalance` + `buildSilhouetteShadowBuffer`)은 전역 화이트밸런스와
단순 타원 그림자만 맞추는 수준이라 그런 정밀한 상호작용까지는 못 갖춥니다. 그래서
이번엔 "사물을 넣자"가 아니라, **화장품 카테고리에서 이미 하고 있는 절충안을
나머지 카테고리로 확장**하는 방향으로 브리프를 씁니다.

화장품의 `radiant`/`premium_dark` 템플릿을 보면 이미 "delicate flower petal or
silk fabric hint at frame edge", "fine suspended powder or mist particles" 같은
흐릿하고 가장자리에만 걸치는 재질 힌트를 씁니다 — 제품이 그 위에 정확히 "놓일"
필요가 없는 배경 요소라 원근/그림자 문제가 안 생기면서도 텍스처가 생깁니다. 지금
나머지 5개 카테고리 템플릿에는 이 절충안이 전혀 없고 순수 그라데이션뿐입니다.

## 이번 라운드 원칙

작업 A는 **실제 배경 생성 프롬프트를 바꾸는 작업**이라 검증에 진짜 이미지 생성이
필요합니다 — 이번엔 전체 카테고리가 아니라 **식품·전자제품 2개 카테고리만** 소규모
실제 생성 테스트로 검증해주세요 (52차처럼 QA 테스트 계정 크레딧 사용, 카테고리당
1회). 작업 B는 지난 라운드처럼 코드 전용/무료입니다.

## 작업 A — 카테고리별 배경 템플릿에 "가장자리 재질 힌트" 추가 (식품·전자제품 우선)

`lib/backdrop-prompt-templates.ts`의 `CATEGORY_PHOTOGRAPHY_TEMPLATES`에서
`식품/건강기능식품`과 `전자제품` 두 항목의 `texture`/`prompt`를 화장품
`radiant`/`premium_dark`와 같은 절충안으로 보강해주세요:

- **식품**: 지금 "smooth warm cream-to-sand soft-focus gradient, no food props"
  → 여기에 "흐릿하게 아웃포커스 처리된 우드 그레인 또는 리넨 텍스처가 프레임
  가장자리에만 살짝 걸치는" 힌트를 추가. 마켓컬리에서 본 것처럼 따뜻한 나무
  질감이 식품 카테고리에 잘 맞습니다. 단, "no plates, no dishes, no ceramic
  objects with defined edges" 같은 배제 문구는 그대로 유지 — 뚜렷한 윤곽의 접시
  같은 사물은 여전히 금지, 흐릿한 재질 텍스처만 허용.
- **전자제품**: 지금 "smooth cool gray-to-slate soft-focus gradient, no
  geometric props" → 흐릿한 브러시드 메탈 또는 콘크리트 텍스처가 가장자리에만
  걸치는 힌트 추가. 역시 뚜렷한 사물 윤곽은 계속 배제.

두 카테고리 모두 기존 "no product, no text, no logo" 등 안전장치 문구는 그대로
유지하고, **오직 가장자리 아웃포커스 재질 텍스처만 추가**하는 최소 변경으로
해주세요. `matchCutoutWhiteBalance`/그림자 생성 로직은 건드리지 마세요 — 이미
잘 동작하고 있고 이번 문제의 원인이 아닙니다.

### 검증 (실제 생성 필요, 카테고리당 1회로 제한)

- QA 테스트 계정에 크레딧이 부족하면 `grant_credits`로 최소량만 충전 (52차와
  동일 방식, 내부 SQL이라 무료)
- 식품·전자제품 각 1개 상품, 실제 `mode: final` 생성 1회씩만 실행 (전체 5카테고리
  재실행 금지 — 이번엔 비용을 최소화해야 합니다)
- 스크린샷으로 배경이 (a) 여전히 재질 텍스처가 사물처럼 어색하게 겹치지 않는지,
  (b) 이전보다 확실히 더 고급스러워 보이는지 육안 확인 후 보고

## 작업 B — 크기비교 다이어그램 일반화 (55차 사이즈 다이어그램 확장, 코드 전용/무료)

마켓컬리 상세정보 탭에서 발견한 패턴입니다: 와규 스테이크 실물 사진 옆에 500ml
음료수 캔 실루엣을 그려놓고 "6.5cm / 16.5cm" 치수를 표시해서, 실물 크기를 직관적
으로 가늠하게 해줍니다. 이건 55/56차에서 만든 패션 사이즈 다이어그램과 원리가
같습니다 — 단지 옷이 아니라 아무 카테고리에나 적용 가능한 "크기 비교" 버전입니다.

요청:
- `lib/fashion-size-diagram.ts`의 SVG 화살표 다이어그램 로직을 참고해서,
  카테고리 무관하게 쓸 수 있는 "크기 비교" 다이어그램을 하나 추가해주세요.
  기준 사물은 흔히 아는 것 중 하나(예: 500ml 캔, 신용카드, A4 용지) 실루엣 +
  제품 쪽 실측값(스펙 테이블에 이미 있는 가로/세로/높이/지름 중 하나라도 있으면)
  으로 매칭.
- 어떤 spec_table 행이 "크기" 관련인지 라벨 화이트리스트로 매칭하세요 (예: 가로,
  세로, 높이, 지름, 길이, 사이즈, 크기). 매칭되는 값이 하나도 없으면 다이어그램을
  렌더링하지 않습니다 (플레이스홀더 값도 55차와 동일하게 제외).
- 패션의 `size_table`과 겹치지 않도록, 이 크기비교는 `spec_table`(일반 제품정보)
  슬롯에서만 동작하게 해주세요 — 패션 사이즈는 이미 55차가 처리합니다.
- 기존 인증 하이라이트(`isCertificationHighlight`)와 55차 퀵팩트 스트립이 이미
  "핵심 스펙 강조" 역할을 하고 있어서, 이번 라운드에 별도로 스펙 값 강조 스타일을
  더 추가할 필요는 없다고 판단했습니다 — 스킵하셔도 됩니다.

### 검증 (무료, `/dev/detail-preview?capture=1` 재활용)

- 56차와 같은 방식으로 실측 값이 있는 전자제품/식품 목업 시나리오를 추가하고
  캡처해주세요. `/api/generate` 호출 없이 확인 가능합니다.
