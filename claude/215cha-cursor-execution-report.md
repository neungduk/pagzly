## 2. graspOverlapFraction을 원시 좌표에서 독립적으로 재계산

보고서에 찍힌 overlap 값이 실제로 코드의 공식(`getBestGraspOverlapFraction` —
교집합 면적 / placement 면적)대로 나온 값인지, run-log에 남은 원시 bbox 좌표로
직접 재계산해 검증했습니다:

- **electronics attempt 1**: placement=(35,45,28×32), grasp=(38,58,18×20)
  → 교집합 18×19=342, placement 면적 28×32=896 → 342/896=**0.3817** ≈ 보고된 0.382 ✅
- **living attempt 2**: placement=(28,35,18×28), grasp=(28,42,12×14)
  → 교집합 12×14=168, placement 면적 18×28=504 → 168/504=**0.3333** = 보고된 0.333 ✅
- **beauty attempt 1**: placement=(35,30,20×35), grasp 2개 중 최댓값
  → g1과의 교집합 8×18=144, 면적 700 → 144/700=**0.2057** ≈ 보고된 0.206 ✅

세 건 모두 코드에 정의된 공식과 정확히 일치 — 보고서 수치가 조작되거나 어림값이 아니라
실제 Vision 응답 좌표에서 그대로 계산된 값임을 확인했습니다.
