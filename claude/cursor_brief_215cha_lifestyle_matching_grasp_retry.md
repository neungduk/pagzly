# 215차 — 라이프스타일 합성 매칭 3축 실사 검증 재시도 (유료, 정확히 4건만)

## 배경 — 214차는 왜 실패했나

214차(2건, $0.1087)는 정확히 지시대로 실행됐지만, 2건 모두 89차 grasp 세이프가드
(`detectHandPlacementWithGraspRetry`, `not-overlapping-grasp-region`)에 걸려
`pasteCutoutOnScene()`(211차가 수정한 매칭 경로)이 구조적으로 실행되지 않고
`nano-banana-fallback`으로만 끝났습니다(`214cha-cursor-execution-report.md` 참고).

원인을 코드(`lib/detect-held-object-placement.ts`)로 직접 추적한 결과, 문제는 세이프가드
자체가 아니라 **214차가 골랐던 라이프스타일 사진 2장이 애초에 "쥐는 사진"이 아니었던 것**
이었습니다:

- beauty 케이스(`pixabay-6886590.jpg`): 손등에 크림을 **비비는** 사진 — Vision 프롬프트가
  명시적으로 "손을 비비거나 쥘 틈이 없으면 graspRegions:[] 와 confidence:'low'"라고
  지시하는 바로 그 케이스였습니다. 애초에 쥐는 동작이 아니었습니다.
- electronics 케이스(`hand-31203656.jpeg`): 손이 **머그컵**을 감싸 쥐고 있는데, 짝지은
  상품은 **우드 아로마 디퓨저**(다른 카테고리, 다른 형태)였습니다 — 사진 속 실제 쥐는
  동작과 상품의 배치 제안이 서로 다른 자리를 가리켜 겹침이 낮게 나왔습니다.

## 절대 원칙 — 반드시 지킬 것

**정확히 4건의 실제(`mode: final`, `TEST_MODE=false`) 생성만 실행하세요. 5건째부터는
사용자 재허가 없이 절대 실행 금지입니다.** 위 표의 4쌍 그대로 사용하세요 — 다른 이미지로
바꾸지 마세요(이미 제가 골라둔 근거가 있습니다). 재시도·QA 재실행도 이 4건 카운트에
포함됩니다. **1건이 실패해도 무한 재시도하지 말고, 로그를 남긴 뒤 다음 건으로 진행**하세요
(214차와 달리 이번엔 "실패 시 즉시 전체 중단"이 아니라 "그 건만 기록하고 다음 건 진행" —
4건 각각의 성공/실패 패턴 자체가 이번 라운드의 관찰 대상입니다). 단, 4건을 모두 소진하면
그걸로 끝입니다 — 5건째는 없습니다.

## 할 것

1. 위 표의 4쌍을 그대로 사용해 `compositeProductOnLifestylePhoto()`를 4번 호출하세요
   (214차 스크립트 `scripts/214cha-lifestyle-matching-live.ts`를 템플릿으로 재사용해도
   좋습니다 — `CASES` 배열만 위 4쌍으로 교체하고 `MAX_RUNS = 4`로 변경).
2. AI가 인물을 새로 생성하는 옵션(img2img)은 이번에도 끄세요 — 실제 라이프스타일 사진 +
   실제 상품 컷아웃 픽셀 페이스트 경로만 대상입니다.
3. **건마다 `detectHandPlacementWithGraspRetry`의 콘솔 로그(각 attempt의
   `graspOverlapFraction`, `reliable`, `reject` 값)를 빠짐없이 보고서에 남기세요** — 214차
   보고서와 동일한 형식입니다. 성공하든 실패하든 이 로그가 핵심 증거입니다.
4. 결과 `method`가 `pixel-paste`/`pixel-paste+grasp-refine`으로 나온 건이 있으면, 그
   합성 이미지를 `review/215cha-live/`에 저장하고 **원본 라이프스타일 사진과 나란히 비교할
   수 있게** 함께 저장하세요 — 컷아웃이 배경과 잘 섞였는지(화이트밸런스·선명도·그레인)
   보는 게 이번 라운드의 핵심 목적입니다.
5. `nano-banana-fallback`으로 떨어진 건이 있어도 정상 기록하고 다음 건으로 진행하세요 —
   4건 중 일부만 성공해도 유의미한 결과입니다.
6. 실제 API 비용 로그를 4건 전부 빠짐없이 남기세요(214차와 동일 형식).
