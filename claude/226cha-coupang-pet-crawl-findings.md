# 226차 — 쿠팡 반려동물(강아지 사료) 실제 상세페이지 크롤링 — 발견사항 (2026-09-18)

Claude(Cowork)가 Claude-in-Chrome으로 쿠팡에 직접 접속해 확보한 실제 상세페이지 근거입니다.
"새 마켓플레이스/카테고리 크롤링" 방향 선택에 따라, `marketplace_crawl_findings_2026-09-07.md`가
아직 다루지 않은 카테고리(반려동물)를 이미 접근 가능이 확인된 마켓(쿠팡, 210차)에서 크롤링했습니다.

## 0. 대상

쿠팡 "마이펫닥터 강아지 시그니처 티어스 컨트롤 기능성 사료"(상품번호 6224528154, 기능성사료,
눈물개선/눈건강, 후기 23,922개) — 기능성/문제해결형 반려동물 사료로, Pagzly의 반려동물 카테고리
(222차에서 컴플라이언스 완료)와 직접 비교 가능한 사례.

## 1. 관찰 순서

히어로(제품컷+가격) → "함께 비교하면 좋을 상품"(교차판매) → 유튜브 광고 영상 임베드 2개 →
**pain-point 대비 헤드라인 배너**("반려견 눈 건강 맞춤 유기농 70% 사료 / 시그니처 티어스 컨트롤") →
**실제 고객 Before/After 사진 + 리뷰 인용 카드(반복, 최소 2세트 확인)** → "상품정보 더보기"(접힌
아코디언) → **집계 평점 강조 섹션**("소비자들의 이유 있는 선택" + 4.85/5 대형 숫자 + 리뷰 스크린샷
스타일 카드, 닉네임·별점·하이라이트 인용문) → "*마이펫닥터 네이버스토어 구매자 후기를 발췌 및
인용하였습니다" 출처 고지 → **해시태그 뱃지 헤드라인**("#유기농맛집 #기호성PICK") → **원형 인증
씰 그래픽**(유기농70% ORGANIC 70%, HACCP) → 교차판매/리뷰탭.

## 2. 발견 패턴 4건 — 코드 대조 결과

### 2.1 Before/After 실사진 비교 모듈 (가장 뚜렷한 패턴, 최소 2세트 반복)

"Before"/"After" 라벨이 붙은 반쪽 이미지 쌍(눈물자국 있는 강아지 → 개선된 강아지) 아래에 실제
구매자 리뷰(별점+짧은 인용)가 바로 붙어, "사진으로 보여주는 효과 + 그걸 증언하는 후기"를 한
블록으로 묶은 구성. 기능성/문제해결형 상품(반려동물뿐 아니라 화장품/뷰티, 건강기능식품에도 흔한
패턴)에 특히 강력.

**코드 대조**: `lib/types/generate.ts`를 전수 검색(`before`/`Before`/`beforeAfter` 등) — 0건.
`DetailSection` 어떤 타입에도 "비교 전/후 사진 쌍" 필드가 없고, `ProductInput`에도 사용자가 이런
사진을 입력할 필드 자체가 없음(`imageShape`/`annotations`/`circlePair`/`circleSolo`는 있지만 전부
다른 용도). **결론: 코드 버그가 아니라 입력 기근(입력 부족)** — Pagzly가 이 섹션을 만들려면 판매자가
실제 "효과 전/후" 사진 쌍을 올릴 수 있는 새 입력 필드가 먼저 필요하고, 입력 없이 AI가 전/후 사진을
지어내는 것은 지어내기 금지 원칙에 정면 위반. **코드 브리프 대상 아님 — 신규 입력 기능(제품 폼에
"효과 비교 사진" 업로드 슬롯 추가) 후보로만 기록, 제품 결정 필요.**

### 2.2 개별 리뷰어 "스크린샷 스타일" 인용 카드 (닉네임+별점+하이라이트 형광펜 표시)

"소비자들의 이유 있는 선택" 섹션에서 `jdla*****`, `wimd*****` 같은 마스킹된 닉네임 + 별점 5개 +
원문 그대로의 리뷰 텍스트(형광펜으로 핵심 구절 강조)를 카드로 나열. 실제 리뷰 캡처를 흉내 낸 UI.

**코드 대조**: `lib/types/generate.ts`의 `ReviewHighlightSection` 주석(430~433행)이 명시적으로
"praises는 원문 그대로의 인용문이 아니라 여러 리뷰에서 반복된 내용의 요약"이며 "렌더링 시 특정
인물이 말한 것처럼(가짜 이름·별점 등) 표시하지 않는다"고 **이미 이 패턴을 의도적으로 배제**하고
있음을 확인. Pagzly의 리뷰 파이프라인은 집계·요약만 보관하고 개별 리뷰 원문·작성자를 보존하지
않는 구조라, 이 패턴을 흉내 내려면 (a) 실제로 존재하지 않는 리뷰어 닉네임/별점을 지어내거나 (b)
집계 요약을 마치 한 사람이 쓴 것처럼 재포장해야 함 — 둘 다 지어내기 금지 원칙 위반. **채택 금지로
확정 기록.**

### 2.3 원형 인증 씰 그래픽 (유기농 70% ORGANIC, HACCP — 뱃지 아이콘)

텍스트 pill 뱃지가 아니라 원형 씰(seal) 형태의 인증 아이콘을 제품컷 옆에 나란히 배치. Pagzly의
`trustStripHtml()`/`extractTrustChips()`는 현재 pill 형태 텍스트 배지만 렌더링(기존 코드 확인 완료,
206~222차에 걸쳐 다수 카테고리 컴플라이언스 작업에서 재확인한 구조).

**판단**: 이건 사실(인증) 표시 방식의 시각적 스타일 차이일 뿐 기능 결손이 아님 — pill 배지도 인증
정보를 정확히 전달하고 있어 "버그"로 분류할 근거가 약함. 07차 지마켓 크롤링에서 이미 "MD
캐릭터/손글씨 뱃지 같은 과장된 톤은 Pagzly의 미니멀·프리미엄 원칙과 배치"로 채택 비권장 판단을
내린 전례와 결이 비슷하나, 원형 씰 자체는 과장된 톤이 아니라 오히려 표준적인 인증 표기 관행이라
완전히 같은 논리는 아님. **취향 차이 후보로만 기록** — 강제로 도입하지 않음, 사용자가 원하면 별도
SVG 배지 컴포넌트(기존 `*-diagram.ts` 패턴 재사용 가능)로 다음 라운드 검토 가능.

### 2.4 해시태그 뱃지 헤드라인 ("#유기농맛집 #기호성PICK")

빅 헤드라인 위/아래에 인스타그램풍 해시태그 pill을 나열하는 장식적 패턴. 정보량 없이 톤앤매너
장식 요소. **취향 차이 후보로만 기록**, 우선순위 낮음.

## 3. 결론 — 이번 라운드(226차) 코드 변경 없음

4개 패턴 모두 (1) 입력 기근(2.1, 새 입력 필드가 필요한 제품 결정 사항)이거나 (2) Pagzly 자체
원칙과 정면 충돌해 채택 불가(2.2)이거나 (3) 순수 취향/스타일 차이(2.3, 2.4)로 분류돼, **§3(코드만으로
가능한 미해결)에 추가할 항목이 없음** — 208/210/213차와 같은 계열의 정직한 null 결과.

가장 유력한 후속 조치는 2.1(Before/After 효과 비교 사진)이지만, 이는 코드 브리프가 아니라 **제품
결정**(판매자가 이런 사진을 올릴 입력 슬롯을 새로 만들지, 만든다면 어떤 카테고리에 어떤 가드레일을
둘지)이 먼저 필요합니다.

## 4. 절대 원칙 재확인

1. 경쟁사 카피/디자인 복제 금지 — 구조·패턴만 참고.
2. 개별 리뷰어 닉네임·별점을 지어내거나, 집계 요약을 실명 인용처럼 재포장 금지 (2.2 채택 금지 근거).
3. 입력되지 않은 전/후 비교 사진·통계·인증 정보 날조 금지 (2.1 입력 기근 판단 근거).
4. `section-templates` 슬롯 순서/종류 변경 금지 (승인 없이).
