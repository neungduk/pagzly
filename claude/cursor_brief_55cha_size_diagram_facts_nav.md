# 55차 — 사이즈 다이어그램 · 퀵팩트 스트립 · 섹션 앵커 내비게이션 (코드 전용)

생성: 2026-09-01

## 배경

실제 마켓플레이스(무신사·29CM·아마존) 상세페이지를 다시 벤치마크 리서치했습니다.
그 결과를 우리 코드베이스(`lib/types/generate.ts`, `lib/section-templates.ts`,
`DetailSectionRenderer.tsx`, `export-detail-html.ts`)와 하나씩 대조해서, 실제로
비어 있는 부분과 이미 있어서 손댈 필요 없는 부분을 나눴습니다.

**이미 커버되어 있어 이번 라운드에서 다루지 않는 것** (참고용):
- 아마존 A+의 속성 비교표(제품 A vs B 항목별 값) → `comparison_table` 타입과 구조
  동일
- 아마존의 수치 막대 비교 → `comparison_chart`("우리 제품 vs 일반 제품")로 이미 커버
- 아이콘+라벨 4칸 기능 그리드 → `checklist`/`highlight_box`로 대응 가능
- 29CM 전자제품 스펙 테이블이 텍스트 위주인 것 → 우리도 동일 방식이고 53차에서
  이미 상품 사진 썸네일을 붙였으므로 추가 작업 불필요

**실제로 비어 있는 것 — 이번 라운드 대상**은 아래 작업 A/B/C입니다.

## 이번 라운드 원칙 — 비용 발생 없음

이번에도 코드 수정 + 무료 검증만 합니다. 새 AI 이미지 생성이나 API 호출은 필요
없습니다.

## 작업 A (최우선) — 사이즈 다이어그램 (패션 카테고리 전용)

`lib/section-templates.ts`를 보면 패션의 `size_table` 슬롯은 `spec_table` 타입이라
순수 텍스트표이고, `fit_guide` 슬롯은 `image_text`라 실제 상품 사진 + 설명 한두
줄일 뿐입니다. 무신사처럼 옷 실루엣 위에 화살표로 "어깨너비/가슴단면/총장/소매길이"
같은 치수 위치를 짚어주는 도식이 어디에도 없습니다.

이건 실제 상품 사진이 아니라 선으로 그린 스키마틱이므로 AI 이미지 생성 없이
코드에서 SVG로 그릴 수 있습니다. `size_table`에 이미 들어가는 실측 데이터
(`rows: { label, value }[]`)를 그대로 재사용하면 됩니다.

요청:
- 패션 카테고리의 `size_table` 섹션 렌더링(`DetailSectionRenderer.tsx`와
  `export-detail-html.ts` 양쪽)에, 기본 상의 실루엣 SVG + 화살표/라벨을 얹은
  다이어그램을 표 위(또는 옆)에 추가해주세요.
- 실측 항목명(어깨너비/가슴단면/총장/소매길이 등 자주 쓰이는 라벨)과 다이어그램
  화살표 위치를 매칭하는 프리셋을 하나 정의하고, 매칭되는 라벨이 있을 때만 해당
  화살표를 표시하세요. 매칭 안 되는 항목("판매자 확인 필요" 등)은 화살표 없이
  생략하고, 표는 기존처럼 그대로 병행 표시합니다.
- 스코프를 좁히기 위해 상의 실루엣 1종 프리셋으로 시작하는 걸 권장합니다. 하의/
  아우터 등 다른 실루엣은 다음 라운드로 미뤄도 됩니다.
- 새 섹션 타입을 만들기보다는 기존 `size_table`(`spec_table`) 렌더링에 다이어그램을
  "추가"하는 방향으로 해주세요. 패션이 아닌 카테고리는 기존과 동일하게 다이어그램
  없이 표만 표시합니다.

무신사의 "키/몸무게 입력 → 비슷한 체형 추천 사이즈" 개인화 도구는 이번 라운드
범위가 아닙니다. 필요하면 다음 라운드에서 별도로 검토합니다.

## 작업 B — 퀵팩트 스트립

무신사 "정보" 탭 상단에는 품번/성별/시즌/누적판매처럼 훑어보기용 압축 한 줄
요약이 있는데, 우리 상세페이지에는 이런 압축 라인이 없습니다.

요청:
- T1-A 브랜드 타이틀 카드 직후에, 해당 상품의 `spec_table` rows 중 핵심 2~4개를
  뽑아 얇은 가로 스트립으로 보여주는 컴포넌트를 추가해주세요. 예:
  "소재 : 코튼 100%  ·  원산지 : 국내  ·  색상 : 3종".
- 새 카피를 만들지 말고 기존 spec_table 데이터를 그대로 재사용하세요. 어떤 rows를
  "핵심"으로 뽑을지는 복잡하게 만들지 말고, 라벨 화이트리스트(소재/원산지/용량/
  색상/제조사 등 자주 나오는 라벨)와 매칭되는 것을 우선하거나, 없으면 앞쪽 1~2개
  rows를 기본으로 쓰는 정도로 단순하게 처리해주세요.
- spec_table 자체가 없거나 매칭되는 값이 하나도 없으면 스트립을 아예 렌더링하지
  않도록 해주세요.

## 작업 C — 섹션 앵커 내비게이션 (고정 점프 바)

페이지가 길어서 이동이 불편한 문제입니다. 무신사처럼 탭 전환까지 만드는 건 이번
스코프가 아니고, 클릭하면 해당 섹션으로 스크롤 이동하는 얇은 sticky 바 정도면
충분합니다.

`export-detail-html.ts`를 보면 하단 CTA 바가 이미 `position:sticky`로 실제
프로덕션에서 정상 렌더되는 걸 51~53차 스크린샷으로 확인했습니다. 같은 기법을
재사용하면 리스크가 낮습니다.

요청:
- 상단(또는 CTA 바로 아래)에 섹션 앵커 바를 추가해주세요. 실제로 그 페이지에
  존재하는 주요 섹션(제품정보/사이즈/구성/후기 등, 있는 것만)에 `id`를 부여하고,
  앵커 바 클릭 시 해당 섹션으로 스크롤 이동하도록 해주세요.
- 존재하지 않는 섹션에 대한 링크는 만들지 마세요.

**주의**: 이 결과물이 실제로 올라가는 곳(스마트스토어 등 마켓플레이스 상세설명
에디터)이 sticky/앵커 스크립트를 그대로 보존하는지는 확신할 수 없습니다. 로컬 QA
프리뷰에서 정상 동작하는 것만 확인하고, 실제 마켓플레이스 붙여넣기 호환성은 이번
라운드에서 "정상 동작함"이라고 단정하지 말고 "확인 필요"로 보고해주세요.
