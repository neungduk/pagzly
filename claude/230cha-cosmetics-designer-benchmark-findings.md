# 230차 — 화장품/뷰티 카테고리 디자이너 벤치마크 (무료, 신규 크롤링)

생성: 2026-09-22 · 유료 API 0건 · 코드 변경 0(조사만)

## 배경

229차실행검증까지 마친 뒤 사용자가 "디자이너가 만들었다고 할 정도로 나와야해 퀄리티가"로
장기 과제("디자이너·후커블 수준" 품질 기준, 63차~228차 다수)를 재확인. 228차가 같은 날 이미
hookable.ai + 전자제품·생활용품 Behance 레퍼런스를 새로 벤치마크했으므로, 겹치지 않는 카테고리로
넓히는 게 가장 가치 있다고 판단해 **화장품/뷰티** 카테고리를 선택했습니다 — 이 카테고리의 마지막
전용 크롤링은 159차(2026-09-10)와 181차(2026-09-14, 6카테고리 얕게 훑음)로, 12일 이상 지났고
그 사이 188/189차(WCAG), 195~198차(에디토리얼 오버레이), 228차(리뷰 하이라이트) 등 다수 변경이
있었습니다.

## 방법

158/159/160/181/228차와 동일한 4축(레이아웃 / 타이포·여백 / 이미지 합성 자연스러움 / 정보 위계)
+ 격차 3분류(버그 / 취향 차이 / 입력 부족) 규율 그대로 적용. Behance에서 화장품/뷰티 카테고리와
정확히 겹치는 실제 판매 상세페이지 1건을 신규 크롤링(159/181/228차와 겹치지 않는 레퍼런스).

### 레퍼런스: "Neriah Stellar Water Fluid Ampoule Page" (Moon Joo won, Behance)

수분 앰플(히알루론산 + 판테놀) 자사몰 상세페이지. 히어로부터 전성분/주의사항 고시까지 전체
스크롤(약 5만px) 직접 열람.

## 발견 패턴과 코드 대조

1. **리뷰 인용구 내 핵심 문구 인라인 강조**(파란색 텍스트, 말풍선 카드 2곳) — 228차가 같은 날
   이미 구현·Cursor 실행 완료한 `splitTextByKeywords()`(리뷰 하이라이트 키워드 인라인 강조)와
   정확히 같은 패턴입니다. **재작업 불필요, 이미 오늘 자로 구현됨** — 오히려 이번 벤치마크가
   228차 판단이 옳았음을 실제 판매 사이트로 재확인해준 셈입니다.

2. **별점(★5) + 마스킹 아이디 + "자사몰 리뷰" 태그 + 실제 리뷰어 언박싱 사진**(리뷰 카드 다수) —
   226차 쿠팡 반려동물 크롤링에서 이미 동일 패턴을 발견해 "`ReviewHighlightSection`의 가짜
   귀속 금지 원칙과 충돌 + `reviewInsights` 타입에 rating/사진 필드 없음"으로 **채택 금지
   확정**한 바 있음 — grep으로 타입 재확인, 결론 동일. **재확인만, 신규 아님.**

3. **원형 크롭 사진 + 성분명 + 효능 한 줄**(성분 카드, "베타글루칸" 등) — `lib/apply-ingredient-circle-pair.ts`
   (207차 texture_feel 폴백까지 구현됨)의 원형 사진 페어 패턴과 구조적으로 동일. **신규 격차
   아님.**

4. **"바르고 난 직후 / 24시간 후" 실사진 Before/After 비교**(얼굴 클로즈업 2장, 라벨 캡션) —
   227차가 이미 "Before/After 효과 비교 입력" 기능을 구현했으나, **화장품/뷰티는 A안(226차
   발견 후 227차 설계검토)에서 서버·UI 이중 차단으로 명시적으로 제외한 카테고리**입니다(사유:
   "효과·효능 확정 주장"이 법적으로 민감, 화장품법상 텍스트 regex로 순화 불가능한 시각적 효능
   주장). 즉 이 레퍼런스가 실제로 쓰고 있는 패턴이지만 **Pagzly는 227차에서 이미 이 카테고리에
   한해 의도적으로 막아둔 상태** — 재확인만, 코드 변경 없음.

5. **"사용 전 → 사용 직후 → 7일 사용 후" 3시점 임상 추이 꺾은선 그래프**(수분측정/탄력도측정/
   민감도측정 3종, 각각 "네리아 본사 측정/내부 항목 테스트/일시적/개인차 있음/측정장비명" 출처
   각주 포함) — **이번 라운드에서 가장 눈에 띈 패턴**이었습니다. `lib/types/generate.ts`를
   확인한 결과 Pagzly의 기존 수치 인포그래픽 2종은 이 패턴을 커버하지 못합니다:
   - `StatInfographicSection`(348행)의 metrics는 **단일 시점 값**(bar/number/ring)만 표현 —
     시간 축이 없음.
   - `ComparisonChartSection`(266행)은 "우리 제품 vs 비교 대상" **정적 2열 비교**일 뿐,
     3개 이상의 시점을 잇는 추이선(trend line)은 표현할 수 없음.

   즉 **Pagzly에는 "시간 경과에 따른 수치 변화(꺾은선)"를 그릴 수 있는 컴포넌트 자체가 없습니다**
   — 이건 렌더링 버그가 아니라 순수한 기능 공백(신규 컴포넌트가 필요한 "제품 결정" 스코프)입니다.

   **하지만 이 패턴을 실제로 구현하는 것은 권장하지 않습니다.** 이유는 4번 항목과 정확히
   같습니다 — "바르고 난 직후/24시간 후 피부가 이렇게 좋아진다"는 사진 Before/After보다, **수치로
   "7일 만에 피부 탄력이 90% 개선됐다"는 시계열 꺾은선 그래프가 오히려 더 명시적인 효능 확정
   주장**입니다. 227차가 화장품/뷰티·반려동물·식품/건강기능식품 3카테고리를 Before/After에서
   제외한 근거(컴플라이언스 모듈이 이미 존재하는, 효능 주장에 법적으로 민감한 카테고리)가 이
   패턴에는 **더 강하게** 적용됩니다. 레퍼런스 자체도 "네리아 본사 측정"(제3자 인증기관 아닌
   자체 측정), "개인차가 있을 수 있음" 각주를 달아 리스크를 인지하고 있는 것으로 보입니다.

   **판단: 227차 A안과 동일한 경계로 신규 컴포넌트를 만들지 않습니다.** 화장품/뷰티·반려동물·
   식품/건강기능식품에는 애초에 부적합(효능 시계열 주장), 전자제품/생활용품/패션은 애초에 이런
   "시간에 따른 신체/제품 변화 추이"를 측정할 대상 자체가 자연스럽지 않아(예: 전자제품이 "7일
   후 개선"될 일이 없음) 실사용 니즈가 낮습니다. **6개 카테고리 전부에 대해 "만들지 않는 게
   맞다"는 결론이라, §3(미해결·API불필요)에도 등록하지 않고 여기 기록만 남깁니다** — 158/159차
   "억지 구현 금지" 원칙, 227차 컴플라이언스 판단과 동일한 결.

6. **"STEP1/STEP2 사용법 + 괄호 안 빨간 주의문구 + 하단 TIP 콜아웃"**(모델링팩과 앰플을 섞어
   쓰는 특수 사용법) — `UsageStepsSection`(`lib/types/generate.ts` 221행)의 `steps: string[]`는
   이미 자유 텍스트 배열이라 "STEP1. ...(물은 조금 적게 넣어주세요)" 같은 괄호 주의문·TIP 문장을
   **스텝 텍스트 안에 그대로 포함해서 쓸 수 있음**(구조 변경 불필요, AI 카피 작성 방식의 문제일
   뿐). **코드 격차 아님.**

7. **전성분/주의사항 법정 고시 표** — Pagzly의 `spec_table`(화장품 카테고리 필수 슬롯, 이미
   구현됨)과 구조적으로 동일. **재확인만.**

## 결론

이번 라운드는 **정직한 null 결과**입니다 — 6개 발견 패턴 중 5개는 이미 해결됨/이미 의도적으로
막아둠/이미 기존 스키마로 커버 가능이었고, 유일한 신규 패턴(시계열 추이 그래프)은 227차가 이미
확립한 컴플라이언스 경계(화장품/뷰티 등 효능-민감 카테고리에서 "효과 확정 시각화"를 만들지
않는다)를 오히려 더 강하게 재확인시켜주는 사례였습니다. 새 브리프는 작성하지 않았습니다 —
§3(미해결·API불필요)는 계속 비어 있는 상태이며, 다음 라운드는 사용자 지정 방향으로 진행하는 게
맞다고 판단합니다.
