# 107차 — 화장품 카테고리 주석 콜아웃 확장 + 브랜드 스토리 깊이

생성: 2026-09-03
전제: 사용자가 실제 판매 중인 고품질 상세페이지(마유에스테, 버가못 BB, 이어폰, 락토핏, 후커블로 만든 glowiest 페이지)를 레퍼런스로 제시하며 "우리 결과물과의 격차를 메워달라"고 요청했습니다. 감사 결과 격차의 상당 부분은 **코드에 기능이 없어서**가 아니라 **있는 기능이 좁은 조건에 막혀 있거나, 섹션 구조 자체가 얕아서**였습니다.

이번 라운드는 그중 **임팩트가 크고 리스크가 낮은 두 가지**를 실행합니다. 나머지는 마지막 "후속 로드맵"에 정리했습니다.

## 작업 A — 제품 사진 위 주석 콜아웃을 화장품까지 확장

### 현재 상태

레퍼런스들의 가장 눈에 띄는 공통 장치가 **제품 사진 위에 선·원으로 특정 부위를 가리키며 라벨을 다는 주석 콜아웃**입니다(마유에스테의 물방울 버블 라벨, 이어폰 사진의 기능 설명 원형 콜아웃).

이 기능은 **이미 완성되어 있습니다**:
- `components/AnnotatedImageOverlay.tsx` — 렌더링 완성
- `lib/analyze-product-annotations.ts` — Vision으로 주석 지점 분석
- `lib/product-annotations.ts:29-37` — 신뢰도 판정(라벨 2개 이상, 서로 다른 그리드 셀, 서로 다른 라벨)
- `lib/apply-electronics-annotations.ts:5,13,17-19` — 적용

그런데 실제로 켜지는 조건이 `app/api/generate/route.ts:1354`의 **`category === "전자제품" && mode === "final"`** 뿐이고, 적용 슬롯도 `feature_detail` 하나입니다. **화장품·식품·생활용품에서는 원천적으로 나올 수 없습니다.**

### 해야 할 일

1. **카테고리 게이트를 화장품/뷰티까지 확장**하세요(`route.ts:1354`). 구조상 `apply-electronics-annotations.ts`가 전자제품 전용 문구를 담고 있다면, 카테고리별 라벨 생성 규칙을 분리한 `apply-cosmetics-annotations.ts`를 새로 만들고 공통 로직은 재사용하세요.
2. **적용 슬롯을 넓히세요.** 화장품에서는 `feature_detail` 외에 `packaging_design`(용기 구조), `texture_feel`(제형), `size_options`(용량 표기)가 콜아웃과 잘 맞습니다. 다만 한 페이지에 콜아웃이 남발되면 지저분해지므로 **최대 2개 섹션까지만** 적용하세요.
3. **신뢰도 게이트(`product-annotations.ts:29-37`)는 그대로 유지**하세요. 라벨이 1개뿐이거나 지점이 겹치면 적용하지 않는 게 맞습니다.

### 반드시 지킬 것 — 라벨 내용 규칙

**콜아웃 라벨은 사진에서 실제로 보이는 물리적 특징만 가리켜야 합니다.** 예를 들어 이번 glowiest 미스트라면:

- 좋은 예: "미세 분사 노즐", "오일층·워터층 경계", "35mL 컴팩트 보틀", "프로스트 글라스", "무광 블랙 캡"
- **금지**: "속건조 케어", "24시간 보습", "피부 장벽 강화" 같은 **효능·효과 주장**. 사진의 특정 지점이 그 효능을 증명하지 않으며, 화장품 표시광고 규제 대상이 됩니다.

리포에 이미 `lib/cosmetics-compliance.ts`가 있습니다. **생성된 콜아웃 라벨을 반드시 이 가드를 통과시키세요.** 통과하지 못하는 라벨은 버리고, 남은 라벨이 2개 미만이면 콜아웃 자체를 적용하지 마세요.

Vision 프롬프트에도 "물리적으로 보이는 구조·재질·표기만 지목하고, 효능이나 사용 결과는 언급하지 말 것"을 명시하세요.

## 작업 B — 브랜드 스토리 섹션의 깊이

### 현재 상태

`components/DetailSectionRenderer.tsx:2562-2646` `case "brand_story"`는 브랜드명 컬러 블록 + `QuickFactStrip` + **제목 한 줄 + 본문 한 단락**이 전부입니다. **이미지 필드가 아예 없습니다.**

레퍼런스(마유에스테)는 여기서 공장·창업자·원산지 사진과 함께 서사를 풀어 신뢰를 만듭니다. 우리 쪽은 구조적으로 그게 불가능합니다.

### 해야 할 일

1. **`brand_story` 섹션 타입에 선택적 이미지 슬롯을 추가**하세요. 1~2장을 받아 본문 옆이나 아래에 배치하는 레이아웃을 넣습니다. 이미지가 없으면 지금과 동일하게 텍스트만 렌더링해야 합니다(하위 호환).
2. **이미지는 "남는 컷"에서만 가져오세요.** 104차에서 확인했듯 공급이 부족한 상황이라, 브랜드 스토리가 성분·질감·패키지 같은 더 중요한 슬롯의 이미지를 뺏으면 안 됩니다. `assignDistinctSectionImages`에서 **다른 모든 슬롯 배정이 끝난 뒤 미사용 컷이 남아 있을 때만** 브랜드 스토리에 배정하세요. 남는 게 없으면 텍스트 전용으로 두는 게 맞습니다.
3. **본문 길이 제한을 완화**하세요. 지금 한 단락으로 고정된 구조라면 2~3단락까지 허용하고, `section-templates.ts`의 `brand_story` note에도 "브랜드의 시작·철학·만드는 방식 중 하나를 골라 2~3문단으로"처럼 서사를 유도하는 지시를 넣으세요. 단, **판매자가 입력하지 않은 사실(창업 연도, 공장 위치, 수상 이력 등)을 지어내지 말 것**을 프롬프트에 명시하세요. 입력이 없으면 짧게 쓰는 편이 낫습니다.

# 후속 로드맵 (108차 이후 — 이번 라운드에서 하지 말 것)

감사에서 확인된 나머지 격차입니다. 각각 별도 라운드로 진행합니다.

### 108차 예정 — 장식적 배경 허용 범위 확대
`lib/design-tokens.ts:64-66` 주석에 **"그라데이션은 hero 전용"** 이라고 못박혀 있고, 본문 섹션은 A/B/C/D/E 5종 옅은 그라디언트 + 카테고리별 SVG 패턴(불투명도 4~6%, `:133-139`)만 허용됩니다. 레퍼런스의 골드 글리터·물 스플래시 같은 **사진형 텍스처 배경은 설계상 배제**돼 있습니다.
→ 전면 개방은 위험하므로, **강조 섹션 1~2개에 한해** 사진형 배경을 허용하는 슬롯 화이트리스트 방식으로 여는 것을 검토. 텍스트 가독성(대비비) 검증이 필수.

### 109차 예정 — 히어로 워드마크 타이포
레퍼런스는 브랜드명을 로고처럼 조판합니다(glowiest 페이지 상단). 리포 전체 검색 결과 **관련 코드가 0건**입니다.
→ 브랜드명을 히어로에서 워드마크 스타일로 조판하는 옵션 추가. 실제 로고 파일 업로드 슬롯을 두는 편이 더 정확할 수 있으니 함께 검토.

### 110차 예정 — 설명형 다이어그램
현재 인포그래픽(`DetailSectionRenderer.tsx:1935-2093` `stat_infographic`)은 **숫자 카드·원형 게이지·막대**뿐입니다. 레퍼런스의 피부 장벽 구조도, 지방산 비교표 같은 **그림형 설명 다이어그램**은 없습니다.
→ 카테고리별 개념 다이어그램 세트를 준비하거나 생성하는 방향. 난이도 상, 별도 설계 필요.

### 별도 검토 — 픽셀 합성 전환 (103차에서 이월)
AI 사용샷이 제품을 재생성하는 구조를 **빈 인물 씬 생성 + 실제 누끼 합성 + 실측 치수 기반 스케일**로 바꾸는 근본 수정. 필요한 부품(`lifestyle-product-composite.ts`, `detect-held-object-placement.ts`)은 64~93차에 이미 있습니다. 106차의 옵트인·배지는 그때까지의 임시 방편입니다.
