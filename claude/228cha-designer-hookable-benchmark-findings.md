# 228차 — 후커블·디자이너 벤치마크 재크롤링 (무료)

생성: 2026-09-22 · 유료 API 0건 · 코드 변경 0(이번 문서는 조사·지시서 작성만)

## 배경

사용자 요청: "디자이너 그리고 후커블이 만든것과 똑같은 퀄리티가 나와야해 알아서 크롤링을 해도
되고 학습해서 우리가 보완해야할점 지시사항 남겨줘. 유료 api 호출은 하지마."

"후커블과 디자이너가 만든 수준" 장기 과제(63~219차 다수, 158/159/160/181차가 정립한 4축
방법론)의 다음 한 걸음입니다. 직전 재벤치마크는 219차(2026-09-17, 무료·기존 자료 재열람)였고,
그 이후(220~227차)는 대부분 export/라이브 패리티 버그 수정과 카테고리 컴플라이언스 롤아웃이라
새 디자인 레퍼런스를 크롤링한 지는 181차(2026-09-14) 이후 처음입니다.

## 방법

158/159/160/181/219차와 동일한 4축(레이아웃 / 타이포·여백 / 이미지 합성 자연스러움 / 정보
위계) + 격차 3분류(버그 / 취향 차이 / 입력 부족) 규율을 그대로 적용했습니다. 148/160차의
"입력 기근 함정" 교훈에 따라, 레퍼런스에서 본 패턴을 채택 후보로 올리기 전에 반드시 실제
코드(타입·함수·렌더러)를 열어 "이미 있는지/입력이 있는지/버그인지"부터 확인했습니다.

## 1. 후커블(hookable.ai) — 자사 마케팅 페이지 직접 크롤링

로그인 없이 접근 가능한 공개 랜딩 페이지만 크롤링(실제 생성 예시는 로그인 후에만 노출되는
것으로 보임 — 63차 때와 동일한 제약).

- **"원하는 디자인 레퍼런스, 가져만 오세요"**: 무드/톤앤매너 분석 + 레퍼런스 URL 입력 필드.
  Pagzly는 `referenceImage`(업로드 이미지 기반 색상/무드 분석)는 있으나 **URL 기반 레퍼런스
  입력은 없음** — 입력 방식 차이일 뿐 기능적으로는 유사한 목적. 신규 채택 여부는 이번 스코프
  밖(별도 제품 결정 필요, §3에 올리지 않음).
- **카피라이팅 설득 프레임워크 태그(인증/비교/요약/문제제기/반박 제거/소구점 구체화/사회적
  증거/나열)**: 코드 확인 결과 **138차에 이미 `lib/section-persuasion-labels.ts`로 구현
  완료** — 파일 자체 주석이 "후커블의 페르수전 태그 시스템을 참고하되, 두려움 조성 표현(반박
  제거 등)은 배제"라고 명시. **재작업 불필요, 이미 해결됨.**
- **이미지 생성 프롬프트(DALL·E/Midjourney) 복사 제공**: 후커블은 자체 이미지 생성 없이
  사용자가 프롬프트를 복사해 외부 도구에 붙여넣는 구조. Pagzly는 Replicate 기반 인하우스
  생성이라 오히려 **더 자동화된 구조** — 격차 아님, 채택 후보 아님(오히려 Pagzly가 앞서는 지점).
- 데이터 분석 대시보드(어떤 섹션이 시선을 끌었는지), 피그마 내보내기, 팀 협업, 모바일
  반응형 — 전부 제품 인프라/과금 레벨 기능이라 이번 "디자인 퀄리티" 스코프 밖으로 판단,
  기록만 하고 §3엔 올리지 않음.

158/159/181차와 겹치지 않는 레퍼런스를 우선 선택(159차는 pet+beauty, 181차는 6카테고리
전체를 얕게 훑음 — 이번엔 최근 코드 변경(223~225차 export 패리티, 222차 컴플라이언스)이

### (A) "주방 가전 상세페이지 디자인" — OHMY SOOJIN, 전자제품(주방가전) 카테고리

RICOPA 오븐 토스터. 히어로부터 CTA까지 전체 스크롤 직접 열람.

1. **리뷰 섹션 — 별점 + 실사용자 사진 + 핵심 문구 하이라이트("#리얼후기")**: 5성 평점,
   판매자 실제 사용 사진(토스터에 넣은 토스트, 완성된 빵 등), 리뷰 문장 내 핵심 구절에
   노란 형광펜 스타일 배경 강조("토스트 구워먹는게 너무 맛있어요", "겉바속촉을 즐길 수
   있어서 너무 행복해요"). **코드 대조 결과 2가지로 나뉨**:
   - 별점 + 실사용자 사진: 226차가 쿠팡 반려동물 크롤링에서 이미 동일 패턴을 발견해
     "입력 기근 + `ReviewHighlightSection`의 가짜 귀속 금지 원칙과 충돌"로 **채택 금지
     확정**한 바 있음(리뷰 파일은 텍스트만 파싱하고 평점·사진 필드가 없음, `reviewInsights`
     타입에 rating 필드 없음 — grep 확인). **재확인만, 결론 동일.**
   - **핵심 문구 인라인 하이라이트는 별개 발견**: 이건 "가짜 개인 귀속"이 아니라 **이미
     실제로 존재하는 집계 요약 텍스트(`praises`)의 타이포그래피 표현 방식**일 뿐입니다.
     `lib/review-insights.ts`(45~54행)의 `extractCoreKeywords()`가 이미 각 praise 문장에서
     핵심 키워드(2자 이상 토큰, 최대 4개)를 추출해 원문 리뷰 라인과 대조(`matchCount`
     계산)하는 데 쓰고 있습니다 — 즉 **"이 praise의 어떤 단어가 실제 리뷰에서도 확인됐는지"
     데이터가 이미 계산돼 있는데, 지금은 매칭 건수(배지)로만 쓰이고 텍스트 자체엔 시각적으로
     반영되지 않습니다.** 신규 입력·신규 AI 호출 없이 "표시 방식"만 바꾸면 되는 **진짜
     코드 격차** — 아래 §4에서 브리프로 분리.
2. **조리 가이드 표 하단 주의 문구 박스**("조리기준은 재료의 종류와 크기에 따라 상이할 수
   있습니다"): 스펙표가 아니라 "조리 시간 가이드"라는 가전(특히 오븐·에어프라이어류) 전용
   서브 패턴이라 Pagzly의 범용 `spec_table`로 일반화하기 애매함. **취향/입력부족 후보로만
   기록**(가전 세부 카테고리 전용 슬롯을 새로 만들 가치가 있는지는 차후 판단).
3. **부품 사용법 라벨 오버레이**(토스터 내부 "수분코팅" 점 마커 + 인출선): 구조적으로
   Pagzly의 `AnnotatedImageOverlay`(223차 export 복원 완료)와 동일한 패턴. **이미 해결됨,
   재작업 불필요.**
4. **히어로 스타일드 플랫레이 사진, 크루아상 김 나는 순간 촬영 등 고품질 라이프스타일
   사진**: 이건 코드가 아니라 **촬영/합성 품질 격차**(183차가 이미 "히어로/라이프 실사
   비중 확대"로 §4 API 필요 항목에 등록). **재확인만, 신규 아님.**

### (B) "수납함 상세페이지 디자인" — Sora Shin, 생활용품(수납함) 카테고리

제니바코 커버형 수납함.

1. **미니멀 타이포 히어로**(헤어라인 구분선 + 킥커 + 3줄 볼드 헤드라인, 사진 없이 순수
   타이포로 시작): Pagzly에 이미 `SectionAccentHairline`이 8개 섹션 타입에 배선돼 있음을
   grep으로 재확인. **이미 해결됨, 재작업 불필요.**
2. **실제 제품 사진 위에 치수선(20cm/44cm/25cm 화살표)을 직접 오버레이**: Pagzly의
   `lib/size-comparison-diagram.ts`를 읽어 대조한 결과, 현재는 **추상 실루엣 다이어그램**
   (제품을 단순 사각형으로 그리고 기준 캔 실루엣과 나란히 비교)이지, **실제 업로드 사진
   위에 치수선을 얹는 방식이 아닙니다.** 이 레퍼런스처럼 실사진 위에 정확히 겹치려면 사진
   속 제품의 실제 경계 좌표를 알아야 하는데, Pagzly는 이를 검출하는 메커니즘(오브젝트
   디텍션/좌표 보정 UI)이 없습니다 — 새로 만들려면 상당한 CV/UI 공수와 부정확한 오버레이로
   신뢰도를 해칠 리스크가 있습니다(217차 "컷아웃 형태 문제"와 비슷한 종류의 함정). **코드
   전용 버그가 아니라 구조적으로 더 큰 작업 — 이번 라운드는 후보로만 기록, 바로 착수하지
   않음**(158/159차 "공수 대비 이득" 판단 기준 적용).
3. **색상/무드 섹션 해시태그 뱃지**("#차분한무드 #깔끔함"): 226차가 이미 "취향, 낮은 우선순위"로
   기록한 것과 동일 패턴. **재확인만, 신규 아님.**
