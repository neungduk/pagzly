# 218차 — 211차 매칭 3축 보정 강도 보강 (코드 변경, 유료 API 0건 — 유닛 테스트로만 검증)

생성: 2026-09-17 · 217차 조사에서 컷아웃 형태 문제를 확인한 뒤, 사용자가 216차
원인 후보 (1) "매칭 강도 부족"을 이어서 진행하기로 선택. **이번 라운드는 유료
생성 API를 전혀 쓰지 않습니다** — 기존 `scripts/211cha-lifestyle-matching-verify.ts`
같은 순수 함수 유닛 테스트만으로 검증 가능한 범위로 스코프를 제한했습니다.

## 배경 — 왜 이 3개 상수인가

216차 electronics 케이스(상품컷의 강한 블루/오렌지 스튜디오 조명 vs. 배경의 어둡고
중립적인 조명)를 육안 검증한 결과, 색온도 매칭이 걸렸음에도 격차를 거의 흡수하지
못했습니다. `lib/photo-composite.ts`를 읽어 원인을 코드로 확인했습니다 —
`matchCutoutWhiteBalance()`가 **의도적으로 매우 보수적인 상한**을 걸고 있습니다:

```ts
const colorMix = 0.22;      // 채널별 색 보정 강도
const lumMix = 0.14;        // 전체 밝기 보정 강도
const contrastMix = 0.16;   // 콘트라스트 보정 강도
const clampScale = (s) => Math.max(0.82, Math.min(1.18, s));   // 채널 스케일 상한 ±18%
const clampContrast = (s) => Math.max(0.88, Math.min(1.15, s)); // 콘트라스트 상한
```

즉 배경과 상품컷의 색이 아무리 크게 달라도, 채널별 보정은 최대 ±18%까지만 적용되게
클램프돼 있습니다. 216차 케이스처럼 격차가 큰 조합에서는 이 상한이 보정 효과를
사실상 무력화합니다. 주석에 적힌 원래 의도("제품 고유 색이 과하게 왜곡되지 않게")는
유효한 우려이므로, **완전히 풀지 않고 상한을 넓히는 선에서** 절충합니다.

`matchCutoutGrain()`도 비슷하게 `unifyCompositeGrain()`의 기존 상수(0.045)를
넘지 않도록 알파를 0.02~0.05로 캡핑하고 있어, 실제 사진의 거친 암부 그레인 대비
매칭 효과가 미미합니다.

**`matchCutoutSharpness()`는 이번 스코프에서 제외**합니다 — 216차에서 관찰된
"가장자리가 이질적으로 보임" 문제는 이 함수의 보정 강도 부족이 아니라, unreliable
placement로 인한 위치/스케일 어긋남(216차 브리프가 이미 알려진 원인으로 지목)에서
온 것으로 보이고, 이 함수는 구조적으로 배경이 더 흐릴 때만 흐리게 하는 단방향
함수라 "강도"를 올리는 것만으로 해결되는 문제가 아닙니다. 건드리면 별도 스코프가
필요합니다.

## 정확히 지킬 것

1. **`lib/photo-composite.ts`의 `matchCutoutWhiteBalance()`만** 상수를 다음과 같이
   변경하세요 (로직 구조는 그대로, 숫자만 조정):

   | 상수 | 현재 | 변경 |
   |------|------|------|
   | `colorMix` | 0.22 | **0.34** |
   | `lumMix` | 0.14 | **0.20** |
   | `contrastMix` | 0.16 | **0.24** |
   | `clampScale` 범위 | [0.82, 1.18] | **[0.70, 1.32]** |
   | `clampContrast` 범위 | [0.88, 1.15] | **[0.80, 1.25]** |

   함수 상단 주석에 "218차 — 매칭 강도 보강, 상한 확대(216차 극단 색역 케이스
   대응)"를 한 줄 추가하세요.

2. **`matchCutoutGrain()`**의 알파 범위만 조정하세요:

   | 상수 | 현재 | 변경 |
   |------|------|------|
   | 알파 범위 | 0.02~0.05 | **0.03~0.07** |

   `unifyCompositeGrain()`의 0.045를 상한으로 삼는다는 기존 주석은 더 이상
   맞지 않으니, "218차 — 실사진 배경의 거친 그레인 대비를 더 잘 흡수하도록 상한을
   `unifyCompositeGrain` 기준값(0.045)보다 높임"으로 주석을 갱신하세요.
   `skipThreshold`(2.2)는 건드리지 마세요 — 배경이 매끈할 때 스킵하는 기준은
   이번 스코프 밖입니다.

3. **`matchCutoutSharpness()`, `lib/detect-held-object-placement.ts`(세이프가드),
   `lib/lifestyle-product-composite.ts`는 손대지 마세요.** 이번 변경은
   `lib/photo-composite.ts`의 위 두 함수 내부 상수만 대상입니다.

4. **유료 생성 API 호출 절대 금지** — Replicate/Claude Vision/DeepSeek 어느 것도
   호출하지 마세요. 이번 라운드는 순수 함수 유닛 테스트로만 검증합니다.

5. **`scripts/211cha-lifestyle-matching-verify.ts`를 그대로 실행**해 기존
   회귀가 없는지 확인하세요. 단, 이 스크립트의 129~133행은 프로덕션 코드의
   grain alpha 공식을 스크립트 안에 그대로 복제해 재계산하는 방식이라, 알파 범위
   상수가 바뀌면 이 부분(`const alpha = 0.02 + t * 0.03;`과 범위 assert)도
   **새 상수(0.03 + t * 0.04, 범위 0.03~0.07)에 맞춰 함께 갱신**해야 정상
   통과합니다 — 프로덕션 로직을 바꾼 게 아니라 테스트가 그 로직을 그대로
   따라가는 것뿐임을 유의하세요.

6. **새 유닛 테스트 케이스를 추가**하세요 (`scripts/211cha-lifestyle-matching-verify.ts`에
   이어 쓰거나 `scripts/218cha-matching-intensity-verify.ts`로 신규 작성 — 편한
   쪽으로 선택, 단 기존 스크립트는 보존):
   - **극단 색역 케이스** (216차 실제 상황 재현): 배경은 어둡고 중립적인 회색
     계열(예: RGB 40,40,45 유사), 컷아웃은 파랑/주황이 섞인 강한 색(예: 파란
     절반 + 주황 절반, 또는 채널 편차가 큰 그라디언트)로 합성 이미지를 만들어
     `matchCutoutWhiteBalance()`를 적용하고, **보정 전후 컷아웃 평균색과 배경
     평균색 사이의 유클리드 거리(RGB space)** 를 계산해 "변경 전 상수 기준
     거리"보다 **뚜렷이(최소 30% 이상) 줄어드는지** assert 하세요. (변경 전
     기준값은 하드코딩하지 말고, 같은 테스트 안에서 이전 상수 값으로 한 번 더
     계산해 두 결과를 직접 비교하는 방식을 권장합니다 — 그래야 "실제로 더
     보정됐다"를 상수와 무관하게 증명할 수 있습니다.)
   - **회귀 케이스** (이미 잘 맞는 조합): 배경과 컷아웃 색이 이미 비슷한
     경우(예: 기존 스크립트의 `smoothGradient` 계열)에 새 상수를 적용해도
     결과가 "과보정"으로 튀지 않는지 — 예컨대 보정 후 컷아웃 평균색이 배경
     평균색을 오버슈트(역전)하지 않는지를 assert 하세요. 이 케이스가 이번
     변경에서 가장 중요한 안전장치입니다 — 화장품처럼 상품 고유색이 중요한
     카테고리에서 과보정이 나타나면 218차는 되돌려야 합니다.
   - 그레인도 마찬가지로 거친 텍스처 배경 케이스에서 새 알파 범위(0.03~0.07)
     안에 실제로 들어오는지 assert 하세요.

7. 모든 유닛 테스트가 통과할 때까지 이번 라운드를 완료로 보고하지 마세요.
