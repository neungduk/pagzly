# 116차 — 카피 톤·리듬 고도화 (후커블 격차 해소, 신규 영역)

생성: 2026-09-04
전제: 프로가 "후커블과 퀄리티가 비슷하게 나오도록 다음 지시사항을 알아서 정해달라"고 요청했습니다. 97~115차는 전부 **이미지**(사이즈·중복·역할·합성·다이어그램·배경·로고) 쪽이었고, **카피(문장) 품질은 이 프로젝트 전체에서 아직 한 번도 다룬 적이 없습니다.** 제가 `lib/copy-orchestrator/*` 코드를 직접 열어 확인한 결과, 실제로 손대지 않은 채 방치돼 있었습니다.

---

## 1. 확인한 현재 상태

`lib/copy-orchestrator/claude-structure.ts`의 시스템 프롬프트(라인 65-95)를 보면 `copyTone` 필드가 그냥 `"copyTone": "..."` 로만 정의돼 있고, **어떤 톤이어야 하는지에 대한 기준이 프롬프트 어디에도 없습니다.** Claude가 알아서 아무 문자열이나 채웁니다.

그 결과를 그대로 받는 `lib/copy-orchestrator/deepseek-copy.ts`의 `buildDeepSeekPrompt`(라인 52-119)도 마찬가지입니다. 환각 금지 규칙(`buildAntiHallucinationBlock`)은 꼼꼼하지만, **문장이 어떻게 읽혀야 하는지에 대한 지시가 전혀 없습니다.** "짧고 리듬감 있게", "진부한 문구 금지" 같은 것도 없어서, 지금 나오는 카피가 일반적인 "AI가 쓴 티 나는" 문장(예: "당신을 위한 완벽한 선택", "이제 고민은 그만" 류의 상투구)이 되기 쉬운 구조입니다. 후커블 레퍼런스가 갖는 인상 — 짧고 임팩트 있는 헤드라인, 감각적인 단어 선택, 문장 리듬의 강약 — 은 지금 프롬프트로는 우연히만 나옵니다.

참고로 `lib/copy-orchestrator/pipeline.ts`를 보면 이 두 호출(Claude 구조 + DeepSeek 카피)은 **`TEST_MODE`와 무관하게 항상 실제로 호출됩니다**(이미지 생성만 TEST_MODE로 막혀 있음). 즉 이번 작업의 검증은 원래도 실비용(센트 단위)이 드는 부분이라, 별도로 "저비용 검증 스크립트"를 새로 만들 필요 없이 기존 파이프라인을 텍스트만으로 직접 호출하면 됩니다.

## 2. 고칠 것

### (a) `claude-structure.ts` — `copyTone`을 구체화하도록 지시

시스템 프롬프트에 톤 판단 기준을 추가하세요. 막연히 "친근한 톤" 같은 한 단어가 아니라, **이 상품에 맞는 구체적 스타일 앵커 2~3개**를 뽑도록 하세요. 예: "미스트 제품이면 '가볍다/산뜻하다' 계열의 감각 어휘를 헤드라인 축으로 삼을 것" 같은, 상품 사실에 근거한 구체적 지시. 추상적인 형용사 나열이 아니라 **문장에 실제로 쓸 수 있는 앵커**여야 합니다.

### (b) `deepseek-copy.ts` — 문체 루브릭 블록 추가

`buildDeepSeekPrompt`에 새 섹션을 추가하세요(환각 금지 블록과 같은 위치, 별도 섹션으로):

- **헤드라인은 짧게**: `mainHeadline`은 한국어 기준 대략 25자 내외, 한 문장에 개념 하나만. 줄바꿈했을 때도 리듬이 살아야 함.
- **추상적 형용사 대신 구체적 어휘**: "최고의", "완벽한", "특별한", "놀라운" 같은 빈 형용사보다, 입력된 사실(성분/질감/사용 장면)에서 나온 구체적 단어를 쓰도록.
- **문장 리듬 변화**: 같은 길이의 문장을 반복하지 말고 짧은 문장과 긴 문장을 섞도록.
- **진부한 AI-카피 클리셰 금지 목록을 프롬프트에 명시**: "이제 고민은 그만", "당신을 위한 선택", "새로운 시작", "여기 있습니다", "지금 바로 만나보세요" 류의 상투구를 예시로 나열하고 피하라고 지시.
- 이 블록은 어디까지나 **문체 지시**이며, 기존 환각 금지 규칙(`buildAntiHallucinationBlock`)은 절대 건드리지 마세요 — 그대로 유지.

### (c) 진부함 감지 — 재시도 트리거 확장 (경량, 신규 API 호출 없음)

`lib/copy-orchestrator/validate-copy.ts`에 이미 `detectCopyHallucinations` 같은 패턴이 있으니 같은 스타일로 `detectGenericCliches(copy: DetailPageCopy): string[]` 순수 함수를 추가하세요. (b)의 클리셰 목록을 정규식으로 검사해, `mainHeadline`/`subHeadline`/`cta`에 클리셰가 걸리면 경고를 반환합니다.

`generateDetailCopyWithDeepSeek`에 **이미 있는 재시도 로직**(라인 185-201, 스키마 검증 실패 시 1회 재시도)의 트리거 조건에 "클리셰 2개 이상 감지"도 추가하세요. **새 호출을 추가하는 게 아니라 기존 최대-1회-재시도 한도 안에서 조건만 넓히는 것**입니다 — 총 호출 수는 지금과 동일(최대 2회)하게 유지하세요.

## 3. 하지 않는 것

- 상품 생성(이미지) 실행 금지. `TEST_MODE=true` 유지 — 단, 이건 원래 이미지 쪽 얘기고 이번 작업의 텍스트 호출과는 무관합니다.
- 기존 `buildAntiHallucinationBlock`/환각 검증 로직을 수정하지 마세요. 이번 건 순수 문체 개선입니다.
- 재시도 횟수를 2회 초과로 늘리지 마세요(비용 통제, 기존 한도 유지).
- 클리셰 목록을 이유로 카피 내용(사실 관계)까지 바꾸지 마세요 — 표현만 다듬는 것.
- 새 모델이나 새 API를 추가하지 마세요. 기존 Claude 구조 호출 + DeepSeek 호출 프롬프트만 강화합니다.

## 4. 검증 방법

**무비용**
- `detectGenericCliches` 단위 테스트: 클리셰 포함 카피 픽스처 → 감지됨 / 클리셰 없는 카피 픽스처 → 통과.
- `npx tsc --noEmit` 0건.
- 프롬프트 dry-run(문자열 조립 결과만 확인, API 미호출)으로 (a)/(b) 지시문이 실제로 들어갔는지 확인.

**소액 실비용 (기존에도 발생하던 비용 — 새로 승인받을 필요 없음, 다만 보고는 해주세요)**
- `runDetailCopyPipeline`을 테스트 상품 데이터(예: 기존 글로위스트 데이터) 1~2건으로 직접 호출해 실제 출력 카피를 `review/116cha-copy-samples.md`에 저장하세요.
- 개선 전/후 카피를 나란히 비교해서 보고하세요 — 실제로 헤드라인이 짧아지고 클리셰가 줄었는지 육안 확인이 핵심입니다.
- 이 호출들의 실제 비용(Claude+DeepSeek, 보통 상품당 몇 센트 수준)을 합산해 보고하세요.
