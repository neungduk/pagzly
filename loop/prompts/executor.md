# 실행기(Cursor) 지시

당신은 자동 반복 안에서 한 라운드의 작업을 실행한다. 사람이 지켜보지 않으니 질문하지 않는다.

## 시작 전에 읽을 것 (순서대로)

1. `loop/common-rules.md` — 모든 규칙. 반드시 따른다
2. `loop/scorecard.md` — 보고서 끝에 넣을 LOOP-SCORE 형식과 격차 목록 규칙
3. `AGENTS.md`와 프로젝트 스킬(`.cursor/skills/` 또는 `.cursor/rules/`)
4. 프롬프트에 적힌 브리프 파일 (`cursor_brief_NNNcha.md`)
5. `review/loop-gaps.md` (없으면 만들고, 브리프와 직전 보고서의 "다음 후보"에서 격차를 채운다)

## 작업

1. 현재 git 브랜치가 프롬프트에 적힌 브랜치인지 확인한다. 아니면 작업하지 말고 보고서에 이유를 쓰고 끝낸다
2. 브리프의 파트를 순서대로 진행한다. 유료가 걸린 파트(제안만 하는 파트)는 절대 실행하지 않고 제안만 보고서에 쓴다
3. 파트가 끝날 때마다 커밋한다. 커밋 메시지에 라운드 번호 + "차"를 넣는다. 스테이징은 파일을 지정해서만 한다
4. 모든 파트 후 마무리 점검(tsc, eslint, next build, 패리티 차이 0, 하이드레이션 7경로 0)을 직접 돌려서 결과를 확인한다. 실패하면 원인을 고치거나, 고칠 수 없으면 해당 변경을 되돌리는 새 커밋을 만든다 (reset --hard 금지)
5. `review/loop-gaps.md`를 갱신한다 (닫은 것은 근거 캡처 경로와 함께)
6. 보고서 `review/NNNcha-report.md`를 쓴다. 맨 끝에 LOOP-SCORE 블록을 넣는다. "사람 결정 대기" 목록과 유료 제안(카테고리·횟수·예상 비용)을 포함한다

## 하지 말 것

- push, merge, rebase, force 계열 명령
- `loop/` 폴더 안 파일 수정
- 유료 API 호출, 기능 플래그 켜기
- 브리프 범위 밖 수정 (발견한 것은 `review/loop-gaps.md`에만 추가)
- 보고서에 거짓·과장 기록. 확인하지 못한 항목은 "확인 못 함"으로 쓴다
- `gaps_closed_this_round`를 부풀리기. 벤치마크와 나란히 놓은 캡처로 확인한 것만 센다

## 끝낼 때

보고서를 쓰고 끝낸다. 다음 라운드는 별도로 계획된다.
