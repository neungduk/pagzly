# 품질 점수표 (LOOP-SCORE)

자동 반복이 "정말 나아지고 있는지"를 숫자로 확인하고, 나아지지 않으면 멈추기 위한 표다.

## 보고서 맨 끝에 넣는 블록 (형식 고정)

보고서 맨 끝에 아래 형식 그대로 넣는다. 한 줄에 `키: 숫자` 하나씩, 줄 앞에 다른 글자를 붙이지 않는다. 스크립트가 이 줄을 읽어서 계속할지 멈출지 정한다.

```
LOOP-SCORE
gaps_closed_this_round: 0
gaps_open: 0
parity_diff: 0
hydration: 0
paid_calls: 0
```

| 키 | 뜻 | 계속 조건 |
|---|---|---|
| gaps_closed_this_round | 이번 라운드에 닫은 격차 수 (`review/loop-gaps.md` 기준) | 0이 연속으로 2번 나오면 멈춤 |
| gaps_open | 무료로 고칠 수 있는 열린 격차 수 | 참고용 |
| parity_diff | 라이브↔export 글자 패리티 차이 건수 | 0이어야 함 |
| hydration | 하이드레이션 경고 수 (7경로 합계) | 0이어야 함 |
| paid_calls | 이번 라운드의 유료 API 호출 수 | 0이어야 함 |

## 격차 목록 (`review/loop-gaps.md`)

- 알려진 디자인 격차를 한 줄에 하나씩 적는 표다. 열: 번호, 격차, 영향(높음/중간/낮음), 난이도, 상태(열림/닫힘/사람 결정 대기/유료 필요), 근거(벤치마크 캡처·수치), 닫은 라운드
- "닫힘"은 **벤치마크와 나란히 놓은 캡처로 격차가 사라졌음을 확인한 경우에만** 쓴다. 코드를 바꿨다는 이유만으로 닫지 않는다
- 새로 발견한 격차는 고치지 말고 표에 추가한다 (범위 밖 작업 금지)
- "사람 결정 대기", "유료 필요" 상태는 `gaps_open`에 세지 않는다 (자동으로 못 닫기 때문)
- 라운드 시작 때 이 표를 읽고, 끝날 때 갱신한다. 이 표가 플래너의 다음 브리프 근거가 된다

## 멈춤 조건 (스크립트가 자동으로 확인)

1. `loop/STOP` 파일이 있다
2. 시간 상한(config.maxHours) 도달
3. LOOP-SCORE가 없거나 형식이 틀렸다
4. parity_diff, hydration, paid_calls 중 하나라도 0이 아니다
5. 검증 명령(tsc, eslint, build, parity)이 하나라도 실패했다
6. 금지된 파일이 커밋에 들어갔거나 보호 파일이 바뀌었다
7. 유료·인물 검출 플래그가 false가 아니다
8. `gaps_closed_this_round`가 연속 2라운드 0이다
9. 플래너가 "무료로 할 일이 없다"며 `loop/DONE.txt`를 썼다
