## 3. 목표 (코드 전에 확정, 낮추지 않는다)

- 진한 면: lightOnly·tintAlt 6종 평균 ≤15%·최악 ≤25%, **전면 스크림 배너 0개/페이지**(①′, 이 둘은 의도된 진한 성격이라 제외) / blockAlt(impact) 평균 25~45% / colorCollide(pop) 평균 30~55%.
- 읽히는 초점 비율 중앙값: 강도 5 ≥ 2.6 / 강도 4 ≥ 2.2 / 강도 3 ≥ 1.9.
- 구도: 단일 컬럼 ≤ 0.55, 풀블리드+비대칭 ≥ 0.30, 겹침 ≥ 0.25.
- 빈 틀: 폴백 틀 최대 높이 ≤ 320px, 사진 수 < 틀 수 섹션에서 폴백 틀이 사진 틀보다 큰 경우 0건.
- 틀 종류 비율 ≥ 0.7.

## 4. `clamp()` / `cqi` 조사 (B-4)

- export는 이미 `clamp(2.25rem,11cqi,4.25rem)`(키워드), `titleFitCss`의 `pz-fit`(`min(var(--pz-fs), calc(100cqi / var(--pz-fit-em)))`)을 쓰고, 래퍼 `.pagzly-wrap{container-type:inline-size}`로 `cqi`가 동작한다. 라이브 컴포넌트도 컨테이너 쿼리 변수(`--pz-t-section-b`)를 쓴다. 즉 **레포는 clamp/cqi를 쓴다**.
- 그러나 V5 임팩트·v4 블록 마크업은 라이브·export 문자열 한 벌이고 이 블록 루트에는 `container-type`이 없다(래퍼에는 있음). 라이브가 같은 `cqi` 환경인지 확신이 없어, 이번엔 **입력 글자 수·가장 긴 어절 길이로 고르는 결정적 단계 함수**(px 고정)를 쓴다 — `cqi` 의존이 없고 PNG 복제 경로에서도 같다. 단계는 320폭 안전(가용 폭 272px = 320 − 좌우 24px 패딩)에서 `가장 긴 어절 글자 수 × 폭계수 × px ≤ 272`로 상한을 둔다(한글 1.0em, 라틴 대문자 .72em, 소문자·숫자 .6em, 자간 보정은 포함하지 않고 안전 쪽).

## 5. photo-fallback 조사

- `lib/photo-fallback.ts`: 사진 로드 실패 시 틀(overflow:hidden 부모)에 `data-pz-np`를 달고 CSS가 `deepAccent` 틴트 α.08 + 흰 α.09 + 사선(어두운 α.10 1px / 밝은 α.14 1px, 14px 주기)을 깐다. 틀에 aspect-ratio가 없으면 실패한 사진 상자 비율을 예약한다. export는 문서 머리 error 캡처 리스너(**런타임 판정**), 라이브는 `watchNoPhotoFrames`. 서버 측 판정은 없다.
- 대비: 틴트 α.08 + 선 α.10은 면과의 대비가 약 1.05~1.1:1 → 눈에 거의 안 보이는 "거의 무색"(평가 4번과 일치). 높이 상한 없음 → 3:4 틀 576폭이면 768px.
- gallery/mosaic/polaroid는 `<img>` 개수만큼 타일을 만들고 실패해도 타일 수는 줄지 않는다(런타임 판정이라 정적으로 알 수 없음).
- 결정(Phase 4): V5 켜짐에서만 `[data-pz-np]`에 `max-height:280px!important`, 줄무늬 대비 상향, 사진 수 부족(정적으로 알 수 있는 경우 — 사진 URL이 비는 경우)엔 타일 수를 사진 수에 맞춘다. 기준(꺼짐)의 같은 문제는 **기존 결함, V5 한정 수정, 꺼짐 수정은 별도 결정**.
